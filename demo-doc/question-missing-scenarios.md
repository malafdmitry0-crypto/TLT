# Вопрос к заказчику: недостающие пользовательские сценарии

## Контекст

Функциональный аудит текущего контура показал: **полный цикл работы инженера покрыт**
(создание проекта → добавление объектов → теплорасчёт → подбор кабеля →
спецификация → отчёт). Однако найдены **11 сценариев**, которые еще не
реализованы. Не все из них нужны всем заказчикам — ниже они сгруппированы
по приоритетам с оценкой трудозатрат.

**Просьба:** отметить какие сценарии актуальны, какие второстепенны, какие
не нужны. Это определит бэклог следующей очереди.

---

## 🔴 Блокеры для «Полной версии»

### UC-A. Расчёт **резистивных** кабелей (однопроводный / трёхпроводный)

**Актор:** Инженер-проектировщик.
**Сценарий:** На объектах с высокой требуемой мощностью (> 100 Вт/м) или
при магистральном обогреве саморегулирующийся кабель не подходит, нужен
резистивный постоянной мощности (ТРМ, ТСОЭ).

**Что сейчас:** В UI пункт `single_core` есть в выпадающем списке, но
API возвращает 400 «поддерживается только self_regulating».
Формула-заглушка в `backend/app/formulas/electrical/resistive.py`.

**Оценка:** 3–5 дней (формула + тесты + UI).

---

### UC-B. Расчёт **кабелей с минеральной изоляцией** (MI)

**Актор:** Инженер, работающий с высокотемпературными средами (> 250°C).

**Сценарий:** Обогрев промышленного оборудования при T продукта выше
возможностей самрег/резистивных кабелей.

**Что сейчас:** Аналогично UC-A — заглушка в `mineral.py`.

**Оценка:** 5 дней.

---

## 🟡 Удобство / ускорение работы (Should)

### UC-1. Копирование проекта как шаблона

**Актор:** Сотрудник.
**Сценарий:** «У меня в 2024 году был проект 50 труб на ДНС-7. В 2025 делаю
ДНС-8 — 80% объектов те же, просто другой адрес. Хочу скопировать ДНС-7,
переименовать, поправить 20% отличий».

**Что сейчас:** Невозможно. Обходной путь — экспорт объектов в Excel
старого проекта → новый проект → импорт → правки. 4 клика + открытие 2
окон.

**Оценка:** 1 день (endpoint `POST /projects/{id}/duplicate` + UI-кнопка).

---

### UC-2. Inline-редактирование ячеек таблицы

**Актор:** Любой инженер.
**Сценарий:** «В таблице труб вижу что для трубы №3 изоляция 50 мм,
а нужна 80. Хочу кликнуть в ячейку `δ_из` и сразу исправить, без
открытия мастера на 3 шага».

**Что сейчас:** Только через `Edit` → Modal-мастер → 3 клика.

**Оценка:** 2–3 дня (добавить `editable` в antd Table + валидация +
debounced автосохранение). **Связка с US-09.13** (копипаст диапазонов
ячеек из Excel — зависит от inline-edit).

---

### UC-3. История изменений коэффициентов (audit log)

**Актор:** Администратор + контролирующие органы.
**Сценарий:** «Вышел новый норматив — меняю `safety_factor` с 1.1 на 1.2.
Через полгода аудитор спрашивает: когда и кто менял? Как обосновать
проекты, рассчитанные до и после?»

**Что сейчас:** Нет лога изменений. В БД хранится только текущее значение.

**Оценка:** 1 день (таблица `coefficient_history` + endpoint + UI-панель
«История» в админке).

**⚠️ Может быть критично** для ГОСТ-аккредитации или ISO-сертификации.

---

### UC-4. Уведомление при истечении сессии

**Актор:** Любой пользователь.
**Сценарий:** Пользователь отошёл на 40 минут. Возвращается, правит объект
— данные пропадают, молча редиректит на /login. Неприятный опыт.

**Что сейчас:** При 401 клиент просто редиректит. Никакого Alert.

**Оценка:** 0.5 дня (модалка «Сессия истекает, нажмите продлить»).

---

### UC-5. Выборочный экспорт отчёта (мастер разделов)

**Актор:** Сотрудник.
**Сценарий:** «Мне для тендера нужен отчёт без раздела «Теплотехнический
расчёт» — только спецификация и титул».

**Что сейчас:** Экспортируется всё целиком, убирать разделы вручную в Word.

**Оценка:** 1 день (чекбоксы на ReportPage + параметр `sections=[...]` в API).

---

## 🟢 Качество жизни (Could)

### UC-6. Комментарии / примечания к объекту

**Актор:** Инженер.
**Сценарий:** «Для трубы №5 заказчик сказал "проверить диаметр, возможно
125 мм". Хочу сохранить это замечание рядом с объектом, чтобы не забыть».

**Что сейчас:** Использовать поле `name` (захламит наименование).

**Оценка:** 0.5 дня (поле `notes: str | None` в `params`).

---

### UC-7. Split-view сравнения вариантов СО1..СО4

**Актор:** Инженер.
**Сценарий:** «Хочу видеть СО1 и СО2 бок о бок: одна таблица слева, другая
справа — сразу вижу разницу по току / мощности / длине кабеля».

**Что сейчас:** Только переключатель — видите один вариант за раз.

**Оценка:** 2 дня (React split-layout + синхронная прокрутка + diff-подсветка).

---

### UC-8. Архивирование проектов (мягкое удаление)

**Актор:** Сотрудник / менеджер проектов.
**Сценарий:** «У меня 500 старых проектов, 90% не нужны для работы.
Хочу архивировать — пропадают из списка по умолчанию, но данные
сохранены».

**Что сейчас:** Только удаление (необратимо, CASCADE). Фильтр по году
`completed` частично решает.

**Оценка:** 1 день (флаг `is_archived` + фильтр + действие).

---

### UC-9. Копирование СО1 → СО2 как стартовая точка

**Актор:** Инженер.
**Сценарий:** «СО1 посчитан с ТЛТ-25. Хочу СО2 сделать как копию СО1,
потом поменять на ТЛТ-40 — быстрее чем считать с нуля».

**Что сейчас:** Для каждого варианта всё считается с нуля.

**Оценка:** 0.5 дня (endpoint `POST /electrical/variant/{from}/copy-to/{to}`).

---

### UC-10. Выгрузка объектов в Excel из UI

**Актор:** Сотрудник.
**Сценарий:** «Хочу скачать список моих труб в Excel — поделиться с коллегой
или сохранить копию».

**Что сейчас:** Backend-endpoint готов (`GET /objects/export-excel`), но
UI-кнопки нет. US-09.2 в бэклоге отмечена как «частично ✅».

**Оценка:** 0.5 дня (одна кнопка на HeatCalcPage).

---

### UC-11. Кастомные материалы изоляции / кабели без пересборки

**Актор:** Администратор.
**Сценарий:** «Появился новый материал "аэрогель-X", λ=0.018. Хочу добавить
через админку, не ждать обновления системы».

**Что сейчас:** Материалы зашиты в `backend/app/reference_data/insulation.json`.
Админка для `cables_extended` есть, но расширенных материалов изоляции нет.

**Оценка:** 1 день (таблица `insulation_extended` + CRUD в админке).
