# Раздел I. Режим «Пользователь» (без регистрации)

## Почему мы задаём эти вопросы

В ходе доработки режима «Пользователь» мы упростили флоу до схемы
«зашёл → посчитал → ушёл»: один авто-проект, 20 минут неактивности → данные
удаляются. Это повышает приватность и снижает нагрузку на БД, но **расходится
с буквой ТЗ** (п. 4.2.1 — «создать новый проект»), где явно упоминается
возможность создания проектов пользователем.

---

## Вопрос 1. Сколько проектов может быть у одного пользователя одновременно?

### Контекст

- **ТЗ (п. 4.2.1):** «Создать новый проект» — функция пользователя без
  указания лимита.
- **Сейчас:** ровно 1 авто-проект, создаётся при входе. Второй — запрещён.
- **Риск без лимита:** один клиент/бот может создать тысячи проектов.

### Варианты

| Вариант | Описание | Плюсы | Минусы |
|---|---|---|---|
| **A** | **1 проект** (текущая реализация) | Максимально простой UX. Минимум мусора в БД | Неудобно вести несколько объектов параллельно |
| **B** | **Без лимита** | Полное соответствие ТЗ | Риск DoS, захламление БД |
| **C** | **Фиксированный лимит N (3 / 5 / 10)** | Баланс | Нужно выбрать N |

### Рекомендация команды

**Вариант C, N = 5.** Достаточно для работы, ограничено настолько, что
бот-атака бессмысленна.

### Ответ заказчика

> ☐ A (1 проект) ☐ B (без лимита) ☐ C: N = ______ ☐ Свой вариант: ______________

## Вопрос 2. Видит ли пользователь список своих проектов?

### Контекст

Если у пользователя может быть >1 проекта, нужен способ переключаться
между ними. ТЗ (п. 4.3.5) «Проводник проектов» — функция **сотрудника**.

### Варианты

| Вариант | Описание |
|---|---|
| **A** | Дропдаун в шапке (макс N проектов). Кнопки «Новый» / «Удалить» внутри |
| **B** | Полноценный `/projects` как у сотрудника, но только свои |
| **C** | Только первый активный проект; переключение через API |

### Рекомендация

**Вариант A (дропдаун в шапке).** Если по вопросу 1 — А (1 проект), не актуально.

### Ответ заказчика

> ☐ A (дропдаун) ☐ B (полноценная страница) ☐ C (один активный) ☐ Не актуально

### Контекст

### Варианты

| **C** | Диалог: «Продолжить прошлый сеанс?» / «Начать заново» |

### Рекомендация

**Вариант B.** UX «случайно закрыл вкладку» — частый кейс.

### Ответ заказчика

## Вопрос 4. Подтверждаете ли авто-очистку «20 мин неактивности → удаление»?

### Контекст

Ваше требование: «Не позднее чем через 10 мин вся информация должна чиститься».
Реализация:
- `GUEST_SESSION_TTL_MINUTES = 20` (протухание)
- `GUEST_CLEANUP_INTERVAL_MINUTES = 10` (фоновая очистка)

Максимум времени жизни после ухода: ~30 мин.

### Варианты

| Вариант | TTL | Интервал | Макс. время после ухода |
|---|---|---|---|
| **A** | 20 мин | 10 мин | ~30 мин (текущее) |
| **B** | 10 мин | 2 мин | ~12 мин (строго по вашему требованию) |
| **C** | 5 мин | 1 мин | ~6 мин (агрессивно) |

### Рекомендация

**Вариант A.** Слишком агрессивная очистка (C) рискует удалить данные
отвлёкшегося пользователя.

### Ответ заказчика

> ☐ A (20/10) ☐ B (10/2) ☐ C (5/1) ☐ Другие: TTL = ___ мин, интервал = ___ мин

## Вопрос 6. Защита от DoS-атак через пользовательский режим

### Контекст

Пользовательский режим **анонимный** — злонамеренный пользователь может
перегрузить приложение массой сессий, проектов, объектов, тяжёлых расчётов.

### Поверхности атаки сейчас

| Поверхность | Защита | Риск |
|---|---|---|
| Создание сессий | Rate limit 10/IP/час (in-memory) | Средний: VPN даёт новые IP |
| Создание проектов | `GUEST_MAX_PROJECTS=1` | Низкий (при N=1) |
| Создание объектов | `MAX_OBJECTS_PER_PROJECT=50` | Средний |
| Импорт Excel/CSV | Нет лимита размера | **Высокий**: 10 МБ × 10k строк |
| Пакетный расчёт | Нет rate limit | Средний |
| Cleanup сессий | Раз в 10 мин | Окно для взрывного роста |

### Варианты

| Вариант | Что добавить | Стоимость |
|---|---|---|
| **A. Минимум** | Лимит файла 500 КБ, rate limit на batch 10/мин/сессия, `MAX_OBJECTS_TOTAL=100` на сессию | 0.5 дня |
| **B. Полноценный** | + Redis rate limiter + лимит по сессии 100 req/мин + CAPTCHA | 2–3 дня |
| **C. Жёсткий** | + email/SMS-верификация (отменяет анонимность) | 5+ дней |

### Рекомендация

**Вариант A немедленно** (дешёвые векторы закрыты). **B** — следующей очередью, если
приложение выставляется во внешнюю сеть. **C** — если бизнес готов отказаться
от анонимности.

### Ответ заказчика

> ☐ A (минимум) ☐ B (полноценный) ☐ C (отказ от анонимности) ☐ Принять риск

**Если A — согласуете ли пороги?**
> Размер файла импорта: ___ КБ (рекомендация 500)
> Строк в импорте: ___ (рекомендация 2000)
> Batch-расчётов/мин/сессия: ___ (рекомендация 10)
> Объектов суммарно/сессия: ___ (рекомендация 100)

# Раздел III. Формат выгрузки спецификации

## Контекст

В текущем контуре реализовано:
- **Просмотр на экране** — `Шаг 3 → Спецификация` (все роли).
- **Полный отчёт** в PDF / DOCX / XLSX (сотрудник). Отчёт содержит 5 разделов,
  включая спецификацию.

Вопрос: нужна ли **отдельная** выгрузка только спецификации в Excel и/или Word?

---

## UC-S1. Выдача проектной документации

**Сценарий:** Инженер формирует **полный отчёт** в PDF, передаёт заказчику.

**Достаточно ли сейчас?** ✅ Да. **Нужна отдельная спека?** ❌ Нет.

---

## UC-S2. Передача в отдел закупок / сметный

**Сценарий:** Менеджеру по закупкам нужна **только таблица позиций**, без
расчётов. Копируется в ERP / 1С / смету.

**Сейчас:** Открывают XLSX отчёта, вычищают лишние страницы. На 5–10 проектов
в месяц — терпимо; на 50+ — раздражает.

**Нужна отдельная?** ✅ Да, если этот сценарий встречается.

---

## UC-S3. Согласование с заказчиком до полного отчёта

**Сценарий:** Заказчик просит «показать, что будем ставить». Инженер шлёт
**только спецификацию** (Word) → правки → утверждение → полный отчёт.

**Сейчас:** PDF всего отчёта избыточен. Скриншот не подходит для правок.

**Нужна отдельная?** ✅ Да, желательно в **Word** (для комментариев).

---

## UC-S4. Включение в тендерную документацию

**Сценарий:** В тендер идёт **таблица спецификации** с артикулами — без
упоминания ПО и внутренних расчётов. Стандарт — Excel.

**Сейчас:** Ручное копирование из полного отчёта в шаблон.

**Нужна отдельная?** ✅ Да, в **Excel**.

---

## UC-S5. Архивная копия

**Сценарий:** После сдачи объекта — хранение в архиве.

**Сейчас:** PDF-отчёт содержит спеку, Ctrl+F работает.

**Нужна отдельная?** ❌ Нет.
