# Пользовательские истории

## Соглашения

**Формат истории:** `Как <роль>, я хочу <действие>, чтобы <ценность>`

**Оценка:** Story Points по шкале Фибоначчи (1, 2, 3, 5, 8, 13)

**Приоритет:** Must / Should / Could / Won't (MoSCoW)

**Статус:** ✅ Реализовано | 🔄 В разработке | ⬜ Бэклог

---

## EPIC-01: Аутентификация и управление доступом

> **Бизнес-ценность:** Обеспечить безопасный и удобный доступ для всех категорий пользователей — от внешних проектировщиков (без регистрации) до административного персонала (с полным контролем).

---

### US-01.1: Гостевой вход

**Как** внешний проектировщик,  
**я хочу** начать работу без регистрации,  
**чтобы** немедленно приступить к расчётам без административных задержек.

| Атрибут | Значение |
|---------|----------|
| Приоритет | Must |
| SP | 3 |
| Статус | ✅ |

**Критерии приёмки:**
- [ ] На главной странице есть кнопка «Пользователь» (вход как гость)
- [ ] После нажатия система создаёт гостевую сессию (POST /auth/guest → `session_id`)
- [ ] `session_id` сохраняется в localStorage и передаётся в заголовке `X-Session-Id`
- [ ] Пользователь перенаправляется на рабочий стол (`/workspace`)
- [ ] Гостевая сессия изолирована — другие пользователи не видят гостевых данных
- [ ] После закрытия браузера и повторного открытия — сессия восстанавливается

**Бизнес-правила:**
- BR-01: Гость видит только те проекты, которые созданы в его сессии
- BR-02: Гостевые данные хранятся в рамках жизненного цикла сессии

---

### US-01.2: Вход сотрудника

**Как** инженер-проектировщик,  
**я хочу** войти в систему по корпоративному email и паролю,  
**чтобы** получить доступ к полному функционалу, включая экспорт отчётов.

| Атрибут | Значение |
|---------|----------|
| Приоритет | Must |
| SP | 3 |
| Статус | ✅ |

**Критерии приёмки:**
- [ ] На главной странице есть кнопка «Сотрудник»
- [ ] Форма логина содержит поля email и пароль с валидацией
- [ ] При успешном входе возвращается `access_token` (JWT, 30 мин) и `refresh_token` (7 дней)
- [ ] Токены сохраняются в localStorage
- [ ] При неверных данных — сообщение об ошибке (HTTP 401), пароль не раскрывается
- [ ] При неактивном аккаунте — HTTP 401 с понятным сообщением

---

- [ ] Исходный запрос повторяется с новым токеном

**Как** любой пользователь (гость, сотрудник, администратор),

|---------|----------|
| Приоритет | Must |
| SP | 2 |
| Статус | ✅ |

**Критерии приёмки:**

- [ ] Созданный проект имеет статус `draft`
- [ ] Проект автоматически привязывается к текущей сессии или пользователю

## EPIC-03: Теплотехнический расчёт

> **Бизнес-ценность:** Автоматизация расчёта теплопотерь по закону Фурье устраняет ручные ошибки и обеспечивает единообразие методологии расчёта для всех инженеров компании.

---

### US-03.1: Добавление трубопровода с расчётом теплопотерь

**Как** инженер,  
**я хочу** ввести параметры трубопровода и сразу получить результат расчёта теплопотерь,  
**чтобы** быстро оценить потребность в электрообогреве.

| Атрибут | Значение |
|---------|----------|
| Приоритет | Must |
| SP | 8 |
| Статус | ✅ |

**Критерии приёмки:**
- [ ] Форма ввода параметров: наружный диаметр (DN), толщина стенки, материал трубы, тип и толщина изоляции, температуры (окружающей среды и продукта), длина трубопровода
- [ ] Автоматический расчёт при добавлении объекта
- [ ] Результат: `heat_loss_per_meter` (Вт/м), `total_heat_loss` (Вт), `thermal_resistance` (м²·К/Вт)
- [ ] При невалидных параметрах: `is_valid = false`, заполнен `validation_errors`
- [ ] Ошибка отображается в ячейке таблицы с красной подсветкой

**Бизнес-правила:**
- BR-03: Диаметр DN ≥ DN6 (0.0108 м), DN ≤ 3000 мм (3.0 м)
- BR-04: Температура окружающей среды: от −70°C до +70°C
- BR-05: Температура продукта > температуры окружающей среды
- BR-06: Минимальная длина трубопровода: 0.5 м

---

### US-03.2: Автопересчёт при изменении параметров

**Как** инженер,  
**я хочу** чтобы при изменении любого параметра объекта расчёт обновлялся автоматически,  
**чтобы** мгновенно видеть влияние изменений на результат.

| Атрибут | Значение |
|---------|----------|
| Приоритет | Must |
| SP | 3 |
| Статус | ✅ |

**Критерии приёмки:**
- [ ] PUT /projects/{pid}/objects/{oid} автоматически запускает расчёт
- [ ] Обновлённые `results`, `is_valid`, `validation_errors` возвращаются в ответе
- [ ] Изменение одного параметра не влияет на другие объекты проекта

---

### US-03.3: Расчёт с многослойной изоляцией

**Как** инженер,  
**я хочу** задать несколько слоёв изоляции с разными материалами,  
**чтобы** точнее моделировать реальные конструкции (например, ПУ + минвата + оцинкованный лист).

| Атрибут | Значение |
|---------|----------|
| Приоритет | Should |
| SP | 5 |
| Статус | ✅ |

**Критерии приёмки:**
- [ ] Поддерживается от 1 до 3 слоёв изоляции
- [ ] Каждый слой: толщина (м), материал (из справочника), опциональная λ (переопределяет справочник)
- [ ] 4 слоя → HTTP 422 с понятным сообщением
- [ ] Тепловые сопротивления слоёв суммируются по формуле многослойной цилиндрической стенки

---

### US-03.4: Расчёт подземной прокладки

**Как** инженер,  
**я хочу** указать глубину заложения трубы,  
**чтобы** учесть теплопередачу через грунт при подземной прокладке.

| Атрибут | Значение |
|---------|----------|
| Приоритет | Should |
| SP | 5 |
| Статус | ✅ |

**Критерии приёмки:**
- [ ] При указании `burial_depth > 0` применяется формула arccosh для R_ground
- [ ] `ground_conductivity` берётся из параметров или из коэффициента `ground_conductivity` БД
- [ ] Глубина заложения < радиуса изоляции → ошибка расчёта
- [ ] При надземной прокладке (по умолчанию) используется формула R_external

---

### US-03.5: Расчёт теплопотерь резервуара

**Как** инженер,  
**я хочу** рассчитать теплопотери резервуара (цилиндр / прямоугольник / шар),  
**чтобы** определить мощность обогрева ёмкостного оборудования.

| Атрибут | Значение |
|---------|----------|
| Приоритет | Must |
| SP | 5 |
| Статус | ✅ |

**Критерии приёмки:**
- [ ] Форма: cylindrical (диаметр + высота), rectangular (длина + ширина + высота), spherical (диаметр)
- [ ] Результат: `heat_loss_per_m2` (Вт/м²), `total_heat_loss` (Вт), `surface_area` (м²)
- [ ] Площадь поверхности вычисляется точной формулой для каждой формы

---

## EPIC-04: Электротехнический расчёт

> **Бизнес-ценность:** Автоматический подбор марки кабеля по рассчитанным теплопотерям устраняет необходимость ручного просмотра каталогов и исключает ошибки подбора.

---

### US-04.1: Подбор саморегулирующегося кабеля ТЛТ

**Как** инженер,  
**я хочу** автоматически подобрать марку саморегулирующегося кабеля для объекта,  
**чтобы** не листать каталог вручную и не ошибиться с мощностью.

| Атрибут | Значение |
|---------|----------|
| Приоритет | Must |
| SP | 5 |
| Статус | ✅ |

**Критерии приёмки:**
- [ ] POST /calc/electrical с `cable_type = self_regulating`
- [ ] При явном указании марки — проверка соответствия требуемой мощности
- [ ] При неизвестной или отсутствующей марке — автоподбор ближайшего подходящего кабеля
- [ ] Результат: `selected_cable`, `cable_length`, `total_power` (Вт), `current` (А)
- [ ] Учитывается `safety_factor` (коэффициент запаса по мощности)
- [ ] Если ни один кабель каталога не обеспечивает мощность → ошибка с описанием

---

### US-04.2: Несколько вариантов расчёта для объекта

**Как** инженер,  
**я хочу** рассчитать несколько вариантов кабельного обогрева для одного объекта,  
**чтобы** сравнить и выбрать оптимальное техническое решение.

| Атрибут | Значение |
|---------|----------|
| Приоритет | Should |
| SP | 3 |
| Статус | ✅ |

**Критерии приёмки:**
- [ ] Параметр `variant_number` позволяет сохранить несколько расчётов для одного `object_id`
- [ ] Каждый вариант хранится как отдельная запись `ElectricalCalculation`
