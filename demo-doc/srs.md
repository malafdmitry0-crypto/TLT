# SRS — Software Requirements Specification

Документ собирает функциональные и нефункциональные требования к программному комплексу
HeatCalc (теплотехнические и электротехнические расчёты систем электрообогрева ТЛТ)
в одном месте. Источник — ТЗ (Приложение № 1 к договору) + материалы анализа в `docs/analysis/`.

Актуальное правило: текущий целевой уровень проекта — полная версия. Раздел
базового уровня ниже оставлен как ссылка на структуру ТЗ и не снижает критерии
приемки для формул, алгоритмов и справочников.

## 1. Назначение

Программа предназначена для использования инженерным персоналом с целью:

- автоматического расчёта тепловых потерь с поверхности обогреваемых объектов;
- подбора греющего кабеля для компенсации теплопотерь;
- составления перечня оборудования, необходимого для обогрева.

## 2. Роли и матрица доступа

| Роль | Описание | Документ |
|---|---|---|
| Гость (Пользователь) | Анонимный доступ без регистрации, ограниченный набор функций | [personas.md](analysis/personas.md), [business-rules.md](analysis/business-rules.md) |
| Сотрудник | Авторизованный инженер компании-заказчика | то же |
| Администратор | Управление пользователями, коэффициентами, внешней БД | то же |

Полная матрица функция × роль — см. ТЗ Приложение 1 и `docs/analysis/personas.md`.

## 3. Функциональные требования

Источник — детально расписаны в [`docs/analysis/user-stories.md`](analysis/user-stories.md)
по эпикам US-01..US-12. Сценарии использования и data-flow — в
[`docs/analysis/diagrams-flows.md`](analysis/diagrams-flows.md).

### 3.1 Общие требования (любая роль)

- FR-01. Веб-интерфейс с поддержкой Chrome / Firefox / Edge / Яндекс.
- FR-02. Форма выбора уровня доступа на главной (Пользователь / Сотрудник).
- FR-03. Управление проектами: создание, открытие, сохранение, удаление.
- FR-04. Мастер пошагового добавления объектов (трубопровод / резервуар) с подсказками,
  автозаполнением и валидацией.
- FR-05. Табличное представление объектов по типам (отдельная таблица на тип).
- FR-06. Автоматический пересчёт при изменении любого параметра.
- FR-07. Подсветка незаполненных и некорректных ячеек.
- FR-08. Drag-and-drop изменения порядка строк.
- FR-09. Импорт / экспорт таблиц в формате MS Excel.
- FR-10. Корректирующие коэффициенты задаются администратором.

### 3.2 Базовый уровень ТЗ (уровень «Пользователь»)

- FR-BASE-01. Расчёт теплопотерь трубопроводов (формулы из ТНП для базового уровня).
- FR-BASE-02. Расчёт теплопотерь резервуаров (формулы из ТНП для базового уровня).
- FR-BASE-03. Электротехнический расчёт — только саморегулирующийся кабель ТЛТ.
- FR-BASE-04. Один вариант системы обогрева на проект.
- FR-BASE-05. Базовая спецификация (кабель + минимальный набор аксессуаров).
- FR-BASE-06. Базовый отчёт с предпросмотром на экране.

### 3.3 Полная версия (Сотрудник + Администратор)

- FR-FULL-01. Авторизация сотрудников по логину/паролю (JWT).
- FR-FULL-02. Проводник проектов с фильтрацией по типу, году и номеру задачи.
- FR-FULL-03. Просмотр и редактирование чужих проектов.
- FR-FULL-04. Расширенные типы объектов (насосы, площадки, прочее из ТНП).
- FR-FULL-05. Все формулы «для Полной версии» из ТНП.
- FR-FULL-06. Все типы кабеля: саморегулирующийся, одножильный, трёхжильный,
  минеральная изоляция, скин-системы.
- FR-FULL-07. Расширенная база кабелей и аксессуаров (внешняя БД).
- FR-FULL-08. Расчёт, сравнение и сохранение нескольких вариантов обогрева в проекте
  (CO1..CO4).
- FR-FULL-09. Расширенная спецификация: группировка, сортировка, выбор материалов
  из внешней БД.
- FR-FULL-10. Экспорт отчёта в PDF / DOCX / XLSX.
- FR-FULL-11. Мастер выбора состава отчёта (выбор разделов).
- FR-FULL-12. Мастер формирования отчёта в отдельном окне.

### 3.4 Администрирование

- FR-ADM-01. Управление учётными записями сотрудников (создание, деактивация).
- FR-ADM-02. Настройка корректирующих коэффициентов.
- FR-ADM-03. Управление внешней БД кабелей и аксессуаров.
- FR-ADM-04. Управление ключами шифрования (если выбран вариант Б или С,
  см. раздел 5 ТЗ).

## 4. Нефункциональные требования

### 4.1 Производительность

- NFR-PERF-01. Время отклика API на расчёт одного объекта — до 500 мс.
- NFR-PERF-02. Пакетный пересчёт проекта (≤ 50 объектов) — до 5 секунд.
- NFR-PERF-03. Ширина рабочей области ≥ 1280 px (мобильная версия не требуется).

### 4.2 Безопасность

- NFR-SEC-01. Защита backend от несанкционированного доступа (JWT, ролевая модель).
- NFR-SEC-02. Обфускация / минификация frontend-сборки.
- NFR-SEC-03. Шифрование расчётных формул и встроенных справочников
  (см. раздел 5 ТЗ — варианты А / Б / С).
- NFR-SEC-04. Учётные данные сотрудников хранятся в открытой части БД
  (хешированный пароль, не подлежит шифрованию).
- NFR-SEC-05. Файлы конфигурации хранятся в зашифрованном виде при файловом варианте
  хранения.
- NFR-SEC-06. Внешняя база данных не подлежит шифрованию.

### 4.3 Надёжность и развёртывание

- NFR-REL-01. Развёртывание через `docker compose up` локально и on-premise.
- NFR-REL-02. Работа в локальной сети заказчика без выхода в интернет.
- NFR-REL-03. Миграции БД через Alembic (вперёд и назад).
- NFR-REL-04. Гостевые сессии живут 30 дней, привязаны к session_id в localStorage браузера.

### 4.4 Удобство использования

- NFR-UX-01. Язык интерфейса — только русский (i18n не требуется).
- NFR-UX-02. Тёмно-бирюзовая тема (#1a5276 / #2e86c1) — соответствие фирменному стилю ТЛТ.
- NFR-UX-03. Каждое значение результата видно сразу под полем ввода (без перехода).
- NFR-UX-04. Ошибки показываются inline у поля + tooltip с полным описанием.

### 4.5 Тестируемость

- NFR-TEST-01. Покрытие unit-тестами критических чистых функций (формулы) — 100% ветвей.
- NFR-TEST-02. Интеграционные тесты на каждый API-эндпоинт.
- NFR-TEST-03. E2E (Playwright) на каждый ключевой сценарий из приёмочной программы (Прил. 3 ТЗ).

## 5. Бизнес-правила

Каждое правило — формальное условие, которое реализовано в коде и тестируется.
Полный каталог в [`docs/analysis/business-rules.md`](analysis/business-rules.md). Примеры:

- BR-CABLE-01 — минимально-достаточный кабель: подбирается минимальная мощность ≥ требуемой.
- BR-CABLE-02 — длина кабеля = длина трубы × 1.1 (запас 10% на крепёж/петли).
- BR-AUTH-04 — гость видит только свои проекты, сотрудник — все.
- BR-IMPORT-01 — построчная валидация Excel: невалидные строки не блокируют импорт.

## 6. Программа испытаний

См. ТЗ Приложение 3 «Пример Программы тестирования (ПМИ)». Тест-кейсы
сгруппированы по модулям в [`docs/qa/`](qa/) и автоматизированы на трёх уровнях:

| Уровень | Инструмент | Команда | Покрытие |
|---|---|---|---|
| Unit | pytest / vitest | `make test` | формулы, утилиты, store, чистые компоненты |
| Integration | pytest / vitest + RTL | `make test` | API-эндпоинты, страницы с моками |
| E2E | Playwright | `make test-e2e` | приёмочные сценарии из Прил. 3 ТЗ |
