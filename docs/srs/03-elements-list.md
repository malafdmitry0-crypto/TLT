# SRS · Перечень элементов (роли «Пользователь» и «Сотрудник»)

## 1. Назначение документа

Документ содержит формальный перечень элементов, с которыми
взаимодействуют роли **«Пользователь»** (вход без регистрации, далее
«Гость») и **«Сотрудник»** (вход по логину и паролю) в полноценной
версии программного комплекса теплотехнического и электротехнического
расчёта систем электрообогрева: экраны, элементы интерфейса, поля
форм, колонки таблиц, сущности данных, справочники, единицы
измерения, системные ограничения и коды ошибок.

> **Важно.** Текущий целевой уровень проекта — **полноценная версия**.
> Исторические упоминания базового уровня в SRS используются только как
> контекст ТЗ и не снижают критерии приемки.

Документ является частью комплекта SRS из семи взаимодополняющих
документов:

1. Пользовательские истории — бизнес-ценность и критерии приёмки.
2. Сценарии использования — формальные сценарии работы с системой.
3. **Перечень элементов** — этот документ.
4. Валидация — правила проверки входных данных.
5. Функциональные и нефункциональные требования — целевые свойства системы.
6. Программа испытаний — виды, объём и методы проверки.
7. Требования к отчёту — состав и структура итогового отчёта.

## 3. Экраны

|--------|----------------------------------|--------------------|---------------------------------------------------------------------------------------------------------------|
| SC-01  | Главная (выбор режима)           | Гость, Сотрудник   | Вход в систему: кнопки «Войти без регистрации» и «Войти как сотрудник»                                        |

| SC-06  | Рабочий стол — «Отчёт»           | Гость, Сотрудник   | HTML-предпросмотр и печать у обеих ролей; экспорт PDF / DOCX / XLSX и **мастер выбора состава отчёта (SC-09)** — только у Сотрудника  |

> **Различия в навигации:**
>
> - **Гость** входит на главной странице (SC-01), сразу попадает на
>   рабочий стол (SC-03) с автоматически созданным единственным
>   проектом «Мой проект». Отдельного экрана со списком проектов нет.
> - **Сотрудник** входит через форму авторизации (SC-02), попадает в
>   проводник проектов (SC-08). Со страницы проводника может открыть
>   любой проект (свой или чужой) и перейти на рабочий стол (SC-03).

### 4.4. Активные подсказки в формах

Каждое поле ввода в формах объекта, в окне общих первичных данных
и в строке таблицы исходных данных сопровождается активной
подсказкой. Подсказка содержит:

- ожидаемую единицу измерения;
- допустимый диапазон значений;
- короткий пример типового значения;
- условие применения (если поле появляется только при определённых
  значениях других полей).

Формат подачи подсказок (постоянная подпись под полем / всплывающий
tooltip / иконка-«?») — единый по всему приложению, конкретный
формат **подлежит согласованию с Заказчиком** (см. документ
«Пользовательские истории», вопрос Q-C).

### 5.3. Форма трубопровода (встроенная плоская форма)

**Размещение:** форма является частью основного интерфейса SC-03,
не модальным окном. Пользователь может выбрать расположение формы:
сверху, снизу, слева или справа от таблицы. В режиме расположения
«сверху» высота области формы стабильна, чтобы таблица объектов не
смещалась при появлении дополнительных полей; если содержимое секции
не помещается, прокрутка появляется внутри соответствующей секции.
Ошибки выбранной строки показываются поверх верхней служебной панели
и не участвуют в расчёте высоты формы или таблицы.
Все поля доступны без пошагового мастера, вкладок и переключений.
Поля сгруппированы в 3 колонки по смыслу. Ориентир по UX —
программа «Тепломаг».

**Режимы формы:**

- **«Новая запись»** — после нажатия кнопки «+ Добавить» в панели
  действий. Все поля очищены / заполнены значениями по умолчанию
  (из общих первичных данных проекта).
- **«Редактирование»** — после клика по любой строке таблицы.
  Поля наполнены значениями выбранной строки. Над формой
  отображается метка «Параметры объекта (выделена строка №N)».

Сохранение изменений — через кнопку «💾 Сохранить изменения» в
панели действий или через «Применить к одному» / «Применить ко
всем» (для массового применения значений к выделенным строкам).

### 5.5. Форма резервуара (встроенная плоская форма, режим «резервуар»)

Используется **та же** встроенная плоская форма, что и в 5.3 —
переключается в режим «резервуар» при нажатии кнопки «+ Добавить»
с выбором типа «Резервуар» или при клике по строке таблицы с
типом «Рез.». Колонка «Геометрия трубы» заменяется на «Форма и
геометрия резервуара»:

| Поле    | Тип    | Обязательное | Комментарий                                              |
|---------|--------|:------------:|----------------------------------------------------------|
| Форма   | Radio  |      ✅      | Цилиндр / Параллелепипед / Шар                           |
| Диаметр | Number |   ✅ (цилиндр / шар)   | 100 … 50 000 мм                               |
| Высота  | Number |   ✅ (цилиндр / параллелепипед) | 100 … 50 000 мм                       |
| Длина   | Number |   ✅ (параллелепипед)   | 100 … 50 000 мм                               |
| Ширина  | Number |   ✅ (параллелепипед)   | 100 … 50 000 мм                               |

Остальные колонки (теплоизоляция, температурные параметры,
электрические параметры) — те же, что у трубопровода, **в той же
встроенной форме** (без шагов и вкладок). Поля количества
фланцев / опор / задвижек у резервуара отсутствуют.

### 5.9. Управление вариантами расчёта и выбор кабеля (SC-04, страница «Электрорасчёт»)

CO и кабель на SC-04 управляются на **двух уровнях**:

1. **Страничный переключатель CO1 … CO4** — задаёт *активный
   вариант расчёта* для всей страницы. CO применяется ко всему
   проекту (а не к одному объекту).
2. **Карточка объекта** — содержит собственную форму выбора
   кабеля для текущего варианта CO; кабель задаётся **отдельно
   для каждого объекта**.

#### 5.9.1. Страничный переключатель CO (верхняя панель SC-04)

**Размещение:** в верхней части SC-04, **постоянно виден**.

**Структура:**

1. CO-вкладки: «★ CO1 (активный)», «CO2», «CO3», «＋ Добавить
   вариант (CO4)». Активный вариант помечен ★; текущая
   редактируемая вкладка имеет белый фон.
2. Под вкладками — кнопки управления вариантом: [ ★ Сделать
   активным ] / [ ✎ Переименовать ] / [ 🗑 Удалить вариант ] /
   [ ⚡ Пересчитать вариант ].

**Поведение при переключении CO-вкладки:**

- Сводка по проекту обновляется по выбранному варианту.
- Карточки объектов ниже показывают параметры кабеля и результаты
  расчёта для выбранного варианта.

**Правила валидации:** VAL-59 (≤ 4 вариантов CO на проект),
VAL-60 (один активный CO на проект).

> На SC-04 **нет** вкладки «Сравнение вариантов CO» — переключение
> между CO выполняется страничными CO-вкладками.

#### 5.9.2. Форма выбора кабеля в карточке объекта

**Размещение:** в каждой карточке объекта на SC-04 — между
заголовком объекта и блоком результатов. Заполняется параметрами
из текущего выбранного CO (см. 5.9.1).

**Поля параметров** кабеля (4 столбца):

| Поле                  | Тип    | Обязательное | Диапазон / единица |
|-----------------------|--------|:------------:|---------------------|
| Тип кабеля            | Select |      ✅      | Саморегулирующийся / Одножильный пост. мощн. / Трёхжильный пост. мощн. / Кабель с минеральной изоляцией |
| Марка кабеля          | Select |      —       | «Авто» + марки выбранного типа из активной базы расчёта |
| Шаг навива            | Number |      —       | 0 … 500 мм (заблокировано для типа «минеральная изоляция») |
| Количество ниток      | Select |      —       | 1 / 2 / 3 (1 для типа «минеральная изоляция») |

**Правила валидации:** VAL-58 (тип из 4), VAL-61 (мин. изоляция
без навива), VAL-30 (марка из активной базы для выбранного типа),
VAL-31 / VAL-32 (диапазон шага навива), VAL-33 (количество ниток).

> Кабель и параметры укладки задаются **отдельно для каждого
> объекта** в его карточке. На странице «Теплопотери» (SC-03)
> выбора кабеля нет.

### 8.5. Внешняя БД кабелей и аксессуаров (расширенная, только Сотрудник)

Расширенная база, дополняющая встроенный каталог. Доступна
Сотруднику при переключении тогглера «База расчёта» в режим
«Расширенная внешняя» (см. UC-E-10 / US-E-10).

**Назначение:** содержать альтернативные марки кабелей по всем 4
типам и расширенный перечень аксессуаров СЭО (системы
электрообогрева), не входящих в базовый набор.

**Состав записей (предварительно — на согласование Q-G):**

- **Кабели:** тип, бренд, модель, мощность, диапазон температур,
  напряжение, артикул, единица измерения, цена (опционально),
  активность позиции.
- **Аксессуары:** категория, наименование, артикул, единица
  измерения, привязка к типу системы (саморегулирующаяся /
  постоянной мощности и т. п.), цена (опционально), активность
  позиции.

**Управление наполнением:** через интерфейс Администратора (раздел
4.3.6 ТЗ). Подробности административного интерфейса в данный
комплект SRS не входят.

> **Q-G (открытый вопрос).** Окончательная структура полей,
> формат обновления (выгрузка администратором, синхронизация с
> внешним источником, ручной импорт), порядок наполнения и
> поддержки актуальности — подлежат согласованию с Заказчиком.
