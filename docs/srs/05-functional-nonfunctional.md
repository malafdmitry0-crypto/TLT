# SRS · Функциональные и нефункциональные требования (роли «Пользователь» и «Сотрудник»)

## 1. Назначение документа

Документ содержит формальный перечень функциональных (FR) и
нефункциональных (NFR) требований к полноценной версии программного
комплекса теплотехнического и электротехнического расчёта систем
электрообогрева — в части, относящейся к ролям «Пользователь»
(далее «Гость») и «Сотрудник».

> **Важно.** Текущий целевой уровень проекта — **полноценная версия**.
> Исторические упоминания базового уровня в SRS используются только как
> контекст ТЗ и не снижают критерии приемки.

Документ является частью комплекта SRS из семи взаимодополняющих
документов:

1. Пользовательские истории — бизнес-ценность и критерии приёмки.
2. Сценарии использования — формальные сценарии работы с системой.
3. Перечень элементов — экраны, поля, справочники, ограничения.
4. Валидация — правила проверки входных данных.
5. **Функциональные и нефункциональные требования** — этот документ.
6. Программа испытаний — виды, объём и методы проверки.
7. Требования к отчёту — состав и структура итогового отчёта.

## 2. Соглашения

- **ID функционального требования:** `FR-NN`.
- **ID нефункционального требования:** `NFR-XX-NN` (где `XX` —
  категория: PERF / SEC / REL / UX / TEST / DOC).
- **Применимость:** Гость / Сотрудник / обе роли.
- **Источник:** ТЗ (Приложение № 1) или согласовано с Заказчиком.
- **Связанные документы** для трассировки: пользовательские истории
  (документ 1) и программа испытаний (документ 6).
