# SRS · Сценарии использования (роли «Пользователь» и «Сотрудник»)

## 1. Назначение документа

Документ содержит формальные сценарии использования (Use Cases) для
ролей **«Пользователь»** (вход без регистрации, далее «Гость») и
**«Сотрудник»** (вход по логину и паролю) полноценной версии
программного комплекса теплотехнического и электротехнического
расчёта систем электрообогрева.

> **Важно.** Текущий целевой уровень проекта — **полноценная версия**.
> Исторические упоминания базового уровня в SRS используются только как
> контекст ТЗ и не снижают критерии приемки.

Документ является частью комплекта SRS из семи взаимодополняющих
документов:

1. Пользовательские истории — бизнес-ценность и критерии приёмки.
2. **Сценарии использования** — этот документ.
3. Перечень элементов — экраны, поля, справочники, ограничения.
4. Валидация — правила проверки входных данных.
5. Функциональные и нефункциональные требования — целевые свойства системы.
6. Программа испытаний — виды, объём и методы проверки.
7. Требования к отчёту — состав и структура итогового отчёта.

## 2. Соглашения

Сценарий описан в стандартном формате:

- **Актёры** — действующие лица (Гость, Сотрудник, Система).
- **Предусловия** — требуемое состояние системы перед сценарием.
- **Основной поток** — последовательность шагов «счастливого пути».
- **Альтернативные потоки (AF)** — допустимые отклонения.
- **Исключительные потоки (EF)** — ошибки с описанием реакции.
- **Постусловие** — состояние системы после успешного завершения.

Идентификаторы сценариев:
- `UC-G-NN` — сценарии, специфичные для роли «Гость».
- `UC-E-NN` — сценарии, специфичные для роли «Сотрудник».
- Сценарии расчётного контура (UC-G-06…UC-G-19, UC-G-22…UC-G-24)
  применимы к **обеим** ролям — Сотрудник работает с расчётом так
  же, как и Гость, в тех же модальных окнах и таблицах.

## UC-G-01. Вход без регистрации (с автоматическим созданием проекта)

- **Актёры:** Гость, Система.
- **Предусловия:** браузер открыт на главной странице; действующей
  сессии у гостя нет.

**Основной поток:**
1. Система показывает главную страницу с двумя вариантами входа.
2. Гость нажимает «Войти без регистрации».
3. Система создаёт гостевую сессию и **один пустой проект** «Мой
   проект»; проект сразу становится активным.
4. Гость попадает на рабочий стол активного проекта (страницы
   «Список проектов» в гостевом режиме нет).
5. В шапке страницы виден маркер режима «Гость» и название
   активного проекта.

**Исключительные потоки:**
- **EF-1.** Превышен лимит попыток входа с одного IP → сообщение
  «Слишком много попыток входа, попробуйте через час».
- **EF-2.** Сервис временно недоступен → сообщение об ошибке с
  предложением повторить попытку позже.

**Постусловие:** создана действующая сессия, у Гостя есть один
активный пустой проект, открыт рабочий стол.

## UC-G-02. Создание нового проекта (с заменой текущего)

- **Актёры:** Гость.
- **Предусловия:** Гость авторизован (выполнен UC-G-01); в сессии
  активен один проект.

**Основной поток:**
1. В меню проекта Гость выбирает «Создать новый проект».
2. Система открывает форму с полями: «Название» (обязательное),
   «Номер задачи», «Описание».
3. Гость заполняет поля и подтверждает создание.
4. Система показывает подтверждение: «Текущий проект и все его
   данные будут удалены. Продолжить?».
5. Гость подтверждает.
6. Система удаляет текущий активный проект (объекты, расчёты,
   спецификацию) и создаёт на его месте новый пустой проект с
   указанными свойствами.

**Альтернативные потоки:**
- **AF-1.** Гость отменяет ввод формы или подтверждение замены —
  текущий проект остаётся активным, новый не создаётся.

**Исключительные потоки:**
- **EF-1.** Пустое «Название» — кнопка подтверждения недоступна.

**Постусловие:** в сессии по-прежнему ровно один активный проект;
им стал новый пустой проект с заданным названием.

## UC-G-04. Удаление текущего проекта

- **Актёры:** Гость.
- **Предусловия:** в сессии активен один проект.

**Основной поток:**
1. В меню проекта Гость выбирает «Удалить текущий проект».
2. Система показывает подтверждение с предупреждением о
   безвозвратности.
3. Гость подтверждает.
4. Система удаляет текущий активный проект (объекты, расчёты,
   спецификацию).
5. Система автоматически создаёт пустой проект «Мой проект» и
   делает его активным.

**Альтернативные потоки:**
- **AF-1.** Гость отменяет подтверждение — текущий проект остаётся
  активным, удаление не выполняется.

**Постусловие:** прежний проект и все его данные удалены; в сессии
ровно один активный проект — пустой «Мой проект».

## UC-G-06. Заполнение общих первичных данных проекта (модальное окно)

- **Актёры:** Гость.
- **Предусловия:** проект открыт.

**Основной поток:**
1. Гость на рабочем столе нажимает кнопку «Общие первичные данные».
   При первом открытии проекта Система автоматически предлагает
   заполнить общие данные.
2. Система открывает **единое модальное окно**, содержащее все
   общие поля проекта.
3. Гость заполняет поля: климатический регион, температура окружающей
   среды, напряжение питания (220 / 380 В), коэффициент запаса по
   мощности, тип прокладки (надземная / подземная), глубина заложения
   (для подземной).
4. Гость подтверждает ввод. Система сохраняет значения в проекте и
   закрывает модальное окно.
5. При добавлении следующего объекта соответствующие поля в мастере
   предзаполняются значениями из общих параметров.

**Альтернативные потоки:**
- **AF-1.** В проекте уже есть объекты — после сохранения общих
  данных Система предлагает выполнить пересчёт всех объектов по новым
  параметрам.
- **AF-2.** Гость закрывает модальное окно без подтверждения —
  ранее сохранённые значения не изменяются.

**Постусловие:** общие параметры сохранены в проекте.

## UC-G-07. Добавление трубопровода

- **Актёры:** Гость.
- **Предусловия:** проект открыт; в проекте менее 50 объектов.

**Основной поток:**
1. Гость на рабочем столе нажимает «+ Трубопровод».
2. Система очищает **встроенную плоскую форму** в верхней части
   рабочего стола (это часть основного интерфейса, не модальное
   окно) и переключает её в режим «новая запись». Все поля видны
   одновременно (без шагов и вкладок). Поля сгруппированы визуально
   по 4 колонкам: геометрия трубы, теплоизоляция, температура и
   среда, электрика и арматура (фланцы / опоры / задвижки).
3. Гость заполняет нужные поля. Поля, которые имеют значение в
   «Общих первичных данных» проекта, предзаполняются и могут быть
   переопределены локально.
4. Над списком слоёв изоляции — поле «Кол-во слоёв» (1, 2 или 3).
   При его изменении количество отображаемых строк «Толщина / λ /
   Материал» подстраивается. Для материала «Другое» появляется
   поле λ.
5. Гость нажимает «Сохранить» (или «Применить»).
6. Система сохраняет объект и сразу рассчитывает теплопотери.
   Имя формируется автоматически (например, «Труба Ø108 мм
   (DN100), δ=50 мм, МВ, L=50 м, −44→+80 °C»).
7. Новая строка появляется в таблице трубопроводов.

**Альтернативные потоки:**
- **AF-1.** Гость нажимает «↻ Отменить» в панели действий — все
  введённые значения сбрасываются, форма возвращается в исходное
  состояние, объект не сохраняется.

**Исключительные потоки:**
- **EF-1.** Превышен лимит 50 объектов на проект — сохранение
  отклонено.
- **EF-2.** Температура продукта не больше температуры окружающей
  среды — валидация не пропускает форму далее.
- **EF-3.** Параметры вне допустимых диапазонов (температура, диаметр,
  толщина) — поля подсвечиваются с подсказкой.

**Постусловие:** в проекте появился новый трубопровод с рассчитанными
теплопотерями.

## UC-G-08. Добавление резервуара

- **Актёры:** Гость.
- **Предусловия:** проект открыт; в проекте менее 50 объектов.

**Основной поток:**
1. Гость нажимает «+ Резервуар».
2. Система очищает ту же встроенную плоскую форму и переключает её
   в режим «новая запись · резервуар». Первая колонка переключается
   с «Геометрия трубы» на «Форма и геометрия резервуара». Все
   остальные колонки (теплоизоляция, температура, электрика) — те
   же самые.
3. **Шаг 1 — Форма и геометрия:** выбор формы (цилиндр, параллелепипед,
   шар) и ввод габаритов: для цилиндра — диаметр и высота; для
   параллелепипеда — длина, ширина и высота; для шара — диаметр.
4. **Шаг 2 — Теплофизика:** изоляция и температуры (аналогично трубе).
5. **Шаг 3 — Подтверждение.**
6. Система сохраняет объект, рассчитывает площадь поверхности,
   теплопотери на квадратный метр и суммарные теплопотери.
7. Строка появляется в таблице резервуаров.

**Постусловие:** в проекте появился резервуар с рассчитанными
теплопотерями.

## UC-G-09. Редактирование объекта

- **Актёры:** Гость.

**Основной поток:**
1. В строке объекта Гость нажимает кнопку редактирования.
2. Система наполняет встроенную плоскую форму на рабочем столе
   значениями выбранной строки и переключает её в режим
   «редактирование». Никакого модального окна не открывается —
   форма уже находится в основном интерфейсе.
3. Гость изменяет нужные параметры и подтверждает.
4. Система сохраняет изменения и автоматически пересчитывает
   теплопотери и электрорасчёт этого объекта.
5. Строка таблицы обновляется.

**Исключительные потоки:** те же, что в UC-G-07 (проверка
диапазонов, температур, количества слоёв изоляции).

**Постусловие:** объект обновлён, результаты расчёта актуальны.

## UC-G-10. Удаление объекта

- **Актёры:** Гость.

**Основной поток:**
1. В строке объекта Гость нажимает «Удалить».
2. Система запрашивает подтверждение.
3. После подтверждения строка удаляется из таблицы.
4. Суммарные показатели проекта пересчитываются.

**Постусловие:** объект и его результаты расчёта удалены.

## UC-G-11. Изменение порядка строк

- **Актёры:** Гость.

**Основной поток:**
1. Гость захватывает строку таблицы мышью и перетаскивает в новое
   положение.
2. Система обновляет порядок и сохраняет его.
3. Порядок сохраняется при повторном открытии проекта.

**Альтернативные потоки:**
- **AF-1.** Гость нажимает на кнопку в строке (редактирование,
  удаление, выбор марки) без движения мышью — срабатывает нажатие
  кнопки, перетаскивание не начинается.

**Постусловие:** строки упорядочены по выбранной Гостем
последовательности.

## UC-G-12. Импорт объектов из Excel / CSV

- **Актёры:** Гость.
- **Предусловия:** проект открыт.

**Основной поток:**
1. Гость нажимает «Импорт (Excel / CSV)».
2. Система предлагает выбрать файл и показывает ссылки на шаблоны.
3. Гость выбирает заполненный по шаблону файл (`.xlsx` или `.csv`).
4. Система разбирает файл, строит объекты, для каждой строки
   выполняет валидацию и расчёт теплопотерь.
5. Система выводит итоговый отчёт: сколько строк импортировано,
   сколько пропущено с указанием номера строки и причины.
6. Корректные объекты появляются в таблицах, ошибочные строки не
   добавляются.

**Альтернативные потоки:**
- **AF-1.** Часть строк содержит ошибки — остальные строки
  импортируются нормально, импорт не прерывается.

**Исключительные потоки:**
- **EF-1.** Формат файла не поддерживается — операция отклонена с
  соответствующим сообщением.
- **EF-2.** Файл пустой или не содержит данных — операция отклонена.
- **EF-3.** Импорт приводит к превышению лимита 50 объектов —
  импортируются только помещающиеся строки, остальные попадают в
  отчёт как ошибки.

**Постусловие:** в проекте появились импортированные объекты с
рассчитанными теплопотерями.

## UC-G-13. Ручной ввод параметров вместо справочных значений

- **Актёры:** Гость.
- **Предусловия:** Гость находится в форме объекта или общих
  первичных данных и подходит к параметру, имеющему значение по
  умолчанию из справочника.

**Основной поток (на примере λ изоляции):**
1. В поле «Материал изоляции» Гость выбирает пункт «Другое».
2. Система показывает дополнительное поле «λ, Вт/(м·К)».
3. Гость вводит значение в допустимом диапазоне 0,001 … 400.
4. Гость продолжает заполнение формы.
5. При расчёте теплопотерь используется введённое значение λ вместо
   табличного.

**Альтернативные потоки:**
- **AF-1.** Параметр имеет переключатель «Из справочника / Ввести
  вручную». Гость переключает на «Ввести вручную» — рядом
  появляется поле ввода с подсказкой допустимого диапазона.
  Ручное значение замещает справочное только в текущем объекте /
  проекте.

**Исключительные потоки:**
- **EF-1.** Значение вне допустимого диапазона — поле подсвечивается,
  переход к следующему шагу заблокирован.
- **EF-2.** Поле оставлено пустым при выборе ручного ввода —
  валидация не пропускает форму.

**Постусловие:** в объекте / проекте сохранено заданное вручную
значение параметра, которое имеет приоритет над справочным.

> **На согласование с Заказчиком:** конкретный список параметров,
> для которых разрешён ручной ввод (расчётная температура наружного
> воздуха, скорость ветра, коэффициент теплоотдачи α, теплопроводность
> грунта и др.). Текущая базовая редакция гарантирует ручной ввод
> только для λ изоляции через пункт «Другое».

## UC-G-14. Автоматический электротехнический расчёт

- **Актёры:** Гость.
- **Предусловия:** в проекте есть хотя бы один объект с успешно
  рассчитанными теплопотерями.

**Основной поток:**
1. Гость нажимает «Выполнить электрорасчёт».
2. Для каждого объекта, где марка кабеля установлена в «Авто»,
   Система подбирает оптимальную марку
   саморегулирующегося кабеля.
3. Если в текущем варианте CO есть вручную выбранные марки кабеля,
   Система сохраняет их и пропускает эти строки при массовом автоподборе.
4. Для каждого рассчитанного объекта вычисляются: длина кабеля (с учётом запаса и
   параметров навива), суммарная мощность, потребляемый ток.
5. Результаты сохраняются и отображаются в таблице исходных данных
   (колонки результата), а также в сводном виде на странице
   «Электрорасчёт».

**Альтернативные потоки:**
- **AF-1.** Некоторые объекты не прошли расчёт теплопотерь — они
  пропускаются при электрорасчёте и помечаются как «Не рассчитан».
- **AF-2.** Пользователь явно включает «Перезаписать ручные выборы» в
  подтверждении массового пересчёта — Система заново выполняет автоподбор и для
  строк с ручной маркой.

**Исключительные потоки:**
- **EF-1.** Ни один кабель каталога не обеспечивает требуемую
  мощность для объекта — объект получает статус «Ошибка» с
  пояснением; остальные рассчитываются успешно. Ошибка
  сохраняется и отображается после перезагрузки страницы.

**Постусловие:** для всех применимых объектов определена марка
кабеля и электрические параметры; сводка доступна на странице
«Электрорасчёт».

## UC-G-15. Выбор марки кабеля на странице «Электрорасчёт»

- **Актёры:** Гость или Сотрудник.

**Предусловия:** на шаге «Теплопотери» добавлены объекты, расчёт
теплопотерь выполнен. Пользователь перешёл на шаг «Электрорасчёт»
(SC-04) и выделил объект.

**Основной поток:**
1. На странице «Электрорасчёт» во встроенной форме «Кабель»
   (для выделенного объекта и активной CO-вкладки) пользователь
   открывает Select **«Марка кабеля»**.
2. Список марок зависит от выбранного **типа кабеля** (см. UC-G-25)
   и от **активной базы расчёта** (встроенная или расширенная
   внешняя — см. UC-E-10).
3. Пользователь выбирает конкретную марку (вместо значения «Авто»
   по умолчанию).
4. Система сохраняет выбор для **текущего варианта CO** и запускает
   пересчёт электрических параметров с учётом значений «Шаг навива»
   и «Количество ниток».
5. В карточке варианта обновляются длина кабеля, мощность, ток.
6. Если изменён активный вариант — обновляется сводная карточка
   проекта; спецификация и отчёт автоматически пересчитываются.

> На странице «Теплопотери» (SC-03) колонок «Марка», «Тип кабеля»
> и связанных параметров **нет** — кабель управляется только на
> «Электрорасчёте».

**Альтернативные потоки:**
- **AF-1.** Гость выбирает марку с удельной мощностью **меньше**
  линейных теплопотерь объекта на 1 м. Система **не блокирует**
  такой выбор: дефицит должен компенсироваться навивом или
  несколькими нитками (см. UC-G-16). Если совокупная мощность всё
  равно недостаточна — наступает поток EF-1.

**Исключительные потоки:**
- **EF-1.** Совокупная подведённая мощность (с учётом навива и
  количества ниток) меньше суммарных теплопотерь объекта — объект
  переходит в состояние «Ошибка» с подсказкой о причине и
  рекомендацией увеличить количество ниток, уменьшить шаг навива
  или выбрать марку большей мощности.

**Постусловие:** для объекта зафиксирована выбранная марка кабеля,
результаты актуальны.

## UC-G-16. Настройка навива и нескольких ниток

- **Актёры:** Гость.

**Основной поток:**
1. В строке объекта Гость задаёт значения «Шаг навива» (мм) и
   «Количество ниток» (1 / 2 / 3) в блоке «Кабель».
2. Система пересчитывает длину кабеля с учётом навива (для шага
   больше нуля длина увеличивается пропорционально) и количества
   ниток.
3. Совокупная подведённая мощность проверяется как сумма по всем
   ниткам с учётом удельной мощности выбранной марки.
4. Результаты отображаются в соответствующих колонках таблицы.

**Альтернативные потоки:**
- **AF-1.** Гость использует две нитки кабеля с удельной мощностью
  15 Вт/м вместо одной нитки 30 Вт/м (или аналогичная конфигурация).
  Система допускает такой выбор и проверяет суммарную мощность
  «удельная × длина × количество ниток», а не «удельная ≥ q/L».

**Исключительные потоки:**
- **EF-1.** Шаг навива меньше наружного диаметра трубы — настройка
  отклоняется с сообщением «Шаг навива должен быть больше наружного
  диаметра трубы».
- **EF-2.** Совокупная подведённая мощность меньше суммарных
  теплопотерь — объект помечается «Ошибка», см. UC-G-15 / EF-1.

**Постусловие:** параметры навива и ниток зафиксированы, результаты
электрорасчёта актуальны.

> **На согласование с Заказчиком:** точная формула расчёта длины
> кабеля и проверки совокупной мощности с учётом навива и
> количества ниток. Будет передана отдельно.

## UC-G-20. Импорт проекта из CSV (с заменой текущего)

- **Актёры:** Гость.
- **Предусловия:** в сессии есть один активный проект (всегда).
  При необходимости перед импортом Гость может сохранить текущий
  проект через UC-G-19.

**Основной поток:**
1. Гость выбирает операцию «Загрузить проект из CSV».
2. Указывает файл, ранее полученный экспортом (UC-G-19).
3. Система показывает подтверждение: «Текущий проект и все его
   данные будут удалены и заменены на загружаемый. Продолжить?».
4. Гость подтверждает.
5. Система удаляет текущий активный проект (объекты, расчёты,
   спецификацию).
6. Система разбирает файл и восстанавливает на его месте новый
   активный проект.
7. Восстанавливаются: общие первичные данные, объекты, результаты
   электрорасчёта, спецификация.

**Альтернативные потоки:**
- **AF-1.** Гость отменяет подтверждение — текущий проект остаётся
  активным, импорт не выполняется.

**Исключительные потоки:**
- **EF-1.** Файл повреждён или имеет неподдерживаемый формат —
  импорт отклонён с описанием причины. Текущий проект **не**
  удаляется и остаётся активным.

**Постусловие:** активный проект полностью заменён содержимым
загруженного CSV; в сессии по-прежнему ровно один проект.

## UC-G-21. Автоматическое завершение сессии по неактивности

- **Актёры:** Система.

**Основной поток:**
1. Любое действие Гостя в системе продлевает сессию.
2. Фоновая процедура регулярно (не реже одного раза в 10 минут)

3. Сессии без активности дольше 20 минут удаляются вместе со всеми
   связанными данными (проекты, объекты, расчёты, спецификации).

**Альтернативные потоки:**
- **AF-1.** Гость возвращается к работе после удаления сессии —
  Система показывает сообщение «Сессия завершена по неактивности,
  войдите заново» и переводит на главную страницу.

**Постусловие:** не позднее 30 минут после последней активности
данные Гостя удалены из системы.

## UC-G-22. Копирование строки исходных данных (создание объекта на основании)

- **Актёры:** Гость.
- **Предусловия:** в проекте есть исходный объект (трубопровод
  или резервуар); количество объектов в проекте меньше 50.

**Основной поток:**
1. В строке исходного объекта Гость выбирает операцию «Создать на
   основании» (копирование строки).
2. Система создаёт новый объект того же типа со всеми параметрами
   исходного объекта (геометрия, изоляция, температуры, параметры
   кабеля — марка, шаг навива, количество ниток).
3. Новый объект получает автоматически сгенерированное наименование
   с пометкой копии (например, «‹исходное наименование› (копия)»).
4. Система запускает расчёт теплопотерь и электрорасчёт нового
   объекта.
5. Новая строка появляется в таблице.

**Альтернативные потоки:**
- **AF-1.** Гость сразу после копирования открывает новую строку
  на редактирование, чтобы изменить отдельные параметры (типичный
  кейс — линейка однотипных труб с разными длинами).

**Исключительные потоки:**
- **EF-1.** Превышен лимит 50 объектов на проект — операция
  отклонена с соответствующим сообщением.

**Постусловие:** в проекте появилась независимая копия исходной
строки с актуальными результатами расчёта.

## UC-G-23. Работа с таблицей в Excel-подобном режиме

- **Актёры:** Гость.
- **Предусловия:** в проекте есть хотя бы одна строка таблицы
  исходных данных.

**Основной поток (на согласование с Заказчиком):**
1. Гость выделяет диапазон ячеек в таблице исходных данных
   (одиночная ячейка, столбец, строка или прямоугольный блок).
2. Стандартными сочетаниями клавиш (Ctrl+C / Ctrl+V) копирует и
   вставляет диапазон в другое место таблицы.
3. Гость отмечает чекбоксами набор строк и применяет к ним групповую

4. После любой массовой операции Система автоматически пересчитывает

**На согласование (см. вопрос Q-B в документе «Гостьские

- «протягивание» значения вниз по колонке (drag-fill);
- экспорт текущего вида таблицы в Microsoft Excel.

**Исключительные потоки:**
- **EF-1.** Вставленный диапазон содержит значения, выходящие за
  допустимые диапазоны параметров — соответствующие строки помечаются
  невалидными, расчёт по ним не выполняется до исправления.

**Постусловие:** значения в таблице обновлены, для затронутых
строк актуализированы результаты расчёта.

## UC-G-24. Получение подсказок при заполнении формы

- **Актёры:** Гость.
- **Предусловия:** Гость заполняет любую форму ввода (мастер
  объекта, общие первичные данные, параметры кабеля).

**Основной поток:**
1. Гость переходит к полю ввода.
2. Рядом с полем отображается активная подсказка, содержащая:

подсказок — постоянная подпись под полем, всплывающий tooltip при
фокусе или иконка-«?» с раскрывающимся текстом. Формат единый
по всему приложению.

**Постусловие:** Гость заполняет форму без обращения к внешней
документации.

## UC-E-02. Открытие проводника проектов с поиском и фильтром

- **Актёры:** Сотрудник.
- **Предусловия:** Сотрудник авторизован (UC-E-01).

**Основной поток:**
1. Система отображает «Проводник проектов» — таблицу проектов,

5. Клик по строке открывает соответствующий проект на рабочем
   столе.

**Альтернативные потоки:**
- **AF-1.** Сотрудник сортирует таблицу по любой колонке.
- **AF-2.** Сотрудник снимает все фильтры — таблица показывает
  все проекты сотрудников без гостевых проектов подрядчиков.

**Постусловие:** Сотрудник видит отфильтрованный список проектов
сотрудников и может открыть любой из них.

## UC-G-25. Выбор типа кабеля для варианта CO

- **Актёры:** Гость или Сотрудник.
- **Применимость:** обе роли.
- **Трассировка:** US-G-29.

**Предусловия:** пользователь находится на странице «Электрорасчёт»
(SC-04), выделен объект, активна одна из CO-вкладок (CO1 / CO2 / CO3 / CO4).

**Основной поток:**
1. Во встроенной форме «Кабель» на SC-04 пользователь открывает
   Select **«Тип кабеля»**.
2. Выбирает один из 4 типов: саморегулирующийся, одножильный
   постоянной мощности, трёхжильный постоянной мощности, кабель с
   минеральной изоляцией.
3. Система пересчитывает Select «Марка» — отображаются только
   марки выбранного типа из активной базы расчёта.
4. Если выбран тип «кабель с минеральной изоляцией» — поля
   «Шаг навива» и «Количество ниток» блокируются (значения 0 и 1
   соответственно — VAL-61).
5. После «Сохранить» запускается пересчёт электрорасчёта **только
   для текущего варианта CO**; данные теплопотерь объекта не
   меняются.

**Исключительные потоки:**
- **EF-1.** В активной базе нет ни одной марки выбранного типа —
  Select «Марка» показывает только «Авто», результат расчёта —
  «Ошибка: нет подходящих марок в активной базе».

**Постусловие:** для объекта зафиксирован тип кабеля, список марок
обновлён, результат расчёта актуален.

## UC-G-26. Создание варианта расчёта (CO1 … CO4)

- **Актёры:** Гость или Сотрудник.
- **Применимость:** обе роли.
- **Трассировка:** US-G-30.

**Предусловия:** пользователь на странице «Электрорасчёт» (SC-04);
в проекте есть ≥ 1 вариант (CO1 создаётся автоматически при
первом расчёте); количество вариантов < 4.

**Основной поток:**
1. На SC-04 в страничном переключателе CO пользователь нажимает
   «＋ Добавить вариант (CO4)».
2. Система создаёт новый вариант расчёта (CO2 / CO3 / CO4) на
   основании сохранённых строк текущего выбранного варианта. Для
   действия «Создать на основании» выбранные марки проверяются как
   exact choice на текущих данных объекта: валидный, но не
   оптимальный выбор инженера не заменяется автоподбором. Критерий и
   причина подбора остаются такими же, как в source CO. Если
   скопированная марка не проходит проверку, target CO получает
   structured error без подбора другой марки. Если в source CO расчёт
   есть не у всех объектов, остальные объекты в target CO остаются
   «не рассчитаны».
3. Активной становится новая CO-вкладка; карточки объектов ниже
   обновляются — каждая показывает скопированные параметры
   кабеля и скопированные результаты.
4. Пользователь в **карточках объектов** меняет нужные параметры
   кабеля для нового варианта (отдельно для каждого объекта).
5. Система пересчитывает электрорасчёт нового варианта; результаты
   отображаются в карточках объектов и в сводке проекта.

**Альтернативные потоки:**
- **AF-1.** Удаление варианта — кнопка «🗑 Удалить вариант» под
  CO-вкладками. Если удаляется активный — активным становится
  оставшийся вариант с наименьшим номером CO. Удаление невозможно,
  если вариант единственный.
- **AF-2.** Переименование варианта — кнопка «✎ Переименовать»;
  пользователь задаёт пользовательское имя (например, «дешёвый
  вариант»); идентификатор CO1 … CO4 сохраняется.
- **AF-3.** Целевой CO уже содержит электрорасчёты — система
  показывает опасное подтверждение замены. При подтверждении target
  CO полностью заменяется копией source CO; без подтверждения данные
  target CO не меняются.

**Исключительные потоки:**
- **EF-1.** Попытка создать 5-й вариант — операция отклоняется,
  сообщение «В проекте допускается не более 4 вариантов расчёта
  (CO1 … CO4)» (VAL-59).

**Постусловие:** в проекте сохранён новый вариант расчёта с
независимыми параметрами кабеля по объектам и результатами.
