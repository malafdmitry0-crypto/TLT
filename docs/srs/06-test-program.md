# SRS · Программа испытаний (роли «Пользователь» и «Сотрудник»)

## 1. Назначение документа

Документ устанавливает виды, объём, порядок и методы проведения
приёмочных испытаний программного комплекса теплотехнического и
электротехнического расчёта систем электрообогрева по части,
относящейся к ролям **«Пользователь»** (вход без регистрации,
далее «Гость») и **«Сотрудник»** (вход по логину и паролю)
полноценной версии.

> **Важно.** На текущем сайте развёрнута версия MVP. Настоящий
> документ описывает программу испытаний **полноценной версии** и
> является целевым — не все перечисленные здесь проверки применимы
> к работающему на данный момент сайту.

Документ является частью комплекта SRS из семи взаимодополняющих
документов:

1. Пользовательские истории — бизнес-ценность и критерии приёмки.
2. Сценарии использования — формальные сценарии работы.
3. Перечень элементов — экраны, поля, справочники, ограничения.
4. Валидация — правила проверки входных данных.
5. Функциональные и нефункциональные требования — целевые свойства системы.
6. **Программа испытаний** — этот документ.
7. Требования к отчёту — состав и структура итогового отчёта.

## 2. Общие положения

- **Цель испытаний.** Подтвердить, что программа в части
  функциональности обеих ролей соответствует Техническому заданию
  и требованиям, изложенным в настоящем комплекте SRS, выявить
  возможные дефекты и подтвердить готовность к опытной эксплуатации.
- **Вид испытаний.** Приёмочные (дымовое тестирование + проверка
  критического пути сценариев использования).
- **Место проведения.** Среда тестирования, предоставленная
  Исполнителем (аналог продуктивной среды: развёртывание через
  Docker, локальная сеть без выхода в интернет).
- **Средства тестирования.** Стандартные веб-браузеры последних
  версий: Chrome, Firefox, Edge, Яндекс.
- **Участники.** Исполнитель (проводит испытания) и Заказчик
  (наблюдает, подписывает протокол).

## 4. Объекты испытаний

Проверке подлежит функционал, явно указанный в комплекте SRS и
относящийся к ролям «Пользователь» и «Сотрудник»: доступ и
авторизация, управление проектами (одиночный для Гостя, проводник
для Сотрудника), общие первичные данные, ввод объектов, расчёт
теплопотерь, электрический расчёт, спецификация, предпросмотр /
печать / экспорт отчёта, обмен проектами в формате CSV.

Тестирование интерфейса (UI / UX) проводится по принципу
«работает / не работает», без углублённой оценки дизайна, если это
не влияет на выполнение функций.

## 6. Критерии приёмки

Программа считается прошедшей испытания, если:

1. Все критические сценарии расчётного контура (5.3, 5.4, 5.5, 5.6,
   5.7) выполняются без ошибок для обеих ролей, включая работу со
   всеми 4 типами кабеля (5.5.8 — 5.5.12) и множественными
   вариантами расчёта (5.13).
2. Все критические сценарии роли «Гость» (5.1, 5.2, 5.8) выполняются
   без ошибок.
3. Все критические сценарии роли «Сотрудник» (5.10, 5.11, 5.12,
   5.14, 5.15, 5.16) выполняются без ошибок.
4. Соблюдаются системные ограничения и правила валидации
   (лимит объектов, лимит вариантов CO, TTL гостевой сессии,
   диапазоны параметров, ограничения типов кабеля).
5. Гостю недоступны функции, закреплённые за ролью «Сотрудник»
   (экспорт отчётов в файлы, проводник проектов с чужими проектами,
   расширенная внешняя БД, расширенная спецификация, мастер выбора
   состава отчёта).
6. Отсутствуют дефекты, ведущие к потере данных или некорректному
   результату расчёта.

Некритические дефекты интерфейса (опечатки, мелкие визуальные
смещения) не являются препятствием для приёмки, но фиксируются в
протоколе для исправления.

## 7. Оформление результатов

Результаты испытаний оформляются **Протоколом испытаний**, который
содержит:

- перечень проверенных сценариев и их статус;
- обнаруженные замечания (с указанием шага, браузера, воспроизводимости);
- заключение о готовности / неготовности к сдаче;
- подписи представителей Исполнителя и Заказчика.
