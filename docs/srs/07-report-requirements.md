# SRS · Требования к отчёту (роли «Пользователь» и «Сотрудник»)

## 1. Назначение документа

Документ содержит требования к составу, структуре и оформлению
итогового отчёта, формируемого по проекту в полноценной версии
программного комплекса теплотехнического и электротехнического
расчёта систем электрообогрева. Состав отчёта **един** для обеих
ролей — «Пользователь» (далее «Гость») и «Сотрудник»; различаются
только доступные форматы:

- **Гость:** только предпросмотр в браузере и печать средствами
  браузера.
- **Сотрудник:** дополнительно — экспорт в PDF, DOCX и XLSX.

> **Важно.** Текущий целевой уровень проекта — **полноценная версия**.
> Исторические упоминания базового уровня в SRS используются только как
> контекст ТЗ и не снижают критерии приемки.

> **Запрос к Заказчику.** Состав, структура и шаблон итогового
> отчёта в Техническом задании заданы в общих чертах (разделы 4.2.4
> и 4.3.4 ТЗ: «базовый отчёт», «полный отчёт»), без указания
> точного перечня разделов, порядка их следования и визуального
> оформления. В настоящем документе приведены **предлагаемые**
> решения, согласованные Исполнителем на основе аналогов.
> Итоговый состав отчёта, названия разделов и шаблон оформления
> подлежат согласованию с Заказчиком до начала разработки
> (см. раздел 7 «Открытые вопросы к Заказчику»).

Документ является частью комплекта SRS из семи взаимодополняющих
документов:

1. Пользовательские истории — бизнес-ценность и критерии приёмки.
2. Сценарии использования — формальные сценарии работы.
3. Перечень элементов — экраны, поля, справочники, ограничения.
4. Валидация — правила проверки входных данных.
5. Функциональные и нефункциональные требования — целевые свойства системы.
6. Программа испытаний — виды, объём и методы проверки.
7. **Требования к отчёту** — этот документ.

## 2. Общие требования к отчёту

- Отчёт формируется автоматически на основании данных проекта:
  общих первичных данных, перечня объектов, результатов
  теплотехнического и электротехнического расчётов, сформированной
  спецификации.
- Формирование отчёта инициируется на странице «Отчёт» в
  пошаговой навигации проекта.
- **Базовый состав отчёта** одинаков для обеих ролей (см. раздел 3).
  Сотрудник дополнительно может **выбирать состав отчёта в мастере**
  (US-E-12, отдельное окно SC-09): включать / исключать разделы,
  выбирать активный CO, конкретный CO или сводный режим по всем CO
  (US-E-13).
- Отчёт может включать данные **по одному варианту расчёта**
  (активному CO) или **сводно по нескольким вариантам CO1 … CO4**
  (для Сотрудника, по выбору в мастере).
- **Доступные режимы вывода отчёта по ролям:**

  | Режим                                              | Гость | Сотрудник |
  |----------------------------------------------------|:-----:|:---------:|
  | Предпросмотр в браузере (HTML)                      |  ✅   |    ✅     |
  | Печать средствами стандартного диалога браузера     |  ✅   |    ✅     |
  | Экспорт в PDF                                       |  ❌   |    ✅     |
  | Экспорт в DOCX (MS Word)                            |  ❌   |    ✅     |
  | Экспорт в XLSX (MS Excel)                           |  ❌   |    ✅     |

- Язык отчёта — русский.
- Единицы измерения — метрические, согласованы с документом
  «Перечень элементов» (раздел «Единицы измерения и точность»).

## 3. Предлагаемый состав отчёта

Ниже приведён **предлагаемый** состав отчёта — для утверждения
Заказчиком. Разделы приведены в предполагаемом порядке следования.

### 3.1. Титульная часть

| Элемент            | Источник                        | Комментарий                                     |
|--------------------|---------------------------------|-------------------------------------------------|
| Наименование отчёта| Константа                       | «Отчёт по расчёту системы электрообогрева»      |
| Название проекта   | Проект                          | —                                               |
| Номер задачи       | Проект                          | —                                               |
| Дата формирования  | Дата генерации отчёта           | Формат ДД.ММ.ГГГГ                                |
| Описание проекта   | Проект                          | Если заполнено                                   |

*На согласование:* нужен ли логотип, наименование Заказчика,
номер договора, визы (исполнитель / проверил / утвердил). В гостевом
режиме данные об исполнителе отсутствуют.

### 3.2. Общие первичные данные проекта

Таблица «Параметр / Значение», включает:

- климатический регион (город);
- расчётная температура наружного воздуха;
- скорость ветра;
- напряжение питания;
- коэффициент запаса по мощности;
- тип прокладки (надземная / подземная) и глубина заложения.

### 3.3. Исходные данные по объектам

Раздел содержит два подраздела: «Трубопроводы» и «Резервуары».
Для каждого типа — таблица со строкой на объект и колонками:

- **Трубопроводы.** № п/п, наименование, наружный диаметр, условный
  диаметр (DN), длина, толщина стенки, материал и толщина изоляции,
  температура продукта, температура окружающей среды, тип прокладки.
- **Резервуары.** № п/п, наименование, форма, габариты
  (в зависимости от формы), материал и толщина изоляции, температура
  продукта, температура окружающей среды.

### 3.4. Результаты расчёта теплопотерь

Для каждого объекта:

- линейные теплопотери (Вт/м) — для трубопроводов;
- удельные теплопотери (Вт/м²) — для резервуаров;
- дополнительные теплопотери резервуара (Вт) — крышка, днище, опоры и иные
  добавочные нагрузки, если заданы в расчёте;
- суммарные теплопотери (Вт);
- площадь поверхности — для резервуаров.

Итоговая строка: суммарные теплопотери по проекту.

### 3.5. Результаты электротехнического расчёта

Для каждого объекта:

- марка подобранного (или выбранного вручную) кабеля;
- параметры укладки: шаг навива, количество ниток;
- длина кабеля;
- суммарная мощность;
- потребляемый ток.

Сводная часть: суммарные длина кабеля, мощность и ток по проекту.
Сводные показатели считаются только по успешным электрорасчётам: есть
подобранная/выбранная марка кабеля (`cable_mark` или `selected_cable`) и нет
`error_code` / `category` в результате расчёта. Объекты с ошибкой,
неподдержанным сценарием или устаревшим электрорасчётом не включаются в
суммарные длину, мощность и ток; они выводятся отдельным списком с причиной.

*На согласование:* финальная форма отображения объектов с ошибкой расчёта
(текущая реализация — отдельный список с причиной).

### 3.6. Спецификация материалов

Таблица со столбцами: № п/п, категория, наименование, артикул,
единица измерения, количество. Позиции сгруппированы по
категории; кабели агрегированы по марке с суммарной длиной.

### 3.7. Справочная часть

*На согласование:* включать ли в отчёт:

- список применённых коэффициентов запаса;
- примечания и допущения, принятые при расчёте;
- перечень использованных формул со ссылками на нормативные
  документы;
- ФИО исполнителя (в гостевом режиме отсутствует).

## 4. Структурные требования

- **Иерархия заголовков.** Разделы 1-го уровня (3.1 … 3.7 из
  настоящего документа) имеют сквозную нумерацию; подразделы —
  второй уровень нумерации.
- **Таблицы.** Имеют заголовок («Таблица N. ...»), шапку с названиями
  колонок. Числовые значения выровнены по правому краю.
- **Страничные разрывы.** Каждый раздел верхнего уровня — с новой
  страницы (при печати).
- **Колонтитулы при печати.** В нижнем колонтитуле — номер страницы
  и общее число страниц. Содержимое верхнего колонтитула подлежит
  согласованию.
- **Шрифт и размер.** По умолчанию — системный шрифт без засечек,
  14 px в экранном режиме, 10 pt при печати. Для таблиц — 12 px /
  9 pt. *Конкретные шрифты/кегли — на согласование.*

## 5. Требования к печати

- При нажатии «Печать» браузер открывает стандартный диалог печати.
- На печать выводится **только содержимое отчёта** — элементы
  навигации, боковая панель, шапка приложения и индикаторы сессии
  скрываются.
- Ориентация страницы — книжная; для широких таблиц допускается
  сжатие колонок или перенос в альбомную ориентацию соответствующих
  страниц. *На согласование:* допустимо ли изменять ориентацию для
  отдельных таблиц.
- Масштаб по умолчанию — 100 %, поля страницы — стандартные
  (2 см сверху / снизу, 1,5 см по бокам). *На согласование.*

| Экспорт в PDF                                       |  ❌   |    ✅     |

| Экспорт в XLSX (MS Excel)                           |  ❌   |    ✅     |

## 7. Открытые вопросы к Заказчику

Для окончательного утверждения требований к отчёту необходимо
согласование со стороны Заказчика по следующим пунктам.

### 7.1. Состав разделов

- **Q-01.** Перечень разделов отчёта — соответствует ли
  предлагаемый в разделе 3 настоящего документа? Какие разделы
  добавить / убрать?
- **Q-02.** Порядок следования разделов — предлагаемый в разделе 3
  или иной?
- **Q-03.** Нужен ли раздел «Справочная часть» (коэффициенты,
  формулы, нормативы) в отчёте гостевой роли, или он выводится
  только в «полном» отчёте, доступном сотруднику?

### 7.2. Оформление титульной части

- **Q-04.** Нужен ли логотип? Если да — чей (Заказчика, продукта,
  Исполнителя) и в каком виде?
- **Q-05.** Должен ли отчёт содержать наименование Заказчика, номер
  договора, номер задачи?
- **Q-06.** Нужны ли подписные визы (исполнитель / проверил /
  утвердил)? В гостевом режиме ФИО исполнителя отсутствует — как
  отображать: прочерк, «Гость без регистрации», пустое поле?

### 7.3. Содержательные вопросы

- **Q-07.** Как выводить объекты с ошибкой электрорасчёта — в
  общей таблице с пометкой «Ошибка», в отдельном списке или
  исключать из отчёта?
- **Q-08.** Нужно ли указывать в отчёте дату последнего изменения
  проекта, кроме даты формирования отчёта?
- **Q-09.** Нужно ли отображать в отчёте применённые формулы со
  ссылками на нормативные документы (СП, ГОСТ)?
- **Q-10.** Нужно ли выводить в отчёте идентификаторы кабелей из
  каталога (артикул) или достаточно марки?
- **Q-11.** Формат вывода чисел: разделитель десятичной части
  (точка / запятая), разделитель тысяч (пробел / отсутствует)?

### 7.4. Визуальное оформление и шаблон

- **Q-12.** Есть ли у Заказчика утверждённый корпоративный шаблон
  отчёта (Word / PDF), на который нужно ориентироваться при
  вёрстке? Если да — передать образец.
- **Q-13.** Цветовая схема отчёта: нейтральная (только чёрно-белая
  для удобной печати) или с корпоративными акцентами?
- **Q-14.** Какие шрифты использовать? Требуется ли соответствие
  фирменному стилю ТЛТ?
- **Q-15.** Допускается ли альбомная ориентация отдельных страниц
  для широких таблиц?

### 7.5. Поведение при печати

- **Q-16.** Нужны ли в отчёте «шапка» и «подвал» на каждой странице
  (название проекта / номер страницы)? Какое содержимое?
- **Q-17.** Нужна ли нумерация страниц в формате «N из M» или
  достаточно «N»?

### 7.6. Образец-аналог

- **Q-18.** Заказчик прямо ссылается на программу-аналог «Тепломаг»
  как на ориентир по UX и работе с таблицей. Нужно ли
  ориентироваться на «Тепломаг» и при оформлении итогового отчёта?
  Если да — желательно получить образец отчёта «Тепломаг» (PDF /
  скриншоты) для сверки структуры и оформления.
- **Q-19.** Есть ли у Заказчика собственный утверждённый образец
  отчёта (от прежних проектов), на который следует ориентироваться?

### 7.7. Мастер выбора состава отчёта и варианты CO

- **Q-20.** Окончательный набор разделов в мастере состава
  отчёта — должен ли совпадать с предлагаемым в разделе 3 / 5.8
  документа 3 (титул, общие данные, исходные данные, результаты
  теплопотерь, результаты электрорасчёта, спецификация,
  справочная часть)? Какие разделы добавить / убрать?
- **Q-21.** Должны ли в мастере быть «пресеты» под типового
  получателя (Заказчик, ПТО, отдел снабжения), которые
  устанавливают набор разделов в один клик?
- **Q-22.** Оформление сводного отчёта по нескольким CO в самом
  файле:
  - вариант A — для каждого объекта в одной таблице сравнения
    показать все CO с подсветкой активного;
  - вариант B — для каждого объекта несколько подзаголовков
    «Вариант CO1», «Вариант CO2» и т. п. с отдельными таблицами
    результатов и спецификации;
  - вариант C — основной отчёт по активному CO + приложение
    «Альтернативные варианты».
  Какой вариант предпочтителен?
- **Q-23.** В разделе спецификации сводного отчёта показывать
  материалы:
  - только по активному CO;
  - по каждому CO с разделением;
  - сравнительной таблицей.
- **Q-24.** В мастере хранить выбранный состав отчёта на уровне
  проекта (как сейчас в 7.6 модели данных) или на уровне
  Сотрудника (его профиль)?
- **Q-25.** Для XLSX-экспорта: каждый раздел — на отдельном листе
  или один лист с разделами по строкам?

## 8. Порядок внесения изменений

После получения ответов Заказчика на открытые вопросы раздел 3
настоящего документа актуализируется: спорные формулировки
«на согласование» заменяются на утверждённые значения, вопросы
раздела 7 удаляются. Отдельно фиксируется версия документа и дата
утверждения.
