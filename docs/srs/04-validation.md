# SRS · Валидация (роли «Пользователь» и «Сотрудник»)

## 1. Назначение документа

Документ собирает в одном месте **все правила валидации** входных
данных, применяемые в полноценной версии программного комплекса
теплотехнического и электротехнического расчёта систем
электрообогрева для ролей «Пользователь» (далее «Гость») и
«Сотрудник». Назначение документа — обеспечить:

- единый источник истины для разработки и тестирования;
- проверяемость каждого правила в программе испытаний;
- понимание Заказчиком набора защитных проверок системы.

> **Важно.** Текущий целевой уровень проекта — **полноценная версия**.
> Исторические упоминания базового уровня в SRS используются только как
> контекст ТЗ и не снижают критерии приемки.

Документ является частью комплекта SRS из семи взаимодополняющих
документов:

1. Пользовательские истории — бизнес-ценность и критерии приёмки.
2. Сценарии использования — формальные сценарии работы с системой.
3. Перечень элементов — экраны, поля, справочники, ограничения.
4. **Валидация** — этот документ.
5. Функциональные и нефункциональные требования — целевые свойства системы.
6. Программа испытаний — виды, объём и методы проверки.
7. Требования к отчёту — состав и структура итогового отчёта.

## 2. Соглашения

- **ID правила:** `VAL-NN`.
- **Тип:** Поле (валидация значения отдельного поля) / Кросс-поле
  (правило, связывающее несколько полей) / Бизнес (нарушение
  бизнес-логики системы).
- **Срабатывание:** клиент (моментальная подсветка в форме) /
  сервер (защитная проверка при сохранении в БД) / оба уровня
  (рекомендуется для критичных правил).
- **Реакция:** что видит пользователь при нарушении правила.

Все правила, кроме явно отмеченных «только Сотрудник» / «только
Гость», применяются к **обеим** ролям.
