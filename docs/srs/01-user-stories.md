# SRS · Пользовательские истории (роли «Пользователь» и «Сотрудник»)

## 1. Назначение документа

Документ содержит пользовательские истории для ролей
**«Пользователь»** (вход без регистрации, далее «Гость») и
**«Сотрудник»** (вход по логину и паролю) полноценной версии
программного комплекса теплотехнического и электротехнического
расчёта систем электрообогрева.

> **Важно.** На текущем сайте развёрнута версия MVP. Настоящий
> документ описывает требования к **полноценной версии** и является
> целевым — часть перечисленных функций ещё не реализована в
> работающем на данный момент сайте.

> **Образец-ориентир по UX.** Заказчик при формулировании
> требований ссылается на программу-аналог «Тепломаг» — на её
> подход к работе с таблицами исходных данных, выбору кабеля
> прямо в строке и общему UX. Решения, перечисленные в настоящем
> документе, следует трактовать в духе этого ориентира.

Документ является частью комплекта SRS из семи взаимодополняющих
документов:

1. **Пользовательские истории** — этот документ.
2. Сценарии использования — формальные сценарии работы с системой.
3. Перечень элементов — экраны, поля, таблицы, единицы измерения,
   справочники и системные ограничения.
4. Валидация — правила проверки входных данных.
5. Функциональные и нефункциональные требования — целевые свойства системы.
6. Программа испытаний — виды, объём и методы проверки.
7. Требования к отчёту — состав и структура итогового отчёта.

## 2. Соглашения

- **Формат истории:** «Как <роль>, я хочу <действие>, чтобы <ценность>».
- **Приоритет:** Must / Should / Could (шкала MoSCoW).
- **ID:**
  - `US-G-NN` — истории, специфичные для роли «Гость»,
  - `US-E-NN` — истории, специфичные для роли «Сотрудник»,
  - **общие** истории расчётного контура (ввод объектов, расчёт
    теплопотерь, электрорасчёт, спецификация, отчёт, импорт CSV
    объектов) применимы к **обеим** ролям и приведены в разделах
    EPIC-G-2…6 — каждая такая история отмечена пометкой
    «Применимость: Гость + Сотрудник».
- **Критерии приёмки** — проверяемые условия, по которым история
  считается выполненной.

> **Замечание о нумерации.** В перечне историй намеренно отсутствуют
> идентификаторы **US-G-02**, **US-G-04** и **US-G-05** — они были
> зафиксированы в более ранних редакциях SRS («несколько проектов в
> сессии», «переключение между проектами», «создание проекта на
> основании существующего» для Гостя), но **изъяты по итогам
> согласования с Заказчиком**: в полноценной версии Гость работает
> ровно с одним активным проектом. Эквивалентный функционал для
> роли Сотрудник доступен в эпиках EPIC-E-2 (управление проектами в
> проводнике) и EPIC-E-3 (командная работа). Пропуски сохранены
> намеренно — чтобы не ломать ссылки в более старых артефактах
> (тесты, история переписки).

## 3. Обзор ролевой модели

Ролевая модель системы включает три роли: **Пользователь** (анонимный
доступ без регистрации, далее «Гость»), **Сотрудник** (авторизованный
инженер) и **Администратор**. Настоящий документ описывает первые
две роли (Администратор управляет учётными записями и коэффициентами
и в данный комплект не входит).

### Роль «Гость» (вход без регистрации)

- Сессия создаётся одним нажатием кнопки «Войти без регистрации»;
  логина и пароля нет.
- В сессии активен **ровно один** проект. Список нескольких
  проектов и переключение между ними не предусмотрены.
- При входе автоматически создаётся пустой проект «Мой проект».
- Может **создать новый** проект (с заменой текущего),
  **загрузить** проект из CSV (с заменой текущего) или **удалить**
  текущий проект (после удаления автоматически создаётся новый
  пустой «Мой проект»).
- Доступен полный расчётный контур: ввод объектов, расчёт
  теплопотерь, электрорасчёт, спецификация, предпросмотр отчёта,
  печать средствами браузера, экспорт / импорт CSV.
- Сессия завершается автоматически по неактивности.

### Роль «Сотрудник» (вход по логину и паролю)

- Сессия создаётся через форму входа: логин (e-mail) и пароль.
- Может вести **сколько угодно проектов одновременно**: в
  «Проводнике проектов» доступен список своих и чужих проектов с
  поиском и фильтрацией (по типу, году, номеру задачи).
- Может **создавать**, **редактировать**, **удалять**,
  **копировать (создавать на основании)** свои проекты, а также
  **просматривать и редактировать чужие**.
- Доступен **тот же расчётный контур**, что и Гостю (общие истории
  EPIC-G-2…6), без отличий в формулах и интерфейсе расчёта.
- Дополнительно может:
  - **переключать базу расчёта** — встроенный каталог или
    расширенная внешняя БД кабелей и аксессуаров;
  - **редактировать** альтернативные материалы и кабели в активной
    базе;
  - формировать **расширенную спецификацию** — с группировкой,
    сортировкой и заменой позиций на аналоги из внешней БД (у
    Гостя — авто-спецификация без редактирования);
  - использовать **мастер выбора состава отчёта** в отдельном окне
    перед экспортом;
  - формировать **сводный отчёт по нескольким вариантам расчёта**
    (CO1 … CO4);
  - **экспортировать отчёт в файлы** PDF, DOCX, XLSX (у Гостя —
    только предпросмотр и печать).

Гостю **недоступны**: экспорт отчётов в файлы (PDF / DOCX / XLSX),
ведение нескольких проектов одновременно, доступ к проектам других
пользователей, выбор расширенной внешней БД, редактирование
альтернативных материалов и кабелей, мастер выбора состава отчёта,
сводный отчёт по нескольким CO, административные функции.

## EPIC-G-1. Сессия и единственный проект

> **Применимость:** только Гость. У Сотрудника управление сессией и
> проектами реализовано иначе — см. EPIC-E-1, EPIC-E-2.

### US-G-01. Вход без регистрации с автоматическим созданием проекта

**Как** внешний проектировщик,
**я хочу** начать работу одним нажатием кнопки «Войти без регистрации»
и сразу получить рабочий проект,
**чтобы** немедленно перейти к расчётам без создания учётной записи и
без ручного создания проекта.

**Приоритет:** Must.

**Критерии приёмки:**
- На главной странице видна кнопка «Войти без регистрации».
- После нажатия автоматически создаётся гостевая сессия и **один**
  пустой проект «Мой проект» — он сразу становится активным.
- Гость попадает на рабочий стол активного проекта, а не на список
  проектов (списка проектов в гостевом режиме нет).
- В интерфейсе виден маркер режима «Гость» и название активного
  проекта.

---

### US-G-03. Создание нового проекта (с заменой текущего)

**Как** Гость,
**я хочу** создать новый пустой проект с заданным названием,
**чтобы** начать работу «с чистого листа», когда текущий проект
больше не нужен.

**Приоритет:** Must.

**Критерии приёмки:**
- В меню проекта доступна операция «Создать новый проект».
- Открывается форма с полями: «Название» (обязательное),
  «Номер задачи», «Описание» (опциональные).
- Перед созданием Система запрашивает подтверждение: «Текущий
  проект и все его данные будут удалены. Продолжить?». Рекомендуется
  предварительно сохранить текущий проект через экспорт CSV (US-G-24).
- После подтверждения текущий активный проект удаляется (объекты,
  расчёты, спецификация); создаётся новый пустой проект с
  указанными свойствами и становится активным.
- В сессии по-прежнему ровно один проект.

---

### US-G-06. Удаление текущего проекта

**Как** Гость,
**я хочу** удалить текущий проект одной операцией,
**чтобы** очистить рабочее пространство от ошибочно введённых
или больше не нужных данных.

**Приоритет:** Must.

**Критерии приёмки:**
- В меню проекта доступна операция «Удалить текущий проект».
- Запрашивается подтверждение с предупреждением о безвозвратности.
- После подтверждения удаляются проект и все его данные (объекты,
  результаты расчётов, спецификация).
- На месте удалённого Система автоматически создаёт пустой проект
  «Мой проект» — у Гостя всегда есть один активный проект.

---

### US-G-07. Автоматическое завершение сессии по неактивности

**Как** владелец системы,
**я хочу** чтобы данные неактивного Гостя автоматически удалялись,
**чтобы** гарантировать конфиденциальность и не накапливать мусор в
базе.

**Приоритет:** Must.

**Критерии приёмки:**
- Любое действие в системе продлевает сессию.
- Сессия без действий дольше 20 минут удаляется автоматически.
- Вместе с сессией удаляются все её проекты и связанные данные.
- После удаления сессии при повторной попытке работы система
  предлагает войти заново.

## EPIC-G-2. Общие параметры проекта

> **Применимость:** Гость + Сотрудник.

### US-G-08. Общие первичные данные проекта (единое модальное окно)

**Как** Гость,
**я хочу** один раз ввести общие параметры проекта (климатический
регион, температура окружающей среды, напряжение питания, коэффициент
запаса, тип прокладки) в **едином модальном окне**,
**чтобы** не дублировать эти поля в каждом объекте.

**Приоритет:** Must.

**Критерии приёмки:**
- На рабочем столе доступна кнопка «Общие первичные данные».
- Кнопка открывает **единое модальное окно** со всеми общими
  полями проекта; при первом открытии проекта система предлагает
  заполнить общие данные в первую очередь.
- Поля окна: климатический регион (выбор из справочника), температура
  окружающей среды, напряжение питания (220 / 380 В), коэффициент
  запаса по мощности, тип прокладки (надземная / подземная), глубина
  заложения (для подземной).
- Значения предзаполняют соответствующие поля при добавлении
  нового объекта.
- В форме объекта значения можно переопределить локально.
- При изменении общих параметров после добавления объектов система
  предлагает выполнить пересчёт всех объектов.

### US-G-09. Справочник климатических регионов

**Как** Гость,
**я хочу** выбрать климатический регион из списка городов,
**чтобы** автоматически подставилась расчётная температура наружного
воздуха и скорость ветра.

**Приоритет:** Should.

**Критерии приёмки:**
- В поле «Регион» работает поиск по названию города.
- При выборе города автоматически заполняются температура и скорость
  ветра по действующим нормативам.

## EPIC-G-3. Ввод объектов и расчёт теплопотерь

> **Применимость:** Гость + Сотрудник.

### US-G-10. Добавление трубопровода

**Как** Гость,
**я хочу** добавить трубопровод через **единую плоскую форму** —
все параметры видны сразу, без шагов и переходов между вкладками
(ориентир — программа «Тепломаг»),
**чтобы** видеть все поля и значения в одном месте, не
переключаясь между шагами.

**Приоритет:** Must.

**Критерии приёмки:**
- На рабочем столе **постоянно видна** плоская форма редактирования
  объекта со всеми полями одновременно (геометрия, теплофизика,
  изоляция, температурные параметры, арматура). Это **часть
  основного интерфейса**, не модальное окно.
- Шагов / вкладок / переходов «Далее» внутри формы **нет**.
- Клик по строке таблицы → форма наверху обновляется и показывает
  параметры этой строки (режим «редактирование»).
- Кнопка «+ Добавить» → форма очищается, заполняется значениями
  по умолчанию (режим «новая запись»).
- Обязательные параметры: наружный диаметр, длина, толщина стенки,
  материал и толщина изоляции, температура продукта, температура
  окружающей среды.
- Опциональные параметры: количество фланцев / арматуры и их
  эквивалентная длина, скорость ветра, тип прокладки и глубина
  заложения.
- Поддерживается от 1 до 3 слоёв изоляции.
- Наименование объекта формируется автоматически из параметров.
- После сохранения теплопотери рассчитываются автоматически, строка
  появляется в таблице.

### US-G-11. Добавление резервуара

**Как** Гость,
**я хочу** добавить резервуар (цилиндр, параллелепипед или шар) и
получить расчёт теплопотерь,
**чтобы** определить потребность в обогреве ёмкостного оборудования.

**Приоритет:** Must.

**Критерии приёмки:**
- Кнопка «+ Добавить» (при выборе типа «Резервуар») очищает ту же
  встроенную форму, переключает её в режим «резервуар» и
  переименовывает первую колонку «Геометрия трубы» в «Форма и
  геометрия резервуара».
- Форма выбирается на первом шаге: цилиндр (диаметр + высота),
  параллелепипед (длина + ширина + высота), шар (диаметр).
- Параметры изоляции и температуры — как у трубопровода.
- Площадь поверхности и суммарные теплопотери рассчитываются
  автоматически.

### US-G-12. Ручной ввод параметров вместо справочных значений

**Как** Гость,
**я хочу** вручную задавать параметры расчёта вместо значений из
справочника (в первую очередь — коэффициент теплопроводности λ
изоляции через пункт «Другое»),
**чтобы** использовать материалы и условия, отсутствующие во
встроенных справочниках.

**Приоритет:** Must.

**Критерии приёмки:**
- В списке материалов изоляции последним пунктом идёт «Другое»;
  при его выборе появляется обязательное поле «λ, Вт/(м·К)» в
  диапазоне 0,005 … 5,0; введённое значение используется в расчёте
  вместо табличного.
- Аналогичная возможность ручного ввода предусмотрена для прочих
  параметров, для которых в справочниках программы заданы
  значения по умолчанию. **Конкретный перечень параметров
  подлежит согласованию с Заказчиком** (см. раздел 5
  «Открытые вопросы», Q-A).
- Везде, где включён ручной ввод параметра, в форме явно
  отмечается переключение «Из справочника / Ввести вручную».

### US-G-13. Редактирование объекта с автоматическим пересчётом

**Как** Гость,
**я хочу** отредактировать объект и сразу увидеть обновлённые
результаты,
**чтобы** мгновенно оценивать влияние изменений на теплопотери и подбор
кабеля.

**Приоритет:** Must.

**Критерии приёмки:**
- Клик по строке таблицы наполняет встроенную форму её
  заполненными полями.
- После сохранения изменений теплопотери и результаты электрорасчёта
  обновляются автоматически.
- Соседние объекты проекта не затрагиваются.

### US-G-14. Удаление объекта

**Как** Гость,
**я хочу** удалить объект одним действием с подтверждением,
**чтобы** убрать ошибочно добавленную строку.

**Приоритет:** Must.

**Критерии приёмки:**
- Кнопка удаления запрашивает подтверждение.
- После подтверждения строка пропадает из таблицы.
- Суммарные показатели проекта пересчитываются.

### US-G-15. Изменение порядка строк (drag-and-drop)

**Как** Гость,
**я хочу** перетаскивать строки таблицы мышью,
**чтобы** группировать объекты по участкам трассы для удобства
восприятия.

**Приоритет:** Should.

**Критерии приёмки:**
- Строки таблицы можно перетаскивать.
- Порядок сохраняется и восстанавливается при повторном открытии
  проекта.
- Сортировка внутри типа (труба среди труб, резервуар среди
  резервуаров).

### US-G-16. Импорт объектов из Excel / CSV

**Как** Гость,
**я хочу** загрузить объекты пакетом из xlsx- или csv-файла,
**чтобы** не вводить десятки строк вручную.

**Приоритет:** Must.

**Критерии приёмки:**
- Кнопка «Импорт (Excel / CSV)» открывает диалог выбора файла.
- Рядом доступны ссылки на скачивание шаблонов (`.xlsx`, `.csv`).
- XLSX содержит два листа: «Трубопроводы» и «Резервуары».
- CSV содержит столбец «Тип» со значениями «труба» / «резервуар».
- Система принимает синонимы названий материалов и форм резервуаров.
- После импорта выводится отчёт: сколько строк импортировано, какие
  ошибки встретились и в каких строках.
- Ошибка в отдельной строке не прерывает импорт остальных.

### US-G-17. Подсветка невалидных строк

**Как** Гость,
**я хочу** чтобы объекты с ошибками валидации выделялись визуально,
**чтобы** сразу видеть, какие строки требуют внимания.

**Приоритет:** Must.

**Критерии приёмки:**
- Строка с невалидными параметрами имеет красный фон.
- Под таблицей видна легенда «красная строка = не рассчитано».
- При наведении на ячейку ошибки видна подсказка с полной причиной.

### US-G-26. Копирование параметров строки (создание объекта на основании)

**Как** Гость,
**я хочу** создать новый объект как копию любой существующей строки
таблицы исходных данных (по аналогии с операцией «создать проект на
основании», но на уровне отдельного объекта),
**чтобы** быстро добавлять однотипные трубопроводы / резервуары без
повторного ввода всех параметров.

**Приоритет:** Must.

**Критерии приёмки:**
- В строке таблицы исходных данных доступна операция «Создать на
  основании» (копирование строки).
- Создаётся новая строка того же типа (трубопровод / резервуар)
  с полным копированием параметров исходной строки, включая
  параметры кабеля (марка, шаг навива, количество ниток).
- Новая строка получает автоматически сгенерированное наименование
  с пометкой копии (например, «‹исходное наименование› (копия)»).
- Теплопотери и электрорасчёт для новой строки выполняются
  автоматически — копируются только исходные параметры, результаты
  пересчитываются заново.
- Операция учитывается в лимите 50 объектов на проект.

## EPIC-G-4. Электротехнический расчёт

> **Применимость:** Гость + Сотрудник.

### US-G-18. Автоматический подбор кабеля для всех объектов

**Как** Гость,
**я хочу** запустить электрорасчёт одной кнопкой и получить результат
для всех объектов проекта,
**чтобы** не работать с объектами по одному.

**Приоритет:** Must.

**Критерии приёмки:**
- На рабочем столе доступна кнопка «Выполнить электрорасчёт».
- Для объектов с маркой кабеля «Авто» подбирается оптимальная
  марка из активной базы расчёта (встроенный каталог либо
  расширенная внешняя БД, см. US-E-10) с учётом выбранного **типа
  кабеля** (см. US-G-29) и активного варианта расчёта
  (CO1 … CO4, см. US-G-30..32).
- Для каждого объекта возвращаются: тип кабеля, марка, длина,
  суммарная мощность и потребляемый ток. Возвращается результат
  по каждому варианту расчёта, имеющемуся в проекте.
- Если подходящей марки нет, вариант объекта получает статус
  «Ошибка» с пояснением; остальные варианты и объекты
  рассчитываются успешно.
- На отдельной странице «Электрорасчёт» выводится сводка по
  активному варианту: суммарная длина, мощность и ток по проекту,
  список карточек объектов с раскрытием по вариантам CO.

### US-G-19. Выбор типа и марки кабеля на странице «Электрорасчёт»

**Как** Гость,
**я хочу** выбирать **тип кабеля** и **марку** на странице
«Электрорасчёт» — для текущего варианта расчёта CO,
**чтобы** управлять параметрами кабеля отдельно от данных по
теплопотерям. Параметры теплопотерь (геометрия, изоляция,
температура) — на шаге «Теплопотери»; параметры кабеля и варианты
обогрева — на шаге «Электрорасчёт».

**Приоритет:** Must.

**Критерии приёмки:**
- На странице «Электрорасчёт» (SC-04) для **выделенного** объекта
  доступна встроенная форма «Кабель»:
  - **Тип кабеля** — Select из 4 типов (см. US-G-29);
  - **Марка** — Select со значениями «Авто» + марки выбранного
    типа из активной базы расчёта;
  - шаг навива, количество ниток.
- Значение «Авто» (по умолчанию) передаёт выбор автоматическому
  подборщику в пределах выбранного типа кабеля.
- Параметры заполняют **текущий выбранный вариант расчёта**
  (CO1 / CO2 / CO3 / CO4); переключение между вариантами — через
  страничные CO-вкладки (см. US-G-30).
- Подбор кабеля и валидация **не запрещают** выбор кабеля с
  удельной мощностью меньше линейных теплопотерь объекта —
  корректность проверяется по совокупной мощности (см. US-G-20).
- Если выбранная конфигурация кабеля недостаточна по мощности —
  вариант переходит в состояние «Ошибка» с подсказкой.
- В таблице на странице «Теплопотери» **колонок «Тип кабеля» /
  «Марка» / «Шаг» / «Ниток» НЕТ** — там только данные объекта и
  результаты расчёта теплопотерь.

### US-G-20. Навив кабеля и несколько ниток (без ограничения по удельной мощности)

**Как** Гость,
**я хочу** указать, что кабель укладывается с навивом или несколькими
нитками (например, две нитки 15 Вт/м вместо одной 30 Вт/м),
**чтобы** применять типовые конструктивные решения и подбирать кабель
с удельной мощностью меньше теплопотерь на 1 м трубы — компенсируя
дефицит мощности навивом или количеством ниток.

**Приоритет:** Must.

**Критерии приёмки:**
- В строке объекта доступны параметры «Шаг навива» (мм) и «Количество
  ниток» (1 / 2 / 3) для типов «саморегулирующийся», «одножильный
  постоянной мощности», «трёхжильный постоянной мощности».
- Для типа «кабель с минеральной изоляцией» параметры навива
  **запрещены** (шаг = 0, ниток = 1) — см. VAL-61.
- Значение «Шаг навива = 0» означает прямую укладку без навива.
- **Снято** ограничение «удельная мощность кабеля ≥ линейные
  теплопотери на 1 м трубы»: допускается выбор кабеля с меньшей
  удельной мощностью при условии компенсации навивом или
  несколькими нитками.
- Длина кабеля пересчитывается с учётом шага навива и количества
  ниток.
- Суммарная подведённая мощность проверяется по совокупности
  «удельная мощность × длина кабеля × количество ниток» и должна
  быть не меньше суммарных теплопотерь объекта.
- Некорректные комбинации (шаг меньше наружного диаметра трубы)
  отбрасываются с понятным сообщением.

> **Примечание.** Точная формула пересчёта длины кабеля с учётом
> навива и количества ниток будет передана Заказчиком отдельно;
> до её получения логика реализуется по согласованной с Заказчиком
> промежуточной модели.

### US-G-29. Выбор типа греющего кабеля (на странице «Электрорасчёт»)

**Как** Гость или Сотрудник,
**я хочу** выбирать тип греющего кабеля для каждого объекта (для
каждого варианта CO) на странице «Электрорасчёт»,
**чтобы** применять тот тип, который оптимален по конструктивным,
температурным и стоимостным соображениям.

**Приоритет:** Must.

**Применимость:** Гость + Сотрудник.

**Критерии приёмки:**
- На странице «Электрорасчёт» (SC-04) в форме выбора кабеля для
  активного объекта и активной CO-вкладки доступен Select
  **«Тип кабеля»** с 4 значениями:
  - **Саморегулирующийся** (по умолчанию, линейка ТЛТ);
  - **Одножильный постоянной мощности**;
  - **Трёхжильный постоянной мощности**;
  - **Кабель с минеральной изоляцией**.
- При смене типа список доступных марок в Select «Марка»
  обновляется — показываются только марки выбранного типа из
  активной базы расчёта.
- Параметры навива (шаг, количество ниток) применимы ко всем
  типам, **кроме** «кабель с минеральной изоляцией» — для него
  они блокируются (VAL-61).
- При сохранении тип кабеля и марка попадают в результат
  электрорасчёта **выбранного варианта CO**; затем активный CO
  идёт в спецификацию и отчёт.
- На странице «Теплопотери» (SC-03) полей «Тип кабеля» и «Марка»
  **нет** — кабель не участвует в расчёте теплопотерь.

> **Q-E (открытый вопрос).** Опционально включить пятый тип —
> «проводник для скин-системы» (ТЗ 4.3.2 указывает скин-системы
> как опциональные на поздних этапах). Согласовать с Заказчиком.

## EPIC-G-7. Множественные варианты расчёта (CO1 … CO4)

> **Применимость:** Гость + Сотрудник.
>
> **Где живут варианты CO.** Варианты расчёта управляются на шаге
> **«Электрорасчёт» (SC-04)** — это варианты выбора кабеля для
> объектов проекта, у которых уже рассчитаны теплопотери. На шаге
> «Теплопотери» (SC-03) вариантов CO нет — там только данные
> объекта (геометрия, изоляция, температура) и результат расчёта
> теплопотерь (q, Q суммарные).
>
> **Бизнес-ценность.** ТЗ 4.3.2 требует «расчёта, сравнения и
> сохранения нескольких вариантов обогрева в рамках одного
> проекта» — в SRS они трактуются как варианты расчёта (CO1…CO4). В проекте можно завести до 4 альтернативных вариантов
> расчёта (CO1 … CO4) — в каждом для каждого объекта задаётся свой
> кабель (тип, марка, шаг навива, количество ниток) и получается
> свой результат расчёта. **Активный вариант** идёт в спецификацию
> и отчёт.

### US-G-30. Создание нескольких вариантов расчёта в проекте

**Как** Гость или Сотрудник,
**я хочу** создать в проекте несколько вариантов расчёта
(CO1 … CO4), в каждом из которых для объектов проекта подобран
свой кабель (тип, марка, шаг навива, количество ниток),
**чтобы** проработать альтернативы и выбрать оптимальный по
техническим и экономическим соображениям.

**Приоритет:** Must.

**Применимость:** Гость + Сотрудник.

**Критерии приёмки:**
- В проекте по умолчанию создан один вариант — **CO1**.
- На странице «Электрорасчёт» (SC-04) — страничный
  переключатель **CO-вкладок** («★ CO1», «CO2», «CO3», «＋
  Добавить вариант (CO4)»). Под вкладками — кнопки управления
  вариантом: «★ Сделать активным», «✎ Переименовать»,
  «🗑 Удалить вариант», «⚡ Пересчитать вариант».
- Клик по вкладке `＋ Добавить вариант` создаёт новый вариант
  (CO2, CO3, CO4) с начальной копией параметров кабеля по всем
  объектам из текущего варианта; пользователь меняет параметры
  по объектам.
- Лимит — до **4 вариантов** на проект (VAL-59).
- При переключении CO-вкладки карточки объектов ниже показывают
  параметры кабеля и результаты для выбранного варианта;
  кабель в карточке объекта задаётся **отдельно для каждого
  объекта** в текущем CO.
- Удаление варианта возможно, кроме случая, когда вариант
  единственный.
- На странице «Теплопотери» (SC-03) **CO не отображается** —
  таблица содержит только данные объекта и теплопотери.
- На SC-04 **нет** отдельной вкладки «Сравнение вариантов» —
  переключение между CO выполняется страничными CO-вкладками.

### US-G-32. Выбор активного варианта расчёта

**Как** Гость или Сотрудник,
**я хочу** на странице «Электрорасчёт» отметить один из вариантов
CO1 … CO4 как активный,
**чтобы** именно он использовался в спецификации и отчёте.

**Приоритет:** Must.

**Применимость:** Гость + Сотрудник.

**Критерии приёмки:**
- На странице SC-04 в страничном переключателе CO у текущей
  открытой вкладки доступна кнопка «★ Сделать активным».
- Активным может быть только один вариант на проект (VAL-60).
- На вкладке варианта (CO1 … CO4) активный отмечен звёздой ★.
- При смене активного варианта — спецификация (SC-05) и отчёт
  (SC-06) автоматически пересчитываются и обновляются под новый
  активный вариант. На странице «Теплопотери» данные объекта и
  результат теплопотерь не зависят от выбранного активного CO.

### US-G-25. Импорт проекта из CSV (с заменой текущего)

**Как** Гость,
**я хочу** загрузить ранее сохранённый CSV-файл проекта,
**чтобы** продолжить работу с теми же данными — это **единственный**
способ сменить активный проект в гостевом режиме.

**Приоритет:** Must.

**Критерии приёмки:**
- В интерфейсе доступна операция «Загрузить проект из CSV».
- Перед загрузкой система запрашивает подтверждение: «Текущий проект
  и все его данные будут удалены и заменены на загружаемый.
  Продолжить?». Рекомендуется предварительно сохранить текущий
  проект через US-G-24 (Экспорт CSV).
- После подтверждения текущий активный проект удаляется (объекты,
  расчёты, спецификация); из CSV восстанавливается новый проект и
  становится активным.
- Восстанавливаются: общие первичные данные, объекты, результаты
  электрорасчёта, спецификация.
- Некорректный файл отклоняется с понятным описанием причины;
  текущий проект при этом **не** удаляется и остаётся активным.

## EPIC-G-6. Удобство работы и табличный режим

> **Бизнес-ценность.** Заказчик ожидает поведения таблицы исходных

### US-G-27. Excel-подобная работа с таблицей исходных данных

**Как** Гость,
**я хочу** работать с таблицей исходных данных в режиме, близком
к Microsoft Excel (массовые операции над диапазоном ячеек),
**чтобы** быстро вводить однотипные значения и не повторять
одни и те же действия для каждой строки.

**Приоритет:** Must.

**Критерии приёмки:** *(уточняются у Заказчика, см. Q-B в разделе 5)*
- Поддерживается копирование значений выделенного диапазона
  ячеек и вставка их в другой диапазон в пределах таблицы.
- Поддерживается множественный выбор строк (через чекбоксы или
  Shift+клик) и групповое удаление выбранных строк.
- *(на согласование)* Поддерживается inline-редактирование
  значения прямо в ячейке таблицы без открытия мастера.
- *(на согласование)* Поддерживается «протягивание» значения
  вниз по колонке (drag-fill).
- *(на согласование)* Доступен экспорт текущего вида таблицы в
  Microsoft Excel.
- Все массовые операции автоматически запускают пересчёт
  затронутых строк.

> **Финальный набор операций (a)–(e) согласовывается с Заказчиком —
> см. вопрос Q-B.**

### US-G-28. Активные подсказки в формах ввода

**Как** Гость,
**я хочу** видеть пояснения рядом с полями ввода (минимально —
ожидаемые единицы измерения, диапазон допустимых значений и
короткий пример),
**чтобы** заполнять формы без обращения к внешней документации
и не ошибаться в единицах.

**Приоритет:** Must.

**Критерии приёмки:** *(итоговый формат — на согласование, см. Q-C)*
- Каждое поле ввода в формах объекта и в окне общих первичных
  данных сопровождается активной подсказкой.
- Подсказка содержит: единицу измерения, допустимый диапазон,
  короткий пример типового значения.
- В подсказке для полей с зависимостью от других параметров
  (например, «глубина заложения только при подземной прокладке»)
  поясняется условие применения.
- Формат подачи подсказок (постоянная подпись под полем /
  всплывающий tooltip / иконка-«?» с раскрывающимся текстом)
  единый по всему приложению и согласован с Заказчиком.

## EPIC-E-1. Авторизация и сессия Сотрудника

> **Применимость:** только Сотрудник.

### US-E-01. Вход по логину и паролю

**Как** Сотрудник,
**я хочу** войти в систему по корпоративному логину (e-mail) и
паролю,
**чтобы** получить доступ к своим и чужим проектам с полным
функционалом, включая экспорт отчётов в файлы.

**Приоритет:** Must.

**Критерии приёмки:**
- На главной странице доступна вторая кнопка «Войти как сотрудник»
  (рядом с «Войти без регистрации»).
- Кнопка открывает форму входа с полями «Логин (e-mail)» и
  «Пароль».
- При успешном входе Сотрудник попадает в «Проводник проектов»
  (см. US-E-02).
- При неверных данных — сообщение «Неверный логин или пароль»;
  пароль в сообщениях не раскрывается.
- При неактивном аккаунте — сообщение «Учётная запись отключена,
  обратитесь к администратору».
- Сессия Сотрудника не имеет ограничения «1 проект на сессию»,
  не удаляется автоматически по неактивности (поддержка через
  механизм продления токена).

## EPIC-E-2. Управление проектами в проводнике

> **Применимость:** только Сотрудник. Гость работает с одним
> проектом без проводника (см. EPIC-G-1).

### US-E-02. Проводник проектов с поиском и фильтром

**Как** Сотрудник,
**я хочу** видеть единый список проектов системы с поиском и
фильтрами,
**чтобы** быстро находить нужный проект — свой или коллеги.

**Приоритет:** Must.

**Критерии приёмки:**
- Стартовая страница после входа — «Проводник проектов» в виде
  таблицы.
- Колонки: название, номер задачи, владелец, дата создания, дата
  последнего изменения, количество объектов, состояние расчёта.
- Поиск по подстроке в названии и номере задачи.
- Фильтры: по типу объектов в проекте (трубопроводы / резервуары /
  оба), по году (по дате создания), по номеру задачи, по
  владельцу.
- Сортировка по любой колонке.
- Клик по строке открывает проект на рабочем столе.

### US-E-03. Создание нового проекта (без замены текущего)

**Как** Сотрудник,
**я хочу** создать новый пустой проект как отдельную запись в
проводнике,
**чтобы** вести параллельно несколько проектов без потери ранее
введённых данных.

**Приоритет:** Must.

**Критерии приёмки:**
- В проводнике доступна кнопка «Новый проект».
- Открывается форма с полями: «Название» (обязательное), «Номер
  задачи», «Описание».
- Создаётся новый проект со статусом «Черновик», владелец = текущий
  Сотрудник.
- Никакие другие проекты при этом **не** удаляются и не
  изменяются.
- Сразу после создания Сотрудник попадает на рабочий стол нового
  проекта.

### US-E-04. Редактирование свойств проекта

**Как** Сотрудник,
**я хочу** изменить название, номер задачи, описание и статус
проекта,
**чтобы** актуализировать его карточку по мере прогресса работ.

**Приоритет:** Must.

**Критерии приёмки:**
- В меню проекта доступна операция «Редактировать свойства».
- Изменяемые поля: название, номер задачи, описание, статус
  («Черновик» / «Завершён»).
- Изменения сохраняются и отражаются в проводнике.

---

### US-E-05. Удаление проекта из списка

**Как** Сотрудник,
**я хочу** удалить ненужный проект,
**чтобы** очистить проводник от устаревших или ошибочно созданных
записей.

**Приоритет:** Must.

**Критерии приёмки:**
- В проводнике в строке проекта доступна операция «Удалить» с
  запросом подтверждения.
- После подтверждения проект и все его данные (объекты, расчёты,
  спецификация) каскадно удаляются.
- Проект пропадает из проводника. Никакого автосоздания «нового
  пустого» (в отличие от поведения Гостя) не происходит — у
  Сотрудника может быть и ноль проектов.

### US-E-06. Импорт проекта из CSV (без замены)

**Как** Сотрудник,
**я хочу** загрузить ранее сохранённый CSV-файл как новый проект в
проводник,
**чтобы** перенести расчёт между окружениями или восстановить из
бэкапа.

**Приоритет:** Must.

**Критерии приёмки:**
- В проводнике доступна операция «Загрузить из CSV».
- Создаётся **новый** проект с владельцем = текущий Сотрудник.
- Существующие проекты при этом **не** удаляются.
- Восстанавливаются: общие первичные данные, объекты, результаты
  электрорасчёта, спецификация.
- Некорректный файл отклоняется с понятным описанием причины.
- При конфликте номера задачи (`task_number`) у текущего Сотрудника
  имя нового проекта получает суффикс «(импорт)».

### US-E-07. Создание проекта на основании другого

**Как** Сотрудник,
**я хочу** создать новый проект как копию любого видимого мне
проекта (своего или чужого),
**чтобы** быстро итерировать варианты расчёта без повторного
ввода геометрии.

**Приоритет:** Should.

**Критерии приёмки:**
- В проводнике в строке проекта доступна операция «Создать на
  основании».
- Создаётся новый проект с именем «‹исходное› (копия)»,
  статус — «Черновик», владелец — текущий Сотрудник (даже если
  исходный — чужой).
- Копируются `params` объектов и порядок строк; результаты
  расчётов очищаются и пересчитываются заново по актуальным
  коэффициентам.

## EPIC-E-4. Экспорт отчёта в файлы

> **Применимость:** только Сотрудник. Гость может только смотреть
> предпросмотр и печатать средствами браузера (см. US-G-22, US-G-23).

### US-E-09. Экспорт отчёта в форматы PDF, DOCX, XLSX

**Как** Сотрудник,
**я хочу** скачать отчёт по проекту в формате PDF, MS Word или
MS Excel,
**чтобы** передать его на согласование, отправить заказчику или
заказать материалы по спецификации.

**Приоритет:** Must.

**Критерии приёмки:**
- На странице «Отчёт» Сотруднику доступны три кнопки экспорта:
  «PDF», «Word (DOCX)», «Excel (XLSX)».
- Содержимое экспортируемых файлов соответствует составу,
  утверждённому в документе «Требования к отчёту».
- Файлы выдаются с корректными MIME-типами и именем по шаблону
  «‹номер задачи›_‹название›.‹расширение›» (с поддержкой
  кириллицы).
- При попытке открыть тот же endpoint Гостем — сообщение о
  недоступности экспорта в гостевом режиме.

### US-E-12. Мастер выбора состава отчёта в отдельном окне

**Как** Сотрудник,
**я хочу** перед экспортом отчёта выбрать в отдельном окне
(модалке-«мастере») разделы, которые войдут в отчёт, и вариант
обогрева,
**чтобы** формировать отчёт под конкретного получателя (заказчик,
ПТО, отдел снабжения) без лишних разделов.

**Приоритет:** Must.

**Применимость:** только Сотрудник.

**Критерии приёмки:**
- На странице «Отчёт» рядом с кнопками экспорта доступна кнопка
  «⚙ Состав отчёта».
- Кнопка открывает модальное окно с чекбоксами доступных разделов
  отчёта (титульная часть, общие первичные данные, исходные данные
  по объектам, результаты теплопотерь, результаты электрорасчёта,
  спецификация, справочная часть).
- В этом же окне — селектор «Вариант расчёта (CO)»: «Активный CO»,
  «Все варианты сводно», «Конкретный CO» (выбор из присутствующих).
- При нажатии «Применить» состав сохраняется в проекте и
  применяется ко всем последующим операциям экспорта (PDF / DOCX /
  XLSX).
- Должен быть выбран хотя бы один раздел (VAL-63).
- Сводный отчёт по всем CO допустим только при наличии ≥ 2
  вариантов хотя бы у одного объекта (VAL-64).

### US-E-13. Сводный отчёт по нескольким вариантам CO

**Как** Сотрудник,
**я хочу** экспортировать отчёт, в котором по каждому объекту
показаны все рассчитанные варианты CO,
**чтобы** заказчик видел альтернативы и обоснование выбора
активного варианта.

**Приоритет:** Should.

**Применимость:** только Сотрудник.

**Критерии приёмки:**
- В мастере состава отчёта (US-E-12) выбран режим «Все варианты
  сводно».
- В разделах «Результаты электрорасчёта» и «Спецификация» отчёт
  содержит данные по каждому варианту CO.
- Активный вариант явно отмечен (пометкой ★ или жирным шрифтом).
- Доступно во всех трёх форматах (PDF, DOCX, XLSX).

## EPIC-E-5. Расширенная конфигурация Сотрудника

> **Бизнес-ценность.** ТЗ 4.3.2 / 4.3.3 / 4.3.5 предусматривают для

### US-E-10. Переключение базы расчёта (встроенная / расширенная внешняя)

**Как** Сотрудник,
**я хочу** переключаться между встроенным каталогом кабелей и
аксессуаров (10 марок ТЛТ + базовые аксессуары) и **расширенной
внешней БД** с альтернативными кабелями и расширенным перечнем
аксессуаров СЭО,
**чтобы** подбирать кабели и материалы из актуальной номенклатуры
поставщиков.

**Приоритет:** Must.

**Применимость:** только Сотрудник.

**Критерии приёмки:**
- В шапке проекта (или в общих первичных данных) виден тогглер
  «База расчёта»: ( ) Встроенная · ( ) Расширенная внешняя.
- При переключении на «Расширенную внешнюю» Select марок кабеля и
  аксессуаров расширяется альтернативными позициями из внешней БД.
- Гостю тогглер недоступен (всегда «встроенная», VAL-62).
- Переключение применимо к конкретному проекту; выбор сохраняется
  в `common_data` проекта.
- При недоступности внешней БД (отключена администратором) —
  сообщение «Расширенная внешняя БД недоступна, переключитесь на
  встроенную».

> **Q-G (открытый вопрос).** Структура внешней БД: какие поля,
> формат обновления (выгрузка администратором, периодическая
> синхронизация, ручной импорт), порядок наполнения. Согласовать с
> Заказчиком (см. также раздел 8.5 документа `03-elements-list.md`).

### US-E-11. Расширенная спецификация (группировка, сортировка, выбор позиций)

**Как** Сотрудник,
**я хочу** редактировать сформированную спецификацию: группировать
по категории, сортировать, заменять позиции на аналоги из внешней
БД,
**чтобы** подгонять состав под конкретного поставщика и снабжение.

**Приоритет:** Must.

**Применимость:** только Сотрудник. У Гостя — авто-спецификация
без редактирования (см. US-G-21).

**Критерии приёмки:**
- На странице «Спецификация» (SC-05) у Сотрудника видны
  дополнительные элементы:
  - кнопки сортировки по любой колонке;
  - переключатель режима группировки (по категории / по объекту);
  - кнопка «Заменить на аналог» в каждой строке-позиции — открывает
    список аналогов из активной базы;
  - кнопка «+ Добавить позицию» — выбор из активной базы.
- При активной внешней БД (см. US-E-10) появляется возможность
  выбирать аналоги из расширенного каталога.
- Изменения сохраняются в `specifications` проекта (поля «источник
  позиции», «привязка к варианту CO» — см. раздел 7.5 документа 3).
