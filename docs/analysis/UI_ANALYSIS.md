## 2. Закрытые пробелы и текущие замечания

### ✅ 2.1 L_ekv — эквивалентная длина локального элемента

**Текущее состояние:** поле `local_element_equiv_length` выведено в форме трубы
и в таблице, валидируется, попадает в payload и влияет на эффективную длину:
`L_eff = L + N × L_ekv`.

**Оставшийся риск:** в UI используется одно общее `L_ekv` для суммы задвижек,
фланцев и опор. Если заказчику нужны разные эквивалентные длины по типам
локальных элементов, потребуется отдельная таблица/справочник.

### ✅ 2.2 Стенка резервуара — `wall_thickness` и `wall_lambda`

**Текущее состояние:** поля `wall_thickness_mm` и `wall_lambda` добавлены в
`TankGeometryStep`, сериализуются в `wall_thickness`/`wall_lambda` и учитываются
backend-формулой резервуара как `R_wall = δ / λ`.

### ⚠️ 2.3 Текущие нестыковки

| Проблема | Где | Суть |
|---|---|---|
| **Kзап: разный дефолт** | Форма: 1.2, Backend: 1.1 | При новом объекте K=1.2, при пустом поле backend берёт 1.1 |
| **Напряжение дублируется** | Форма объекта + ElecCalcPage | В объекте хранится 220/380 В, но электрорасчёт берёт напряжение со своей страницы. Поле в форме — теневое |
| **Высота резервуара: абсурдный max** | `height_mm`: max=200 000 000 мм = 200 км | Должен быть 200 000 мм (200 м), совпадая с backend `le=200_000.0` |
| **Max T° окр. среды и продукта** | Секция 3 | Чисто информационные, не влияют на расчёт. Стоит обозначить |

## 3. Логика компоновки формы

Форма разбита на 4 горизонтальные секции (колонки):

### Секция 1: Геометрия ✅
- Труба: Ø, длина, толщина стенки, материал / λ трубы, размещение, глубина+грунт
- Резервуар: форма, габариты (Ø/ H/ L/ W динамически), размещение, глубина+грунт

**Оценка:** Логично. Глубина и грунт появляются только при `placement=underground`. Поле «λ трубы» — только при режиме «Вручную».

### Секция 2: Теплоизоляция ✅
- Толщина 1-го слоя, λ 1-го слоя, материал, покрытие, кол-во слоёв
- При 2–3 слоях: материал, толщина и λ для каждого дополнительного слоя
- λ появляется только при `material=other`

**Оценка:** Логично. Поле «λ 1-го слоя» деактивировано для справочных материалов (показывает табличное значение), активно для «Другое».

### Секция 3: Температура и среда ⚠️
- Климат (город → T° и ветер авто), обеспеченность, T° среды, T° продукта
- Ветер, α внеш, макс T° среды/продукта, среда, классификация зоны, T-группа

**Оценка:** **Перегружена.** 10 полей, из которых 4 расчётных (T° среды, T° продукта, ветер, α) и 6 информационных (макс T°, среда, зона, T-группа — для спецификации/отчёта). Пользователь не видит разницы между расчётными и информационными полями.

### Секция 4: Электропараметры и арматура ⚠️
- Мин. T° включения, напряжение, Kзап, Q_доп (только резервуар), пропарка
- Задвижки, фланцы, опоры и `L_ekv` (только труба)

**Оценка:** **Смешаны две независимые группы.** Электропараметры (напряжение, Kзап, мин. T°) и арматура трубопровода (задвижки/фланцы/опоры/L_ekv) — разные этапы проектирования. Это UX-замечание, не пробел расчёта.

### Динамическое поведение ✅

| Триггер | Эффект |
|---|---|
| Выбор города из климата | T° среды и ветер заполняются авто, тег «из климата» |
| Ручной ввод T° среды | Тег меняется на «вручную» |
| Ручной ввод ветра | Тег меняется на «вручную» |
| Выбор грунта из справочника | λ грунта заполняется авто |
| `placement=underground` | Появляются глубина, грунт, λ грунта |
| `pipe_lambda_mode=manual` | Поле «λ трубы» вместо «Материал трубы» |
| `material=other` | Появляется поле «λ N-го слоя» |
| `insulation_layer_count=2/3` | Появляются поля 2-го и 3-го слоёв |

**Оценка:** Продумано, логично.

### Автоимя ✅
Формат: `Труба Ø108 мм (DN100), δ=50 мм, МВ, L=50 м, −20→+80°C`. Генерируется автоматически при изменении параметров. Сохраняется, если пользователь отредактировал вручную.

## 4. Сравнение с топовыми аналогами

### 4.1 Обзор рынка

Два доминирующих продукта в индустрии электрообогрева:

**TraceCalc Pro** (nVent RAYCHEM / Chemelex) — десктопное Windows-приложение. Де-факто стандарт для проектирования систем на кабелях RAYCHEM. Версия 2.19.

**CompuTrace Design Suite** (Thermon) — десктопное приложение, позиционируется как «новый стандарт». Мультипользовательский режим, серверные проекты.

Также существуют:
- **Chromalox онлайн-калькуляторы** (веб, поэлементный расчёт)
- **SST Group CalTrace** (российский аналог для ТТН/ТТВ/ТТХ)
- **Toolgrit Heat Trace Calculator** (веб, базовый)

### 4.3 Где HeatCalc превосходит аналоги

1. **Веб-платформа** — единственный из трёх, работающий в браузере без установки. Не требует Windows. Mac и Linux из коробки.

2. **Гостевой вход** — можно начать расчёт без регистрации. TraceCalc и CompuTrace требуют установки и лицензии.

3. **Встроенный климатический справочник (539 городов РФ)** — аналогам требуется ручной ввод температуры. Для российского рынка это критическое преимущество.

4. **Импорт из Excel/CSV с построчными ошибками** — можно загрузить 100 объектов из таблицы заказчика за секунду. Аналоги не имеют массового импорта — только поэлементный ввод.

5. **4 варианта системы (CO1..CO4)** — стандартная практика российского ТНП: один проект, 4 независимых варианта подбора кабеля. В TraceCalc нужно копировать проект.

6. **REST API** — единственный продукт с программным интерфейсом. Позволяет интегрироваться с BIM/САПР заказчика.

7. **Внешняя БД кабелей** — сотрудник может расширить каталог через админку, не дожидаясь обновления версии.

### 4.4 Где HeatCalc отстаёт

1. **Неполный каталог кабелей** — у RAYCHEM/Thermon встроены полные каталоги своих кабелей (200+ позиций), включая MI и скин-системы с формулами. HeatCalc имеет 74 кабеля, MI и скин — без формул.

2. **Отсутствие детального electrical design** — TraceCalc/CompuTrace выдают: максимальную температуру оболочки, проверку по температуре воздействия, подбор автоматических выключателей с кривыми отключения, расчёт падения напряжения по длине секции. HeatCalc даёт только ток (А).

3. **Локальные элементы менее детальны** — HeatCalc поддерживает общий `L_ekv`
   для суммы локальных элементов; аналоги могут вести индивидуальные справочники
   по типам фиттингов.

4. **Нет расчёта падения напряжения** — критично для длинных секций (>200 м).

5. **Нет проверки по T-классу для взрывоопасных зон** — поле «Температурная группа» есть в форме, но не участвует в проверке: кабель должен гарантировать, что температура его оболочки не превышает допустимую для T-класса.

6. **Генерация отчёта — базовая** — TraceCalc Pro формирует полноценный проектный отчёт с электрическими схемами, спецификацией по модулям и листами заказа.

7. **Desktop-только у конкурентов** — это одновременно и недостаток (нет веба), и преимущество (нет задержки сети, мгновенный отклик, «живой» drag-and-drop без лагов).

## 6. Итоговая оценка соответствия

**По полноте расчётных полей:** SC-03 покрывает расчётные поля труб и
резервуаров, включая `L_ekv`, `wall_thickness` и `wall_lambda`. `volume`
остаётся справочно-информационным и не участвует в текущей формуле.

**По сравнению с аналогами:** HeatCalc — единственный веб-инструмент на рынке с климатической базой РФ, гостевым доступом, API и массовым импортом. Уступает в глубине electrical-расчёта, полноте каталога MI/skin и зрелости отчётности. За 1 год разработки при 1345 тестах — достойный уровень. **Оценка: 7/10 относительно TraceCalc Pro, 8/10 для российского рынка.**
