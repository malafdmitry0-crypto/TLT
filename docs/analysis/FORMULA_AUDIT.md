## Критические ошибки в formules.md

### 1. R_ins (термическое сопротивление изоляции трубы) — арифметическая ошибка в 3,17×

**Где:** Шаг 3.3, пример для изоляции 50 мм из минваты.

**Что в документе:**
```
R_из = ln(0,104 / 0,054) / (2π × 0,045) = 0,654 / 0,283 ≈ 0,732 м·К/Вт
```

**Правильное значение:**
```
ln(0,104 / 0,054) = ln(1,9259) = 0,6553
2π × 0,045 = 0,2827
R_из = 0,6553 / 0,2827 = 2,318 м·К/Вт   ← не 0,732!
```

Ошибка в 3,17 раза. Чтобы получить R_из=0,732 при тех же геометрических параметрах,
нужна λ=0,1425 Вт/(м·К) — это не минеральная вата (0,045), а что-то вроде
влажного пенобетона.

**Влияние:** все последующие числа в примере (q=123 Вт/м, Q=6765 Вт, P_треб=135,3 Вт/м,
выбор ТЛТ-100) — неверны.

### 2. Формула α_внеш — устаревшая (линейная вместо корневой)

**Где:** Шаг 3.4 (труба) и Шаг Б (резервуар).

**Что в документе:**
```
α_внеш = 11,6 + 7 × v          (линейная)
Пример при v=3: α = 32,6
```

**Что в коде (исправлено 2026-05-06 по SNiP 41-03-2003):**
```python
alpha = 11.6 + 7.0 * math.sqrt(v)    # корень из скорости
При v=3: α = 23,7
```

Зафиксировано в `pitfalls.md` (строка «Расчёт α_внеш с ненулевым ветром давал заниженный результат»),
но `formules.md` не обновлён.

**Влияние:** при v=3 м/с завышение α на 37% → занижение R_ext → завышение теплопотерь.
При v=0 (штиль) значения совпадают, поэтому пример резервуара (v=0) — корректен.

| v, м/с | α (документ) | α (правильно, √v) | Ошибка |
|---|---|---|---|
| 0 | 11,6 | 11,6 | 0% |
| 1 | 18,6 | 18,6 | 0% |
| 3 | 32,6 | 23,7 | +37% |
| 5 | 46,6 | 27,2 | +71% |
| 10 | 81,6 | 33,7 | +142% (вышло бы за диапазон 11,6–52) |
| 20 | 151,6 | 42,9 | +253% |

## Расхождения средней тяжести

### 3. Каскадная ошибка в примере подбора кабеля ТЛТ

Поскольку q завышено в ~3 раза, весь расчёт кабеля в документе неверен:

| Параметр | В документе | Правильно | Разница |
|---|---|---|---|
| q, Вт/м | 123 | 42 | −66% |
| P_треб (×1,1) | 135,3 | 46,2 | −66% |
| Выбранный кабель | **ТЛТ-100** (150 Вт/м) | **ТЛТ-50** (50 Вт/м) | На 2 ступени ниже |
| L_кабеля, м | 55 | 55 | — |
| P_total, Вт | 5500 | 2750 | −50% |
| I, А | 25,0 | 12,5 | −50% |

**Практическое следствие:** читатель документации, проверяющий пример вручную,
выберет кабель на 2 типоразмера выше необходимого.

### 4. Коэффициент навива и количество ниток не описаны в formules.md

Код в `calc_self_regulating` учитывает:
```python
layout_factor = winding_coefficient * number_of_threads
cable_length = pipe_length * 1.1 * layout_factor
```

Документация в разделе «Шаг 4.3 — Длина кабеля» показывает упрощённую формулу
`L_кабеля = L_трубы × 1,1` без упоминания коэффициента навива и многожильности.

**Влияние:** низкое — формула в документе верна для базового случая
(прямая укладка, 1 нитка), но неполна.

## Что проверено и подтверждено (код = документ)

Ниже перечень всех формул, где реализация полностью соответствует документации
и физическому смыслу. Пометка ✅ означает совпадение.

### Теплопотери трубопровода

| Формула | Код | Статус |
|---|---|---|
| T_ср = (T_прод + T_ср) / 2 | `t_mean = (process + ambient) / 2.0` | ✅ |
| λ_трубы = A + B×(T_ср + 40) | `a + b * (temperature + 40)` | ✅ |
| R_слоя = ln(r_out/r_in) / (2π×λ) | `math.log(r_out/r_in) / (2*pi*lam)` | ✅ |
| R_external = 1/(2π×r×α) | `1.0 / (2*pi*r*alpha)` | ✅ |
| R_ground = arccosh(H/r) / (2π×λ_gr) | `acosh / (2*pi*lambda_gr)` | ✅ |
| q = ΔT / R_total | `delta_t / r_total` | ✅ |
| L_eff = L + n_i × L_ekv | `pipe_length + n_i * l_ekv` | ✅ |
| Q = q × L_eff × K | `q_linear * l_eff * k` | ✅ |

### Теплопотери резервуара

| Формула | Код | Статус |
|---|---|---|
| S_цил = πdH + 2π(d/2)² | `pi*d*h + 2*pi*(d/2)**2` | ✅ |
| S_прям = 2(LW+LH+WH) | `2*(l*w + l*h + w*h)` | ✅ |
| S_шар = 4π(d/2)² (= πd²) | `4*pi*(d/2)**2` | ✅ |
| R_wall = δ/λ (плоская) | `wall_thickness / wall_lambda` | ✅ |
| R_ins = Σ δ_i/λ_i | `sum(thickness/lam for layers)` | ✅ |
| R_ext = 1/α | `1.0/alpha` | ✅ |
| q = ΔT / (R_wall+R_ins+R_ext) | `delta_t/(r_common+r_ext)` | ✅ |
| Q = q×S×K | `q_per_m2 * area * k` | ✅ |
| Разделение S_возд/S_гр | `_surface_area_split()` | ✅ |
| q_гр = ΔT/(R_общ + h/λ_гр) | `delta_t/(r_common+r_ground)` | ✅ |
| Q_подз = (q_возд×S_возд+q_гр×S_гр)×K | `(q_air*s_air+q_ground*s_ground)*k` | ✅ |

## Защитные механизмы в коде (подтверждены)

| Механизм | Где | Замечание |
|---|---|---|
| λ_трубы ≥ 0,001 | `loader.py:max(lambda, 0.001)` | Защита от отрицательной λ при экстремальных T |
| α ∈ [11,6; 52,0] | `calc_alpha_vnesh: clamp` | Соответствует `coefficients.MD` |
| H/r ≥ 1 для arccosh | `_r_ground: if x < 1.0` | Труба физически не может быть выше поверхности |
| r_inner > 0 для стенки | `_r_wall: if r_inner <= 0` | Толщина стенки не может превышать радиус |
| ΔT > 0 | `validate_temperature_range` | T_продукта обязана быть выше T_среды |
| Double safety factor protection | `_tank_heat_loss_without_double_safety` | Для резервуара Q/K перед подачей в электрорасчёт |
| Количество ниток | `_number_of_threads` | ТЛТ manual 1–3; ТТН/ТТВ/ТТХ и резистивный auto допускают full-version значения до 100 |
| Шаг навива > диаметра трубы | `_winding_coefficient` | Геометрическая невозможность навива |
| Максимальный Kn(D) | `_validate_winding_coefficient_limit` | Hard-limit по ТНП |

## Статус рекомендаций на 2026-05-17

### Закрыто

1. **R_ins в `formules.md` исправлен**: пример пересчитан на `R_из = 2,318`,
   `q ≈ 42`, `P_треб ≈ 46,2` и выбор `ТЛТ-50`.

2. **Формула `α_внеш` обновлена**: используется `11,6 + 7×√v` с clamp
   `[11,6; 52,0]`, пример при `v=3` приведен к `α≈23,7`.

3. **Навив и количество ниток задокументированы** в текущем контракте и
   покрыты backend/QA-agent проверками: `Kn_max(D)`, ручной override ниток и
   full-version policy для ТТН/ТТВ/ТТХ.

4. **Геометрия укладки на резервуар отражена** в `docs/context/formulas-summary.md`
   и `docs/business-logic-contract.md`.

### Открыто

5. **Климатический справочник**: backend resolver и QA-agent oracle закрепляют
   правила `K/T` из ТНП, но выборочная сверка 5–10 городов с первичным источником
   остаётся полезной.

6. **Температурная зависимость λ изоляции** (`lambda(tm)`) не реализована.
   Это зафиксированный full-version gap; для высокотемпературных применений
   погрешность может быть значимой.

7. **Валидация q_additional** — сейчас `or 0.0` в `calc_tank_heat_loss`.
   Pydantic-валидатор `ge=0` уже отсекает отрицательные, но дублирующая проверка
   в коде избыточна.
