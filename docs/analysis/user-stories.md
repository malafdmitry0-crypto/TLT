# Пользовательские истории

## Соглашения

**Формат истории:** `Как <роль>, я хочу <действие>, чтобы <ценность>`

**Оценка:** Story Points по шкале Фибоначчи (1, 2, 3, 5, 8, 13)

**Приоритет:** Must / Should / Could / Won't (MoSCoW)

**Статус:** ✅ Реализовано | 🔄 В разработке | ⬜ Бэклог

---

## EPIC-01: Аутентификация и управление доступом

> **Бизнес-ценность:** Обеспечить безопасный и удобный доступ для всех категорий пользователей — от внешних проектировщиков (без регистрации) до административного персонала (с полным контролем).

---

### US-01.1: Вход пользователя без регистрации

**Как** внешний проектировщик,  
**я хочу** начать работу без регистрации с единственным авто-проектом,  
**чтобы** сразу перейти к расчётам, не тратя время на создание/выбор проекта.

| Атрибут | Значение |
|---------|----------|
| Приоритет | Must |
| SP | 3 |
| Статус | ✅ |

**Критерии приёмки:**
- [x] На главной странице есть кнопка «Начать без регистрации»
- [x] `POST /auth/guest` создаёт `GuestSession` + сразу единственный `Project`
  («Мой проект»), возвращает `{session_id, project}`
- [x] `session_id` сохраняется в localStorage и передаётся в `X-Session-Id`
- [x] Возвращённый проект сразу становится текущим (`projectStore`)
- [x] Пользователь перенаправляется на `/workspace/heat-calc`
- [x] UI-элементы «Новый проект» / «Открыть проект» скрыты для роли guest
- [x] Попытка создать второй проект (`POST /projects`) → HTTP 429
- [x] Сессии изолированы: пользователь видит только свои данные

**Бизнес-правила:**
- BR-01: У пользователя ровно один проект (`GUEST_MAX_PROJECTS=1`)
- BR-02: Данные пользователя хранятся до истечения TTL (см. US-01.5)

---

### US-01.5: Автоматическая очистка данных пользователя

**Как** владелец системы,  
**я хочу** чтобы данные ушедшего пользователя автоматически удалялись,  
**чтобы** база не накапливала мусор и приватность гарантированно соблюдалась.

| Атрибут | Значение |
|---------|----------|
| Приоритет | Must |
| SP | 3 |
| Статус | ✅ |

**Критерии приёмки:**
- [x] Любой запрос с `X-Session-Id` обновляет `GuestSession.last_activity`
- [x] Фоновая задача (`_periodic_guest_cleanup`) раз в
  `GUEST_CLEANUP_INTERVAL_MINUTES` (10 мин) удаляет сессии с
  `last_activity < now() - GUEST_SESSION_TTL_MINUTES` (20 мин)
- [x] Удаление каскадное: `ON DELETE CASCADE` снимает проект, объекты, расчёты,
  спецификации
- [x] Startup-cleanup выполняется один раз при `lifespan`-старте приложения
- [x] Пользователь закрыл браузер → не позднее чем через TTL+интервал (≤30 мин,
  типично ≤20 мин) все данные удалены
- [x] Неизвестный `X-Session-Id` → HTTP 401

**Бизнес-правила:**
- BR-03: TTL отсчитывается от последней активности, не от создания сессии
- BR-04: Свежая сессия никогда не трогается cleanup-задачей

## EPIC-03: Теплотехнический расчёт

> **Бизнес-ценность:** Автоматизация расчёта теплопотерь по закону Фурье устраняет ручные ошибки и обеспечивает единообразие методологии расчёта для всех инженеров компании.

---

### US-03.1: Добавление трубопровода с расчётом теплопотерь

**Как** инженер,  
**я хочу** ввести параметры трубопровода и сразу получить результат расчёта теплопотерь,  
**чтобы** быстро оценить потребность в электрообогреве.

| Атрибут | Значение |
|---------|----------|
| Приоритет | Must |
| SP | 8 |
| Статус | ✅ |

**Критерии приёмки:**
- [ ] Форма ввода параметров: наружный диаметр (DN), толщина стенки, материал трубы, тип и толщина изоляции, температуры (окружающей среды и продукта), длина трубопровода
- [ ] Автоматический расчёт при добавлении объекта
- [ ] Результат: `heat_loss_per_meter` (Вт/м), `total_heat_loss` (Вт), `thermal_resistance` (м²·К/Вт)
- [ ] При невалидных параметрах: `is_valid = false`, заполнен `validation_errors`
- [ ] Ошибка отображается в ячейке таблицы с красной подсветкой

**Бизнес-правила:**
- BR-03: Диаметр DN ≥ DN6 (0.0108 м), DN ≤ 3000 мм (3.0 м)
- BR-04: Температура окружающей среды: от −70°C до +70°C
- BR-05: Температура продукта > температуры окружающей среды
- BR-06: Минимальная длина трубопровода: 0.5 м
