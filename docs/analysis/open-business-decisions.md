# Реестр открытых бизнес-решений (блокеры 100% по полному ТЗ)

**Дата среза:** 2026-05-20
**Связанные документы:** [docs/tz-compliance.md](../tz-compliance.md),
[docs/srs/07-report-requirements.md](../srs/07-report-requirements.md),
[docs/srs.md](../srs.md) (NFR-SEC-03),
[docs/deployment.md](../deployment.md) § «Шифрование формул».

Пока пункты ниже в статусе **Open**, итоговая приёмка **полной версии** по ТЗ
ограничена (~**85%** по взвешенной сводке в `tz-compliance.md`). Реализация кода
в закрытом контуре не блокируется; блокируется **подписание** без оговорок.

## Условные обозначения

| Статус | Значение |
|---|---|
| **Open** | Ожидается решение заказчика |
| **Interim** | Рабочая реализация по варианту по умолчанию до подписи |
| **Closed** | Утверждено заказчиком, отражено в SRS/шаблонах |

## SEC — безопасность (раздел 5 ТЗ, NFR-SEC-02..05)

| ID | Вариант | Суть | Статус реализации | Статус решения |
|---|---|---|---|---|
| SEC-A | **А** | Формулы в `.py` и JSON-справочники в Docker-образе; ротация = пересборка образа | **Interim** — зафиксировано в `deployment.md`, SRS NFR-SEC-03 | **Open** — нужна подпись заказчика |
| SEC-B | **Б** | Шифрование формул/справочников в образе, расшифровка при старте контейнера | Не реализовано | **Open** |
| SEC-C | **С** | KMS/Vault, ротация ключей без пересборки; UI админа для ключей (FR-ADM-04) | Не реализовано | **Open** |
| SEC-02 | Обфускация frontend | Vite/esbuild минифицирует `dist/`; явный obfuscator не подключён | **Interim** | **Open** — нужен ли webpack-obfuscator |
| SEC-05 | Конфиги | `.env` в открытом виде; для prod рекомендованы Docker Secrets / Vault | **Interim** | **Open** — политика on-premise заказчика |

**Влияние на % ТЗ:** раздел 5 — **~68%** до подписи SEC-A; переход на Б/С — отдельный объём работ.

**Действие после Closed (SEC-A):** в `tz-compliance.md` пункты шифрования формул/справочников → ✅; FR-ADM-04 остаётся N/A.
