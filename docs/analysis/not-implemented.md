# Что не реализовано по текущему контракту

**Дата среза:** 2026-05-17

Этот список фиксирует незакрытые пункты по текущему full-version target. Источники:
`docs/business-logic-contract.md`, `docs/analysis/full-version-status.md`,
`docs/analysis/current-status-and-missing-info.md`, `docs/tz-compliance.md`.

## Критично для расчётов

1. **Температурозависимая теплопроводность изоляции `lambda(tm)`**

   Backend сейчас использует фиксированную `conductivity` из справочника
   теплоизоляции. Для полного ТНП-контракта нужно считать `lambda(tm)` и
   покрыть deterministic tests.

2. **Кабель с минеральной изоляцией `mineral`**

   Тип есть в схемах/UI, но расчётной методики нет. Нужны формулы,
   ограничения по длине, мощности, температуре и напряжению.

3. **Скин-системы `skin`**

   Тип есть, но формул и алгоритма подбора нет. Нужно решение, включаем ли
   скин-системы в текущую версию, и отдельная методика расчёта.

4. **Объекты `pump`, `platform`, `other`**

   Типы перечислены в backend enum, но нет UI-форм, формул теплопотерь,
   импортных контрактов и отчёта для этих объектов.

5. **Точные заводские thermal `p3`-лимиты для ТТ Р1 / ТТ Р3**

   Full-version автоподбор резистивных кабелей реализован с fallback по
   `65 А`, но точные thermal caps должны быть заполнены в БД.

## Воспроизводимость расчётов

6. **Audit log изменений коэффициентов**

   Сейчас хранится текущее значение коэффициента. Нет истории: кто, когда,
   старое значение, новое значение.

7. **Snapshot коэффициентов и справочников в расчёте**

   Нельзя строго воспроизвести старый расчёт после изменения коэффициентов
   или справочников.

8. **Версионирование источников формул и справочников**

   Нужно фиксировать, какие версии формул, справочников и бизнес-контракта
   применялись при конкретном расчёте.

## Безопасность и защита формул

9. **Явная обфускация frontend**

   Vite/esbuild минифицирует production bundle, но отдельного mangle/obfuscation
   target нет.

10. **Шифрование встроенных справочников**

    JSON-справочники сейчас находятся открыто внутри Docker-образа.

11. **Шифрование конфигов и secrets**

    Сейчас используется `.env`. Для production нужно утвердить Docker Secrets,
    Vault или другой механизм.

12. **Управление ключами шифрования**

    Для принятого варианта А это не требуется, потому что формулы находятся в
    backend-коде внутри образа. Если будет выбран вариант Б/С, нужен механизм
    выдачи и ротации ключей.

## Отчёты и документация

13. **Финальный корпоративный шаблон отчёта**

    Рабочий отчёт есть, но не утверждены титул, логотип, визы, состав разделов,
    отображение объектов с ошибками и необходимость включать нормативную часть.

14. **Отдельный справочник кодов ошибок**

    Ошибки описаны точечно в API/SRS, но отдельного `docs/error-codes.md` пока
    нет.

15. **Единый формат кодов ошибок импорта CSV/XLSX**

    Нужен стабильный формат для диагностики, поддержки и автотестов импорта.

## UX и таблицы

16. **Полный Excel-like UX**

    TSV copy/export есть, но не закрыты полностью drag-fill, массовое
    редактирование диапазонов и финальный набор inline/bulk операций.

17. **Детализация `L_ekv` по типам фиттингов**

    Общий `L_ekv` реализован. Если нужны разные эквивалентные длины для
    фланцев, арматуры, опор и других локальных элементов, нужен отдельный
    справочник.

## Справочники и админка

18. **Финальная структура внешней БД кабелей и аксессуаров**

    CRUD есть, но поля каталога, артикулы, цены, ограничения, связи аксессуаров
    и правила актуальности пока предварительные.

19. **Коммерческое ранжирование вне первого ТЛТ-среза**

    Первый vertical slice коммерческого автоподбора реализован для
    саморегулирующегося ТЛТ: `selection_policy`, deterministic ranking,
    public `commercial` catalog, result snapshot, UI-control, report block и
    базовые тесты. Остаётся расширить этот слой на другие ветки, если бизнес
    решит ранжировать резистивные/ТТН/ТТВ/ТТХ варианты по тем же коммерческим
    политикам.

    Отдельно не закрыт `balanced`: он не должен работать на неутверждённых
    весах, поэтому сейчас остаётся controlled fallback.

20. **Неиспользуемые коэффициенты `location_indoor`, `location_outdoor`**

    `wind_factor` уже применяется для `α_внеш` надземных труб. Остались
    `location_indoor` и `location_outdoor`: они есть в таблице коэффициентов,
    но не влияют на расчёт. Нужно подключить их по утверждённому правилу,
    убрать или явно пометить как неактивные.

## Приоритет закрытия

1. Реализовать `lambda(tm)` для изоляции.
2. Зафиксировать и реализовать методики `mineral` и `skin`.
3. Закрыть формулы и UI для `pump`, `platform`, `other`, если они входят в
   текущую поставку.
4. Добавить audit log и snapshot расчётов.
5. Заполнить `p3`/thermal limits и коммерческие критерии для резистивного
   автоподбора.
