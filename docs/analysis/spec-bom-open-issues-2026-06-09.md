## 1. Нужно бизнес-решение заказчика

| # | Вопрос | Текущее поведение кода | Риск |
|---|---|---|---|
| Б-1 | **`N,секц` vs нитки.** Лист «Список переменных» различает `N,секц` (кол-во нагревательных секций) и `Ns,секц` (число ниток алгоритма). Backend не секционирует кабель по строительной длине, правило секционирования самрега в контракте отсутствует. | `N,секц = num_circuits` (нитки) | На длинных трубах занижены КСН/КСВ, коробки, вводы |
| Б-2 | **Темп-класс ТЛТ.** Лист покрывает только ТТН/ТТВ/ТТХ; `T,секц` в источнике трёхзначный (низкий/средний/высокий), в коде — двухзначный. Высокотемпературные ТЛТ (до 190 °C) попадают в «низкотемпературные» КСН/КСР-1/ЛКС. | `_temp_class()`: всё, кроме ТТВ/ТТХ → `low` | Неверные комплекты для горячих ТЛТ |
| Б-3 | **Граница `dтр = 57 мм` ровно.** ТНП задаёт только `>57` и `<57`; случай равенства не определён (аналогично закрытому решению по границе темп-класса, `docs/audit/2026-06-07-temperature-class-boundary-decision.md`). | 57 относится к «малым» (СКВ 1202/1602) | Неоднозначность на границе |
| Б-4 | **Приоритет К2i над К1i при обоих «да».** Комбинированный случай в ТНП не описан; правило в коде изобретено. | `k2i_active` побеждает `k1i` в `_box_bucket` | Возможен неверный вариант СКВ |
| Б-5 | **BOM для резервуаров.** Источник — расчёт «трубы». Для танков diameter подставляется как dтр, height — как Lтр; формулы лент/этикеток/коробок по периметру бака никем не подтверждены. | Резервуары идут по pipe-алгоритму | Аксессуары бака приблизительные |
| Б-6 | **База длины кабеля basic vs full.** Basic берёт коммерческий `required_order_length` (строительные длины), full — `installed_cable_length × R,гр` по ТНП. Переключение режима меняет метры кабеля в одной записи. Какую длину заказывать в полном BOM? | Разные базы в двух режимах | Расхождение закупки кабеля |
| Б-7 | **Суффикс ТТВ/ТТХ в номенклатуре.** В номенклатурной базе ТНП (строки 17–26) ТТВ/ТТХ существуют **только** с `-СР`, а VSDX-алгоритм строит суффикс по агрессивности для любой серии. Код для неагрессивной среды выдаёт `30ТТВ2-СТ` — марки нет в номенклатуре (нет кода 001-002-xxx). Противоречие двух первоисточников. | Суффикс по агрессивности для всех серий | Марка вне номенклатурной базы |
| Б-8 | **Ленты и КСР от длины с резервом.** ЛКС/ЛКВ и ремкомплекты считаются от `L×R,гр`, хотя резервный кабель физически не монтируется. В источнике формула `Kr1` использует `L1` (длину с резервом) — видимо осознанно, но стоит подтвердить. | Лента/КСР включают резерв | Завышение ленты при R>1 |
| Б-9 | **`Lтр` для этикеток.** Сервис подставляет `results.effective_length` (с L,доп локальных элементов), тогда как `MrEl1` в ТНП считается от длины трубопровода. | effective_length приоритетнее pipe_length | Небольшое завышение этикеток |
| Б-10 | **КИП/шкаф/монтажные кабели/ЗИП** (строки 59+ источника) — проектные ручные позиции, в авто-BOM осознанно не входят. Подтвердить, что ручного добавления из расширенной БД достаточно. | Только ручные позиции | — |

## 4. Исправлено кодом 2026-06-09 (для истории)

- **Упаковочный коэффициент (колонка I)** применяется: `package_factor` в
  `spec_accessories.json`, количество = `ceil(формула × коэф.)`. Ранее клей
  завышался ~в 7 раз, герметик — в 4, ХК30 — до 30, Z-профиль — в 2, а сам
  коэффициент был ошибочно записан как `mass_kg`.
- **Фильтр по типу кабеля**: BOM самрега больше не применяется к резистивным
  ТТ Р1/ТТ Р3 (и прочим типам); такие объекты учитываются в `skipped_objects`.
- **Квантование перед `ceil`**: 10 секций × R=1.3 больше не дают 14 вместо 13.
- **К2i по длине секции**: порог `L,К2i` сравнивается с `L,секц`
  (= installed/N), а не с суммарной длиной позиции; КСН-2/КСВ-2 считаются
  только по секциям, прошедшим порог (согласовано с корзинами коробок).
- **Валидация входов**: позиция с нулевой длиной не порождает аксессуары;
  `num_circuits` округляется и ограничивается снизу 1 (отрицательное значение
  одного объекта больше не уменьшает комплекты других).
- **Резервуары**: `diameter` подставляется как dтр (вместо молчаливого d=0 и
  «малого диаметра»); полноценный BOM бака — см. Б-5.
- **Режим генерации персистится** (`generation_mode`/`generation_options`,
  миграция 0026): «Пересчитать» и фоновая регенерация больше не подменяют
  полный BOM базовым; UI восстанавливает режим и опции после reload.
- **Гость + `mode=full` → 403** вместо тихого даунгрейда; ответ генерации
  содержит `mode` и `skipped_objects`, UI предупреждает о неполной спецификации.
- **UI**: добавлены опции К1i/К2i/Кiu/L,К2i на странице спецификации (ранее
  4 из 6 опций ТНП были недостижимы); `_is_aggressive` (мёртвый код) удалён;
  `readStorageJson` не падает на SecurityError; баннер ошибок электрорасчёта
  не показывает счётчик без текста.
- **Модалка выбора марки**: сохранённая марка с суффиксом, не совпадающим с
  текущим переключателем агрессивности (например, `-СР` при выключенной
  агрессивной среде), больше не теряется — добавляется fallback-опция
  «сохранён в расчёте», характеристики кабеля резолвятся по базовой модели.
