## 2. Где информации ещё недостаточно

### 2.1. Кабели полной версии

| Тема | Чего не хватает | Риск |
|---|---|---|
| Одножильный постоянной мощности | Точные заводские thermal `p3`-лимиты для production-БД | Full-version VSDX-подбор ТТ Р1 и commercial ranking реализованы; dev/test seed заполняет demo commercial data, production должен заменить их реальными данными |
| Трёхжильный постоянной мощности | Точные заводские thermal `p3`-лимиты для заполнения БД и проектные ограничения по применению схем | Full-version VSDX-подбор ТТ Р3 реализован; fallback по `65 А` безопасен, но БД-лимиты должны уточнить thermal cap |
| Кабель с минеральной изоляцией | Методика расчёта, ограничения по длине, мощности, температуре, напряжению | Сейчас допустимо только как тип/каталог, не как расчёт |
| Скин-системы | Решение, включаем ли в текущую версию, и отдельные формулы | В SRS отмечено как открытый Q-E |
| Автоподбор внутри каждого типа | Production-данные цены/склада/поставщиков и финальные правила аксессуаров | Для ТЛТ и резистивного auto-подбора ranking реализован; для ТТН/ТТВ/ТТХ, mineral и skin нужен отдельный candidate set, если бизнес решит ранжировать эти ветки |
| Навив и несколько ниток | Базовая формула реализована: для трубы геометрический коэффициент спирали, для резервуара шаг укладки по периметру; финальные проектные ограничения по типам кабеля можно уточнять отдельно | Без финальных правил оптимальности пользователь может получить корректный расчёт, но не всегда коммерчески оптимальный вариант |

### 2.2. Расширенные типы объектов

| Тема | Чего не хватает | Риск |
|---|---|---|
| Насосы | Формулы теплопотерь и набор исходных полей | `ObjectType` допускает `pump`, но UI/формул нет |
| Площадки | Формулы, геометрия, правила подбора кабеля | Нельзя реализовать без ТНП |
| Прочие объекты | Классификация, поля, формулы, импорт, отчёт | Иначе получится произвольная модель без подтверждения |

### 2.3. Отчёт

| Тема | Чего не хватает | Риск |
|---|---|---|
| Финальный состав разделов | Утверждение Q-01..Q-03 | Мастер состава отчёта может не совпасть с ожиданиями заказчика |
| Титульная часть | Логотип, заказчик, договор, визы | Нельзя сделать финальный шаблон PDF/DOCX |
| Объекты с ошибкой электрорасчёта | Показывать в общей таблице, отдельным списком или исключать | Может отличаться от приёмочного ожидания |
| Формулы и нормативы в отчёте | Нужно ли включать справочную часть | Влияет на полноту и объём отчёта |
| Визуальный шаблон | Word/PDF-шаблон, шрифты, колонтитулы, ориентация страниц | Сейчас реализован рабочий шаблон, не утверждённый корпоративный |

### 2.7. Коэффициенты и воспроизводимость расчётов

| Тема | Чего не хватает | Риск |

## 4. Рекомендованный порядок закрытия пробелов

1. **Поддерживать справочник изоляции конкретными кодами/плотностями.** Не возвращать generic материалы в расчётный контракт; при импорте generic строк пользователь должен уточнить материал.
2. **Зафиксировать оставшиеся расчётные методики кабелей полной версии.** ТТ Р1,
   ТТ Р3 и ТТН/ТТВ/ТТХ уже включены как расчётные типы; для `mineral` и `skin`
   методики всё ещё нет.
3. **Выбрать стратегию безопасности раздела 5 ТЗ.** Минимум: явно утвердить
   вариант А/Б/С для формул, справочников и конфигов.
4. **Утвердить отчёт.** Нужны ответы по составу, титулу, ошибочным объектам,
   справочной части и шаблону.
5. **Добавить audit/snapshot расчётов.** Это повышает воспроизводимость и
   снижает риск претензий к результатам после изменения справочников/коэффициентов.
