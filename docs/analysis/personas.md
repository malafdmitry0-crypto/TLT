# Персоны пользователей

## Методология

Персоны построены на основе анализа ролевой модели системы, архитектуры доступа (`guest` / `employee` / `admin`) и типичных сценариев эксплуатации систем кабельного обогрева в нефтегазовой отрасли.

---

## Персона 1 — Алексей, Внешний проектировщик (Guest)

```
┌─────────────────────────────────────────────────────────────────┐
│  Роль в системе: Гость (guest)                                  │
│  Возраст: 32 года                                               │
│  Должность: Главный инженер проекта, сторонняя ПКФ             │
│  Опыт в отрасли: 8 лет                                         │
└─────────────────────────────────────────────────────────────────┘
```

### Контекст

Алексей работает в проектной компании-подрядчике. Его фирма получает задание от нефтяной компании разработать проект кабельного обогрева для нового объекта. У него нет учётной записи в корпоративной системе заказчика.

### Цели

- Быстро рассчитать теплопотери для 5–15 трубопроводов и 2–3 резервуаров
- Подобрать кабель и сформировать спецификацию материалов
- Получить предварительный отчёт для согласования с заказчиком
- Не тратить время на регистрацию и ожидание одобрения аккаунта

### Боли

- Не хочет устанавливать тяжёлое специализированное ПО
- Нет корпоративного доступа к внутренним системам заказчика
- Excel-таблицы устарели и содержат ошибки
- Нет стандартного шаблона отчёта, каждый раз приходится оформлять вручную

### Сценарий использования

> «Я захожу на сайт, нажимаю "Пользователь", создаю проект. За час заполняю данные по трубам, вижу результаты расчётов в реальном времени. Смотрю HTML-предпросмотр отчёта — показываю заказчику прямо с браузера. Если нужно — прошу сотрудника заказчика выгрузить XLSX.»

### Ограничения в системе

| Возможность | Доступно |
|-------------|----------|
| Создание проекта | ✅ |
| Расчёт теплопотерь | ✅ |
| Просмотр HTML-предпросмотра | ✅ |
| Экспорт PDF/DOCX/XLSX | ❌ (только для сотрудников) |
| Просмотр расширенных справочников | ❌ |
| Доступ к проектам других пользователей | ❌ |

## Персона 2 — Мария, Инженер-проектировщик (Employee)

```
┌─────────────────────────────────────────────────────────────────┐
│  Роль в системе: Сотрудник (employee)                           │
│  Возраст: 27 лет                                                │
│  Должность: Инженер-теплотехник, проектный отдел               │
│  Опыт в отрасли: 3 года                                        │
└─────────────────────────────────────────────────────────────────┘
```

### Контекст

Мария — штатный сотрудник нефтяной компании. Ежемесячно обрабатывает 10–30 проектов кабельного обогрева: от проверки расчётов субподрядчиков до самостоятельного проектирования. Работает в корпоративной сети.

### Цели

- Быстро проверить расчёты, сделанные гостями-подрядчиками
- Самостоятельно рассчитать теплопотери для объектов заказчика
- Выгрузить финальный отчёт в PDF для передачи в ПТО
- Сформировать XLSX-спецификацию для отдела снабжения
- Видеть все проекты системы для координации с коллегами

### Боли

- Раньше приходилось переписывать расчёты из Excel вручную — ошибки при перепечатке
- Хочет стандартизированный шаблон отчёта, одобренный главным инженером
- Нужен экспорт в форматах, принятых в компании (DOCX для согласования, XLSX для снабжения)

### Сценарий использования

> «Подрядчик сдал расчёт. Я захожу, нахожу его проект в общем списке, сверяю параметры. Вижу предупреждения о невалидных объектах — прошу уточнить данные. После исправления нажимаю "Экспорт PDF" — отправляю главному инженеру на подпись.»

### Ограничения в системе

| Возможность | Доступно |
|-------------|----------|
| Все функции гостя | ✅ |
| Экспорт PDF/DOCX/XLSX | ✅ |
| Просмотр всех проектов | ✅ |
| Расширенные справочники | ✅ |
| Управление пользователями | ❌ |
| Изменение коэффициентов | ❌ |

## Персона 3 — Владимир, Главный инженер / Администратор (Admin)

```
┌─────────────────────────────────────────────────────────────────┐
│  Роль в системе: Администратор (admin)                          │
│  Возраст: 48 лет                                                │
│  Должность: Главный инженер проектного отдела                  │
│  Опыт в отрасли: 22 года                                       │
└─────────────────────────────────────────────────────────────────┘
```

### Контекст

Владимир — технический руководитель, несёт ответственность за корректность всех расчётов в компании. Он утверждает методику расчёта, определяет допустимые значения коэффициентов запаса и контролирует доступ к системе.

### Цели

- Установить единые корректирующие коэффициенты для всего отдела
- Управлять учётными записями сотрудников и подрядчиков
- Ввести в систему новые марки кабелей и аксессуаров из актуальных каталогов поставщиков
- Обеспечить соответствие расчётов актуальным нормативам

### Боли

- Раньше каждый инженер мог применять свои коэффициенты — отсутствовала единая методология
- Смена поставщика кабеля требовала обновления таблиц у каждого инженера отдела
- Сложно отследить, кто и когда изменил параметры расчёта

### Сценарий использования

> «Вышел новый норматив — коэффициент запаса нужно увеличить с 1.1 до 1.2. Я вхожу в Admin → Коэффициенты → меняю `safety_factor`. Все новые расчёты автоматически будут использовать обновлённое значение. Параллельно добавляю в каталог 3 новых кабеля от нового поставщика.»

### Ограничения в системе

Администратор имеет полный доступ ко всем функциям системы.

---

> **Техническая заметка:** Гость **не является** записью в таблице `users`.
> `User.role` в БД допускает только `employee | admin`. Идентификация гостя —
> через запись в отдельной таблице `guest_sessions` (`session_id` передаётся
> клиентом в заголовке `X-Session-Id`). У пользователя ровно один авто-проект
> (`GUEST_MAX_PROJECTS=1`), привязанный к `session_id`. Фоновая задача раз в 10 мин
> каскадно удаляет сессии с неактивностью > 20 мин вместе со всеми данными.
