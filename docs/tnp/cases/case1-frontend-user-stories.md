## EP-AUTH — Гость, сессия, справка

### US-AUTH-01 · Старт без регистрации  
**P0** · §4.1–4.2

**Как** инженер-гость,  
**я хочу** нажать «Начать без регистрации» и сразу попасть в рабочую область с одним временным проектом,  
**чтобы** не тратить время на регистрацию и список проектов.

**AC**

- [ ] На home видны CTA «Начать без регистрации» и «Войти с паролем».
- [ ] После клика создаётся guest session + временный проект.
- [ ] Не показываются «Мои проекты» и форма создания проекта.
- [ ] Активна вкладка исходных данных (Heat).

---

### US-AUTH-02 · Срок сессии и честная справка  
**P1** · §3.10, §4.2

**Как** гость,  
**я хочу** в справке и на home видеть реальные правила (3 дня, 500 объектов, 5 ЭР, файл проекта),  
**чтобы** не потерять работу из-за устаревших текстов.

**AC**

- [ ] Help: «до 3 дней после последней активности» (не 30).
- [ ] Help: лимит 500 объектов, 5 электрорасчётов.
- [ ] Help: без файла проекта данные не восстанавливаются после TTL.
- [ ] Help: гость — HTML/печать отчёта; PDF/DOCX/XLSX — сотрудник.
- [ ] CTA в help совпадает с home («Начать без регистрации»).

---

### US-AUTH-03 · Восстановление истёкшей сессии  
**P1** · §3.10, AUTH-05

**Как** гость с истёкшей сессией,  
**я хочу** получить один новый временный проект без ошибок в консоли и «битых» экранов,  
**чтобы** продолжить работу, а не отлаживать 401/404.

**AC**

- [ ] При 401 guest: cancel + remove queries старого project id **до** установки нового.
- [ ] Нет повторных запросов к старому UUID.
- [ ] Пользователь видит одно понятное сообщение о новой сессии.
- [ ] Console: 0 error/warn от stale project fetch после recovery.

## EP-HEAT — Исходные данные

### US-HEAT-01 · Добавление и расчёт трубы/резервуара  
**P0** · §5.3–5.4  
*(в основном реализовано — story для регрессии/приёмки)*

**Как** инженер,  
**я хочу** заполнить формы трубы или резервуара, добавить объект и увидеть теплопотери и статус,  
**чтобы** подготовить данные к электрорасчёту.

**AC**

- [ ] Обязательные поля валидируются; при ошибке объект не создаётся.
- [ ] После успеха строка в таблице со статусом и Q.
- [ ] Edit → Save пересчитывает; Add создаёт новый, не перезаписывает.
- [ ] «Пол» недоступен (future).

---

### US-HEAT-02 · Групповая корректировка выбранных  
**P1** · §5.8

**Как** инженер,  
**я хочу** для выбранных строк задать один параметр и новое значение и применить ко всем,  
**чтобы** не править десятки объектов вручную.

**AC**

- [ ] При selection ≥1 активна «Групповая корректировка».
- [ ] UI: выбор параметра → значение → «Применить».
- [ ] Вызов BE `POST .../objects/group-update` (не N×PATCH).
- [ ] Если значение нельзя применить хотя бы к одному — rollback + список проблемных.
- [ ] После успеха heat пересчитан, ЭР/spec помечены stale где нужно.

---

### US-HEAT-04 · Переход к электрорасчёту  
**P0** · §5.13

**Как** инженер,  
**я хочу** нажать «Далее → Электротехнический расчёт» и перейти только если объекты готовы,  
**чтобы** не создавать ЭР на битых данных.

**AC**

- [ ] При ошибках остаёмся на Heat; проблемные строки подсвечены.
- [ ] При успехе открывается ЭР; объекты в «Нераспределённые».

---

### US-HEAT-05 · Напряжение 230 В (не 220)  
**P0** · **ТЗ DEC-11** (PDF §6.13 допускает user voltage; продукт = 230)

**Как** инженер,  
**я хочу** видеть нормативное напряжение 230 В без выбора 220,  
**чтобы** не расходиться с TT-расчётом.

**AC**

- [ ] Нет editable 220 в defaults heat/elec (`project_object_params` / forms).
- [ ] 230 отображается read-only (или убрано с heat, если U только в ЭР).
- [ ] Fixtures/e2e не утверждают 220 как норму MVP.
- [ ] Copy: источник «норматив / система», не «выбор пользователя», если U fixed.

## EP-ELEC — Электротехнический расчёт

### US-ELEC-01 · MVP: только Самрег  
**P0** · §6.1–6.2

**Как** инженер в текущей версии,  
**я хочу** видеть только саморегулирующийся кабель,  
**чтобы** не путаться с Резистив/Скин, которые недоступны.

**AC**

- [ ] Нет активных вкладок/кнопок «Резистив», «Скин».
- [ ] Нет саммари-карточек Резистив/Скин (или одна info: «доступен только Самрег»).
- [ ] Assign предлагает только саморегулирующийся.
- [ ] Copy: «В этой версии активен тип «Саморегулирующийся».»

---

### US-ELEC-02 · Варианты ЭР (до 5)  
**P0** · §6.3–6.7, §6.20

**Как** инженер,  
**я хочу** создавать до 5 независимых ЭР, копировать, удалять с подтверждением и переименовывать,  
**чтобы** сравнивать варианты решения.

**AC**

- [ ] Add / copy / delete / rename работают.
- [ ] На 5-м: create/copy disabled + пояснение.
- [ ] Delete confirm с номером/именем ЭР.
- [ ] Copy не переносит спецификацию как готовую для нового ЭР.
- [ ] Имя ЭР отражается на вкладке спецификации.

---

### US-ELEC-03 · Назначение типа: кнопка  
**P0** · §6.10

**Как** инженер,  
**я хочу** выбрать объекты и назначить «Самрег»,  
**чтобы** запустить автоподбор кабеля и секций.

**AC**

- [ ] Без selection кнопки assign disabled.
- [ ] После assign объекты уходят из unassigned; стартует расчёт.
- [ ] Ошибка расчёта → статус «Требуется корректировка» + причина, не silent success.

---

### US-ELEC-04 · Назначение типа: DnD + клавиатура  
**P1** · §6.11, FE-12

**Как** инженер,  
**я хочу** перетащить выбранные строки на вкладку «Самрег» или сделать то же с клавиатуры,  
**чтобы** быстро распределять объекты.

**AC**

- [ ] DnD работает в **default** table engine (glide), не только AntD-ветке.
- [ ] Drop-zone highlight.
- [ ] Keyboard: select rows → action «Назначить Самрег» (тот же эффект, что DnD).
- [ ] Результат идентичен кнопке assign.

---

### US-ELEC-05 · Сводка показателей  
**P0** · §6.8

**Как** инженер,  
**я хочу** видеть саммари Самрег и Итого (объекты, Lфакт, секции, P, Iст, Iраб),  
**чтобы** контролировать вариант целиком.

**AC**

- [ ] Метрики совпадают с BE summary (длина = Lфакт, не Lзаказ).
- [ ] Unassigned не входят в итоги системы.
- [ ] После recalc/assign числа обновляются.

---

### US-ELEC-06 · Нитки 1…3  
**P0** · §6.13

**Как** инженер,  
**я хочу** задавать только 1–3 нитки,  
**чтобы** не получить формально успешный, но недопустимый вариант.

**AC**

- [ ] UI input max 3 для `self_regulating_tt`.
- [ ] Значение &gt;3 невозможно ввести / валидация.
- [ ] Если 3 ниток мало — error state, не «успех».

---

### US-ELEC-07 · Iдоп: UI ввода (BE уже fail-closed)  
**P0** · §6.14

**Как** инженер,  
**я хочу** задать допустимый стартовый ток секции (проект / объект) в интерфейсе,  
**чтобы** пройти секционирование (без Iдоп BE возвращает `SECTION_CURRENT_LIMIT_REQUIRED`).

**Зависимость BE:** fail-closed в `sections.py` **уже есть**. Не дублировать backend work.

**AC**

- [ ] UI настроек проекта: `max_section_start_current_a` (Iдоп), API electrical-settings.
- [ ] Optional override на объекте/assignment (если BE отдаёт поле).
- [ ] Без Iдоп: blocking UI «Задать допустимый стартовый ток» + CTA в настройки; не маскировать как success.
- [ ] С Iдоп: Lогр / Nсек / токи согласованы с расчётом; source Iдоп виден (project/object/catalog).

---

### US-ELEC-08 · Ручная марка и навив  
**P1** · §6.16

**Как** инженер,  
**я хочу** в таблице сменить марку или навив и сразу увидеть пересчёт строки,  
**чтобы** уточнить решение без модалки секций.

**AC**

- [ ] Смена марки/навива → auto recalc только этой строки.
- [ ] Ручная марка не подменяется автоподбором при batch без флага.
- [ ] Ошибка → «Требуется корректировка» + причина; введённое значение сохраняется.
- [ ] Связанная spec → stale.

---

### US-ELEC-09 · Вернуть в нераспределённые  
**P0** · §6.15, §6.17

**Как** инженер,  
**я хочу** снять назначение с подтверждением,  
**чтобы** очистить кабель/секции, сохранив теплопотери.

**AC**

- [ ] Confirm с текстом последствий.
- [ ] После: unassigned; cable/sections cleared; heat intact.
- [ ] Summary пересчитан.

### US-ELEC-10 · Перерасчёт после изменения Heat  
**P0** · §6.19

**Как** инженер,  
**я хочу** явно видеть устаревшие строки ЭР после правки исходных данных и пересчитать их по кнопке,  
**чтобы** не использовать старые токи/длины незаметно.

**AC**

- [ ] Баннер: «N объектов требуют перерасчёта».
- [ ] Строки: статус «Требуется перерасчёт» + highlight + «Пересчитать».
- [ ] До пересчёта stale values не в «актуальных» итогах (как в ТЗ).
- [ ] Multi-ER: независимо по каждому варианту.
- [ ] Spec связанных ЭР → stale.

## EP-SPEC — Спецификация

### US-SPEC-01 · Первое формирование (выбранные ЭР)  
**P0** · §7.2, §7.4

**Как** инженер,  
**я хочу** выбрать один или несколько ЭР, задать Ex/K*/R_gr и способ группировки и сформировать спецификации,  
**чтобы** получить BOM только для нужных вариантов.

**AC**

- [ ] Пустое состояние: «Спецификации ещё не сформированы» + CTA.
- [ ] Modal/settings: multi-select ЭР (max 5), options, grouping.
- [ ] Generate **только** выбранных (не auto-all).
- [ ] Канонический V2 body: `variant_ids` + `options` + flags.
- [ ] После успеха — вкладки только для выбранных ЭР.

---

### US-SPEC-02 · Нераспределённые: Исправить / Всё равно  
**P0** · §7.3, §6.18

**Как** инженер,  
**я хочу** при наличии unassigned увидеть предупреждение с действиями «Исправить» и «Всё равно сформировать»,  
**чтобы** либо дораспределить объекты, либо осознанно исключить их.

**Факт:** сейчас modal «Подтвердить и сформировать» / «Отмена» — partial proceed **есть**, navigate **нет**.

**AC**

- [ ] Warning: ЭР + количество unassigned + пояснение (не сырой `<pre>{code}`).
- [ ] Proceed → generate с `exclude_unassigned_confirmed` (copy PDF: «Всё равно…» или эквивалент).
- [ ] **«Исправить»** → первый проблемный ЭР + вкладка «Нераспределённые» + highlight.
- [ ] На partial spec — баннер «часть объектов не учтена».

---

### US-SPEC-03 · Разделы Трубы / Бочки / Общие  
**P0** · §7.1, §7.4, §7.6

**Как** инженер,  
**я хочу** видеть материалы по разделам типов объектов (и общие),  
**чтобы** сверять BOM с проектом, а не одну кучу «Общие материалы».

**AC**

- [ ] `bomSectionOf` использует `object_type_section` / корректный section key.
- [ ] При `separate_by_object_type`: pipe / tank / common.
- [ ] Пустая секция: «Нет позиций» ≠ «Расчёт для типа недоступен».
- [ ] Unsupported type — отдельный copy.
- [ ] При merge_materials — согласованное отображение (design).

### US-SPEC-04 · Диагностики по kind

**чтобы** понимать, что нажать дальше.

**AC**

- [ ] `blocking` → danger, без CTA generate.
- [ ] `confirmable` → warning + confirm actions.
- [ ] `selection_required` → panel кандидатов (не один red alert).
- [ ] Diagnostics привязаны к ЭР (не flatMap в одну кучу без контекста).
- [ ] Settings modal не закрывается так, что diagnostics пропадают (fix Slice 0).

## EP-IO — Файл и отчёт

### US-IO-01 · Файл проекта (schema v3 CSV) — UX + proof  
**P0** · §4.2, §5.11–5.12

**Как** гость,  
**я хочу** скачать и загрузить **полный** проект (объекты, ЭР, спецификация, настройки) с понятными названиями действий,  
**чтобы** продолжить работу в другой сессии.

**Факт:** BE `export-csv` / `import-csv` = секционный **schema v3** (не «только объекты»). FE labels сейчас «Скачать/Загрузить (CSV)».

**AC**

- [ ] Round-trip proof: heat + assigned ER + generated spec → export → new session import → данные на месте.
- [ ] Labels/help: «файл проекта» / формат `.tlt.csv` schema v3; не обещать «только объекты».
- [ ] Import: warn replace; corrupt → current project intact.
- [ ] Guest path: те же кнопки без employee «Открыть/Новый».

---
