## US-HEAT-01 · Добавление и правка объекта
**P0** · §5.3–5.4 · ✅

**Как** инженер, **я хочу** заполнить формы трубы или резервуара, добавить объект
и увидеть теплопотери и статус, **чтобы** подготовить данные к электрорасчёту.

**AC**
- Обязательные поля валидируются; при ошибке объект не создаётся, поля
  подсвечиваются, введённые значения остаются в формах (§5.3 «Ошибка заполнения»).
- После успеха — строка в таблице со статусом и результатом.
- Клик по строке грузит объект в формы, «Сохранить» становится активной (§5.4).
- «Сохранить» правит существующий объект; «Добавить объект» всегда создаёт новый.
- После сохранения формы возвращаются в режим добавления.
- Вкладка «Пол» недоступна (future).

## US-HEAT-02 · Групповая корректировка выбранных
**P1** · §5.8 · ⚠️ реализовано, сквозной сценарий не прогнан

**Как** инженер, **я хочу** задать один параметр и новое значение для выбранных
строк, **чтобы** не править десятки объектов вручную.

**AC**
- При выборе ≥1 объекта кнопка «Групповая корректировка» активна — ✅.
- Форма: выбор параметра → значение → «Применить» — ✅ (`HeatCalcGroupUpdateModal`).
- Один вызов `POST …/objects/group-update`, не N×PATCH — ✅.
- Всё-или-ничего: при недопустимом значении хотя бы для одного объекта данные не
  меняются, показан перечень проблемных объектов — ✅ код и unit-тест.
- После успеха теплопотери пересчитаны, ЭР и спецификация помечены stale — ✅ на
  бэкенде.
- **Не проверено:** применение к реальным объектам в браузере. Для проверки нужен
  засеянный проект; токен гостя живёт в памяти, а не в localStorage, поэтому
  быстрый seed через API не срабатывает. Закрывается e2e-сценарием.

## US-HEAT-04 · Переход к электрорасчёту
**P0** · §5.13 · ✅

**Как** инженер, **я хочу** нажать «Далее → Электротехнический расчёт» и перейти
только если объекты готовы, **чтобы** не создавать ЭР на битых данных.

**AC**
- При ошибках остаёмся на теплопотерях, проблемные строки подсвечены.
- При успехе открывается ЭР, объекты в «Нераспределённые».
- Кнопка неактивна, пока в проекте нет объектов.

## US-HEAT-07 · Объект на основании открытого
**P1** · §5.6 · ✅

**Как** инженер, **я хочу** открыть существующий объект, поправить параметры и
нажать «Добавить объект», **чтобы** получить новый объект, не трогая исходный.

**AC**
- Параметры выбранного объекта грузятся в формы.
- «Добавить объект» создаёт новый объект с собственным идентификатором.
- Исходный объект не меняется.
- Если параметры не правили — создаётся полная копия.

## US-HEAT-08 · Копии выбранных объектов
**P1** · §5.7 · ✅

**Как** инженер, **я хочу** отметить строки чекбоксами и нажать «Добавить на
основании», **чтобы** размножить объекты одним действием.

**AC**
- Кнопка активна только при выборе ≥1 объекта — ✅.
- Число новых объектов равно числу выбранных строк.
- Формы исходных данных при массовом копировании не открываются.
- Теплопотери копий рассчитываются заново; исходные объекты не меняются.
- Показано количество созданных объектов.

**P1** · §5.9 · ⚠️ реализовано, хранение не проверено

**Как** инженер, **я хочу** выбрать, какие столбцы видны в таблице, **чтобы**
работать только с нужными параметрами.

**AC**

- У каждого столбца признак «показывать / скрыть»; есть сброс к стандартному набору.

- **Не проверено:** требование PDF «настройки действуют в рамках текущей сессии» —
  в модели предпочтений хранение в session/localStorage не найдено.

## Чего в PDF нет

**Методики расчёта теплопотерь в документе нет.** Разделы с формулами в конце
(6.13 подбор кабеля, 6.14 нагревательные секции, 7.10–7.15 материалы
спецификации) теплопотерь не касаются. Теплопотери фигурируют только как вход и
результат: «система выполняет расчёт тепловых потерь», «Тепловые потери, Вт/м —
результат теплотехнического расчёта», «если нет теплопотерь → ошибка».

§3.9 прямо говорит: расчётные формулы на серверной стороне не должны быть
доступны через интерфейс — то есть методика вынесена из документа намеренно.

PDF задаёт по теплопотерям только **перечень входных параметров** (§5.2,
стр. 22–27) и **перечень результатов**: теплопотери трубы на метр, общие
теплопотери трубопровода, теплопотери резервуара на м², общие теплопотери
резервуара.

**Следствие:** сверить реализацию расчёта с кейсом нельзя — нужен первоисточник
методики (отдельный документ, «Список переменных трубопровода.xlsx», справочники).
