## C. Входные параметры (§5.2, стр. 22–27)

**Общие:** тип объекта · наименование · температура продукта · температура
окружающей среды · источник температуры (ручной ввод или климатический
справочник) · размещение (помещение / улица / под землёй) · скорость ветра
(если на улице) · коэффициент запаса · условия для расчёта изоляции
(помещение, улица зима/лето, канал, тоннель, чердак, подвал).

**Изоляция:** наличие · толщина по каждому слою · материал из справочника или
нестандартный · количество слоёв (1–3) · λ нестандартного материала ·
температурный диапазон нестандартного материала · покровный материал
(хранится, на расчёт не влияет).

**Трубопровод:** наружный диаметр · длина участка · толщина стенки · материал
трубы · λ трубы вручную · глубина заложения · тип или λ грунта · количество
локальных элементов · эквивалентная длина локального элемента.

**Резервуар:** форма (цилиндрический / прямоугольный / сферический) · диаметр ·
высота · длина · ширина · объём (хранится) · толщина стенки · λ стенки ·
высота подземной части · тип или λ грунта · дополнительные теплопотери, Вт.

Статус: все перечисленные есть в реестре `heatcalc-fields.default.json`
(43 неслужебных поля на тип объекта). **Сферический резервуар** в кейсе есть —
в приложении форма выбирается, проверить покрытие расчётом отдельно.

## G. Чего в кейсе нет

**Методики расчёта теплопотерь.** Формулы в конце документа (§6.13 подбор
кабеля, §6.14 нагревательные секции, §7.10–7.15 материалы спецификации)
теплопотерь не касаются. Теплопотери — только вход и результат.

**Требований к разрешению экрана.** §3.2 задаёт лишь браузеры: Chrome, Firefox,
Яндекс. Профиль 1280/1440/1920 — внутреннее решение проекта.

**Расчёта для типов «Бочка» и «Пол».** §5.3 прямо выводит их за рамки
документации; «Пол» — будущее расширение.

## Дефекты, найденные при написании e2e (2026-08-05)

1. **Резервуары из штатного шаблона импорта не рассчитываются.** В шаблоне
   (`GET …/objects/import-template`) у строк «резервуар» пуст столбец «Скорость
   ветра», а бэкенд требует `wind_speed` для `placement=outdoor`. Все три
   примера бака приходят с `is_valid=false`. Пин:
   `e2e/tests/heat-excel-import.spec.ts` — «резервуары из штатного шаблона…».
2. **Объект с напряжением по умолчанию нельзя сохранить из формы.** Бэкенд
   подставляет `supply_voltage=230` (DEC-11), а справочник поля предлагает
   только 220 и 380 → при «Сохранить» форма ругается «Выберите значение из
   списка» на поле, которого пользователь не касался. Блокирует §5.4 для любого
   объекта, созданного без явного напряжения. Пин:
   `e2e/tests/heat-object-lifecycle.spec.ts` — «объект с напряжением…».
3. **Ошибка заполнения показывает сырой ответ бэкенда.** При отправке пустой
   формы в toast прилетает дамп pydantic на английском вместо «поле + что
   исправить» (§3.11). Текст в e2e намеренно не зафиксирован.
4. **Два e2e-теста красные не из-за теплопотерь:**
   `inline-form-dependencies.insulation-layers.spec.ts` сеет объекты через
   параметры, запрещённые инвариантом записи с 2026-08-03 (`burial_depth`,
   `insulation_layer_count`, `valve_count`, `flange_count`, `support_count`) →
   422 вместо 201.
