## 1. Цель

Спроектировать **недостающие состояния и микровзаимодействия** экрана «Спецификация», чтобы:

1. Предупреждения **вели к действию** (не только «ок, сформировать»).
2. Blocking / confirmable / selection_required **читались по-разному**.
3. Таблица соответствовала **составу строки** кейса (без выдуманных кодов — layout + placeholder-паттерн «значение с backend»).
4. Пустые секции **не врали** («недоступен» vs «ещё не сформировано» vs «нет позиций»).
5. После F5 / смены ЭР пользователь **понимал статус** без повторного «угадывания».

**Не цель:** редизайн; макеты admin-каталога; макеты «owner-approved nomenclature»; heat/электрика; отчёт как отдельный кейс.

## 4. Обязательные кадры (P0)

Для каждого кадра: **1440** (primary) + **1000** (functional, без горизонтального overflow). 1280 — желательно.

**Три ограничения, действующие во всех кадрах ниже** (из PDF и замеров — они не «пожелания»):

1. **Сортировщики и фильтры не рисуем.** §7.1 (стр. 57): фильтрация и сортировка в текущей версии не реализуются, пользователь делает их после выгрузки в Excel. Текущий макет `03-specification` нарисовал ⇅ на всех колонках — это лишнее.
2. **Таблица — в скролл-контейнере с закреплённой первой колонкой.** Замер (`case1-design-review.md` §4.3): таблица спецификации требует 1105 px, то есть на 1000 px не помещается. Без контейнера она распирает страницу, а бриф §5 запрещает page overflow. Кадр на 1000 px показывается именно со скроллом внутри таблицы.
3. **Два способа формирования — оба кадром.** §7.4 (стр. 59): «Разделять по типам объектов» (материалы разных типов не объединяются даже при одинаковой номенклатуре) и «Объединять материалы» (одинаковые позиции с одной базой и кодом суммируются). Разница видна только на результате, поэтому нужны два состояния таблицы, а не только переключатель в модалке.

### D-SPEC-01 — Unassigned: две CTA

**Состояние:** backend вернул `confirmation_required` (есть нераспределённые объекты).

**Сейчас:** есть proceed («Подтвердить и сформировать» / аналог).

**Нужно:**

1. Алерт/модал с понятным текстом: *какие ЭР / сколько unassigned* (данные с backend — layout slots).
2. **Две кнопки:**
   - **Primary secondary / danger-outline:** «Исправить»  
   - **Primary:** «Всё равно сформировать» (exclude unassigned / confirm)
3. Спецификация перехода «Исправить»:
   - уход на **Электротех. расчёт**;
   - активный **первый ЭР с unassigned** (если multi-ER — приоритет: текущий ЭР вкладки, иначе первый из diagnostics);
   - целевая зона: **«Нераспределённые объекты»** (вкладка/фильтр/якорь — выбрать один паттерн и зафиксировать в аннотации);
   - **подсветка** строк unassigned (1 состояние: highlight row).
4. Microcopy: без жаргона API (`confirmation_required` не показывать пользователю).

**DoD кадра:** обе CTA, transition «Исправить» описан, 1440+1000.

### D-SPEC-02 — Три визуальных языка diagnostics (по `kind`)

Backend шлёт `diagnostics[].kind`:

| kind | Смысл | UI-паттерн (зафиксировать) |
|---|---|---|
| `blocking` | нельзя сформировать | danger / error alert + список причин; **нет** ложного success |
| `confirmable` | можно продолжить с подтверждением | warning + CTA из D-SPEC-01 |
| `selection_required` | нужен выбор номенклатуры | info/warning + **панель кандидатов** (не общий danger dump) |

**Сейчас:** часто один danger-алерт на все diagnostics.

**Нужно:** 3 отдельных визуальных паттерна (можно один компонент Alert с tone + layout slots).  
Не дублировать панель кандидатов внутри danger-текста.

**Кадры:**

1. Только blocking (пример: нет кандидата / не ready)  
2. Только selection_required + panel  
3. Mixed multi-ER: один ER selection, другой blocked (если влезает — chips на вкладках, см. D-SPEC-05)

**DoD:** таблица kind → tone/CTA; 3 кадра минимум.

### D-SPEC-03 — Состав строки спецификации (§7.3)

Таблица должна **уметь** показать (не обязательно всё в одной узкой строке — допустим expand/drawer/tooltip):

| Поле кейса | UI |
|---|---|
| Наименование | primary cell |
| Марка | cell |
| Номенклатурный код | cell (не «—» как default layout) |
| Поставщик (если есть) | secondary / optional column |
| Ед. поставки | cell |
| Количество | numeric, tabular |
| Категория / раздел | section header **или** badge |
| Id + версия строки каталога | secondary (expand / detail) |
| Параметры + формула qty | detail panel |

**Нужно решить и нарисовать:**

1. **Default density** (что в строке всегда).  
2. **Detail** (клик / «Подробнее» / side panel) — обязательно для catalog id/version + formula params.  
3. Состояние detail **пусто/нет данных с backend** — «Нет данных provenance», не выдуманные коды.

**DoD:** 1 кадр collapsed table + 1 кадр expanded detail; аннотация колонок.

### D-SPEC-04 — Пустые секции: честные empty states

**Проблема:** «Расчёт спецификации для данного типа объекта пока недоступен» показывается там, где spec **просто не сформирована** или секция **пуста после generate**.

Развести **3 empty-state**:

| Ситуация | Заголовок (черновик) | CTA |
|---|---|---|
| A. Spec ещё не формировали | «Спецификация не сформирована» | «Сформировать» |
| B. Сформировали, в секции нет позиций | «Нет позиций в разделе „Трубы“» | без «недоступен» |
| C. Тип объекта unsupported (tank и т.п.) | «Расчёт для этого типа пока недоступен» | без ложного generate success |

**DoD:** 3 маленьких кадра/фрагмента секций + когда какой текст.

### D-SPEC-05 — Статус на вкладках ЭР + F5

Backend отдаёт `generation_status`: `generated` | `selection_required` | `confirmation_required` | `blocked` | (нет строки).

**Нужно:**

1. **Chip/badge на вкладке** ЭР (компактный, в стиле R1):  
   - нет spec — нейтральный / «не сформирована» (опц., не шуметь)  
   - generated — ok  
   - selection_required — attention  
   - confirmation_required — attention  
   - blocked — danger  
   - stale (is_stale) — отдельно или комбинация «устарела»
2. После F5: тот же badge + соответствующий body (panel/alert), **без** авто-открытия модалки настроек.
3. Панель кандидатов: **имя ЭР** рядом с группой (не сырой UUID как primary label). UUID можно secondary mono.

**DoD:** 1 кадр multi-tab с разными badges; 1 кадр selection panel с именем ЭР.

### D-SPEC-06 — «Выбор устарел / выпал из кандидатов»

**Нужно:**

- warning: «Сохранённый выбор больше не подходит — выберите позицию заново»;
- старый draft **не** предвыбирается;
- CTA: остаться в panel выбора.

**DoD:** 1 кадр + microcopy.
