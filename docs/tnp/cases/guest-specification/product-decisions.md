# Product Decision Log — динамические ЭР и гостевая спецификация

Даты фиксации: **18.07.2026** и **19.07.2026**.

Источник решения: явные ответы пользователя в текущем диалоге после аудита
PDF редакции 4 от 07.07.2026. Эти решения являются целевым продуктовым
контрактом для будущей ветки динамических ЭР и сильнее расходящихся legacy SRS,
кода и golden-тестов. Изменять их можно только новым явным продуктовым решением.
PDL-ER-18…25 фиксируют восемь ответов **А**, явно утверждённых пользователем
18.07.2026. PDL-ER-26…28 фиксируют три дополнительных ответа **А**, явно
утверждённых пользователем 19.07.2026. PDL-ER-29…41 фиксируют утверждённые
ответы **А** по контракту Phase 5: specification/report/project I/O.

| ID | Тема | Утверждённое решение | Следствие для реализации и приёмки |
|---|---|---|---|
| PDL-ER-01 | Scope генерации спецификации | Пользователь выбирает один или несколько ЭР; UI также даёт действие `Выбрать все`. | Никакой неявной генерации всех ЭР. API принимает явный список UUID, валидирует единый проект и определяет атомарность/partial result. |
| PDL-ER-02 | Количество кабеля в закупочном BOM | Используется **заказная длина**: фактическая длина с резервом 10% и коммерческим округлением. `Lсек × Nсек` хранится отдельно как фактическая инженерная величина. | В модели и отчёте трассируются обе длины. Закупочная позиция использует только утверждённую заказную длину; тесты не должны смешивать две величины. |
| PDL-ER-03 | Ручное изменение секций | Прямое изменение длины, количества и состава секций запрещено. | PDL-ER-04 | BOM для гостя | Гостю доступен **полный BOM по PDF**. Ручное добавление, удаление и редактирование позиций остаётся только сотруднику/администратору. | Guest больше не получает `403` для утверждённой full generation. Автоматический результат сохраняется в его временном проекте; write API ручных строк защищён backend RBAC. |
| PDL-ER-05 | Отчёт гостя | Гостю доступны HTML-предпросмотр и печать средствами браузера. Серверные экспорты PDF/DOCX/XLSX доступны только сотруднику/администратору. | Нужны доступная кнопка/действие печати и print CSS. Guest export endpoints остаются закрыты backend RBAC. |
| PDL-ER-06 | Типы объектов MVP | Поддерживаются `Трубопровод` и `Ёмкость`. `Бочка` — синоним/пользовательское название ёмкости, а не отдельный backend type. | Канонические backend/import keys остаются `pipe` и `tank`; `barrel` не создаёт третью доменную сущность. `Пол` не входит в MVP и может отображаться только как disabled future option. |
| PDL-ER-07 | Scope настроек спецификации | Настройки хранятся как project defaults. При каждой генерации сохраняется snapshot и настройки применяются только к явно выбранным ЭР. | Сохранение defaults не перегенерирует все ЭР автоматически. Спецификации с отличающимся snapshot помечаются stale; выбранные ЭР регенерируются явно. |
| PDL-ER-08 | Порог диаметра коробок | Граница включительная: `dтр ≥ 57 мм`. | Ровно 57 мм относится к ветке большого диаметра; обязательны boundary tests ниже, ровно и выше 57 мм. |
| PDL-ER-09 | Имена ЭР | Имена уникальны внутри проекта после `trim + casefold`. | DB/API отклоняют пустые и конфликтующие имена стабильным error code; display name сохраняет пользовательский регистр. |
| PDL-ER-10 | Резистивный расчёт | Действующий резистивный flow сохраняется. `single_core` и `three_core` нормализуются в assignment `resistive`. | Динамические ЭР не создают регрессию утверждённого резистивного расчёта; disabled остаются только неподдержанные MI/skin. |
| PDL-ER-11 | Unsupported/mineral | `system_type` отделяется от `assignment_state`; исходный `requested_cable_type` сохраняется. Mineral/MI нельзя выбрать как новый target, но tabs migrated unsupported rows доступны для просмотра и confirmed unassign. | Legacy diagnostics мигрируют losslessly, не превращаются в успешный self-reg/resistive результат и не остаются stranded за полностью disabled вкладкой. |
| PDL-ER-12 | Первый ЭР | `ЭР1` создаётся при первом readiness-gated переходе в электрический расчёт, а не вместе с пустым проектом. | Mutation повторно валидирует объекты под project lock и атомарно создаёт active `ЭР1` с assignments `unassigned`; при ошибке ЭР не создаётся. |
| PDL-ER-13 | Copy specification | Готовая specification не копируется. Target ЭР получает состояние `not_generated` и требует явной generation. | Copy не переносит потенциально устаревший BOM/manual items и не запускает неявную генерацию. |
| PDL-ER-14 | Atomicity multi-ЭР generation | Список выбранных ЭР обрабатывается одной транзакцией. Partial допускается только внутри каждого ЭР после явного подтверждения. | Internal failure откатывает весь список; исключённые objects возвращаются с IDs/error codes. |
| PDL-ER-15 | Данные секционирования | Phase 4 останавливается до утверждённого источника `Lmax`, пускового тока/`kпуск` и необходимых токовых данных. | Запрещены фиктивные defaults и вывод секций из `num_circuits`. |
| PDL-ER-16 | Приоритет BOM-источников | PDF от 07.07.2026 задаёт семантику; XLSX от 29.05.2026 используется только как каталог/источник данных там, где не противоречит PDF. | Конфликтующие legacy golden переписываются только с PDF oracle; непротиворечащая номенклатура XLSX сохраняется. |
| PDL-ER-17 | Rollback | Expand compatibility window, затем one-way UUID cutover с проверенным backup/recovery point. | После пятого ЭР lossless downgrade запрещён; rollback после cutover выполняется только restore к объявленной точке. |
| PDL-ER-18 | Источник данных секционирования | `Lmax`, токовые и пусковые характеристики берутся только из официального каталога или утверждённой методики производителя ТЛТ. | XLSX или код не становятся источником истины без подтверждённого происхождения. Перед Phase 4 источник регистрируется с названием, версией, датой и страницей/строкой. |
| PDL-ER-19 | Неполные данные каталога | Если для комбинации условий отсутствует хотя бы одно обязательное значение, секции не рассчитываются. | Возвращается диагностируемая ошибка с `error_code`; запрещены defaults, интерполяция ближайшей марки и подмена данными другого кабеля. |
| PDL-ER-20 | Допустимый ток `Iдоп` | `Iдоп`, А, задаётся отдельным утверждённым значением для марки кабеля и напряжения. | Нельзя неявно выводить `Iдоп` из номинала автомата или использовать одно глобальное значение. |
| PDL-ER-21 | Стартовый ток | Источник хранит непосредственный удельный стартовый ток `Iст.уд`, А/м. | В Phase 4 не вводится общий `kпуск` и не вычисляется `Iст.уд` из рабочего тока без нового продуктового решения и независимого oracle. |
| PDL-ER-22 | Температура холодного пуска | Для выбора каталожных ограничений используется расчётная минимальная температура конкретного объекта/климата. | Температура в °C входит в ключ выбора строки данных и сохраняется в traceability результата; температура поддержания её не заменяет. |
| PDL-ER-23 | Напряжение | Ограничения секции задаются и проверяются отдельно для каждого напряжения. | Нельзя переносить `Lmax`, `Iдоп` или `Iст.уд` между напряжениями либо нормализовать их к одному напряжению. |
| PDL-ER-24 | Округление `Lогр` | Округление вниз выполняется только по правилу официального каталога/методики. | Если источник не задаёт точность или шаг округления, применяется PDL-ER-19 и расчёт блокируется; неявное округление до целого метра запрещено. |
| PDL-ER-25 | Scope Phase 4 | Новый алгоритм секционирования Phase 4 применяется только к саморегулирующемуся кабелю. | Существующий резистивный flow сохраняется без притворного применения нового section contract; MI/skin остаются unsupported до отдельных методик. |
| PDL-ER-26 | Guest persistence и TTL | Временное хранение гостевого проекта в PostgreSQL разрешено на 3 дня с момента последней активности, со строгой изоляцией по guest session и автоматическим удалением после TTL. Валидная сохранённая в браузере guest session восстанавливает тот же временный проект; после expiry UI явно сообщает об окончании сессии и создаёт новый пустой проект, а старый можно восстановить только из локального project-файла. | Это не считается постоянным сохранением проекта в аккаунте. Нужны sliding-expiry, cleanup, recovery в пределах TTL, explicit expiry UX и negative tests против cross-session access; текущие 20 минут являются несоответствием реализации. |
| PDL-ER-27 | Масштаб и производительность | Целевой продуктовый лимит — 500 объектов на проект и 5 ЭР. Текущий предел 50 повышается только после performance-проверки импорта, batch-расчёта, таблиц, спецификации и отчёта; расчёт 500 объектов и спецификация одного ЭР должны укладываться в 30 секунд на минимальной конфигурации PDF. | Нельзя объявлять поддержку 500 только изменением константы. До зелёного performance gate 50 остаётся rollout guard, а требование 500 — незавершённым контрактом. |
| PDL-ER-28 | Фактический источник Phase 4 | Для Phase 4 должен быть предоставлен официальный каталог/«Таблица Виктора» с `Lmax`, `Iдоп`, прямым `Iст.уд`, напряжением, температурой холодного пуска и правилом округления. Имеющиеся PDF/XLSX не считаются заменой отсутствующих значений. | Выбор источника закрыт, но data blocker не снят: до регистрации самого артефакта с версией и точными строками/страницами Phase 4 остаётся blocked PDL-ER-15/18/28. |
| PDL-ER-29 | Канонический режим спецификации | Целевой продукт использует один автоматический **full data-driven BOM по PDF**. `basic` не остаётся пользовательским режимом: он допустим только как внутренний переходный compatibility path во время expand-window и удаляется в Phase 6. | UI/API не предлагают переключатель `basic/full` и не выдают разные закупочные количества для одного входа. Legacy basic-result не считается актуальной Phase 5 specification и мигрирует в stale/not-generated по доказанному правилу. |
| PDL-ER-30 | Поддерживаемая ширина UI | Рабочий интерактивный flow официально поддерживается при ширине от `1280 px`; полноценный mobile workflow не входит в Phase 5. На меньшей ширине показывается понятное предупреждение, а browser print остаётся адаптивным. | Phase 5 нельзя блокировать отсутствием mobile `390 px`, но desktop layout обязан пройти verifier без clipping/overflow/overlap. Малый viewport не должен притворно считаться поддержанным; print CSS проверяется отдельно. |
| PDL-ER-31 | Семантика `Rгр` | `Rгр` — отдельный коэффициент горячего резервирования с project-default `1.0`, а не закупочный запас 10% из PDL-ER-02. Он влияет только на явно зарегистрированные правила каталога/формулы и не умножает весь BOM глобально. | Snapshot generation settings хранит `Rгр` отдельно от order reserve. Диапазон/допустимые значения валидируются по источнику; отсутствие явной связи правила с `Rгр` означает, что коэффициент к этой позиции не применяется. |
| PDL-ER-32 | Неполные методики BOM | Для ёмкостей и резистивного кабеля в specification включаются только позиции с доказанной формулой/источником. Pipe-формулы нельзя переносить на tank, а self-reg accessories — на resistive. Недоказанные группы исключаются с диагностикой; результат имеет `partial`, а не успешный full-status, и требует явного подтверждения. | Достоверный кабель и другие независимо доказанные позиции не теряются. API возвращает исключённые группы/объекты и error codes; UI не маскирует неполноту и не создаёт приблизительные закупочные позиции. |
| PDL-ER-33 | Идентичность номенклатуры и выбор позиции | `mark`, `nomenclature_code`, `temperature_group` и применимость берутся из явных полей утверждённого каталога. Запрещены вывод по префиксу/суффиксу и выбор по порядку строк. При нескольких применимых позициях каталог задаёт ровно один default либо пользователь делает явный выбор, который попадает в settings snapshot. | Отсутствующий код/группа/default даёт диагностируемый fail/choice-required, а не выдуманную марку. Round trip и отчёт сохраняют точную catalog identity/source version. |
| PDL-ER-34 | Приоритет источника спецификации | Для состава, семантики, входов и формул specification PDF от 07.07.2026 всегда является главным источником. XLSX может поставлять только справочные/каталожные значения для правила, предусмотренного PDF или отдельно утверждённого новым контрактом. Формула, существующая только в XLSX, автоматически в Phase 5 не переносится. | PDL-ER-34 уточняет PDL-ER-16. Legacy XLSX-builder и его golden не являются oracle Phase 5; любое XLSX-only правило требует отдельного source mapping/PDL, иначе позиция исключается с диагностикой и partial-status. |
| PDL-ER-35 | Условия коробок `Ex/Rгр` | Значения условий `Ex` и `Rгр` по каждой строке коробки должны быть предоставлены официальным источником. Пока матрицы нет, зависимые коробки не рассчитываются; пропуск нельзя трактовать как `не используется` и нельзя молча заполнять из старого XLSX. | Это data blocker затронутых BOM-позиций, а не разрешение на default. Нужны source/version/row traceability и golden/boundary cases после получения таблицы. |
| PDL-ER-36 | UX partial multi-ЭР generation | До записи система выполняет preflight всех явно выбранных ЭР и показывает одно окно со списком/count исключений отдельно по каждому ЭР. Одно подтверждение запускает одну атомарную транзакцию выбранного списка; отмена не меняет ни одной specification. | PDL-ER-36 уточняет PDL-ER-14. Internal failure откатывает весь список; подтверждённые business exclusions остаются per-ЭР diagnostics и не смешиваются с transaction failure. |
| PDL-ER-37 | Представление stale specification | Последний stale snapshot можно просматривать только read-only с явной красной пометкой. Он исключается из успешных итогов, browser print, отчётов и server exports; актуальный документ требует явной regeneration. | Нельзя выдавать stale quantities как закупочный результат даже с неочевидным banner. API/preview/export имеют единый status gate; manual items не маскируют stale auto-part. |
| PDL-ER-38 | Группировка BOM по умолчанию | По умолчанию specification разделена на `Трубопроводы`, `Ёмкости` и `Общие материалы`. Пользователь может выбрать объединение; одинаковые позиции суммируются только после отдельного расчёта по типам и только при совпадении catalog base и nomenclature code. | Настройка хранится как project default и generation snapshot. Объединение меняет представление/агрегацию, но не подменяет формулы разных типов объектов. |
| PDL-ER-39 | Multi-ЭР report | Пользователь передаёт явный список UUID ЭР. Формируется один отчёт с независимой главой и specification каждого выбранного ЭР; успешные суммы разных ЭР не объединяются. Ошибки, stale/unsupported и подтверждённые исключения показываются отдельными диагностическими разделами. | Report preview/job не берёт active/localStorage selection неявно. Названия ЭР читаются по UUID; ни таблицы, ни итоги, ни спецификации разных ЭР не смешиваются. |
| PDL-ER-40 | Scope оформления отчёта Phase 5 | Отсутствие финального корпоративного шаблона не блокирует Phase 5. Принимаются функциональный HTML preview и browser print; логотипы, подписи, фирменные шрифты, колонтитулы и финальная корпоративная вёрстка остаются отдельным report brief. | Phase 5 требует корректного состава, no-mixing, diagnostics, accessibility и print CSS. Текущий шаблон не объявляется окончательным корпоративным артефактом; Q-04…Q-25 продолжают блокировать только соответствующую финальную приёмку employee exports. |
| PDL-ER-41 | CSV v3 compatibility и trust | Project export после Phase 5 создаётся только в v3. V2 остаётся import-only boundary adapter до отдельного решения об удалении. При несовпадении/отсутствии formula или catalog version граф и inputs восстанавливаются, но calculations/sections/specifications помечаются `stale`/`unsupported`, а не актуальными. Guest import с manual BOM rows отклоняется атомарно. | Нельзя экспортировать новый state обратно в lossy v2, доверять импортированному calculated snapshot без доступного source contract или обходить guest manual-write RBAC через файл. Ошибки не приводят к silent drop и не заменяют текущий проект. |
| PDL-ER-42 | Guest «не в БД» vs session | Уточняет PDL-ER-26: формулировка PDF «данные не сохраняются в БД системы» означает **нет постоянного проекта в аккаунте / нет «Мои проекты» для гостя**, а **не** запрет временного server-side store. Канон: PostgreSQL guest session + 1 temp project + TTL 3 дня + file save/open. | Документация/Home/SRS не должны обещать «только localStorage без сервера». Acceptance: session isolation, TTL cleanup, no cross-session; file — перенос между сессиями. Не считать session Postgres нарушением PDF guest case. |
| PDL-ER-43 | Home: 2 vs 3 входа | PDF §4 описывает инженерный guest/employee path (`Начать без регистрации` / `Войти с паролем`). **Третья карточка «Администратор» утверждена** как отдельный system role (не engineering MVP). | UI Home: 3 role cards — PASS. Не требовать удаление admin entry «ради 1:1 PDF». PDF-GUEST-02 в матрицах трактовать: два **инженерных** действия + admin entry вне guest case scope. |
| PDL-ER-44 | Соединительные комплекты (после SEEDS) | После регистрации section-каталога (SEEDS) **PDF §7.10** — канон: по temp group **одна** позиция комплекта (catalog default **или** явный выбор инженера, PDL-ER-33); `qty = ceil(Nсек / sections_per_kit)`. Dual emission «КСН-1=ΣN и КСН-2=N×2 как end-kits» — legacy XLSX, **не** Phase 5 oracle. K2i/end-section kit, если нужен, — **отдельное** catalog rule/PDL, не подмена PDF «комплект на 2 секции». | Пока SEEDS пусты — fail-closed (не выдумывать Nсек). После SEEDS: переписать emission под pick-one + sections_per_kit; golden PDF 9/2→5; XLSX dual golden не блокируют. |
| PDL-ER-45 | IA vs макеты PDF 21/35/49/56 | Утверждена **текущая product IA**: wizard 4 шага (heat / electrical / specification / report), denser SC-03 tables, UUID ЭР chips, assignment panel. ## Дополнительные правила интерпретации

- `Выбрать все` в PDL-ER-01 — явное действие пользователя, а не скрытая
  автоматическая генерация.
- Резерв 10% и коммерческое округление в PDL-ER-02 должны иметь отдельные
  traceability fields; фактическая длина не перезаписывается заказной.
- PDL-ER-04 разрешает гостю автоматическую full generation, но не ослабляет
  ownership, rate-limit и ручные write permissions.
- PDL-ER-06 не требует миграции существующего `tank` в новый `barrel` enum.
- PDL-ER-07 требует versioned/snapshotted settings, чтобы результат можно было
  воспроизвести после изменения project defaults.
- PDL-ER-10 сильнее противоречащего PDF-предложения показать `Резистив` disabled:
  уже утверждённый и работающий резистивный расчёт нельзя отключать скрытой
  регрессией.
- Disabled в PDL-ER-11 относится к выбору `skin/mineral` как target, а не к
  доступности вкладки: migrated unsupported rows должны быть видимы и доступны
  confirmed unassign.
- PDL-ER-12 допускает 0 ЭР у проекта до успешного readiness initialization; после
  него проект всегда имеет 1…5 ЭР и ровно один active.
- PDL-ER-13 относится и к UUID lifecycle copy, и к legacy calculation-copy:
  target specification остаётся `not_generated`, а explicit запрос её
  regeneration отклоняется fail-closed до mutation.
- PDL-ER-15 блокирует только section/formula Phase 4 и зависимые от реальных
  секций BOM-фазы, но не DB/lifecycle/UUID/assignment infrastructure.
- PDL-ER-18…25 закрывают выбор семантики источника и обработки данных, но не
  подтверждают наличие числового каталога. Phase 4 остаётся заблокированной,
  пока официальный артефакт не предоставлен и не зарегистрирован в formula/data
  contract.
- PDL-ER-26 разрешает только временное server-side хранение гостевого проекта;
  оно не создаёт аккаунт, бессрочный проект или доступ другой guest session.
- PDL-ER-27 фиксирует целевой масштаб 500, но не разрешает повышать runtime limit
  без измеримого performance evidence по полному пользовательскому потоку.
- PDL-ER-28 подтверждает, что официальный numeric artifact нужно предоставить;
  само текстовое решение не содержит числовых данных и не снимает stop condition.
- PDL-ER-29 означает, что `basic` не является fallback при ошибке full BOM:
  ошибка/partial остаётся диагностируемой, а не маскируется упрощённым ответом.
- PDL-ER-31 не заменяет `installed × 1.1 → min_order_quantity → order_multiple`
  из PDF/PDL-ER-02 и не должен приводить к двойному резерву.
- PDL-ER-32/35 требуют fail-closed на уровне недоказанных BOM-групп, но
  разрешают явно подтверждённый partial с сохранением доказанных позиций.
- PDL-ER-33 запрещает зависимость бизнес-результата от порядка строк JSON/XLSX.
- PDL-ER-34 означает, что молчание PDF не превращает XLSX-only формулу в
  утверждённое правило specification.
- PDL-ER-36 требует, чтобы preflight не имел side effects и использовал тот же
  snapshot/version, который затем атомарно подтверждается generation.
- PDL-ER-37 запрещает stale не только в итогах UI, но и во всех печатных и
  файловых представлениях.
- PDL-ER-38 не разрешает суммировать одинаковое название без совпадающего
  catalog base + nomenclature code.
- PDL-ER-39/40 закрывают функциональный scope Phase 5 report, но не утверждают
  отсутствующий корпоративный шаблон employee exports.
- PDL-ER-41 сохраняет v2 только как входной migration adapter; numeric slot не
  возвращается в authoritative domain model.
- PDL-ER-42 закрывает CONFLICT «PDF не в БД»: session store = temp, не account.
- PDL-ER-43: admin Home card — утверждённый system entry, не drift guest PDF.
- PDL-ER-44: kit BOM после SEEDS = PDF pick-one; не dual XLSX без нового PDL.
- PDL-ER-45: mock PNG PDF ≠ wireframe acceptance; IA = текущий wizard.

## Что этими решениями не разрешено

Продуктовые вопросы guest persistence/TTL, целевого лимита 500 объектов,
контракта Phase 5 и PROD-01…04 (PDL-ER-42…45) закрыты PDL-ER-26/27,
PDL-ER-29…41 и PDL-ER-42…45. Реализация ER5 residual / import confirm / 500
gate / Phase 6 execute — отдельные CODE-пункты `STATUS.md`. Внешними data
deliverables остаются:

- официальный section-каталог для PDL-ER-15, PDL-ER-18…24 и PDL-ER-28;
- официальная матрица условий коробок `Ex/Rгр` для PDL-ER-35;
- отдельные подтверждённые методики аксессуаров ёмкости/резистивного кабеля,
  если от Phase 5 требуется результат шире partial-контракта PDL-ER-32.

Финальная корпоративная вёрстка employee exports отложена PDL-ER-40 и требует
отдельного report brief. Удаление v2 import adapter требует нового явного
решения; PDL-ER-41 само по себе его не разрешает.
