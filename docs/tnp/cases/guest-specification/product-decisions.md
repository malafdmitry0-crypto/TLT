# Product Decision Log — динамические ЭР и гостевая спецификация

Дата фиксации: **18.07.2026**.

Источник решения: явные ответы пользователя в текущем диалоге после аудита
PDF редакции 4 от 07.07.2026. Эти решения являются целевым продуктовым
контрактом для будущей ветки динамических ЭР и сильнее расходящихся legacy SRS,
кода и golden-тестов. Изменять их можно только новым явным продуктовым решением.

| ID | Тема | Утверждённое решение | Следствие для реализации и приёмки |
|---|---|---|---|
| PDL-ER-01 | Scope генерации спецификации | Пользователь выбирает один или несколько ЭР; UI также даёт действие `Выбрать все`. | Никакой неявной генерации всех ЭР. API принимает явный список UUID, валидирует единый проект и определяет атомарность/partial result. |
| PDL-ER-02 | Количество кабеля в закупочном BOM | Используется **заказная длина**: фактическая длина с резервом 10% и коммерческим округлением. `Lсек × Nсек` хранится отдельно как фактическая инженерная величина. | В модели и отчёте трассируются обе длины. Закупочная позиция использует только утверждённую заказную длину; тесты не должны смешивать две величины. |
| PDL-ER-03 | Ручное изменение секций | Прямое изменение длины, количества и состава секций запрещено. Пользователь может менять разрешённые параметры — марку кабеля и навив/шаг; секции после этого пересчитываются автоматически. | UI не предоставляет прямой section editor. Пересчёт секций и зависимых итогов выполняется атомарно, ошибки сохраняются структурированно. |
| PDL-ER-04 | BOM для гостя | Гостю доступен **полный BOM по PDF**. Ручное добавление, удаление и редактирование позиций остаётся только сотруднику/администратору. | Guest больше не получает `403` для утверждённой full generation. Автоматический результат сохраняется в его временном проекте; write API ручных строк защищён backend RBAC. |
| PDL-ER-05 | Отчёт гостя | Гостю доступны HTML-предпросмотр и печать средствами браузера. Серверные экспорты PDF/DOCX/XLSX доступны только сотруднику/администратору. | Нужны доступная кнопка/действие печати и print CSS. Guest export endpoints остаются закрыты backend RBAC. |
| PDL-ER-06 | Типы объектов MVP | Поддерживаются `Трубопровод` и `Ёмкость`. `Бочка` — синоним/пользовательское название ёмкости, а не отдельный backend type. | Канонические backend/import keys остаются `pipe` и `tank`; `barrel` не создаёт третью доменную сущность. `Пол` не входит в MVP и может отображаться только как disabled future option. |
| PDL-ER-07 | Scope настроек спецификации | Настройки хранятся как project defaults. При каждой генерации сохраняется snapshot и настройки применяются только к явно выбранным ЭР. | Сохранение defaults не перегенерирует все ЭР автоматически. Спецификации с отличающимся snapshot помечаются stale; выбранные ЭР регенерируются явно. |
| PDL-ER-08 | Порог диаметра коробок | Граница включительная: `dтр ≥ 57 мм`. | Ровно 57 мм относится к ветке большого диаметра; обязательны boundary tests ниже, ровно и выше 57 мм. |

## Дополнительные правила интерпретации

- `Выбрать все` в PDL-ER-01 — явное действие пользователя, а не скрытая
  автоматическая генерация.
- Резерв 10% и коммерческое округление в PDL-ER-02 должны иметь отдельные
  traceability fields; фактическая длина не перезаписывается заказной.
- PDL-ER-04 разрешает гостю автоматическую full generation, но не ослабляет
  ownership, rate-limit и ручные write permissions.
- PDL-ER-06 не требует миграции существующего `tank` в новый `barrel` enum.
- PDL-ER-07 требует versioned/snapshotted settings, чтобы результат можно было
  воспроизвести после изменения project defaults.

## Что этими решениями не разрешено

Отдельными решениями остаются guest persistence/TTL (`3 дня` против текущих
`20 минут` и вопрос временного хранения в PostgreSQL), политика duplicate names
ЭР, точная rollback-стратегия необратимой миграции и копирование готовой
спецификации при `Создать на основании`. Эти вопросы нельзя считать решёнными
на основании PDL-ER-01…08.
