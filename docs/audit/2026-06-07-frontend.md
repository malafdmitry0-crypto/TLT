## СИЛЬНЫЕ СТОРОНЫ

### 1. Образцовая строгость TypeScript
`tsconfig.json`: `strict: true` + `noUnusedLocals` + `noUnusedParameters` +
`noFallthroughCasesInSwitch`. **0** вхождений `any`/`as any`/`@ts-ignore` на 235
файлов — редкость для проекта такого размера. Основная масса `as`-кастов (88 в
`utils/objectWizardUtils.ts`) — структурно неизбежный мост «динамическая форма
AntD ↔ типизированный API payload». Path-alias `@/*` в tsconfig и vite.

### 2. Чистое разделение слоёв, нет god-компонентов «со всей логикой»
Слои разведены: `pages/` (111), `components/` (57), `hooks/`, `api/` (10),
`store/` (4), `types/` (6), `domain/` (4), `utils/` (28). Крупнейшие файлы
(`ElecCalcPage.tsx` 1596, `FormulasPage.tsx` 1475, `HeatCalcNormalGlideGrid.tsx`
1264, `HeatCalcPage.tsx` 968) держат лишь **4–5** `useState` — вся логика вынесена
в feature-хуки и под-компоненты. Это оркестраторы, а не свалки состояния. Логика
колонок вынесена в registry-утилиты (`heatCalcFieldRegistry.ts`, `*TableColumns.ts`)
— единый источник правды.

### 3. Зрелый API-слой (`api/client.ts`)
Типобезопасные обёртки (`apiClient.post<HeatLossResponse>`). Interceptors:
**silent refresh** JWT для employee/admin (single-flight дедуп), **авто-восстановление
guest-сессии** при 401 (single-flight), **сетевой retry** с backoff `[200,500,1200]`
только для идемпотентных методов, очистка устаревшего проекта на 403 `/projects/`.
CSRF-токен только на мутации; `X-Request-Id` на каждый запрос; идемпотентность через
`withIdempotencyKey`. Нормализация ошибок FastAPI (string / Pydantic-массив / объект
`{code,message}`) в единый `ApiError`.

### 4. Грамотная граница server-state / client-state
Zustand-сторы намеренно крошечные: `authStore` (101 стр), `projectStore` (20 стр —
только `currentProject`), `calculationVariantStore` (37), `workspaceHeaderStore` (19).
Серверные данные — в TanStack Query. QueryClient осознанно настроен (`retry: 1`,
`refetchOnWindowFocus: false`, `staleTime: 30s` + точечные переопределения).
Инвалидация явная и локализованная (16 файлов с `invalidateQueries`), без глобального
`clear()`.

### 5. Полный code-splitting
`routes/index.tsx`: **все 18** страниц/layout через `React.lazy` + `Suspense`.
`vite.config.ts` `manualChunks`: react-vendor / query-vendor / dnd-vendor разнесены
для стабильного кэширования вендоров.

### 6. Корректное решение race-condition гидратации
`authStore.readInitialState()` читает localStorage **синхронно при импорте модуля**,
до первого рендера — закрывает баг редиректа `ProtectedRoute` при reload
(зафиксирован в pitfalls.md). Архитектурное решение, не костыль с `useEffect`.

### 7. Доказуемая a11y-дисциплина с CI-gate
`e2e/tests/accessibility.spec.ts` — axe-core gate (`@axe-core/playwright`,
`wcag2a/2aa/21a/21aa`), падающий на `critical`/`serious`, на **двух вьюпортах**
(desktop 1440×900 и mobile 390×844). `auditKeyboardFocus()` программно жмёт Tab до
35 раз, ловит фокус на невидимом элементе. A11y не декларируется, а проверяется.

### 8. Активное focus-management больших таблиц
`useFocusableTableScrollRegions.ts` навешивает `tabIndex=0` + `aria-label` на
`.ant-table-body` (WCAG 2.1.1, scrollable-region-focusable), MutationObserver с
rAF-коалесингом — без удара по hot-path ввода. `role="status"` + `aria-live="polite"`
для динамического статуса (`ElecCalcCandidateCompareBar`, `HeatCalcSelectedRowErrorsOverlay`).

### 9. Отличный UX ошибок электрорасчёта
`utils/electricalErrorGuidance.ts` классифицирует ошибки бэкенда
(`MISSING_TANK_LAYOUT`, `POWER_TOO_HIGH`, `TEMPERATURE_TOO_HIGH`,
`RESISTIVE_SECTION_NOT_FOUND`) в типизированные `suggestedActions` (`TRY_2_THREADS`,
`TRY_RESISTIVE`, `CHECK_PROCESS_TEMPERATURE`…). Пользователь видит не стектрейс, а
конкретные действия.

### 10. Глубокое и сфокусированное тестовое покрытие
166 файлов / ~907 тестов на правильных местах: `objectWizardUtils` (мм↔м),
`validators`, `calcStatus`, `electricalErrorGuidance`, движки таблиц, inline-edit,
clipboard, RBAC. 21 e2e spec / ~94 теста покрывают auth, projects, csv round-trip,
heat/elec calc, cable-business-flows, specification, reports, admin, матрицу
видимости SC-03, accessibility, visual/layout regression.

### 11. Единообразные empty-states, подтверждения, локаль
`EmptyProjectState` на 4 страницах. Деструктивные действия защищены `Popconfirm`/
`Modal.confirm` с `danger`/`okType:'danger'` и динамическим текстом. AntD
`ConfigProvider locale={ruRU}`. 44 вхождения loading-фидбека в pages.

## СЛАБЫЕ СТОРОНЫ

### ✅ ВЫСОКАЯ — Полное отсутствие ErrorBoundary / fallback UI — ИСПРАВЛЕНО (2026-06-07)
**Закрыто.** Добавлен `components/common/ErrorBoundary.tsx` (классовый — вынужденное
исключение из правила «только FC», т.к. `getDerivedStateFromError`/`componentDidCatch`
доступны только в классах). Подключение в трёх уровнях:
- **корневая граница** в `App.tsx` — последний рубеж (сбои lazy-чанков, роутер);
- **route-scoped `RouteErrorBoundary`** в `MainLayout` и `AdminLayout` — при ошибке
  страницы каркас (шапка/навигация/меню проекта) выживает, а переход на другой
  маршрут автоматически снимает экран ошибки (сброс по `location.pathname`).

Fallback — AntD `Result` с кнопками «Попробовать снова» (сброс границы без reload) и
«Перезагрузить страницу»; в dev показывается текст ошибки. Сбой логируется в ту же
телеметрию `clientAudit` (`frontend.render.error_boundary`, severity `critical`).
Покрыто тестом `ErrorBoundary.test.tsx` (4 кейса: рендер, fallback+телеметрия,
recovery, сброс при навигации). Белый экран с потерей ввода устранён.

**Исходная проблема (для истории):** `App.tsx` был `return <AppRoutes />` без обёртки;
grep по `ErrorBoundary|componentDidCatch|getDerivedStateFromError|react-error-boundary` →
**0** во всём `frontend/`.
- **Последствие:** любая неперехваченная ошибка рендера (неожиданная форма данных
  API в таблице, баг в glide-grid, расхождение `as`-каста с реальной структурой)
  роняет **весь** React-tree в белый экран. Пользователь теряет несохранённый ввод
  формы SC-03 без объяснения. `clientAudit.ts:147` ловит `window.error`/
  `unhandledrejection`, но это **только телеметрия** — UI-восстановления нет.
- **Зона риска усугубляется** двойными кастами `as unknown as` (9 вхождений:
  `heatCalcInlineEdit.ts:195-196`, `ObjectWizard.tsx:429-430`, `ConfirmStep.tsx:48-50`,
  grid-event-касты) — они отключают проверку типов, и рантайм-ошибка всплывёт именно
  там, где нет boundary.
- **Рекомендация:** добавить корневой ErrorBoundary с fallback и reload, лучше —
  гранулярные boundaries вокруг тяжёлых таблиц/форм. Это #1 пробел фронтенда.

### 🟠 СРЕДНЯЯ — `as unknown as` на стыке форм и типов (9 вхождений)
`heatCalcInlineEdit.ts:195-196`, `ObjectWizard.tsx:429-430`, `ConfirmStep.tsx:48-50`
(form values → `PipeFormValues`/`TankFormValues`), event-касты в grid
(`HeatCalcGlideGrid.tsx:88`, `EditableTableCell.tsx:96`,
`useHeatCalcTableColumns.tsx:465`). Двойной каст полностью отключает компилятор:
расхождение `PipeFormValues` с реальной AntD-формой не поймается до рантайма.
Локализовано, но требует дисциплины (связано с отсутствием ErrorBoundary выше).

### 🟠 СРЕДНЯЯ — Документация `frontend/CLAUDE.md` рассинхронизирована
В стеке заявлены `xlsx (SheetJS)`, `React Hook Form`, `Zod` — но **0** импортов

### 🟡 НИЗКАЯ — Концентрированное дублирование инфраструктуры таблиц
Параллельные зеркальные стеки heatcalc/electrical: `heatCalcTableColumns.ts` (586) /
`electricalTableColumns.ts` (418); три `ColumnSettingsModal` (694 + 631 + 450); три
`*GlideGrid` (1264 + 675 + 471). ~3000+ строк потенциально общей инфраструктуры
«настройка/видимость/ширина/порядок колонок + glide-grid» реализовано трижды.
Обобщённый `<DataGrid columnsRegistry=... settings=.../>` сократил бы поверхность
поддержки. Работает, но дорого в сопровождении.

### 🟡 НИЗКАЯ — Нет undo для деструктивных операций
Grep `undo|откат` → **0**. Защита только forward (`Popconfirm`/`Modal.confirm`).
После подтверждённого удаления строки/папки/объекта отката нет. Для Excel-подобного
UX больших таблиц undo был бы ценным (косвенно признано в Q-B
`current-status-and-missing-info.md`).

### 🟡 НИЗКАЯ — i18n структурно невозможен без рефакторинга
i18n-библиотек нет — **сознательное решение** (`frontend/CLAUDE.md`: «только русский»).
Русские строки хардкожены в JSX по всему коду. Для текущих требований
(русскоязычный on-premise) — **не дефект**, но добавление второго языка потребует
сплошного рефакторинга 100+ файлов. Слабость готовности к мультиязычности.

### 🟡 НИЗКАЯ — Прочие наблюдения
- `getCableOptions` возвращает `Promise<unknown[]>` (`calculations.ts:43`) —
  единичный пробел в типизированном API-слое.
- `projectStore` персистит весь `currentProject` (server-state) в localStorage;
  риск устаревания частично закрыт interceptor'ом на 401/403.
- a11y-gate фильтрует только `critical`/`serious`, пропуская `moderate`/`minor`
  (контраст кастомных тёмных акцентов #1a5276/#2e86c1 не покрыт явными тестами).
- Два канала фидбека (111 `message.*`/`notification.*` + 11 `<Alert>`) без явной
  единой политики «toast vs inline».
- Версии зависимостей опережающие (`vite ^8`, `vitest ^4`) — на грани bleeding edge.

## Итог

Фронтенд — **выше среднего по зрелости**. Сильнейшее: дисциплина типизации (ноль
`any`/`ts-ignore` на 44k строк), правильная граница TanStack Query / Zustand,
продуманный API-клиент (silent refresh, guest-recovery, idempotency, retry,
нормализация ошибок), полный lazy-routing, отсутствие god-компонентов, доказуемая
a11y с CI-gate на двух вьюпортах, отличный UX-гайд при провале электрорасчёта,
глубокое тестовое покрытие (166/~907 unit, 21/~94 e2e).

**Приоритет улучшений:**
1. **Добавить ErrorBoundary** — единственный заметный архитектурный пробел; одна
   ошибка рендера = белый экран с потерей ввода.
2. Приструнить `as unknown as` на стыке форм/типов.
3. Добавить Skeleton-загрузчики для тяжёлых таблиц.
4. Синхронизировать `frontend/CLAUDE.md` с реальным стеком.
5. (Долгосрочно) обобщить тройное дублирование grid/column-settings.
