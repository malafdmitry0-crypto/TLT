# Детальный разбор: «N без навива» (самрег) и шаг U (резистив)

**Дата:** 2026-06-07
**Повод:** в VSDX «Самрег трубы» число ниток `N = ОКРУГЛ.ВВЕРХ(PОб / Pi.ном(T3))`
— **без** коэффициента навива; код делит на `q_б · winding_coefficient · threads`.
Вопрос: реальный ли это баг в числе ниток / длине кабеля?
**Вердикт: НЕ баг.** Разбор ниже.

---

## 1. Что говорит первоисточник (VSDX, лист 1)

`Алгоритм Самрег.трубы.vsdx`:
- `Pi.ном(T3) = Q(i,1)·T3 + Q(i,2)` — уд. мощность кабеля, Вт/м.
- Условие подбора: `Pi(T3) >= PОб`.
- Число ниток: `N = ОКРУГЛ.ВВЕРХ(0) PОб / Pi.ном(T3)` — **коэф. навива в формуле не фигурирует.**
- В конце листа 1 — **«См. следующий лист»**, а лист 2 в `.vsdx` и PDF **отсутствует**.

Навив описан **отдельной** блок-схемой (`алгоритм навив.vsdx`) и задаёт только
**максимальный** `Kn` по диаметру (1.0…1.5) — это ограничение, а не цель.

## 2. Что делает код

`self_regulating.py`:
```
installed_linear_power(q_b, threads) = q_b · winding_coefficient · threads   # стр. 330
N (num_circuits) = ceil(q_required / (q_b · winding_coefficient))            # стр. 404 / 427
cable_length = base_length · winding_coefficient · num_circuits              # стр. 444
total_power  = q_b · cable_length                                            # стр. 446
current      = total_power / U                                               # стр. 461
q_required   = required_power_per_meter · safety_factor                      # стр. 321
```

`winding_coefficient` по умолчанию = **1.0** (`calculation_service.py:2361-2391`,
дефолт из вызова на стр. 2557): навив > 1 включается **только** если пользователь
явно задал шаг навива (`pitch`), тогда `k = √(1 + (π·D/pitch)²)`, ограниченный
`Kn_max(D)`.

## 3. Баланс мощности (доказательство корректности)

Доставленная мощность на 1 метр **трубы**:
```
P_доставл/м_трубы = total_power / base_length = q_b · k · N = installed_linear_power(q_b, N)
```
А по построению `N`: `q_b · k · N ≥ q_required`. Значит **доставленная мощность на
метр трубы всегда ≥ требуемой** — недогрева быть не может. `k` входит **один раз в
N** (уменьшает число ниток) и **один раз в длину** (увеличивает метраж) — это
физически согласовано (спираль = больше кабеля, но меньше ниток), **двойного учёта
нет**. `total_power = q_b · cable_length` — мощность реального уложенного кабеля,
`I = total_power/U` — её ток. Всё замкнуто корректно.

## 4. Когда код совпадает с VSDX, а когда расходится

| Случай | VSDX лист 1 | Код | Совпадение |
|---|---|---|---|
| **Навив не задан (k=1)** — основной сценарий | `N = ceil(PОб/q_б)` | `N = ceil(q_required/q_б)` | ✅ **совпадают** (с учётом единственного `safety_factor`) |
| **Навив задан (k>1)** | формула листа 1 `k` не учитывает | `N = ceil(q_required/(q_б·k))` | различаются (см. пример) |

**Пример** (PОб=30 Вт/м, q_б=20 Вт/м):
- `k=1`: VSDX `N=ceil(30/20)=2`; код `N=ceil(30/20)=2`. **Одинаково.**
- `k=1.5`: VSDX (лист 1) `N=2` прямых ниток (даёт 40 Вт/м, с запасом);
  код `N=ceil(30/30)=1` спиральная нитка (даёт ровно 30 Вт/м).
  Обе раскладки **покрывают** теплопотери; код экономичнее по метражу.

## 5. Вердикт по «N без навива»

**Это не баг.**
1. В **основном** пути (навив не задан, `k=1`) код **точно воспроизводит** VSDX.
2. При заданном навиве код **физически корректен**: `k` входит согласованно,
   баланс мощности соблюдён, **недогрев исключён**, двойного учёта нет.
3. Литеральная формула листа 1 не учитывает навив, потому что навив — **отдельная**
   процедура, а их взаимодействие, судя по «См. следующий лист», описано на
   **отсутствующем листе 2**.

**Остаточный риск (низкий):** литеральное взаимодействие «навив × N» из листа 2 не
подтверждено документом. Текущая реализация — разумная и безопасная инженерная
трактовка (никогда не недогревает). Закрыть полностью можно только получив **лист 2
алгоритма самрег**.

> Изначальное подозрение «реальный баг в числе ниток/длине» — **снято**. При навиве
> код даёт *меньше* кабеля, чем буквальная прямая раскладка VSDX, но всё ещё
> покрывает теплопотери; это оптимизация, а не ошибка.

## 6. Резистив: шаг снижения напряжения `U=U-1` vs `voltage_step=5`

`Алгоритм подбора резистив.vsdx`: при неуспехе подбора `U=U-1` (снижение по **1 В**).
Код (`resistive.py`, fallback в `formulas-summary.md`): `voltage_step=5`,
`min_adjusted=40`, `start=220`, `high=380`.

**Эффект:** код перебирает напряжения сеткой по 5 В (220, …, 40), VSDX — по 1 В.
Код может **пропустить** допустимое напряжение между узлами сетки и выбрать
чуть менее оптимальный вариант (большее сечение/другую схему), но результат всё
равно удовлетворяет ограничениям (`p2<p3`, `I≤65 A`). **Недо-/перегрева нет** —
это про оптимальность подбора, не про корректность.

**Серьёзность:** низкая. **Статус:** значения `voltage_step/min/start/high` в коде —
явный fallback (`docs/context/formulas-summary.md`), т.к. в первоисточнике нижняя
граница U и шаг (кроме `U-1`) не заданы числом.
**Рекомендация:** либо привести шаг к `1 В` (буквально по VSDX), либо
зафиксировать `5 В` как осознанное продуктовое решение в
`open-business-decisions.md`. До решения — оставить как fallback.

## 7. Итоговые действия
- «N без навива» — **не баг**, правок кода не требует. Запросить **лист 2** алгоритма
  самрег, чтобы подтвердить взаимодействие навив×N буквой документа.
- Шаг U резистива — низкий приоритет; решить `1 В` (по VSDX) vs `5 В` (текущий
  fallback) бизнес-решением.
- Оба пункта внесены в реестр (`knowledge-ledger.md §3c`).
