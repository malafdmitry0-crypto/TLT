## 2. Расчёт нагревательных секций — НОВОЕ ключевое требование

Это звено **отсутствует в текущем коде**: сейчас электрорасчёт считает нитки
(навив, `N_circuits`) и общую длину кабеля `L_каб`, но **не режет кабель на
нагревательные секции по предельной длине**. Заказчик описывает обязательный шаг.

### Суть
Нельзя сделать бесконечно длинную нитку греющего кабеля — у каждой марки есть
**максимальная длина нагревательной секции**. Для саморегулирующегося кабеля это
**список предельных длин по маркам** (передавался заказчиком — «таблица Виктора с
максимальными длинами нагревательных секций»).

### Алгоритм (дословно из записи)
```
Дано: L_каб — общая уложенная длина кабеля позиции (после навива/ниток), м
      L_max — максимальная длина одной нагревательной секции для выбранной марки, м

Шаг 1.  N_секц = ОКРУГЛ.ВВЕРХ(L_каб / L_max ; 0)      # число секций, целое вверх
Шаг 2.  L_секц = L_каб / N_секц                        # равные секции

Пример: L_каб = 120 м, L_max = 65 м
        N_секц = ОКРУГЛ.ВВЕРХ(120/65) = ОКРУГЛ.ВВЕРХ(1.846) = 2
        L_секц = 120 / 2 = 60 м  →  две равные секции по 60 м
```
**Важно:** деление **равномерное** (120 → 2×60), а **не** «65 + остаток 55».

### Граничные случаи [инж. поправка]
- `L_каб ≤ L_max` → `N_секц = 1` (без разбиения).
- Округление строго **вверх до целого** (`;0`); `2.1 → 3` (пример из записи).
- Расчёт **независим для каждой строки** электрорасчёта (у каждой позиции своё
  `N_секц`).

### Физический смысл предела и связь с током [инж. поправка]
Заказчик предлагает «для саморегулирующегося кабеля ввести ограничение и по токам».
С инженерной точки зрения это **одно и то же ограничение**, а не два:

- Предельная длина саморег-секции определяется **пусковым (холодным) током**
  кабеля при минимальной температуре пуска и напряжении питания — при холодном
  старте сопротивление минимально, ток максимален, и автомат/кабель ограничивают
  длину. Таблица «максимальных длин» — это уже **производная от пускового тока**
  (обычно при опорной T_пуска и 230 В).
- Поэтому корректная модель:
  `L_max = min(L_max_по_таблице, L_по_пусковому_току, L_по_падению_напряжения)`,
  а `N_секц = ОКРУГЛ.ВВЕРХ(L_каб / L_max)`.
- Для **резистивного** кабеля отсечка иная — по **максимальному рабочему току**
  (в коде `I ≤ 65 A`) и максимальной линейной мощности; длина секции выводится из
  сопротивления и напряжения. Это уже частично реализовано в `resistive.py`.

**Рекомендация:** хранить таблицу `L_max(марка, U, T_пуска)` как справочник (от
заказчика) и использовать её как первичный предел; ток/падение — как
дополнительная проверка. Это унифицирует саморег и резистив под одну формулу
`N_секц`.

## 3. Электрические параметры секции — требование к отображению

После разбиения на секции электрорасчёт должен показывать параметры **секции**, а
не всего кабеля:

- **Пусковой (стартовый) ток** секции, А.
- **Рабочий ток** секции, А.
- **Мощность секции**, Вт.

[инж. поправка] Формулы по секции:
```
P_секц = q_б(T3) × L_секц          # мощность одной секции, Вт   (q_б — уд. мощность марки)
I_раб  = P_секц / U                 # рабочий ток секции, А       (U = паспортное напряжение, см. §1 — 230 В)
I_пуск = I_раб × k_пуск(T_пуска)    # пусковой ток (холодный старт), k_пуск из паспорта марки (обычно ×2…×6)
```
`k_пуск` — паспортный коэффициент кратности пускового тока саморег-кабеля при
температуре пуска; для боевой версии нужен из справочника марок
**[уточнить у заказчика]** (в текущих JSON его нет).

**UI:** заказчик предлагает выбрать строку → снизу раскрывается дополнительная
таблица с параметрами секций этой позиции (число секций, пусковые/рабочие токи,
мощность). Допустимо и «всё в одной строке», но **информация о секциях обязательна**.

## 4. Температурные классы и выбор серии (ТТН/ТТВ/ТТХ → MI)

Каждая строка имеет температурные пределы процесса. Два параметра:
- **T1** = температура техпроцесса (постоянная).
- **T2** = температура **пропарки** (кратковременное превышение). Может
  **отсутствовать** — тогда в выборе не участвует.

Класс определяется по **обоим** параметрам — берётся более высокий из двух.

| Класс | T1 (техпроцесс), °C | T2 (пропарка), °C | Серия кабеля |
|---|---|---|---|
| Низкий | ≤ 65 | ≤ 85 | **ТТН** (N — низкотемпературный) |
| Средний | > 65 … ≤ 120 | ≤ 210 | **ТТВ** |
| Высокий | > 120 … ≤ 150 | ≤ 250 | **ТТХ** |
| Сверхвысокий | > 150 | > 250 | **резистивный с минеральной изоляцией (MI)** |

> Знаки `≤`/`>` в таблице — для читаемости диапазонов. **Поведение ровно на
> границе (65/120/150, 85/210/250) НЕ определено этой таблицей** и решается по
> `2026-06-07-temperature-class-boundary-decision.md` (по умолчанию — строгое `<`
> из VSDX).

Правила:
- `класс = max(класс_по_T1, класс_по_T2)`. Если хотя бы один параметр выше — класс
  повышается.
- Если `T1 > 150` **или** `T2 > 250` → программа должна **предложить кабель MI**
  (отдельная ветка расчёта, появится после стабилизации механики резистива).

**Граница на точных значениях (`<` vs `≤`) — НЕ решена аудио. ИСКЛЮЧЕНО.**
Ранее здесь была инженерная поправка: «заказчик вербально говорит "не более
65/120/210" → принимаем `≤` (включительно)». Эта поправка **отозвана**: вербальная
фраза в ASR-расшифровке слишком слаба, и **сам заказчик мог оговориться/ошибиться**.
Полное обоснование и действующее правило — в
`2026-06-07-temperature-class-boundary-decision.md`.

Действует: до явного бизнес-решения граница определяется **первоисточником VSDX =
строгое `<`**; расхождение код (`≤`) ↔ VSDX (`<`) на точках `T1∈{65,120,150}`,
`T2∈{85,210,250}` — **открытый дефект** (`Needs business decision`). **Значения**
пределов 65/85, 120/210, 150/250 не оспариваются; спорна только их
включительность на самой границе.

## 6. Формирование спецификации

Вход: по каждой строке электрорасчёта — **(а) число нагревательных секций `N_секц`**
и **(б) общая длина кабеля `L_каб`** (+ температурный класс, Ex, длины секций).

Алгоритм (подтверждает `spec-bom-oracle.md`):
- Таблица спецификации = **полный перечень возможных материалов**; проход
  построчно по номенклатуре, поиск соответствия в позициях расчёта (если марки в
  расчёте нет — позиция пропускается: «10 ТТН нет, 17 нет, 25 нет, 50 есть → берём»).
- **Греющий кабель** уже посчитан на этапе электрорасчёта (`L_каб`).
- **Соединительные комплекты заделки** — по температурному классу секции:
  **КСН** (низкотемпературные, серия ТТН) и **КСВ** (высокотемпературные, серии
  ТТВ/ТТХ). [уточнение: высокотемпературная заделка — **КСВ**, не «КСН».]
  ```
  Кол-во комплектов (класс) = Σ(i) N_секц(i, данного класса) × R,гр
  ```
  Пример: 2 низкотемпературные секции (ТТН) → 2 комплекта **КСН** (× резерв).
  По эталону: КСН-1/КСН-2 = `Fl1/Fl2`, КСВ-1/КСВ-2 = `Fl3/Fl4`
  (`spec-bom-oracle.md`).
- Коробки СКВ, хомуты, ленты, ЗИП — по формулам `spec-bom-oracle.md`, с учётом
  условий из диалога §5 (Ex, мин. длина секции).

## 7. Варианты (СО) — терминология

- **СО** = «спецификация оборудования» (не «система обогрева»).
- Варианты рождаются от **разных вариантов электрорасчёта** (авто-подбор, ручная
  правка марок и т.п.), а не от разных спецификаций. Спецификация —
  **детерминированное следствие** конкретного варианта электрорасчёта.
- [инж. поправка] Это уточняет формулировку в `CLAUDE.md` («Варианты системы
  обогрева CO1..CO4 через variant_number»): корректнее — «варианты электрорасчёта;
  каждому соответствует своя спецификация».

## 9. Открытые вопросы к заказчику

1. **Таблица максимальных длин секций** `L_max` по маркам саморега (U, T_пуска) —
   та самая «таблица Виктора»; в репозитории её пока нет.
2. **Коэффициент кратности пускового тока** `k_пуск` по маркам (для §3).
3. **`R,гр`** — значение по умолчанию и кто задаёт.
4. Точные **коды/артикулы** комплектов заделки (низко-/высокотемпературных) и
   вариантов коробок СКВ — из `Полный перечень продукции` (669 строк, в код не
   загружены).
5. Граница класса `<` vs `≤` на точных значениях (65/120/150, 85/210/250) —
   требуется **письменное** бизнес-решение (аудио исключено как основание, заказчик
   мог оговориться); по умолчанию действует VSDX `<`. См.
   `2026-06-07-temperature-class-boundary-decision.md`.
6. Запись обрывается — **нужна полная аудиозапись/продолжение** (коробки СКВ,
   резистивная ветка, MI описаны не до конца).

## Ответ на исходный вопрос «можем ли оформить спецификацию?»

С этим дополнением **методику** (алгоритм секций + температурные классы + поток
формирования + BOM) можно задокументировать и реализовать — данный файл это и
делает. **Полную боевую спецификацию с реальными артикулами и количествами** — пока
нет: блокируют 4 пункта данных из §9 (таблица `L_max`, `k_пуск`, номенклатура 669,
`R,гр`). Это вопросы к заказчику/данным, не к коду.
