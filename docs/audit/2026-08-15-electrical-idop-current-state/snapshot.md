# Электрический ТТ-расчёт: `I доп` и остальные величины — состояние на 2026-08-15

Это не нормативная документация и не описание желаемой системы. Это снимок фактической реализации на `HEAD a511d6c` с проверяемым candidate-изменением рабочего дерева.

## Краткий вывод

Дефект обязательного ручного `I доп` исправлен в candidate:

- пустое проектное значение (`null`) означает автоматический режим;
- в автоматическом режиме для каждого объекта берётся выбранная строка внутреннего каталога секционирования и вычисляется

  ```text
  I доп = L макс × I ст.уд
  ```

- сохранённое положительное число остаётся ручным ограничением и имеет приоритет;
- источник и фактически применённое значение возвращаются в результате расчёта;
- seed больше не создаёт магическое проектное значение `13.065 А`;
- существующие ненулевые значения не мигрируются и продолжают считаться ручными.

Это делает расчёт работоспособным без ручного заполнения `I доп`, но не превращает его в полноценный расчёт защитного аппарата: тип и номинал автоматического выключателя в системе отсутствуют. Поэтому итоговая оценка всей электрической ветки — не 100%.

## `I доп`: до и после

### До изменения (`HEAD a511d6c`)

- Label: `I доп проекта — допустимый стартовый ток одной секции, А`.
- Variable/API: `max_section_start_current_a`.
- Источник: только сохранённое проектное значение.
- Диапазон: `> 0`; `null` запрещал пересчёт.
- Seed принудительно сохранял `13.065 А`.
- Backend при `null` возвращал `SECTION_CURRENT_LIMIT_REQUIRED`.

Значение `13.065` не выводилось из марки, температуры, длины либо каталога. Это был технический default, а не расчёт.

### После изменения (candidate)

Режим `auto`:

```text
row = exact(cable_mark, Tcold)
   or nearest_colder(cable_mark, Tcold)

I доп = L макс(row) × I ст.уд(row)
source = section_catalog_derived
```

Режим `manual`:

```text
I доп = project.max_section_start_current_a
source = project_setting
```

Общие downstream-формулы:

```text
L ток = I доп / I ст.уд
L огр = floor_0.001(min(L макс, L ток))
N сек = ceil(L треб / L огр)
L сек = L огр
L факт = L сек × N сек
```

В автоматическом режиме по определению `L ток = L макс`, поэтому секционирование ограничивается `L макс` строки каталога. Это именно fallback «по максимальной длине», а не независимая проверка автомата.

### Пример

Для строки `30ТТВ2`, `−20 °C`:

```text
L макс = 95 м
I ст.уд = 0.195 А/м
I доп(auto) = 95 × 0.195 = 18.525 А
L ток = 18.525 / 0.195 = 95 м
```

### Трассировка результата

Фактически применённое значение остаётся числом для совместимости, а источник добавлен отдельно:

```json
{
  "section_plan": {
    "max_start_current_a": 18.525,
    "max_start_current_source": "section_catalog_derived"
  },
  "resolved_inputs": {
    "max_section_start_current_a": "18.525"
  },
  "input_sources": {
    "max_section_start_current_a": "section_catalog_derived"
  },
  "provenance": {
    "section_current_limit": {
      "value_a": 18.525,
      "source": "section_catalog_derived"
    }
  }
}
```

Для ручного режима source во всех этих местах — `project_setting`.

## Алгоритм трубы

```text
Heat result / object form
  q, K, Lbase, D, Tproduct, Tenv, Tcold
              │
Electrical overrides
  S, N or auto, manual full_mark, optional manual Iдоп
              │
              ▼
P_req = q × K
Kнав = 1  (прямая укладка)
     or sqrt(1 + (πD/S)²)
Lтреб = Lbase × Kнав × N
              │
              ▼
Выбор кабеля
  manual: exact full_mark
  auto: temperature gates → power gate → technical sort
              │
              ▼
Строка секционирования по mark + Tcold
  exact; иначе ближайшая более холодная
  → Lмакс, Iст.уд
              │
              ▼
Iдоп = manual project value
    or Lмакс × Iст.уд
Lток = Iдоп / Iст.уд
Lогр = floor(min(Lмакс, Lток), 0.001)
Nсек = ceil(Lтреб / Lогр)
Lсек = Lогр
Lфакт = Lсек × Nсек
              │
              ▼
Pсек = Pcable × Lсек
Iраб.сек = Pсек / U
Iст.сек = Iст.уд × Lсек
totals = section values × Nсек
Lorder = ceil(Lфакт × 1.10, 0.001)
```

## Алгоритм резервуара

Форма даёт:

- `shape`: `cylindrical` / `rectangular`;
- цилиндр: `diameter_mm=100…30000`;
- параллелепипед: `length_mm,width_mm=100…100000`;
- `heating_height≥0.001 м`;
- `laying_step=0.1…0.4 м`.

Расчёт базовой длины:

```text
perimeter = πD                    (цилиндр)
perimeter = 2 × (L + B)           (параллелепипед)

Lbase = (perimeter / 2) × heating_height / laying_step
```

Далее применяется тот же подбор кабеля и секционирование, что у трубы, но:

```text
Kнав = 1
pipe diameter / winding pitch запрещены
```

Тепловой запас не дублируется:

```text
q = (total_heat_loss_design / K) / Lbase
P_req = q × K
```

То есть `K` применяется ровно один раз. Эта ветка соответствует Case 1; старый документ «Алгоритм Самрег. трубы» резервуары не описывает.

## Что существует, но не участвует в текущем ТТ-расчёте

- `q1`, `q2`, `max_vapor_temp` из `cables_tt.json` — legacy metadata; температурная формула `Pл(T)=q1×T+q2` не используется.
- `maintain_temperature`, `vapor_temperature`, `steam_tracing`, `connection_type`, aggressive-product — исключены из текущего TT contract.
- `working_current_total_a` — legacy аргумент секционирования, не используется.
- `voltage` строки section catalog — не является критерием lookup; downstream используется проектное `U`.
- `Pст, кВт` из workbook — не возвращается runtime.
- Коммерческие minimum order/multiple, цена и срок — не участвуют; применяется только `technical_minimum`.

## Подтверждённые проблемы, из-за которых это не 100%

1. `Tmin` ошибочно выводится из минимальной температуры строк секционирования (`−40 °C`), хотя паспорт разрешает эксплуатацию до `−60 °C`.
2. Для ТТХ runtime использует `Tmax=150 °C`, паспорт — `205 °C`.
3. Признак `normal/aggressive` не выбирает оболочку. При одинаковых параметрах техническая сортировка склоняется к `-СР`; исходные XLSX/flowchart требуют `-СТ` для нормальной и `-СР` для агрессивной среды.
4. Паспортный `Lмакс` зависит от типа/номинала автомата, а этих входов нет. Например, для одной марки паспорт может давать разные длины при 16/20/32 А.
5. Auto-`Iдоп=Lмакс×Iст.уд` делает расчёт работоспособным, но математически сводит `Lток` к `Lмакс`; это не независимая защита.
6. `U=230 В` фиксировано проектом/UI. Case 1 называет U вводом пользователя, formula workbook использует 220 В, паспорт — 230 В.
7. Текущий Case 1 использует паспортную номинальную мощность; старый flowchart/XLSX использует температурную мощность. Нужен выбор единственного нормативного алгоритма.
8. Runtime всегда добавляет 10% к заказной длине. В спецификационном XLSX резерв `Rгр` задаёт пользователь.
9. Основная электрическая таблица не выводит рядом все колонки §6.14; часть значений доступна только в summary/expanded view.
10. Label `Мощность, Вт` конфликтует с formatter: при значении свыше 1000 UI показывает кВт.
11. Диапазон `K` различается между формой трубы, формой резервуара и direct API.
12. `Lbase` трубы фактически включает эквивалентную длину локальных элементов; §6.13 не фиксирует это явно.

## Ошибки и защитные отказы

- `SECTION_CURRENT_LIMIT_REQUIRED` остаётся только для явно переданного неположительного ручного значения; `null` больше не ошибка.
- Неизвестная марка или отсутствие exact/nearest-colder строки каталога завершают расчёт доменной ошибкой.
- `Tproduct>Tmax`, `Tenv<Tmin`, неположительные длины/мощности/напряжение и нарушения геометрии навива отклоняются до формирования результата.
- Final gate повторно проверяет баланс длин, мощностей и токов с допусками: `0.0005 м`, `0.01 Вт`, `0.001 А`.
- Изменён formula identity: `electrical-tt-v3-case1-r4` → `r5`; сохранённые старые результаты требуют пересчёта.
