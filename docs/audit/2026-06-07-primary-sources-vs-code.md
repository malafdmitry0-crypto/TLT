# Аудит: первоисточники (не-MD) ↔ код

**Дата:** 2026-06-07
**Назначение:** сверка бинарных первоисточников (ТЗ PDF, формулы DOCX, справочники
XLSX, алгоритмы VSDX/PDF, инженерный эталон спецификации) с реализацией и со слоем
конвертаций `docs/tnp/`. Основание приёмки — `docs/context/full-version-rule.md`.

## Метод и оговорка о доверии

Первичный разбор выполнен агентами (извлечение из бинарных Office-документов:
OMML-парсер для формул DOCX, openpyxl для XLSX, pypdf/Read для PDF, unzip для VSDX).
Высокоэффектные находки затем **перепроверены вручную по сырому XML/JSON** — это
важно: при автоизвлечении уже случались ошибки (см. REFUTED ниже). Каждая строка
помечена уровнем доверия: **[проверено]** = сверено лично по исходнику; **[агент]**
= по отчёту агента, лично не пересверено.

## Находки (по убыванию серьёзности)

### REFUTED — λ изоляции «тёплый режим» НЕ фабрикация [проверено]
**Первоначальная гипотеза агента:** warm-формулы `λ = a + b·tm` (колонка «20 и
выше») в `insulation.json`/`docs/tnp/internal-references/insulation.md` выдуманы,
т.к. в `Теплоизоляция.docx` эти ячейки пусты.
**Проверка по сырому XML (`word/document.xml`):** ячейки **не пусты** — они содержат
уравнения **OMML (Office MathML)**, которые `python-docx .text` молча отбрасывает.
В XML присутствуют ровно `0,045+0,00021×tm`, `0,049+0,0002×tm` и все 26 формул.
**Вывод:** конвертация и `insulation.json` **корректны**. Правка не требуется. Это
напоминание: DOCX-таблицы с формулами нельзя проверять через `.text` — только по
OMML. Урок для drift-аудита `docs/tnp` ↔ бинарь.

### CONFIRMED · Высокая · Каталог ТЛТ без первоисточника [проверено]
`cables_tlt.json` содержит 10 марок `ТЛТ-10…ТЛТ-100` (мощность = число марки,
`max_temperature=65`, `min_temperature=-40`, `voltage=220`). Поиск марки `ТЛТ-<число>`
по **всем** PDF/DOCX/XLSX/VSDX дал **0 совпадений**. Единственный «ТЛТ» в
первоисточниках — `Договор…ТЛТ_Инжиниринг.pdf` (название компании). Блок-схема
«Самрег трубы» и `docs/tnp/algorithms/self-regulating-pipe-selection.md` оперируют
только **ТТН/ТТВ/ТТХ** (0 упоминаний ТЛТ). Весь автоподбор ТЛТ (N=1..3, ранжирование,
потолок мощности) не выводится из предоставленных ТНП.
**Статус:** *Needs business decision* — либо ТЛТ это отдельная продуктовая линейка,
чей даташит не передан в репозиторий, либо синтетический placeholder.

### CONFIRMED · Средняя (широкий охват) · Напряжение 220 вместо 230 В [проверено]
Первоисточник qб задаёт ток как `I = (P)/(230)` (зафиксировано в конвертации
`pipe-heat-loss-and-cable-selection.md:125`, `tank-...:206`), а в
`Самрег характеристики.pdf` «230» встречается 6 раз, «220» — 0. В коде
`self_regulating.py` ток считается как `total_power / applied_voltage`, где
`applied_voltage = catalog voltage (ТЛТ=220) or supply_voltage` (обычно 220).
**Эффект:** ток завышен на ~`230/220 ≈ 4.5%` по всем самрег-веткам. Конвертация
верна (230), расходится **код**.

### CONFIRMED · Высокая · Спецификация: 6 generic vs условный BOM ~120 позиций [проверено]
`accessories.json` = **6** generic-позиций; `builder.py` добавляет кабель +
`list_basic_accessories()` с плоским `per_object * accessory_count`. Инженерный
эталон `Расчет_спецификации_трубы_самрег29_05_26.xlsx` (лист «Список материалов
Самрег», 192 строки) задаёт **условный BOM** с готовыми правилами (коробки СКВ по
Ø/Ex/К1i/К2i, КСН по темп-классу, хомуты/ленты/ЗИП по Ø, коэф. резерва `R,гр`,
`округл.вверх(L/150)`). Извлечённые правила → `docs/audit/spec-bom-oracle.md`.
**Это самый крупный функциональный разрыв** и одновременно готовый oracle.

значения 75/89/108 не покрыты ни одной веткой. Код

`<`); `formulas-summary.md` пишет `57<D<=75` — расходится с ТНП. → *Needs business
decision* по трактовке граничных диаметров.

## Вывод про deterministic oracle

**Независимого численного oracle теплопотерь среди первоисточников нет.**
`ТНП/Мой проект (копия).xlsx` — это экспорт самого приложения (подтверждает только
сам себя, не годится как эталон). Инженерный XLSX — это BOM-шаблон спецификации, а
не числовой расчёт теплопотерь. Значит текущий oracle (`qa-agent/.../registry.yaml`)
не привязан к независимому первоисточнику по теплопотерям — это **риск
циркулярности** (тесты могут подтверждать формулу самой формулой).
**Единственный извлекаемый из первоисточника oracle — спецификационный BOM** (см.
`spec-bom-oracle.md`).
