# Bug audit системы от 2026-05-08

## Краткий вывод

Система в текущем состоянии не проходит полный quality gate: frontend typecheck, frontend lint, frontend unit/integration tests и backend pytest проходят, но `make lint-backend` падает на форматировании одного backend-файла, а полный Playwright E2E прогон падает на 16 сценариях из 48.

Ключевой риск не в том, что вся функциональность обязательно сломана в runtime, а в том, что E2E-набор больше не соответствует актуальному UI после последних изменений теплового расчета. Из-за этого проверки не отделяют реальные регрессии от устаревших ожиданий и не могут служить надежным релизным барьером.

## Проверенный контур

- Docker-окружение поднято: `heatcalc_frontend`, `heatcalc_backend`, `heatcalc_db`, `heatcalc_redis` в состоянии `healthy`.
- Frontend: typecheck, lint, unit/integration tests.
- Backend: pytest и backend lint.
- E2E: полный Playwright-набор через Chrome against `http://localhost:3003` и API `http://localhost:8000`.
- Недавние изменения: последние 2 коммита в основном затрагивают `frontend/src/pages/HeatCalcPage.tsx`, `frontend/src/styles.css`, импорт/экспорт объектов, seed-скрипт и тесты теплового расчета.

## Найденные проблемы

### BLOCKER: полный Playwright-набор красный

Факт: полный E2E-прогон завершился с результатом `32 passed, 16 failed`.

Затронутые сценарии:

- `e2e/tests/cable-business-flows.spec.ts:227` ожидает локальную вкладку `Результаты расчёта`.
- `e2e/tests/heat-calculation.spec.ts:13` ожидает старый empty state `Объекты не добавлены`.
- `e2e/tests/heat-calculation.spec.ts:23`, `:24`, `:26` ожидают текстовые пункты выбора `Трубопровод` и `Резервуар`.
- `e2e/tests/heat-calculation.spec.ts:48`, `:64` ожидают вкладку `Результаты расчёта`.
- `e2e/tests/inline-form-dependencies.spec.ts:12`, `:20` открывают тип объекта через старый текстовый выбор.
- `e2e/tests/inline-form-dependencies.spec.ts:337` также ожидает вкладку `Результаты расчёта`.
- `e2e/tests/project-csv.spec.ts:30`, `:43`, `:78` используют слишком широкий селектор `/Скачать/i`.

Вероятная причина:

- UI теплового расчета был изменен: появились компактные кнопки типа объекта, кнопка добавления работает от активного типа, локальная вкладка результатов была убрана или перенесена в общий верхний workflow.
- Поведение сохранения тоже изменилось: после сохранения форма должна оставаться открытой, но переходить в режим добавления новой записи с дефолтными значениями. Один E2E-сценарий все еще ожидает, что в форме останется только что сохраненное имя.

Риск:

- E2E сейчас не является надежным сигналом. Часть падений похожа на устаревшие тесты, но на их фоне легко пропустить настоящую регрессию.
- Любой CI/CD, который запускает полный Playwright-набор, будет блокироваться.

Рекомендация:

- Обновить E2E под текущую модель UI:
  - тип объекта выбирать через доступные имена кнопок/aria-label, а не через `getByText('Трубопровод')`;
  - добавление объекта проверять через активный тип и кнопку `+`;
  - сценарии сохранения переписать под правило "после сохранения открыта новая запись с дефолтами";
  - проверки `Результаты расчёта` заменить на актуальный путь пользователя: общий верхний раздел расчета, таблицу источников или новый экран результатов, если он является продуктовым источником истины.

### BLOCKER: backend lint падает на форматировании

Факт: `make lint-backend` падает на `ruff format --check app`.

Файл:

- `backend/app/services/calculation_service.py`

Подтверждение:

- `ruff format --diff app/services/calculation_service.py` показывает, что форматтер хочет изменить многострочное выражение около расчета `effective_length` и перенос выражения `total_count` около `backend/app/services/calculation_service.py:635`.

Риск:

- Backend lint будет падать в CI, даже если логика работает корректно.

Рекомендация:

- Запустить форматирование только для затронутого файла или внести эквивалентную форматирующую правку:
  - `ruff format app/services/calculation_service.py`

### HIGH: кнопки скачивания имеют неоднозначные accessible names

Факт: сценарии `project-csv.spec.ts` падают на `getByRole('button', { name: /Скачать/i })`, потому что Playwright находит сразу несколько кнопок:

- скачать проект;
- скачать шаблон XLSX;
- скачать шаблон CSV.

Риск:

- Это не только проблема теста. Для accessibility и устойчивой автоматизации кнопки с похожим действием должны иметь точные имена.
- Пользователь визуально видит разные кнопки, но для assistive technologies и тестов обобщенный `Скачать` становится неоднозначным.

Рекомендация:

- Задать точные `aria-label` или видимые подписи по смыслу действия:
  - `Скачать проект CSV`;
  - `Скачать шаблон XLSX`;
  - `Скачать шаблон CSV`.
- В E2E использовать точные имена, а не регулярку `/Скачать/i`.

### MEDIUM: в frontend-тестах много предупреждений, которые маскируют реальные проблемы

Факты из `npm run test:run`:

- React Router future flag warnings.
- React `act(...)` warnings в тестах с мутациями теплового расчета.
- AntD предупреждает, что `InputNumber addonAfter` deprecated, нужно использовать `Space.Compact`.
- AntD предупреждает, что `Card bodyStyle` deprecated, нужно использовать `styles.body`.
- AntD Form предупреждает: `Form already set 'initialValues' with path ... Field can not overwrite it`.

Риск:

- Тесты проходят, но лог зашумлен. При появлении нового warning или реальной проблемы ее сложнее заметить.
- Некоторые warnings указывают на будущие breaking changes библиотек.

Рекомендация:

- Отдельным техническим проходом убрать warnings:
  - обернуть асинхронные мутации в тестах корректным ожиданием;
  - заменить deprecated AntD API;
  - пересмотреть конфликт `initialValues` и `initialValue` внутри Form.

### MEDIUM: backend предупреждает о слабой длине JWT HMAC-ключа

Факт: backend pytest выводит `InsecureKeyLengthWarning`: HMAC key is 23 bytes, recommended at least 32 bytes for SHA256.

Риск:

- Если это только test/dev secret, риск ограничен шумом и плохим примером конфигурации.
- Если такой же secret может попасть в staging/production, это уже security issue.

Рекомендация:

- В тестовой и dev-конфигурации использовать secret длиной минимум 32 байта.
- В runtime-конфигурации валидировать минимальную длину JWT secret на старте приложения.

### LOW: backend содержит устаревающие API и некорректные pytest-маркеры

Факты:

- FastAPI/Starlette предупреждает, что `HTTP_422_UNPROCESSABLE_ENTITY` deprecated, нужно использовать `HTTP_422_UNPROCESSABLE_CONTENT`.
- Несколько backend-тестов помечены `@pytest.mark.asyncio`, хотя сами тесты не async:
  - `app/tests/integration/api/test_import_excel.py::test_template_builder_roundtrip`;
  - `app/tests/integration/api/test_import_excel.py::test_csv_template_has_type_column`.

Риск:

- Сейчас это не ломает тесты, но создает технический шум и будущие upgrade-проблемы.

Рекомендация:

- Заменить deprecated HTTP-константу.
- Убрать лишние `@pytest.mark.asyncio` с синхронных тестов.

## Что не подтвердилось как ошибка

- Frontend TypeScript ошибок не выявил.
- Frontend ESLint ошибок не выявил.
- Frontend unit/integration suite зеленый: 184 теста проходят.
- Backend pytest зеленый и проходит минимальный порог покрытия.
- Быстрый поиск по `TODO`, `FIXME`, `BUG`, `HACK`, `XXX` в `frontend/src`, `backend/app`, `e2e/tests` не показал явных оставленных bug-маркеров в прикладном коде. Найденные `type: ignore` и тестовые security payloads не выглядят самостоятельными блокерами.

## Приоритет исправлений

1. Исправить форматирование `backend/app/services/calculation_service.py`, чтобы вернуть зеленый `make lint-backend`.
2. Обновить E2E-сценарии теплового расчета под новый command bar, активный тип объекта и правило очистки формы после сохранения.
3. Уточнить продуктово: локальная вкладка `Результаты расчёта` действительно удалена. Если да, тесты должны проверять новый путь. Если нет, это отдельная UI-регрессия.
4. Развести accessible names для кнопок скачивания проекта и шаблонов.
5. Снизить warning-noise в frontend/backend тестах, чтобы будущие регрессии были заметнее.
