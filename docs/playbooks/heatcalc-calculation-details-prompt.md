# HeatCalc: расчетные детали в таблице и расшифровке

Дата заметки: 2026-05-13.

## Контекст

В `frontend/src/pages/HeatCalcPage.tsx` есть компактный блок `renderAssumptionsPanel()`.
Сейчас он выводит:

- `Расчетные допущения`
- `Tср`
- `ветер`
- `alpha`
- `K`
- `Rст`
- `Rиз`
- `Rвнеш` / `Rгр`
- `Lэфф`

Проблема: `Tср` в текущем UI фактически берется из `selectedParams.ambient_temperature`.
Это температура окружающей среды, а не средняя температура. Поэтому подпись вводит в заблуждение.

Часть значений уже есть в интерфейсе:

- `T окр.` отображается в таблице по умолчанию.
- `ветер`, `alpha внеш`, `Kзап` есть в форме объекта и как настраиваемые колонки.
- `Rст`, `Rиз`, `Rвнеш/Rгр`, `Lэфф`, площади резервуаров - это расчетные результаты, их нет в обычной таблице по умолчанию.

## Продуктовое решение

Сделать расчетные детали доступными в двух местах, но с разными ролями:

1. Таблица - для сравнения объектов.
2. Компактная расшифровка - для объяснения расчета выбранного объекта.

Таблицу не перегружать по умолчанию. Расчетные детали должны быть доступны как скрытые настраиваемые колонки.

Расшифровку сделать настраиваемой отдельно от таблицы, чтобы пользователь мог выбрать, какие расчетные метрики видеть в компактном блоке.

## Рекомендуемая модель

### Таблица

Добавить группу скрытых колонок `Расчетные детали`.
Все эти колонки должны быть выключены по умолчанию.

Кандидаты:

- `delta_t` / `ΔT`
- `calculated_alpha_vnesh` / `alpha расч.`
- `calculated_safety_factor` / `Kзап расч.`
- `thermal_resistance` / `RΣ`
- `wall_resistance` / `Rст`
- `insulation_resistance` / `Rиз`
- `external_resistance` / `Rвнеш` или `Rгр`
- `effective_length` / `Lэфф` только для труб
- `surface_area` / `Sпов.` только для резервуаров
- `air_surface_area` / `Sвозд` только для подземных резервуаров
- `ground_surface_area` / `Sгр` только для подземных резервуаров

Важно: не смешивать ручные параметры и расчетные результаты.

- Текущая колонка `alpha_vnesh` показывает ручной override из `params.alpha_vnesh`.
- Для рассчитанного значения нужна отдельная колонка, например `calculated_alpha_vnesh`, которая читает `results.alpha_vnesh`.
- Аналогично для `K`: ручной параметр и расчетное значение лучше не смешивать.

### Компактная расшифровка

Переименовать блок:

- Было: `Расчетные допущения`
- Лучше: `Расшифровка расчета` или `Детали расчета`

Сделать список метрик настраиваемым.

Минимальная настройка:

- пресеты `Кратко`, `Стандарт`, `Подробно`
- чекбоксы метрик
- настройки сохранять отдельно от настроек колонок таблицы

Рекомендуемый дефолт `Стандарт`:

- `ΔT`
- `alpha расч.`
- `Kзап`
- `Rиз`
- `Rвнеш/Rгр`
- `Lэфф` для труб
- `Sпов.` для резервуаров

Подробный режим:

- все из стандартного
- `Rст`
- `RΣ`
- `ветер`
- источники температуры/ветра, если заданы
- `Sвозд`, `Sгр` для подземных резервуаров

Краткий режим:

- `ΔT`
- `alpha расч.`
- `Kзап`
- `Rиз`
- `Lэфф` / `Sпов.`

## UX-правила

- Не показывать `Tср`, если это не настоящая средняя температура.
- Если нужно показать текущую температуру окружающей среды, подписывать как `T окр.`.
- Лучше показывать `ΔT = Tподд - Tокр`, потому что это полезнее для объяснения теплопотерь.
- Не выводить источник как `(—)`. Если источник не задан, ничего не показывать.
- В режиме `Все` для неприменимых расчетных колонок показывать `—`, как уже сделано для типоспецифичных полей.
- По умолчанию таблица должна остаться чистой.

## Готовый промпт для реализации

```text
Проанализируй и доработай отображение расчетных деталей в HeatCalc workspace.

Цель:
Сделать расчетные детали доступными и в таблице, и в компактной расшифровке выбранного объекта, но не перегружать интерфейс по умолчанию.

Контекст:
- Основной файл UI: `frontend/src/pages/HeatCalcPage.tsx`.
- Текущий блок `renderAssumptionsPanel()` выводит `Расчетные допущения`.
- Сейчас `Tср` фактически показывает `selectedParams.ambient_temperature`, то есть `T окр.`, а не среднюю температуру.
- В таблице уже есть входные параметры: `T окр.`, `ветер`, `alpha внеш`, `Kзап`.
- `alpha внеш` в таблице/форме - это ручной override из `params.alpha_vnesh`.
- `results.alpha_vnesh` - это рассчитанное backend значение, его нельзя смешивать с ручным override.
- `Rст`, `Rиз`, `Rвнеш/Rгр`, `Lэфф`, площади резервуаров - это расчетные результаты.

Требования:

1. Не менять backend-формулы.

2. Переименовать компактный блок:
   - с `Расчетные допущения`
   - на `Расшифровка расчета` или `Детали расчета`.

3. Убрать misleading `Tср`.
   - Не показывать `Tср`, если оно не считается как средняя температура.
   - Вместо этого показывать `ΔT = Tподд - Tокр`, рассчитанное на frontend из `params.process_temperature` и `params.ambient_temperature`.
   - Если все же нужно показывать температуру окружающей среды, подписывать ее как `T окр.`.

4. Добавить скрытые настраиваемые колонки таблицы в группу `Расчетные детали`.
   По умолчанию они должны быть выключены.
   Минимальный набор:
   - `delta_t` / `ΔT`
   - `calculated_alpha_vnesh` / `alpha расч.` из `results.alpha_vnesh`
   - `calculated_safety_factor` / `Kзап расч.` из `results.safety_factor`
   - `thermal_resistance` / `RΣ`, если доступно
   - `wall_resistance` / `Rст`
   - `insulation_resistance` / `Rиз`
   - `external_resistance` / `Rвнеш` или `Rгр`
   - `effective_length` / `Lэфф` для труб
   - `surface_area` / `Sпов.` для резервуаров
   - `air_surface_area` / `Sвозд` для подземных резервуаров
   - `ground_surface_area` / `Sгр` для подземных резервуаров

5. Не смешивать ручные и расчетные значения.
   - Оставить существующую колонку `alpha_vnesh` как ручной параметр.
   - Добавить отдельную расчетную колонку для `results.alpha_vnesh`.
   - Аналогично различать ручной `params.safety_factor` и расчетный `results.safety_factor`.

6. Сделать компактную расшифровку настраиваемой отдельно от таблицы.
   Минимально:
   - пресеты `Кратко`, `Стандарт`, `Подробно`
   - чекбоксы метрик
   - отдельное сохранение preference от настроек таблицы

7. Дефолт расшифровки:
   `Стандарт`.
   Показывать:
   - `ΔT`
   - `alpha расч.`
   - `Kзап`
   - `Rиз`
   - `Rвнеш/Rгр`
   - `Lэфф` для труб
   - `Sпов.` для резервуаров

8. Подробная расшифровка:
   Показывать дополнительно:
   - `Rст`
   - `RΣ`
   - `ветер`
   - источники температуры/ветра, только если они заданы
   - `Sвозд`, `Sгр` для подземных резервуаров

9. Краткая расшифровка:
   Показывать:
   - `ΔT`
   - `alpha расч.`
   - `Kзап`
   - `Rиз`
   - `Lэфф` или `Sпов.`

10. Для режима `Все`:
    - типоспецифичные расчетные колонки должны показывать `—` для неприменимого типа объекта;
    - таблица по умолчанию не должна стать шире;
    - дефолтные видимые поля не менять без необходимости.

11. Не выводить мусорные источники вида `(—)`.
    Если источник температуры или ветра не задан, просто не показывать источник.

12. Сохранить компактный внешний вид панели, чтобы она не занимала много высоты и не мешала таблице.

Проверка:
- `npm run typecheck`
- релевантные vitest-тесты по `HeatCalcPage` и настройкам колонок
- вручную в гостевом проекте:
  - выбрать трубу;
  - выбрать резервуар;
  - проверить режим `Все`;
  - включить расчетные колонки через настройки таблицы;
  - проверить, что `alpha расч.` берется из `results.alpha_vnesh`, а не из `params.alpha_vnesh`;
  - проверить, что `Tср` больше не отображается ошибочно.
```
