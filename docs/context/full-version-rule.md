# Full Version Rule

## Правило

Текущий целевой уровень проекта — полная версия ТНП-логики и пользовательских
сценариев. Частичная реализация, временное упрощение или ранний этап поставки не
являются приемлемым бизнес-статусом для формул, алгоритмов, справочников,
backend policy, API или UI workflow.

Если реализация не покрывает документацию ТНП и действующий business contract
полностью, она маркируется как одно из состояний:

- `Needs implementation` — функционал отсутствует или закрыт только частично;
- `Needs correction` — функционал реализован, но расходится с контрактом;
- `Needs business decision` — требуется подтверждение спорного правила.

## Как использовать

При проверке формул и алгоритмов агент не снижает ожидаемое поведение до ранней
поставки. Исторические разделы ТЗ, SRS или старые status-файлы можно использовать
только как контекст происхождения требований, но не как разрешение оставить
расхождение.

Для численных проверок источником истины остаются deterministic oracle,
ТНП-документация, `docs/business-logic-contract.md` и registry QA-agent. LLM
может помогать объяснять и группировать расхождения, но не может принимать
частичную формулу как корректную.
