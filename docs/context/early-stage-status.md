# Исторический срез раннего этапа

Этот файл оставлен как историческая сверка ранней поставки с ТЗ. Он не является
текущим критерием приемки бизнес-логики. Для новых проверок и доработок
использовать `docs/context/full-version-rule.md`,
`docs/business-logic-contract.md` и `docs/tnp/project-reconciliation-audit.md`.

## Реализованный функционал (историческая сверка с ТЗ)

По матрице ранней поставки из Приложения №2 ТЗ:

| Раздел ТЗ | Статус | Где реализовано |
|---|:---:|---|
| Вход пользователя без регистрации (авто-проект) | ✅ | `auth/guest`, in-memory IPRateLimiter, `GUEST_MAX_PROJECTS=1` |

| Управление проектом (создание/открытие/сохранение/дублирование) | ✅ | `projects/*` CRUD + `projects/{id}/duplicate` + `projectStore` persist |

## Известные ограничения

| Ограничение | Описание | Решение в следующей версии |
|---|---|---|
| In-memory rate limiter | Сбрасывается при перезапуске, не работает на нескольких инстансах | slowapi + Redis |
| Gap TTL до 30 мин | Cleanup раз в 10 мин + TTL 20 мин → в худшем случае данные живут ещё ~10 мин после ухода | Уменьшить интервал / использовать pg_cron |
| Теплопроводность изоляции | Пока табличное значение λ; температурная зависимость изоляции не реализована | Температурозависимая модель, если она требуется по финальной методике |
| Одноинстансный деплой | Нет горизонтального масштабирования | Docker Swarm / K8s |
| Нет email-верификации | Сотрудник создаётся только администратором | Self-service регистрация |
| Полная матрица типов кабеля ещё не закрыта | Расчётно поддержаны ТЛТ, ТТН/ТТВ/ТТХ, ТТ Р1 (`single_core`) и ТТ Р3 (`three_core`); MI и скин-системы остаются без расчётной формулы | US-09.8 / 09.9, Q-D/Q-F |
| Лимит 50 объектов на проект | Настраивается через `GUEST_MAX_OBJECTS_PER_PROJECT` | — |
| Шифрование формул/справочников | Вариант А (ТЗ §5): внутри Docker-образа | Варианты Б/В (Vault, KMS) |
| Audit/snapshot расчётов | Нет истории коэффициентов и снапшота справочников в каждом результате | Нужен для воспроизводимости расчётов |
