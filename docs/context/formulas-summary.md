## Трубопровод — цилиндрическая многослойная стенка

```
Q = ΔT / (R_стенки + Σ R_изоляции_i + R_внеш) × (L + L_доп) × K    [Вт]

R_слоя = ln(d_внеш / d_внутр) / (2π × λ_слоя)   — цилиндрическое сопр., м·К/Вт на 1 м

Надземно:  R_внеш = 1 / (π × α_внеш × d_нар_из)
Подземно:  R_внеш = arccosh(H / r_нар_из) / (2π × λ_гр)

α_внеш = 11,6 + 7 × √v    [Вт/(м²·К)]
```

Контракт передачи в электрический подбор: для трубы `heat_loss_per_meter`
остается без `K`; электрическая формула применяет свой `safety_factor` ровно
один раз.

`λ_изоляции` для справочных материалов считается как `λ(tm)` по ТНП-справочнику
теплоизоляции. Для теплых режимов (`indoor`, `outdoor_summer`, `channel`,
`tunnel`, `technical_subfloor`, `attic`, `basement`) `tm=(Tж+40)/2`; для
`outdoor_winter` `tm=Tж/2`.

## Резервуар — плоская стенка

```
Q = ΔT / (δ_р/λ_р + δ_из/λ_из + 1/α_внеш) × S × K + Q_доп    [Вт]

S (цилиндр):       π × d × H + π × d²/2
S (параллелепипед): 2 × (L×W + L×H + W×H)
S (шар):           π × d²

α_внеш = 11,6 + 7 × √v    [Вт/(м²·К)]
Q_доп  — дополнительные теплопотери (днище, штуцера и пр.), Вт; default = 0; прибавляется после K
```

## Саморегулирующийся кабель ТЛТ

Тип расчёта: `self_regulating`. Это автоподбор или проверка марки кабеля
линейки ТЛТ по требуемой удельной мощности, температурам и параметрам укладки.

### Вход в алгоритм

Для трубы в электрорасчёт передается `heat_loss_per_meter` без уже примененного
теплового коэффициента запаса. Электрическая формула применяет
`safety_factor` сама:

```
P_треб = required_power_per_meter × safety_factor       [Вт/м]
```

Для резервуара требуемая мощность переводится из полной теплопотери в Вт/м
кабеля через геометрию укладки. `total_heat_loss` уже содержит тепловой `K`,
поэтому сервис делит его на `K`:

```
L_баз = длина укладки по поверхности резервуара
P_треб_на_м = (total_heat_loss / K) / L_баз
```

Для резервуара обязательны форма укладки `cylindrical` или `rectangular`,
`heating_height` и `laying_step`. Сферические резервуары пока не имеют формулы
укладки кабеля и должны попадать в отдельную ошибку/техдолг, а не молча
подбираться как труба.

### Автоподбор марки

Если `cable_mark = null`, алгоритм выбирает кабель из каталога ТЛТ
(`cables_tlt.json` или выбранный источник каталога). Кандидат должен пройти все
условия:

```
min_temperature <= ambient_temperature
max_temperature >= process_temperature
power_per_meter × k_навива × N >= P_треб
```

Если пользователь явно не задал `number_of_threads`, автоподбор сам пробует
`N = 1..3`. Из всех подходящих вариантов выбирается минимальный по порядку:

1. меньшее количество ниток;
2. меньшая паспортная мощность кабеля, Вт/м;
3. меньшая установленная мощность `power_per_meter × N`.

Если `number_of_threads` задано вручную, алгоритм проверяет только это
количество ниток и не увеличивает его автоматически.

### Ручной выбор марки

Если `cable_mark` задан, алгоритм не подбирает другую марку. Он находит
указанный кабель в каталоге и проверяет:

```
power_per_meter × k_навива × N >= P_треб
ambient_temperature >= min_temperature
process_temperature <= max_temperature
```

Если нитки при ручной марке не заданы, используется `N = 1` как значение по
умолчанию, но это не считается ручным вводом пользователя.

### Расчёт результата

```
layout_factor = k_навива × N_применённое
L_каб = L_баз × 1.1 × layout_factor
P_общ = power_per_meter × L_каб
I = P_общ / U_кабеля
```

Для ТЛТ `process_temperature` обязателен, так как без него нельзя проверить
паспортный предел `max_temperature` кабеля.

Для ТЛТ `U_кабеля` берётся из выбранной строки каталога (`voltage`; во
встроенной линейке 220 В). `supply_voltage` из объекта/СО используется только
как fallback для кастомного каталога без паспортного напряжения. Commercial
projection поверх встроенной линейки сохраняет паспортные технические поля
ТЛТ, включая `voltage`, и накладывает только коммерческие данные.

В результатах нужно различать запрошенное и фактически применённое количество
ниток:

- `requested_number_of_threads` — что явно пришло от пользователя, иначе `null`;
- `applied_number_of_threads` / `num_circuits` — сколько ниток применил расчёт;
- `number_of_threads_source` — `auto`, `manual`, `default` или
  `previous_result`.

## Саморегулирующийся кабель ТТН/ТТВ/ТТХ

Тип расчёта: `self_regulating_tt`. Это отдельная линейка саморегулирующихся
кабелей, где серия выбирается по температурам, а фактическая мощность кабеля
считается по температуре поддержания.

```
q_б(T3) = Q1 × T3 + Q2      [Вт/м]  — линейная зависимость от температуры поддержания

Алгоритм серии: ТТН (T1≤65°C, T2≤85°C) → ТТВ (120/210) → ТТХ (150/250)
  Серия выбирается только по температурам T1/T2; мощность не эскалирует серию.
Марка: {мощность}ТТН/ТТВ/ТТХ2-СТ (агрессивная среда: СР)
N_circuits = заданное количество ниток или ceil(q_required / (q_б × k_навива))
L_каб = L_баз × k_навива × N_circuits
P_общ = q_б × L_каб
```

`process_temperature` — это `T1` для выбора серии, `vapor_temperature` — `T2`,
`maintain_temperature` — отдельный `T3` для `q_б(T3)`. Для совместимости
старых запросов отсутствие `maintain_temperature` означает `T3 = T1`.
Ток и `voltage` результата считаются по паспортному `voltage` выбранной строки
ТТН/ТТВ/ТТХ; `supply_voltage` из CO используется только как fallback, если
паспортное напряжение отсутствует.

Температурные пределы ТТН/ТТВ/ТТХ считаются включительными паспортными
максимумами.

Если `cable_mark = null`, алгоритм сначала выбирает минимально подходящую
серию по `T1/T2`, затем внутри серии ищет минимальный номинал, у которого
`q_б(T3) × k_навива` покрывает `q_required`. Если мощности одной нитки
недостаточно, берётся максимальный номинал выбранной серии и считается:

```
N = ceil(q_required / (q_б(T3) × k_навива))
```

Для ТТН/ТТВ/ТТХ в auto-режиме нет искусственного ограничения `N <= 3`: это
full-version правило из VSDX. Серия не повышается только ради уменьшения
количества ниток; серия определяется только температурными пределами.

Если `number_of_threads` задано вручную, алгоритм проверяет только это
количество ниток по `q_б(T3) × k_навива × N >= q_required`. Если `cable_mark`
задан вручную, проверяется указанная марка, её серия, температура и мощность;
автоматическая замена на другую марку не выполняется.

## Навив и несколько ниток

```
Для трубы:
k_навива = 1, если шаг = 0
k_навива = √(1 + (π × D / шаг)²), если шаг > 0

Шаг навива задаётся в мм и должен быть больше наружного диаметра трубы.
Для ТТН/ТТВ/ТТХ автоматический подбор использует full-version правило:
если мощности линейки не хватает, берётся максимальный номинал выбранной серии
и `N = ceil(Pоб / (Pi.ном(T3) × k_навива))` без искусственного ограничения
`N <= 3`.
Длина кабеля и установленная мощность считаются с учётом k_навива и ниток.
```

ТНП-ограничение максимального коэффициента навива по диаметру трубы:

| Диаметр D, мм | Максимальный Kn |
|---:|---:|
| `D < 57` | 1,0 |
| `D = 57` | 1,1 |
| `57 < D <= 75` | 1,2 |
| `75 < D <= 89` | 1,3 |
| `89 < D <= 108` | 1,4 |
| `D > 108` | 1,5 |

## Резистивный одножильный ТТ Р1

```
N = (L + L_доп) × w          — длина кабеля, м
ρ_T = 0.0175 × (1 + 0.0042 × (T_ж − 20))   [Ом·мм²/м]

Линия 220В:  Sк = (Q/U²) × ρ_T × N
Петля 220В:  Sк = (Q/U²) × ρ_T × 2N
Звезда 380В: Sк = (Q/(U/√3)²) × ρ_T × 3N
```

`process_temperature` обязателен для резистивных ТТ Р1/ТТ Р3: это `T_ж` в
расчёте сопротивления/подборе. API и admin formula-check возвращают единую
ошибку `Для электрорасчёта требуется температура продукта`, если поле не
передано и его нельзя взять из параметров объекта.

Если в справочнике есть паспортное `resistance_ohm_km`, подбор мощности и тока
использует паспортное сопротивление, а не `ρ_T / S`:

```
R = resistance_ohm_km / 1000 × L_каб × factor_R
P = U² / R × factor_P
I = P / U
I <= 65 A
```

Known issue: эта паспортная модель сейчас использует холодное `R20` и не
домножает сопротивление на `[1+0.0042×(T_ж−20)]`, хотя первичные DOCX формулы
мощности резистивных кабелей содержат этот множитель. Отклонение и риск
завышения `P/I` при высокой `T_ж` зафиксированы в
`docs/analysis/resistive-temperature-tz-deviation.md`.

Основной автоматический подбор работает в full-version режиме VSDX:

```
p1 = Q_required / L_object
M = 1..max_parallel_schemes
N = 2: петля при U=start, затем петля при U=high
N = 3: звезда при U=high
p2 = I² * resistance_ohm_km / 1000
p3 = min(Imax² * resistance_ohm_km / 1000, max_linear_power_w_m)
select first candidate where p2 <= p3 and p2 * N * M covers p1
```

`Imax`, `start/high/min voltage` и `max_parallel_schemes` могут приходить из
`correction_coefficients`; пока БД не заполнена, backend использует fallback
`Imax=65 A`, `start=220 В`, `high=380 В`, `min_adjusted=40 В`,
`voltage_step=5 В`, `M<=20`. `max_linear_power_w_m` по умолчанию берется из
`resistive_cables.json/common`: для `ТТ Р1` — `40 Вт/м`, для `ТТ Р3` —
`50 Вт/м`; явный override `max_linear_power_w_m` или type-specific coefficient
может заменить это значение.

Справочник ТТ Р1 сверяется с последними пользовательскими скринами:
`docs/tnp/internal-references/resistive-cable-r1.md`. Для ТТ Р1 зафиксированы
питание до `~600 В`, `50 Гц`, линейная мощность до `40 Вт/м`, схемы
линия/петля/звезда, формат заказа и таблица сопротивлений/сечений/диаметров/
длин секций.

## Резистивный трёхжильный ТТ Р3

```
Линия:         Sк = (Q/U²) × ρ_T × N / 3
Петля 2×3ж:    Sк = (Q/U²) × ρ_T × 2N / 3
Петля 1×3ж:    Sк = (Q/U²) × ρ_T × 3N
Звезда 3×3ж:   Sк = (Q/(U/√3)²) × ρ_T × 3N / 3
Звезда 1×3ж:   Sк = (Q/(U/√3)²) × ρ_T × 3N
```

Справочник ТТ Р3 сверяется с последними пользовательскими скринами:
`docs/tnp/internal-references/resistive-cable-r3.md`. Для ТТ Р3 зафиксированы
температуры, сечения жил, линейное тепловыделение до `50 Вт/м`, строительная
длина `200 м`, маркировка и таблица габаритов/массы/радиусов изгиба.

Для машинного расчёта ТТ Р3 справочник хранит `conductor_section_mm2` и
`resistance_ohm_km` явно. Runtime-код сначала использует эти поля; извлечение
сечения из строки `model` оставлено только как fallback для legacy/неполных
каталогов.

В `auto`-подборе ТТ Р3 схемы `N=2` и `N=3` считаются через паспортную модель
трех нагревательных жил, согласованную с ручными схемами:

```
loop_2x3: P = U² / (r × L × 2) × 3
star_3x3: P = (U / √3)² / (r × L × 3) × 3
p2 = P / (L × N)
```

где `r = resistance_ohm_km / 1000`, `L` — длина нагревательной секции, `N` —
схема VSDX (`2` петля, `3` звезда). Такой расчёт не использует универсальное
`per_thread_power × N` для ТТ Р3, потому что справочник описывает кабель как
трехжильный нагревательный кабель.

## Спецификация: полный условный BOM (mode="full")

Источник: `ТНП/Расчет_спецификации_трубы_самрег29_05_26.xlsx`, лист «Список
материалов Самрег» (oracle: `docs/audit/spec-bom-oracle.md`). Применяется
только к саморегулирующимся типам (`self_regulating`, `self_regulating_tt`);
позиции других типов кабеля пропускаются и попадают в `skipped_objects`.

```
Кабель:    L = Σ(L,секц × N,секц × R,гр)             по маркам
КСН-1/КСВ-1: Fl = Σ N,секц × R,гр                     по темп-классу
КСН-2/КСВ-2: Fl = Σ N,секц × R,гр × 2                 только секции с
                                                       L,секц >= L,К2i при К2i=да
КСР-1/КСР-2: ceil(ΣL / 150)
Коробки СКВ: Σ ceil(N,секц / 3) → 12 корзин Nk1..Nk12 по dтр≷57 / К1i / К2i / Кiu / N≥3
Этикетка:    Σ ceil(Lтр / 3.5)
Упаковка:    шт. = ceil(формула × package_factor)     колонка I источника:
             ХК30/ЛКС/ЛКВ ×0.0333334 (рулон 30 м), ЛА ×0.02, NEO ×0.14,
             ГС ×0.25, Z-профиль ×0.5
```

Темп-класс: ТТВ/ТТХ → высокий, остальное (ТТН, ТЛТ) → низкий (упрощение,
см. открытый вопрос Б-2). Реализация:
`backend/app/formulas/specification/full_builder.py` + каталог правил
`backend/app/reference_data/spec_accessories.json`. Режим и опции последней
генерации персистятся (`generation_mode`/`generation_options`); гостю `full`
недоступен (403). Открытые вопросы (секционирование, резервуары, граница
dтр=57, базы длины basic vs full):
`docs/analysis/spec-bom-open-issues-2026-06-09.md`.

## Коэффициенты

Таблица `correction_coefficients` — все роли включая гостей:

| Ключ | По умолчанию | Влияние |
|---|---|---|
| `safety_factor` | 1,1 | Множитель K для Q (трубы **и** резервуары) |

## Реализация

Все формулы — чистые Python-функции (без ORM/БД):
- `backend/app/formulas/heat_loss/pipe.py` — цилиндр
- `backend/app/formulas/heat_loss/tank.py` — плоская стенка
- `backend/app/formulas/electrical/self_regulating.py` — автоподбор ТЛТ и
  ТТН/ТТВ/ТТХ
- `backend/app/formulas/electrical/resistive.py` — расчёт ТТ Р1 и ТТ Р3
- `backend/app/formulas/specification/builder.py` — базовая спецификация
- `backend/app/formulas/specification/full_builder.py` — полный условный BOM ТНП

Коэффициенты передаются как параметр `coefficients: dict[str, float]` —
сервисный слой достаёт их из БД через `get_correction_coefficients()`.

## Валидация входных данных

Pydantic-схемы в `backend/app/schemas/calculation.py` с `Field()` валидаторами:
- `outer_diameter > 0`
- `insulation_thickness > 0`
- `process_temperature > ambient_temperature`
- Для резервуара: `diameter ≤ 3 м` (исторически; при необходимости расширяется)
