# Чеклист улучшений приложения

Дата фиксации: 2026-05-15.

Документ собирает технический и продуктовый бэклог по приложению: корректность
расчётов, UX, производительность, безопасность, тесты и документация.

## Приоритет на ближайший этап

1. Безопасность доступа и корректность массовых операций.
2. UX электрорасчёта с типами кабеля и ручным/автоматическим подбором.
3. Производительность больших таблиц и batch-операций.

## Критично

- [x] Разделить "ошибка расчёта" и "не применимо". Сферический резервуар без
  формулы укладки кабеля сохраняется как `unsupported_layout`, а UI показывает
  серый статус «Не применимо».
- [ ] Сделать действия из подсказок ошибок реальными: "Попробовать другой тип
  кабеля" должен открывать понятный сценарий выбора/пересчёта, а не быть просто
  текстом.
- [ ] Жёстко развести автоматический и ручной подбор кабеля: авто не должен
  перетирать ручной выбор без явного подтверждения.
- [ ] Проверить все batch-операции: "пересчитать все", импорт, массовое
  применение параметров. Главный риск - случайно изменить весь проект.
- [ ] Добавить нормальные structured error codes везде, где сейчас ошибки ещё
  могут приходить текстом.
- [ ] Перепроверить права доступа: guest/employee/admin для проектов, импорта,
  справочников, внешнего каталога, спецификаций.
- [ ] Проверить, что объект одного гостя нельзя получить через прямой
  `project_id`/`object_id` другого гостя.

## UX и Логика

- [ ] Убрать из UI параметры, которые не применимы к выбранному типу кабеля.
  Например "нитки" не должны выглядеть как универсальный параметр.
- [ ] Сделать модалку ручного выбора кабеля: тип кабеля -> марка -> параметры
  -> предпросмотр результата -> применить.
- [ ] Для "Попробовать другой тип кабеля" показывать доступные типы и что
  изменится до пересчёта.
- [ ] Добавить блок "Было / Стало" для электрорасчёта, особенно для массового
  изменения кабеля.
- [ ] Довести статусы: рассчитан, ошибка подбора, не применимо, не рассчитан,
  ручной выбор, массовый выбор.
- [ ] В таблицах закрепить смысл лейблов: входное поле, расчётное значение,
  справочное значение, ручное значение.
- [ ] Проверить все названия колонок: короткое название, полное название,
  tooltip, экспортное название.
- [ ] Убрать остатки "Сообщение" как колонку из JSON/настроек, если оно уже
  вынесено в отдельную область.
- [ ] Сделать поведение выбранных строк предсказуемым: изменение
  типа/марки/параметра применяется только к выбранным.
- [ ] Проверить UX при переключении СО1/СО2/СО3/СО4: выбранные строки, ошибки и
  фильтры не должны сбивать пользователя.

## Теплопотери

- [ ] Окончательно разделить трубы и резервуары в таблице теплопотерь: разные
  колонки, разные обязательные поля, разные результаты.
- [ ] Проверить импорт/экспорт для труб и резервуаров: нужные листы, нужные
  столбцы, сохранение расчётных полей.
- [ ] Добавить/проверить колонки теплопотерь: `heat_loss_per_meter`,
  `heat_loss_per_m2`, `total_heat_loss`.
- [ ] Довести диапазоны резервуаров: диаметр, высота, длина, ширина не должны
  наследовать трубные ограничения.
- [ ] Проверить обязательные поля: красная подсветка, понятная ошибка
  диапазона, без лишнего общего текста.
- [ ] Убрать автогенерацию имени объекта, если это всё ещё где-то осталось.
- [ ] Доработать автозаполнение средними значениями, но только явно по кнопке,
  не скрыто.

## Электрорасчёт

- [ ] Формально описать, какие параметры применимы к каждому типу кабеля.
- [ ] Для каждого типа кабеля сделать свой набор колонок/контролов.
- [ ] Не показывать совет "нитки", пока нет понятного UI, где пользователь
  реально может выбрать 2/3 нитки для этого режима.
- [x] Добавить "не применимо" для сферических резервуаров или реализовать
  формулу укладки для сферы.
- [ ] Проверить, что полный пересчёт действительно приводит все строки к
  выбранному типу, а выбранный пересчёт меняет только выбранные.
- [ ] Проверить сохранение источника марки кабеля: авто / ручной / массовый.
- [ ] Проверить, что спецификация берёт актуальную марку кабеля и не смешивает
  старые результаты.

## Производительность бэка

- [ ] Проверить индексы: `project_objects.project_id`, `sort_order`,
  `electrical_calculations.project_id`, `object_id`, `variant_number`.
- [ ] Убедиться, что batch-расчёты не делают N+1 запросы.
- [ ] Для больших проектов отдавать таблицы через query endpoint с
  фильтрами/сортировкой на SQL, а не на фронте.
- [ ] Ограничить размер JSON `params`/`results`, который уходит в списки, если
  часть полей не нужна таблице.
- [ ] Проверить Celery/worker: отмена задач, повторный запуск, гонки двух
  пересчётов одного проекта.
- [ ] Добавить идемпотентность для массовых операций, где возможно.

## Безопасность

- [ ] Проверить object-level authorization на всех endpoint: проект, объект,
  расчёт, импорт, экспорт, спецификация.
- [ ] Ограничить размер загружаемых файлов Excel/CSV.
- [ ] Валидировать MIME/расширение и содержимое импорта.
- [x] Защититься от formula injection в CSV/XLSX экспорте: значения,
  начинающиеся с `=`, `+`, `-`, `@`.
- [ ] Проверить rate limits для guest-сессий, импорта и batch-пересчёта.
- [ ] Не возвращать внутренние exception-префиксы и traceback пользователю.
- [ ] Проверить CORS, cookies/session storage, guest token/session id.
- [ ] Логи не должны содержать лишние персональные данные или полный импорт.
