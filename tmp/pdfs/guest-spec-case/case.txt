2.     Общее положение
2.1    Термины
Пользователь - общее понятие, обозначающее любого человека, использующего приложение. Пользователем
может быть как авторизованный, так и неавторизованный пользователь.

Гость или Неавторизованный пользователь - это тип пользователя приложения который может:
     создать проект;
     добавлять объекты;
     выполнять расчёты;
     сформировать спецификацию;
     сохранить проект в локальный файл;
     повторно загрузить локальный файл и продолжить работу.
     Не может сохранять проекты в базе данных системы.
     Формировать «Отчет – Проект».

Зарегистрированный пользователь или Авторизованный пользователь - это тип пользователя приложения который
может:
     создавать проекты;
     сохранять проекты в базе данных;
     просматривать список своих проектов;
     открывать ранее сохранённые проекты;
     редактировать проекты;
     удалять проекты;
     создавать и сохранять несколько вариантов электрорасчёта;
     формировать спецификации.

Инженер-проектировщик - это не отдельный тип пользователя по авторизации, а функциональная роль человека,
который работает с расчётами.
Инженер-проектировщик может работать в системе как:
     гость;
     зарегистрированный пользователь.

Администратор - Администратор является авторизованным пользователем с правами управления системой.
Администратор может:
     создавать, блокировать и удалять учётные записи зарегистрированных пользователей;
     назначать и изменять права доступа;
     сбрасывать пароли пользователей;
     просматривать технические журналы системы;
     настраивать корректирующие коэффициенты;
     управлять системными справочниками;
     просматривать, добавлять, изменять и удалять записи базы данных;
     просматривать информацию о состоянии приложения и выполняемых технических операциях.
Администратор не используется как основная роль для выполнения инженерных расчётов. При необходимости
выполнения расчётов администратору должна быть дополнительно назначена соответствующая пользовательская
роль.

Проект - Набор объектов обогрева, теплотехнических расчётов, электрорасчётов и спецификаций, относящихся к
одному проектному решению.

Объект обогрева - Трубопровод или ёмкость / бочка, для которых необходимо рассчитать систему электрообогрева.

Теплотехнический расчёт - Расчёт тепловых потерь объекта и мощности, необходимой для поддержания заданной
температуры.

Тепловые потери -Количество тепловой энергии, которое теряет объект. Значение используется для подбора
мощности системы обогрева и измеряется в Вт/м.

Электротехнический расчёт - Отдельный вариант расчёта, в котором объекты распределяются по типам систем
обогрева, подбирается кабель и формируются нагревательные секции.

Нераспределённый объект - Объект электрорасчёта, которому ещё не назначен тип системы обогрева.

Тип системы обогрева - Способ         обогрева   объекта.   В рамках    текущей     версии     используется   тип
«Саморегулирующийся кабель».

Вкладка системы обогрева - Область интерфейса, в которой отображаются объекты с назначенным типом системы
обогрева.

Саморегулирующийся кабель - Греющий кабель, мощность которого изменяется в зависимости от температуры
окружающей среды.

Марка кабеля - Конкретная позиция греющего кабеля, выбранная системой из базы продукции производителя.

Температурная группа - Параметр, определяющий температурный класс кабеля и совместимых с ним материалов.
Используются группы:
LOW - низкотемпературная;
MEDIUM_HIGH - среднетемпературная и высокотемпературная.

Нитка обогрева - Отдельная линия греющего кабеля, проложенная вдоль объекта.

Нагревательная секция - Отрезок греющего кабеля установленной длины, имеющий собственные электрические
параметры.

Секционирование - Разделение общей длины греющего кабеля на отдельные нагревательные секции с учётом
максимальной длины и допустимого стартового тока.

Максимальная длина секции - Наибольшая длина одной нагревательной секции, допустимая для выбранной марки
кабеля.

Стартовый ток - Ток, возникающий при включении холодного греющего кабеля.

Рабочий ток - Ток, потребляемый нагревательной секцией в рабочем режиме.

Мощность обогрева - Мощность, которую система обогрева передаёт объекту. Используется для сравнения с
тепловыми потерями.

Справочник кабелей - База параметров кабелей, используемая для подбора марки и расчёта нагревательных секций.

База материалов - Набор материалов производителя с параметрами, необходимыми для выбора позиции и расчёта
количества.

Спецификация - Итоговый перечень кабелей, комплектов, лент и других материалов с указанием марок,
номенклатурных кодов, единиц поставки и количества.

Соединительный комплект - Комплект материалов для подключения нагревательной секции. Выбирается по
температурной группе кабеля.

Ремонтный комплект - Комплект для ремонта греющего кабеля. Количество рассчитывается по общей длине кабеля
соответствующей температурной группы.

Сохранённый электрорасчёт- Зафиксированный вариант электротехнического расчёта, который пользователь может
повторно открыть, изменить, скопировать или использовать для расчёта спецификации.

2.2        Назначение документа
Документ описывает требования к системе, предназначенной для расчёта электрообогрева трубопроводов и
ёмкостей / бочек.
В документе определены:
     порядок создания объектов обогрева;
     передача объектов в электротехнический расчёт;
     выбор типа системы обогрева;
     подбор греющего кабеля;
     формирование нагревательных секций;
     ручная корректировка результатов;
     расчёт спецификации материалов;
     сохранение и повторное открытие электрорасчётов.
2.3        Цели документа
      1.   Зафиксировать согласованную логику работы системы.
      2.   Описать действия инженера-проектировщика на каждом этапе расчёта.
      3.   Определить данные, которые система получает от пользователя, из расчётов и справочников.
      4.   Зафиксировать правила автоматического подбора кабеля и формирования нагревательных секций.
      5.   Описать формулы расчёта количества материалов для спецификации.
      6.   Определить структуру интерфейса и порядок отображения результатов.
      7.   Сформировать требования, понятные разработчикам, тестировщикам и инженерам.
      8.   Использовать документ как основу для разработки, проверки и согласования системы.

3.      Нефункциональные требования
3.1     Архитектура и среда выполнения
Программа должна быть реализована в виде веб-приложения.

Серверная часть приложения и база данных должны поддерживать локальное развёртывание на инфраструктуре
Заказчика.

Для развёртывания приложения должны быть подготовлены Docker-образы и файл docker-compose.yml.

Приложение должно поддерживать работу в локальной сети без подключения к интернету.

Для выполнения основных функций приложения не должно требоваться подключение к внешним облачным
сервисам.

Все расчётные формулы, встроенные справочники и данные, необходимые для формирования спецификации,
должны быть доступны локально.

Настройки приложения должны храниться отдельно от исходного кода.

3.2     Поддерживаемые браузеры
Приложение должно поддерживать актуальные на момент ввода в эксплуатацию версии следующих браузеров:

Google Chrome;
Mozilla Firefox;
Opera;
Яндекс Браузер.

Допускаются незначительные различия во внешнем виде стандартных элементов браузеров, если они не влияют на
выполнение функций приложения.


3.3     Минимальные требования к серверу
Для эксплуатации приложения должна быть достаточна следующая минимальная конфигурация сервера:
     процессор: не менее 4 виртуальных ядер;
     рекомендуемая частота процессора: не менее 2,5 ГГц;
     оперативная память: не менее 8 ГБ;
     свободное дисковое пространство: не менее 40 ГБ;
     тип накопителя: SSD;
     операционная система: Linux или другая серверная операционная система с поддержкой Docker;
     установленный Docker Engine;
     установленный Docker Compose;
     сетевое подключение: не менее 100 Мбит/с.

Данная конфигурация рассчитана на эксплуатацию приложения небольшой группой пользователей и выполнение
нескольких расчётов одновременно.

При существенном увеличении количества пользователей, проектов или объектов параметры сервера должны быть
увеличены.

3.4     Производительность
Приложение должно поддерживать работу не менее 10 одновременно активных пользователей.

Открытие основных страниц приложения при нормальной нагрузке должно занимать не более 3 секунд.

3.5    Ограничения по объёму данных

     не менее 50 сохранённых проектов на одного зарегистрированного пользователя;
     не менее 10 000 записей в справочниках кабелей и материалов.

После перезапуска приложения сохранённые проекты должны оставаться доступными.

Приложение не должно сохранять незавершённый расчёт как окончательный результат.

Незавершённые или некорректные расчёты должны иметь соответствующий статус.

После изменения исходных данных связанные результаты должны быть отмечены как требующие перерасчёта.

дублирующихся проектов, расчётов или спецификаций.

При временной потере соединения приложение не должно повреждать ранее сохранённые данные.

Основной сценарий
    Инженер открывает страницу «Мои проекты».

    Инженер продолжает работу.

Ошибка открытия
Если проект не удалось загрузить:
    система остаётся на странице «Мои проекты»;
    отображается сообщение «Не удалось открыть проект»;
    данные других проектов не изменяются.

4.6       Сохранение проекта
Интерфейс
В рабочей области проекта отображается кнопка «Сохранить».
Рядом с названием проекта отображается состояние сохранения:
     «Все изменения сохранены»;
     «Есть несохранённые изменения»;
     «Сохранение».

Основной сценарий
    Инженер изменяет данные проекта.
    Система устанавливает состояние «Есть несохранённые изменения».
    Инженер нажимает кнопку «Сохранить».
    Система сохраняет текущее состояние проекта.
    Система обновляет дату последнего изменения.
    Система отображает сообщение «Проект сохранён».
    Состояние изменяется на «Все изменения сохранены».

Ошибка сохранения
Если проект не удалось сохранить:
    система показывает сообщение «Не удалось сохранить проект»;
    состояние «Есть несохранённые изменения» сохраняется;
    инженер может повторить сохранение.

4.7       Возврат к списку проектов
         Инженер нажимает кнопку «Мои проекты» или «Назад к проектам».
         Если все изменения сохранены, система открывает страницу «Мои проекты».
         Если есть несохранённые изменения, система показывает окно подтверждения.

В окне доступны кнопки:
     «Сохранить и выйти»;
     «Выйти без сохранения»;
     «Отмена».

Цель
Предоставить инженеру-проектировщику интерфейс для ввода, просмотра и изменения исходных данных объектов,
выполнения расчёта тепловых потерь и перехода к электротехническому расчёту.

Акторы
•      Инженер-проектировщик.
•      Система.

Предусловия
Выполнено одно из условий:
•      неавторизованный пользователь нажал кнопку «Начать без регистрации», после чего система открыла
временный проект;
•      авторизованный пользователь создал новый проект или открыл сохранённый проект со страницы «Мои
проекты». Не рассматривается в рамках этой документации.

Открытие страницы проекта
После открытия проекта система отображает раздел «Исходные данные».
Для нового проекта таблица объектов является пустой.

•       «Исходные данные для спецификации».

Каждый блок содержит только параметры, необходимые для соответствующего этапа.
Распределение параметров между блоками определяется файлом «Список переменных трубопровода.xlsx».

Выбор типа объекта
Под блоками исходных данных отображаются вкладки типов объектов:
•      «Трубопровод»;
•      «Бочка»;
•      «Пол».
При выборе вкладки система отображает только объекты выбранного типа.

Набор доступных полей и правила расчёта изменяются в зависимости от выбранного типа объекта.

При открытии нового проекта по умолчанию активна вкладка «Трубопровод».

Таблица объектов
В нижней части страницы отображается таблица объектов выбранного типа.
Каждая строка соответствует одному объекту.
Строка содержит:
•       чекбокс выбора;
•       основные параметры;
•       результат расчёта тепловых потерь;
•       статус объекта.

Список параметров объекта тепловых потерь для бизнеса

Документ описывает, какие данные нужно собрать по объекту, чтобы рассчитать теплопотери и дальше перейти к
подбору кабеля, спецификации и коммерческому предложению. Формулировки ориентированы на бизнес-процесс:
что спросить у клиента, зачем это нужно и когда без параметра расчет нельзя считать достоверным.

Назначение

Объект тепловых потерь — это конкретная труба, участок трубопровода или резервуар, для которого нужно понять:

•      сколько тепла объект теряет в условиях эксплуатации;

•      какая мощность обогрева нужна;

•      можно ли переходить к подбору кабеля и расчету стоимости;

•      Система создаёт новый объект трубопровода.

•      В таблице появился новый объект.

6.13   Алгоритм подбора кабеля
Бизнес-описание подбора саморегулирующегося кабеля ТЛТ
Документ объясняет подбор кабеля ТЛТ простым бизнес-языком: что система должна сделать для пользователя,
какие решения принимает автоматически и какой результат попадает дальше в спецификацию и отчет.
Scope: только саморегулирующийся кабель ТЛТ.
Зачем нужен подбор
После теплорасчета у каждого объекта уже понятно, сколько тепла он теряет. Задача электрорасчета — подобрать
такой кабель ТЛТ, который:
•       покроет теплопотери объекта с запасом;
•       выдержит температуру продукта;
•       сможет работать при заданной температуре окружающей среды;
•       даст корректную длину кабеля для заказа;
•       даст мощность и ток для дальнейшего проектирования;
•       попадет в спецификацию и отчет без ручного пересчета инженером.
Кто использует
Гость и сотрудник используют одинаковую расчетную логику. Разница только в доступных источниках каталога и
правах на дальнейшую работу с отчетами и материалами.
Пользователь может:
•       запустить автоподбор для одного или всех объектов;
•       выбрать марку кабеля вручную;
•       изменить шаг навива;
•       задать количество ниток;
•       выбрать критерий подбора, если есть коммерческие данные.
Что пользователь вводит
Пользователь не должен вручную считать кабель. Он вводит или получает из предыдущих шагов:
•       геометрию объекта;
•       теплопотери;
•       температуру продукта;
•       температуру окружающей среды;
•       напряжение питания;
•       запас по мощности;
•       способ укладки: прямо, с навивом, в одну или несколько ниток;
•       при необходимости — ручную марку кабеля.
Система сама переводит эти данные в требование к кабелю.
Как система принимает решение
Автоматический режим
Если марка кабеля не выбрана вручную, система делает автоподбор:
1.      Берет требуемую мощность объекта после теплорасчета.
2.      Добавляет расчетный запас.
3.      Проверяет каталог ТЛТ.
4.      Убирает кабели, которые не подходят по температуре продукта.
5.      Убирает кабели, которые не подходят по температуре окружающей среды.
6.      Проверяет, хватит ли мощности одной, двух или трех ниток.
7.      Выбирает минимально достаточный вариант.
Бизнес-смысл: система не должна ставить слишком слабый кабель, но и не должна без причины выбирать более
дорогой и мощный вариант.
Ручной режим
Если пользователь выбрал марку ТЛТ вручную, система не заменяет ее другой маркой. Вместо этого она проверяет
выбранный кабель:
•       хватает ли мощности;
•       подходит ли он по температуре продукта;
•       подходит ли он по температуре окружающей среды;
•       корректны ли шаг навива и количество ниток.
Если выбранная марка не подходит, система должна показать ошибку. Это важно: ручной выбор инженера не должен
превращаться в незаметную автоматическую замену.

2.      меньшая мощность кабеля;
3.      меньшая установленная мощность;
4.      стабильный порядок по марке.
Пример: если объекту достаточно ТЛТ-25, система не должна выбирать ТЛТ-40 только потому, что он тоже

•        нет подходящего кабеля по температуре продукта;
•        нет подходящего кабеля по температуре окружающей среды;
•        ручная марка не найдена;
•        ручная марка не подходит;
•        шаг навива некорректен;
•        коэффициент навива выходит за допустимые пределы.
В таких случаях объект должен получить понятную ошибку. Ошибка должна сохраняться, чтобы после перезагрузки
пользователь видел, почему кабель не подобран.
Что происходит при пакетном пересчете

Ошибочные расчеты не должны добавлять кабель в спецификацию.

6.14    Алгоритм формирования нагревательных секций.
Параметры из справочника кабеля название документа «Параметры Кабеля.xlsx»
По марке кабеля и минимальной температуре включения система получает:
•      максимальную допустимую длину одной секции Lмакс;
•      удельный стартовый ток кабеля Iст.уд;
•      температурные ограничения;
•      допустимые значения для выбранной марки кабеля.

 Получение параметров секционирования
1.     Система получает минимальную температуру включения объекта.
2.     Система находит в справочнике строку, соответствующую:
•      выбранной марке кабеля;
•      минимальной температуре включения.
3      Из найденной строки система получает:
•      максимальную длину секции Lмакс;
•      удельный стартовый ток Iст.уд.
4.     Если точного значения температуры в справочнике нет, система применяет согласованное правило выбора
ближайшего допустимого температурного значения.
До окончательного согласования используется ближайшее более низкое значение температуры.

Пример:
Температура включения объекта: -17 °C
Значения в справочнике: -10 °C и -20 °C
Для расчёта используется строка -20 °C

Определение максимальной длины по стартовому току
1.      Система получает максимально допустимый стартовый ток одной секции Iдоп.
2.      Система рассчитывает максимально допустимую длину секции по стартовому току:
Lток = Iдоп / Iст.уд
где:
•       Lток — максимальная длина секции по стартовому току, м;
•       Iдоп — максимально допустимый стартовый ток одной секции, А;
•       Iст.уд — удельный стартовый ток кабеля, А/м.

Определение допустимой длины секции
1.     Система сравнивает:
•      максимальную длину из справочника Lмакс;
•      максимальную длину по стартовому току Lток.

2.      Для расчёта используется меньшее значение:
Lогр = min(Lмакс, Lток)
где Lогр — допустимая длина одной нагревательной секции.
3.      Если значение Lогр содержит дробную часть, оно округляется вниз до установленной точности.
Округление вверх запрещено, поскольку оно может привести:
•       к превышению максимальной длины;
•       к превышению допустимого стартового тока.

Расчёт количества нагревательных секций
1.       Система получает требуемую общую длину кабеля Lтреб.
2        Система рассчитывает минимально необходимое количество секций:
N = ceil(Lтреб / Lогр)
где:
•        N — количество нагревательных секций;
•        Lтреб — требуемая общая длина кабеля;
•        Lогр — допустимая длина одной секции.
3.       Количество секций округляется вверх до целого числа.

6.       Разница рассчитывается как дополнительная длина:
Lдоп = Lфакт - Lтреб
Пример
Требуемая длина кабеля: 200 м
Допустимая длина секции: 67 м
Количество секций:

Длина одной секции:
67 м

Фактическая длина:
67 × 3 = 201 м

Дополнительная длина:
201 - 200 = 1 м

Цель

Предусловия
•      Для объектов выполнен подбор греющего кабеля.
•      Для объектов сформированы нагревательные секции.
•      Для каждой группы секций определены:
o      марка кабеля;
o      длина одной секции;
o      количество одинаковых секций.
•      Электрорасчёт не содержит критических ошибок, препятствующих формированию спецификации.
Основной сценарий
•      Система последовательно обрабатывает все распределённые объекты текущего электрорасчёта.
•      Для каждого объекта система получает сформированные группы нагревательных секций.
•      Для каждой группы система рассчитывает фактическую длину кабеля:
Длина кабеля группы =
длина одной секции × количество секций
•      Если у объекта имеется несколько групп секций, система рассчитывает длину каждой группы отдельно.
•      Система определяет марку кабеля для каждой группы секций.
•      Длины секций с одинаковой маркой кабеля суммируются по всем объектам электрорасчёта:
Общее количество кабеля марки =
сумма длин всех секций данной марки
•      Система находит соответствующую позицию кабеля в выбранной базе номенклатуры.
•      Система добавляет кабель в спецификацию отдельной строкой.
•      Для позиции отображаются:
o      наименование;
o      марка;
o      номенклатурный код;
o      поставщик;
o      единица поставки;
o      рассчитанное количество.

Пример расчёта одного объекта
Для объекта сформирована группа:

Длина одной секции: 60 м
Количество секций: 2
Расчёт:
60 × 2 = 120 м
В спецификацию передаётся 120 м кабеля марки ТТН-20.
Пример суммирования по нескольким объектам
Объект № 1:
ТТН-20: 60 м × 2 секции = 120 м
Объект № 2:
ТТН-20: 45 м × 3 секции = 135 м
Объект № 3:
ТТН-30: 70 м × 2 секции = 140 м
Результат спецификации:
ТТН-20: 120 + 135 = 255 м
ТТН-30: 140 м

Кабели разных марок отображаются отдельными строками.

7. Бизнес-правила
Каждая соединительная коробка хранится в справочнике отдельной строкой.
Каждая строка справочника содержит условия применения и параметры расчёта количества.
Система не должна разбирать текстовые формулы.
Округление хранится одним параметром rounding_mode.
Возможные значения rounding_mode: up, down.
Делитель хранится одним параметром section_divider.
Использование N,секц напрямую выполняется через section_divider = 1.
Минимальное количество хранится параметром min_quantity.
Для соединительных коробок min_quantity = 1.
Если условия применения коробки выполнены, итоговое количество не может быть меньше min_quantity.
Если округление вниз дало 0, но условия применения коробки выполнены, в спецификацию добавляется 1 штука.
Значение dтр = 57 мм относится к условию dтр >= 57.
Если условие строки не выполнено, коробка не рассчитывается и в спецификацию не добавляется.
Одинаковые позиции суммируются по номенклатурному коду.
Изменение параметров модального окна формирования спецификации требует обновления спецификации.
