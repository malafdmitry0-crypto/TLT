## 14.2. Найденные проблемы — требуют действий

### Н-1 (критично). Коэффициент 15ТТВ2 даёт отрицательную мощность

`15ТТВ2: q_б(T3) = −0,491·T3 + 16` — коэффициент Q1 = −0,491 идентичен
33ТТН2 и резко выбивается из ряда серии ТТВ (соседние: 30ТТВ2 −0,141;
60ТТВ2 −0,250). Следствия:

```
q_б(40 °C)  = −3,6 Вт/м   (отрицательная мощность!)
q_б = 0 при T3 = 32,6 °C  — при заявленном пределе серии T1 ≤ 120 °C
```

**Анализ первопричины.** Физика саморегулирующегося кабеля: полимерная
матрица с сажей при нагреве расширяется, проводящие цепочки рвутся,
мощность падает — поэтому Q1 < 0 нормально, а наклон физически
пропорционален номиналу кабеля. Сами данные ТНП эту закономерность
показывают:

| Серия | Номинал → Q1 | Q1 на 1 Вт номинала |
|---|---|---|
| ТТН | 10→−0,155; 15→−0,242; 25→−0,392; 33→−0,491 | ≈ −0,015 |
| ТТВ | 30→−0,141; 45→−0,217; 60→−0,250 | ≈ −0,004…−0,005 |
| ТТХ | 15→−0,072; 30→−0,144; 45→−0,222; 60→−0,283; 80→−0,311; 95→−0,383 | ≈ −0,004…−0,005 |

У высокотемпературных серий (ТТВ/ТТХ) наклон в разы более пологий — они и
спроектированы держать мощность при высоких температурах. Экстраполяция
ряда ТТВ даёт для 15ТТВ2 ожидаемое Q1 ≈ −0,07 (сравнить с 15ТТХ2: −0,072).
В таблице же стоит −0,491 — до последней цифры совпадает с **33ТТН2**,
последней строкой соседней таблицы ТТН. Это классическая ошибка переноса
строки/ячейки между таблицами при наборе первоисточника: «чужой» крутой
наклон + «свой» корректный свободный член (q2 = 16 ≈ номинал при T3 = 0).

Линейная аппроксимация за пределами применимости у любой марки уходит в
минус, но у всех остальных марок ноль мощности лежит при 72…264 °C — **за**
рабочим диапазоном серии. Только у 15ТТВ2 ноль попадает внутрь диапазона
(32,6 °C при заявленных 120 °C): кабель по таблице «не умеет» того, для
чего существует. Значение одинаково в ТНП-первоисточнике и в
`cables_tt.json` — дефект заведён из первички (вероятная опечатка: −0,0491
или −0,091).

**Действие:** запросить у Заказчика паспортную кривую 15ТТВ2; до ответа
автоподбор обязан отбрасывать марки с `q_б(T3) ≤ 0` с явной ошибкой, а не
выдавать отрицательную мощность (VAL-82). Внесено в документ 11 как
**В-14**.

### Н-2 (критично). Модель «звезда» расходится с физической в 9 раз

Формула ТНП для одножильной звезды `Sк = Q/(U/√3)² × ρ × 3N` эквивалентна
**последовательному** включению всей длины 3N на фазное напряжение.
Физическая звезда из трёх параллельных ветвей длиной N даёт при том же
сечении в **9 раз большую** мощность. Аналогичное расхождение — в
`star_3x3` ТТ Р3 (паспортная модель `P = U_ф²/(r·L)` против физической
`9·U_ф²/(r·L)`).

**Анализ первопричины.** Ряд формул одножильного кабеля в ТНП построен по
механическому шаблону «подставь длину и напряжение»:

```
Линия:  Sк = Q/U²      × ρ × N      (длина N,  напряжение U)
Петля:  Sк = Q/U²      × ρ × 2N     (длина 2N, напряжение U)
Звезда: Sк = Q/(U/√3)² × ρ × 3N     (длина 3N, напряжение U_ф)
```

Для линии и петли шаблон совпадает с физикой, потому что цепь там одна и
последовательная: в петле кабель полной длиной 2N включён целиком на U
(`R = ρ·2N/S`, `P = U²·S/(ρ·2N)` — точная обратная к формуле сечения).
Для звезды автор продолжил шаблон («три нитки → 3N, напряжение фазное»),
но звезда — не последовательная цепь, а **три параллельные ветви** по N,
каждая на фазном напряжении:

```
Модель ТНП (шаблон):   P = U_ф² · S / (ρ·3N)      — вся длина 3N последовательно
Физическая звезда:     P = 3 · U_ф² · S / (ρ·N)   — 3 ветви по N параллельно
```

Расхождение — произведение двух «троек»: (1) сопротивление ветви считается
от длины N, а не 3N → ×3 мощности на ветвь; (2) ветвей три и они работают
одновременно → ещё ×3. Итого 3 × 3 = **9**. То, что петля сходится с
физикой, а звезда — нет, доказывает: это не осознанный общий коэффициент
запаса методики, а ошибка вывода именно одной схемы (формула получена
подстановкой в шаблон, а не расчётом цепи).

**Почему не исправлено в одностороннем порядке.** (1) Реализация внутренне
самосогласована: формула мощности ТНП — точная обратная к формуле сечения,
то есть подобранный кабель выдаст ровно Q, *если соединение соответствует
ТНП-модели*. Ключевой вопрос — как фактически монтируется «звезда» у
Заказчика: при реальных трёх параллельных ветвях подобранный по ТНП кабель
выдаст 9Q (перегрев, превышение лимита 65 А). (2) По правилу проекта
первоисточник имеет приоритет, а исправление меняет результаты подбора на
порядок — менять можно только по подтверждению.

**Действие:** запросить у Заказчика golden-пример расчёта звезды с числами
(вход → сечение → мощность → ток): подтвердить ТНП-модель или исправить
формулу. Внесено в документ 11 как **В-13**.

### Н-3 (требование добавлено). Валидация глубины подземной прокладки

`arccosh(H/r)` не определён при `H ≤ r_нар_из`: текущий диапазон ввода
H = 0…200 м допускает H=0 при подземном размещении → математическая ошибка.

**Действие:** добавлено правило **VAL-81** (документ 8): при подземном
размещении `H > d_нар_из/2` (глубина оси больше наружного радиуса
изоляции); рекомендуемый инженерный минимум H ≥ 0,5 м с предупреждением.

### Н-4 (уже учтено как В-2). Холодное R20 в P/I резистивных

Подтверждено направление исправления: формулы ТНП DOCX содержат
`[1+0,0042(Tж−20)]`, паспортная модель и p2/p3 — нет. Несоответствие
внутреннее (Sк уже считается по горячему ρ_T). Остаётся В-2.

### Н-5 (примечание). Напряжение 230 В в первоисточнике

ТНП-формула тока самрега `I = P/230`; действующий контракт считает ток по
паспортному напряжению строки каталога (220 В для встроенных линеек).
Расхождение 230/220 — 4,5% по току. Принято: паспортное U (зафиксировано в
ЭР-07/ЭР-12); при приёмке golden-кейсы считать по паспортному U.

### Н-6 (примечание). «Серые зоны» серии ТТН вблизи T1 = 65 °C

`q_б(65) = 1,77 Вт/м` (15ТТН2) и `5,59 Вт/м` (33ТТН2) — на верхней границе
серии полезная мощность близка к нулю, автоподбор уйдёт в большие N.
Поведение математически корректно, но UI должен показывать применённое
`q_б(T3)`, чтобы инженер видел причину больших N (требование к UI шага 2,
дополнение ФТ-23).

## 14.4. Общий вывод по характеру находок

Обе критичные находки — типовые дефекты «эксельной» методологии
первоисточника, а не ошибки реализации:

- **Н-1** — ошибка копирования данных между соседними таблицами
  (строка 33ТТН2 → ячейка 15ТТВ2);
- **Н-2** — ошибка обобщения формулы по аналогии (шаблон «линия → петля →
  звезда» без расчёта реальной цепи).

Реализация воспроизводит первоисточник точно — поэтому такие дефекты не
ловятся сверкой «код ↔ документ» и выявляются только независимой физической
проверкой (размерный анализ, проверка предельных значений, сверка с
эталонной моделью цепи). Это прямое обоснование требований НФ-27
(независимый deterministic-oracle формул) и НФ-28 (golden-тесты контрольных
примеров) и довод за добавление в приёмочную программу этапа
«физическая валидация данных справочников»: для каждой марки проверять
`q_б(T3) > 0` во всём заявленном температурном диапазоне серии и
монотонность/согласованность коэффициентов внутри линейки.
