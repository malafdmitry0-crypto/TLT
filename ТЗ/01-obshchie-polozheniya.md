# 1. Общие положения

## 1.1. Наименование и назначение системы

Программный комплекс предназначен для использования инженерным персоналом с
целью:

- автоматического расчёта тепловых потерь с поверхности обогреваемых объектов
  (трубопроводы, ёмкости/резервуары; в перспективе — насосы, площадки);
- подбора греющего кабеля, компенсирующего теплопотери (саморегулирующиеся
  линейки ТЛТ и ТТН/ТТВ/ТТХ, резистивные одножильные ТТ Р1 и трёхжильные
  ТТ Р3; в перспективе — кабели с минеральной изоляцией и скин-системы);
- формирования спецификации оборудования и материалов (включая полный
  условный BOM по ТНП);
- формирования отчёта с возможностью печати и экспорта в PDF / DOCX / XLSX.

Система — веб-приложение, развёртываемое on-premise в локальной сети
Заказчика без обязательного выхода в интернет.

## 1.2. Термины и сокращения

| Термин | Значение |
|---|---|
| ТНП | Технологические нормы предприятия — первичные методические материалы Заказчика (DOCX, XLSX, VSDX) |
| Объект | Расчётная единица проекта: трубопровод или резервуар с параметрами геометрии, изоляции и температур |
| СО (CO1..CO4) | Вариант системы обогрева; в проекте допускается до 4 сравниваемых вариантов |
| ТЛТ | Линейка саморегулирующихся греющих кабелей (10 марок, 10–100 Вт/м) |
| ТТН / ТТВ / ТТХ | Линейки саморегулирующихся кабелей: низко-, высоко- и сверхвысокотемпературная серии |
| ТТ Р1 | Одножильный резистивный кабель постоянной мощности |
| ТТ Р3 | Трёхжильный резистивный кабель постоянной мощности |
| MI | Кабель с минеральной изоляцией (тип зарезервирован, методика не утверждена) |
| Скин-система | Индукционно-резистивная система обогрева (тип зарезервирован) |
| Навив | Спиральная укладка кабеля на трубу с шагом; увеличивает длину кабеля на метр трубы |
| Нитка (N) | Количество параллельных линий кабеля вдоль объекта |
| K | Коэффициент запаса мощности |
| K_разм | Прикладной коэффициент размещения (помещение/улица) |
| λ (лямбда) | Коэффициент теплопроводности, Вт/(м·К) |
| α (альфа) | Коэффициент теплоотдачи с поверхности, Вт/(м²·К) |
| tm | Расчётная средняя температура теплоизоляционного слоя, °C |
| BOM | Bill of materials — полный перечень материалов спецификации |
| Гость / Пользователь | Анонимная роль без регистрации |

## 1.3. Роли и матрица доступа

Система поддерживает три роли.

## 1.4. Границы системы

**Входит в объём:**

- теплотехнический расчёт: многослойная цилиндрическая стенка трубы (1–3 слоя
  изоляции), плоская стенка резервуара (цилиндр / параллелепипед / шар),
  надземное, внутрипомещенное и подземное размещение, учёт ветра, климата,
  грунта, локальных элементов и дополнительных теплопотерь;
- электротехнический расчёт: автоподбор и ручной выбор марки кабеля по
  четырём расчётным типам (ТЛТ, ТТН/ТТВ/ТТХ, ТТ Р1, ТТ Р3), навив, нитки,
  схемы подключения (линия / петля / звезда), варианты CO1..CO4;
- спецификация: базовая и полный условный BOM по ТНП;
- отчёты, импорт/экспорт, администрирование, справочники.

**Не входит в объём (текущая очередь):**

- экономические расчёты (цены, сметы, окупаемость);
- расчётные методики для кабелей MI и скин-систем (типы зарезервированы в
  модели данных, отображаются как «не поддержано»);
- объекты «насос», «площадка», «прочее» (тип `pump` зарезервирован);
- мобильная версия интерфейса (минимальная ширина рабочей области 1280 px);
- многоязычность (язык интерфейса — русский).

**Требования следующей очереди** (рекомендуется, по итогам сравнения с
мировыми системами, см. документ 10): температура наружной поверхности
изоляции, типизированные тепловые мосты (арматура/фланцы/опоры), режим
сверки по ASTM C680 / ISO 12241, динамика разогрева/остывания, расширенные
инженерные предупреждения.

## 1.5. Архитектурные требования

| Слой | Требование |
|---|---|
| Frontend | SPA: React 18 + TypeScript (Vite), Ant Design 5; состояние — Zustand (persist), серверный стейт — TanStack Query |
| Backend | Python 3.11+, FastAPI, асинхронный SQLAlchemy 2.x, миграции Alembic (вперёд и назад) |
| БД | PostgreSQL 16 |
| Развёртывание | Docker + docker-compose; запуск одной командой; работа в изолированной сети |
| Расчётное ядро | Все формулы — чистые функции без обращения к БД/ORM; коэффициенты передаются параметром; 100% покрытие ветвей unit-тестами |
| Справочники | Версионируемые JSON в репозитории; справочник теплоизоляции дополнительно синхронизируется в runtime-таблицу БД |
| API | REST `/api/v1/...`, автодокументация OpenAPI (Swagger) |
| Журналирование | Бизнес-аудит мутаций/расчётов/отчётов в БД; технические логи — локальный стек (Loki/Grafana или аналог) |

## 1.6. Принцип расчётного контура (обязательный)

1. При сохранении объекта теплопотери рассчитываются **автоматически**.
2. Электрорасчёт запускается пакетно для всех объектов выбранного варианта СО
   и допускает ручное переназначение марки кабеля по объекту.
3. Коэффициент запаса применяется **ровно один раз**: в электрический подбор
   трубы передаётся удельная теплопотеря без уже применённого K; для
   резервуара — `(Q / K) / L_укладки`. Двойное применение K — дефект.
4. Спецификация и отчёт строятся на сохранённых результатах расчётов;
   изменение исходных данных инвалидирует зависимые результаты и запускает
   пересчёт.
5. Ошибка расчёта по объекту не теряется: сохраняется вместе с результатом и
   отображается пользователю с причиной и рекомендацией.
