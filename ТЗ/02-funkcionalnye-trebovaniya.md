# 2. Функциональные требования

## 2.1. Общий сценарий работы

```
Шаг 0 → Экран выбора режима доступа: «Войти без регистрации» / «Войти как сотрудник»
Шаг 1 → «Расчёт тепловых потерь»: добавление объектов, авторасчёт теплопотерь
Шаг 2 → «Электротехнический расчёт»: выбор СО, типа кабеля, автоподбор/ручной выбор
Шаг 3 → «Спецификация»: базовая / полный BOM ТНП
Шаг 4 → «Отчёт»: предпросмотр, печать, экспорт
```

Навигация — рабочий стол с боковой панелью и индикатором прогресса шагов
1→2→3→4. Все четыре шага доступны всем ролям (с ограничениями по матрице
доступа документа 1).

## 2.2. Доступ и сессии

- **ФТ-01.** Главный экран предлагает два режима: гостевой вход и вход
  сотрудника. Гостевой вход создаёт анонимную сессию и **автоматически один
  проект** («Мой проект»); UI выбора проекта гостю не показывается.
- **ФТ-02.** Любой запрос гостя продлевает срок жизни сессии. Сессия,
  неактивная дольше настраиваемого TTL (по умолчанию 20 мин), удаляется
  фоновой задачей вместе с проектом и всеми данными (каскадно).
- **ФТ-03.** Защита от ботов: лимит создания гостевых сессий — 10 с одного IP
  в час (rate limit скользящим окном); лимит объектов — 50 на проект; лимит
  проектов гостя — 1.
- **ФТ-04.** Авторизация сотрудника/администратора — e-mail + пароль, JWT
  (access 30 мин, refresh 7 дней). Пароли хранятся только в виде хэша.

## 2.3. Проекты

- **ФТ-05.** CRUD проектов: название (1–200 символов), номер задачи (≤50),
  описание (≤2000). У сотрудника — проводник проектов с фильтрами по типу,
  году, номеру задачи и поиском.
- **ФТ-06.** Сотрудник видит проекты всех сотрудников; гостевые проекты
  подрядчиков сотруднику не видны (403 при прямом обращении). Администратор
  видит все проекты.
- **ФТ-07.** Дублирование проекта (сотрудник): копируются параметры объектов,
  затем теплопотери и подбор кабеля пересчитываются заново.
- **ФТ-08.** Импорт/экспорт проекта одним CSV (все роли): секционный формат
  `[SECTION];<name>` с секциями `metadata` / `objects` / `electrical` /
  `specifications`; JSON-поля как строки в ячейках; UTF-8 BOM. У гостя импорт
  замещает авто-проект с подтверждением. Пакетные импорт/экспорт — только
  сотрудник; конфликт `task_number` разрешается суффиксом «(импорт)».

## 2.4. Шаг 1 — Расчёт тепловых потерь

- **ФТ-09.** Встроенная плоская форма объекта (SC-03) с тремя смысловыми
  секциями: геометрия, теплоизоляция, температура/среда. Электрические поля в
  форме теплопотерь не отображаются (напряжение питания вводится на шаге 2).
- **ФТ-10.** Форма работает в **мм**, API — в **метрах**; конвертация
  выполняется на клиенте (поля `*_mm` ↔ м). Длина трубопровода — в метрах.
- **ФТ-11.** Динамические зависимости формы (матрица видимости полей — полный
  перечень в документе 8, VAL-65..VAL-80): размещение
  (улица/помещение/подземно) переключает поля ветра, α, грунта и глубины;
  выбор климатического города автозаполняет температуру и ветер с
  трассировкой источника («из климата» / «вручную»); режим λ трубы
  «Справ./Вручн.»; 1–3 слоя изоляции; материал «Другое» требует ручную λ.
- **ФТ-12.** Автоименование объектов по параметрам, например:
  `Труба Ø108 мм (DN100), δ=50 мм, МВ, L=50 м, -20→+80°C`;
  `Бак цил. Ø2000 мм×H3000 мм, δ=80 мм, МВ, -20→+80°C`.
- **ФТ-13.** При сохранении объекта теплопотери рассчитываются автоматически;
  при изменении параметров — автоматический пересчёт.
- **ФТ-14.** Таблица объектов: режимы «Все / Трубопровод / Резервуар»,
  серверная пагинация, поиск, фильтры, сортировка, настройка колонок,
  inline-редактирование, копирование выбранных строк (TSV), подсветка
  незаполненных/некорректных ячеек. Изменение порядка строк — полным списком
  ID (API), UI drag-and-drop — допустимая опция.
- **ФТ-15.** Панель действий: добавить объект, создать на основании,
  применить к выбранным, удалить, импорт/экспорт XLSX/CSV, шаблоны для
  импорта.
- **ФТ-16.** Импорт объектов из Excel/CSV: XLSX — листы «Трубопроводы»
  («Трубы») и «Резервуары» («Ёмкости»); CSV — колонка «Тип»
  (`труба`/`резервуар`), автодетект разделителя (`;`, `,`, таб) и кодировки
  (UTF-8 / UTF-8-BOM / CP1251). Ответ: `{created: N, errors: [{sheet, row,
  message}]}`; единичные ошибки не прерывают импорт. Generic-материалы
  изоляции («Минеральная вата» без плотности) импортируются как черновик и
  требуют уточнения конкретного материала.

## 2.5. Шаг 2 — Электротехнический расчёт

- **ФТ-17.** Переключатель вариантов системы обогрева CO1..CO4 (см. 2.7).
- **ФТ-18.** Выбор базы расчёта (сотрудник): встроенные справочники /
  расширенная внешняя БД / обе.
- **ФТ-19.** Типы кабеля: `self_regulating` (ТЛТ), `self_regulating_tt`
  (ТТН/ТТВ/ТТХ), `single_core` (ТТ Р1), `three_core` (ТТ Р3) — расчётные;
  `mineral` и `skin` отображаются как «не поддержано» до утверждения методик.
- **ФТ-20.** Ввод напряжения питания для типов, использующих
  `supply_voltage`; для саморегулирующихся ток считается по паспортному
  напряжению выбранной марки (см. документ 4).
- **ФТ-21.** Пакетный электрорасчёт всех объектов выбранного СО одной
  кнопкой; результат — upsert по `object_id + variant_number`. Ошибка расчёта
  сохраняется в результате (`results.error`) и видна после перезагрузки.
- **ФТ-22.** Ручной выбор марки кабеля по объекту из активной базы расчёта с
  проверкой допустимости (мощность, температуры); ручные параметры навива и
  ниток (документ 4).
- **ФТ-23.** Таблица/сводка результатов: марка, длина кабеля, мощность, ток,
  количество ниток (запрошенное и применённое), ошибки с причинами;
  суммарные итоги по проекту/СО.

## 2.6. Шаги 3–4 — Спецификация и отчёт

Требования к спецификации — документ 6, к отчётам — документ 7.

## 2.7. Варианты системы обогрева CO1..CO4

- **ФТ-24.** В проекте допускается 1–4 варианта расчёта (CO1..CO4). Каждый
  вариант хранит собственные настройки подбора (тип кабеля, база расчёта,
  напряжение и пр.) и собственные результаты электрорасчёта по каждому
  объекту.
- **ФТ-25.** Ровно один вариант помечен как активный; смена активного
  варианта снимает признак с предыдущего автоматически.
- **ФТ-26.** Попытка создать пятый вариант отклоняется с сообщением.
- **ФТ-27.** Спецификация и отчёт строятся по выбранному варианту; сводный
  отчёт по всем СО допустим при наличии ≥2 вариантов.

## 2.8. Администрирование

- **ФТ-28.** Управление сотрудниками: создание, деактивация (деактивированная
  учётная запись не проходит вход с понятным сообщением).
- **ФТ-29.** Настройка корректирующих коэффициентов (документ 5, раздел 5.1)
  с валидацией диапазонов. Рекомендуется журнал изменений (кто, когда,
  старое/новое значение) — см. документ 11.
- **ФТ-30.** Управление внешней БД кабелей и аксессуаров: CRUD позиций,
  коммерческие поля (цена, наличие, приоритет) — без участия в физических
  формулах; отключение устаревших позиций.

## 2.9. Справочные данные и подсказки

- **ФТ-31.** Каждое поле формы имеет единицу измерения, допустимый диапазон в
  подсказке и моментальную клиентскую валидацию (дублируемую сервером).
- **ФТ-32.** Климатический справочник (не менее 539 населённых пунктов РФ по
  СП 131.13330 / СНиП 23-01-99): температура наиболее холодных суток
  (обеспеченность 0,98), наиболее холодной пятидневки (0,92), абсолютный
  минимум, скорость ветра. Выбор города автозаполняет поля объекта с
  возможностью ручного переопределения и сохранением источника значения.
