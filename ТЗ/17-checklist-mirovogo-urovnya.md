# 17. Чек-лист выхода в топ программ проектирования электрообогрева

Вопрос: «Реализовав всё ТЗ, войдём ли мы в топ таких программ?»

**Честный ответ.** Реализация документов 01–09 + 12–13 даёт **сильного
лидера ниши РФ/СНГ** и крепкий промышленный инструмент. В **мировой топ**
(nVent TraceCalc Pro, Thermon CompuTrace Design Suite) текущее ТЗ само по
себе не выводит: у лидеров преимущество не в физике стационарных
теплопотерь (тут мы уже на уровне), а в слое над ней — температура
поверхности, стандарты ASTM/ISO/VDI, детальные тепловые мосты, динамика,
сертификационный workflow и отчёты уровня line list. Этот слой — уровни
1–2 ниже. Уровень 3 — уже не софт, а продуктовая экосистема.

Прогресс отмечать прямо здесь чекбоксами.

---

## Уровень 0 — фундамент (= реализация текущего ТЗ)

Что даёт паритет по расчётному ядру и уникальные локальные преимущества.

- [ ] Все формулы ТЗ реализованы и закрыты golden-тестами (ТР/ЭР/СП,
      НФ-27/28); находки реестра со статусами 🟠/🟡 исправлены
- [ ] Все 🔴-вопросы Заказчика закрыты (опросный лист
      `VOPROSY-ZAKAZCHIKU.md`): звезда ×9, кривая 15ТТВ2, П/2 vs П,
      база длины BOM, Ex→СКВ, R20→R(T), множитель 0,9
- [ ] MI-кабель и скин-системы: методики (док. 12–13) утверждены, каталоги
      получены, расчёт включён — **6/6 типов кабеля расчётные**
      (у TraceCalc/CompuTrace скин-системы вынесены в отдельные продукты —
      единый инструмент здесь наше преимущество)
- [ ] Полный условный BOM по ТНП работает на реальной номенклатуре
      (артикулы СКВ из «Полного перечня продукции», 669 строк)
- [ ] Независимый deterministic-oracle сверяет каждую формулу (паритета по
      этому пункту нет ни у одного закрытого vendor-движка — наше
      преимущество для аккредитации)
- [ ] Климат СП 131.13330 (539+ городов), импорт XLSX/CSV, отчёты
      PDF/DOCX/XLSX, роли, on-premise без интернета

**Итог уровня 0:** топ-1..2 в РФ/СНГ по сумме «открытость + ТНП + BOM +
русскоязычный on-premise». Для мирового уровня — необходимое, но
недостаточное.

## Уровень 1 — паритет расчётного ядра с мировыми лидерами (РО-01..РО-06)

Без этого в любом сравнении с 3E Plus/TraceCalc будем проигрывать по
таблице возможностей, даже считая ту же физику.

- [ ] **Температура наружной поверхности изоляции** в каждом расчёте
      (безопасность/ожоги/конденсация — первое, что спрашивают инженеры;
      РО-01)
- [ ] **Режим сверки по международному стандарту**: ASTM C680 или
      ISO 12241 как альтернативный расчётный режим (РО-02)
- [ ] **Численный benchmark**: 5–7 golden-кейсов против 3E Plus /
      TraceCalc / CompuTrace, расхождение q объяснено по каждому кейсу,
      пакет доказательств сохранён (РО-09). Целевой критерий: |Δq| ≤ 10%
      при одинаковых λ и α, причины различий задокументированы
- [ ] **Типизированные тепловые мосты**: задвижка / задвижка с приводом /
      пара фланцев / опора / подвес со справочником добавок вместо одного
      l_экв (РО-03)
- [ ] **Покрытие и эмиссивность** (weather barrier / материал обшивки) во
      внешней теплоотдаче (РО-04)
- [ ] **Динамика**: время разогрева и остывания продукта (heat-up /
      cool-down, как в CompuTrace Design Suite; РО-05)
- [ ] **Инженерные предупреждения** в результатах: большой диаметр,
      высокая температура, жёсткая изоляция, мокрая изоляция (РО-06)

## Уровень 2 — промышленный workflow проектирования (РО-07..РО-08 + электрика)

То, за что платят за TraceCalc/CompuTrace в EPC-проектах.

- [ ] **Электрика цепей**: падение напряжения по длине, пусковые токи
      самрега при T_min, подбор автомата защиты (характеристика C/D, УЗО),
      длина холодных концов
- [ ] **Взрывозащита сквозняком**: класс зоны → T-класс → проверка
      температуры оболочки → допустимые семейства изделий → отражение в
      BOM и отчёте (РО-07; сейчас Ex живёт только в BOM)
- [ ] **Отчёты уровня line list**: project summary line list, electrical
      line list, single line detail с формулами и промежуточными
      величинами (РО-08, ОТ-08)
- [ ] **Импорт line list** проектировщика (трубная ведомость Excel →
      объекты с привязкой к КИП/маркировке цепей)
- [ ] **Снапшот расчёта**: версия справочников + применённые коэффициенты
      в каждом результате; старый проект воспроизводим всегда (В-7)
- [ ] **Сравнение CO1..CO4** как инструмент выбора: сводная таблица
      вариантов с дельтами по мощности/току/материалам (частично есть —
      довести до отчёта)

## Уровень 3 — экосистема (бизнес-слой, не только софт)

У nVent/Thermon это главный ров. Софтом полностью не закрывается.

- [ ] Каталог реальных сертифицированных изделий с актуализацией
      (регламент обновления внешней БД — В-11)
- [ ] Сертификация изделий (ЕАЭС Ex / IECEx) отражена в данных и отчётах
- [ ] Английская локализация интерфейса и отчётов (для экспортных EPC)
- [ ] Программа валидации: протокол сравнительных испытаний с реальными
      объектами (расчёт vs замеры)
- [ ] Поддержка и обучение: встроенная справка по методикам (частично
      есть), обучающие сценарии
- [ ] Интеграционные API: выгрузка в сметные/закупочные системы заказчика

Два структурных преимущества, которых нет у лидеров и которые стоит
удерживать при любом развитии: (1) открытая трассируемость
«первоисточник → формула → код → тест → oracle» — лидеры считают в чёрном
ящике; (2) один инструмент на все 6 типов систем обогрева, включая
скин-системы, против разрозненных продуктов у конкурентов.

Связанные документы: сравнение с аналогами — `10`, требования следующей
очереди РО-01..РО-09 — там же; открытые вопросы — `11`; реестр находок —
`REESTR-NAHODOK.md`.
