# Техническое задание

**Программный комплекс теплотехнического и электротехнического расчёта систем электрообогрева (рабочее название — TLT / HeatCalc)**

Версия ТЗ: 1.0 · Дата: 2026-06-10 · Статус: проект для согласования с Заказчиком

---

## Назначение комплекта

Заказчик не предоставил формализованное ТЗ. Настоящий комплект документов
составлен на основе:

1. первичных материалов ТНП Заказчика (DOCX-методики, XLSX-расчёты,
   VSDX-алгоритмы, скрины внутренних справочников);
2. действующего контракта бизнес-логики проекта
   (`docs/business-logic-contract.md`, `docs/tnp/`);
3. анализа лучших современных систем проектирования электрообогрева:
   nVent RAYCHEM TraceCalc Pro / TraceCalc Net, Thermon CompuTrace
   (Express / Design Suite), NAIMA 3E Plus (ASTM C680), ROCKWOOL Rockassist
   (EN ISO 12241, VDI 2055), Armacell ArmaWin.

Экономические расчёты (цены, сметы, ТЭО) в объём ТЗ **не входят** —
по решению Заказчика. Все физические формулы, коэффициенты, методики и
алгоритмы расписаны полностью.

## Правила чтения

- Требования обозначаются идентификаторами (`ТР-…` — теплотехнический расчёт,
  `ЭР-…` — электротехнический, `СП-…` — спецификация, `ФТ-…` — функциональные,
  `НФ-…` — нефункциональные). Каждое требование проверяемо.
- Формулы приводятся в нотации первоисточников ТНП. Десятичный разделитель
  в тексте — запятая, в коде — точка.
- Слова **«должен / должна»** означают обязательное требование;
  **«рекомендуется»** — требование следующей очереди (см. документ 10).
- При расхождении настоящего ТЗ с историческими документами проекта приоритет
  у настоящего ТЗ и первичных материалов ТНП.

## Целевой уровень

Целевой уровень — **полная версия** ТНП-логики (см.
`docs/context/full-version-rule.md`). Частичная реализация формул, алгоритмов
или справочников не является приемлемым конечным состоянием: каждое
расхождение фиксируется как «требует реализации», «требует исправления» или
«требует решения Заказчика» (документ 11).
