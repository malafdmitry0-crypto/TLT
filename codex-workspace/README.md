# codex-workspace: документация расчётного контура TLT

Описание фактической реализации всех расчётов TLT по этапам:
**теплопотери → электрорасчёт → спецификация**. Источник истины — backend-код;
соответствие первоисточникам ТНП разобрано в `heat-loss/*-source-traceability.md`.

Статус: **перепроверено против кода 2026-06-08.**

## Два типа документов

В каждой папке расчётная логика описана с двух сторон:

- **Для программиста / нейронки** — точный код-уровень: алгоритмы, поля, формулы,
  сверка с первоисточниками (`*-algorithm.md`, `*-fields.md`,
  `*-orchestration.md`, `*-source-traceability.md`).
- **Для инженера** — простым языком: что считается, что задавать на вход и как
  читать результат (`*-engineer-explanation.md`,
  `*-engineer-input-output-guide.md`).

## Сквозной поток данных

```text
Объект (труба/резервуар)
  -> Теплопотери: heat_loss_per_meter / heat_loss_per_m2, total_heat_loss
     (heat-loss/)
  -> Электрорасчёт: required_power / required_heat_loss -> подбор кабеля
     (electrical/electrical-orchestration.md — контракт «один Kзап»)
  -> Спецификация: order_cable_length по маркам + аксессуары
     (specification/)
```

## Сквозные инварианты

- `safety_factor` (Kзап) применяется ровно один раз на всём пути расчёта.
- `location_factor` остаётся в передаче в электрорасчёт; `Kзап` — нет (для ТЛТ/ТТ).
- Длины кабеля везде различают «расчётную» и «заказ» (× 1.1 монтажный запас).
- Подземная ветка теплопотерь включается по `burial_depth > 0`.
- `mineral` и `skin` — типы без расчётной формулы.
