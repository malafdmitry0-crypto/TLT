# Теплопотери резервуара: источники и отличия от первоисточников

Дата проверки: 2026-06-04.
Реализация перепроверена против кода 2026-06-08: `tank.py`,
`schemas/calculation.py`, `project_object_params.py`, `calculation_service.py`
не менялись с момента написания документа, расхождений с описанием не найдено.

Scope: только расчет теплопотерь резервуара. Электроподбор упоминается только в
месте передачи `Q` в расчет кабеля, потому что это влияет на двойное применение
коэффициента запаса.

## Короткий Вывод

Физическая основа расчета резервуара взята из первичных ТНП-документов:

```text
Q = (Tж - Tос)
    / (delta_р/lambda_р + delta_из/lambda_из + R_внеш)
    * S * K
    + Q_доп
```

Для подземной части:

```text
Q = (q_возд*S_возд + q_гр*S_гр) * K + Q_доп
```

Текущая реализация backend в основном совпадает с первоисточником по:

- плоской модели стенки;
- `R_внеш = 1 / alpha`;
- `alpha = 11.6 + 7sqrt(v)`;
- формулам площади цилиндрического и прямоугольного резервуара;
- разбиению подземной и надземной площади;
- добавлению `Q_доп` после основного расчета;
- делению `Q / K` перед электрическим подбором, чтобы не удвоить запас.

Главные отличия текущего приложения от первоисточников:

- `location_indoor = 0.9` / `location_outdoor = 1.0` умножают итоговое `Q`,
  но отдельный множитель размещения не найден в проверенных первичных
  DOCX/XLSX.
- Backend поддерживает сферический резервуар для надземного расчета, а основной
  ТНП-DOCX по резервуарам описывает круглое и прямоугольное сечение.
- Диапазоны геометрии в backend отличаются от XLSX переменных: например
  `diameter 0.1..30.0` вместо `0.0108..3.0`, `length/width 0.1..100.0`
  вместо `0..50`.
- `ground_conductivity` в backend принимает `0.5..3.0`, а XLSX задает
  `0.8..3.0`.
- В ТНП есть строка "Количество локальных элементов", но текущая формула
  резервуара не использует локальные элементы; вместо этого есть ручное
  `Q_доп`.
- Defaults сохраненного объекта (`shape=cylindrical`, `q_additional=0`,
  `safety_factor=1.1`) являются политикой приложения.

## Что Взято Из `P-TANK`

Основная формула для резервуара на воздухе:

```text
Q = (Tж - Tос)
    / (delta_р/lambda_р + delta_из/lambda_из + R_внеш)
    * S * K
    + Q_доп
```

Площадь круглого сечения:

```text
S = pi*d_р^2/2 + pi*d_р*H
```

Backend записывает то же как:

```text
S = pi*d*H + 2*pi*(d/2)^2
```

Площадь прямоугольного сечения:

```text
S = 2*(L+B)*H + 2*L*B
```

Backend записывает эквивалентно:

```text
S = 2*(L*B + L*H + B*H)
```

Внешнее сопротивление:

```text
R_внеш = 1 / alpha_внеш
alpha_внеш = 11.6 + 7sqrt(v)
```

Подземная формула:

```text
Q = [
      ΔT / (delta_р/lambda_р + delta_из/lambda_из + h/lambda_гр) * S_1
    + ΔT / (delta_р/lambda_р + delta_из/lambda_из + R_внеш) * S
    ] * K + Q_доп
```

Площади подземного цилиндра:

```text
S     = pi*d^2/4 + pi*d*(H-h)
S_1   = pi*d^2/4 + pi*d*h
```

Площади подземного прямоугольного резервуара:

```text
S     = 2*(L+B)*(H-h) + L*B
S_1   = 2*(L+B)*h + L*B
```

Эта логика напрямую реализована как `S_air`, `S_ground`, `q_air`,
`q_ground`.

## Что Взято Из `P-TANK-VAR`

XLSX задает обозначения, единицы и диапазоны.

| Символ | Значение по первоисточнику |
|---|---|
| `dр` | `0.0108..3.0 м` |
| `Tж` | `-90..+600 °C` |
| `Tос` | `-70..+70 °C` |
| `delta_из` | строка задает `0.01..500`; в repo трактуется как слой изоляции в метрах/миллиметрах по текущему контракту |
| `H` | `0.5..200000 м` |
| `delta_р` | `0.001..0.5 м` |
| `lambda_р` | `0.001..400 Вт/(м*К)` |
| `lambda_из_i` | `0.001..400 Вт/(м*К)` |
| `v` | `0..20 м/с` |
| `K` | `1.05..1.7` |
| `alpha_внеш` | `7..52 Вт/(м2*К)` |
| `lambda_гр` | `0.8..3 Вт/(м*К)` |
| `B` | `0..50 м` |
| `L` | `0..50 м` |
| `h` | `0..50 м` |
| `Q_доп` | дополнительные теплопотери, Вт |

Лист 2 также содержит историческое сравнение:

| Метод | Без запаса, Вт | С запасом, Вт |
|---|---:|---:|
| разрабатываемая упрощенная методика | `9829.669571` | `11795.603485` |
| `tscalc` | `8655` | `10386` |
| `BARTEC` | - | `10768` |
| `obogrev-kabel.ru/calculators/` | - | `11118.58` |

Это полезный сигнал, что упрощенная методика может давать числа выше vendor или
онлайн-калькуляторов. Но лист не содержит полного набора исходных условий, так
что это не является полноценным численным benchmark.

## Что Закреплено В Business Contract

`docs/business-logic-contract.md` фиксирует для приложения:

```text
tlt_tank_external_resistance:
R_внеш = 1 / alpha

tlt_tank_total_heat_loss:
Q = q*S*K*K_разм + Q_доп
underground:
Q = (q_возд*S_возд + q_гр*S_гр)*K*K_разм + Q_доп

tlt_tank_heat_loss_no_double_k:
в электрический подбор идет (total_heat_loss / K) / cable_length
```

Контракт также явно отмечает source gap для `location_indoor/location_outdoor`.

## Отличия Текущей Реализации От Первоисточников

| Область | Первоисточник | Сейчас в приложении | Статус |
|---|---|---|---|
| Основная формула | `Q = ΔT/R * S * K + Q_доп` | `Q = q*S*K*location_factor + q_additional` | Ядро совпадает; `location_factor` добавлен как app policy. |
| Подземная формула | Раздельно `S` на воздухе и `S_1` в грунте | `S_air`, `S_ground`, `q_air`, `q_ground` | Совпадает по модели. |
| `R_внеш` | `1 / alpha_внеш` | `1 / alpha` | Совпадает. |
| `alpha` | `11.6 + 7sqrt(v)` | То же для улицы; в помещении `9.0`; manual `alpha_vnesh` имеет приоритет | Улица совпадает; помещение и manual - app contract. |
| Сфера | Не описана в `P-TANK` как отдельная форма | Надземная сфера поддержана через `4*pi*(d/2)^2` | Расширение реализации. |
| Подземная сфера | Не описана | Не поддержана, расчет падает | Соответствует ограничению источника. |
| `location_factor` | Не найден в `P-TANK`/`P-TANK-VAR` | `0.9` для помещения, `1.0` для улицы | Source gap, требуется бизнес-решение или отдельный источник. |
| `wind_factor` | Не найден | В резервуарной формуле не применяется, даже если есть в coefficients | Нет расхождения по резервуару; отличается от трубной реализации. |
| `Q_доп` | Прибавляется после `*K` | Прибавляется после `*K*location_factor` | Совпадает по месту относительно `K`; добавлен `location_factor`. |
| `q = Q/N` для кабеля | DOCX делит итоговое `Q` на длину кабеля `N` | Service перед электроподбором использует `total_heat_loss / K`, затем делит на длину укладки | App correction против двойного `K`. |
| Диаметр | `0.0108..3.0 м` | `0.1..30.0 м` | Drift диапазона. |
| Высота | `0.5..200000 м` | `0.1..50.0 м` | Drift диапазона. |
| `L`, `B` | `0..50 м` | `0.1..100.0 м` | Drift диапазона. |
| `lambda_гр` | `0.8..3.0` | `0.5..3.0` | Drift нижней границы. |
| Локальные элементы | В XLSX есть строка количества локальных элементов | В формуле резервуара локальные элементы не используются | Реализовано через ручное `Q_доп`, не через счетчики. |
| `volume` | В ТНП-формуле не используется | Поле есть в schema, но не влияет на расчет | Неактивное поле. |
| `ground_type` | Справочник грунта | Object validator требует, формула использует только `ground_conductivity` | UI/object metadata. |

## Что Считается Источником Правды Сейчас

Для инженерной сверки:

```text
1. Первичные DOCX/XLSX/PDF/VSDX/справочники
2. docs/tnp/correctness-review.md для спорных мест конверсии
3. docs/business-logic-contract.md как текущий продуктовый контракт
4. backend/app/formulas/heat_loss/tank.py как фактическая реализация
5. backend/app/tests/unit/formulas/test_tank_heat_loss.py как executable evidence
```

Для разработки нельзя молча менять expected/golden значения. Если нужно
изменить формулу или диапазон, нужен новый независимый источник правды:
первоисточник, инженерный расчет, справочник, ТЗ или подписанное продуктовое
решение.
