# Теплопотери трубы: источники и отличия от первоисточников

Дата проверки: 2026-06-04.
Реализация перепроверена против кода 2026-06-08: `pipe.py`,
`schemas/calculation.py`, `project_object_params.py`, `calculation_service.py`
не менялись с момента написания документа, расхождений с описанием не найдено.

Scope: только расчет теплопотерь трубопровода. Резервуары, подбор кабеля и
спецификация упоминаются только там, где они нужны для понимания передачи `q`.

## Короткий Вывод

Физическая основа расчета трубы взята из первичных ТНП-документов:

```text
Q = (Tж - Tос) / R_итого * (L + Lдоп) * K

R_итого = R_стенки + сумма R_изоляции + R_внеш
```

Текущая реализация в backend в основном совпадает с первоисточниками по
цилиндрическим сопротивлениям, наружному сопротивлению на воздухе, грунту,
локальным элементам, `lambda(tm)` изоляции и климатическому `K`.

Главные отличия текущего приложения от первоисточников:

- `location_indoor = 0.9` / `location_outdoor = 1.0` применяются к итоговому
  `Q`, но в проверенных первичных DOCX/XLSX отдельного `K_разм` нет.
- `wind_factor` умножает расчетный `alpha`, но в первоисточниках такого
  множителя нет.
- `ground_conductivity` в backend допускает `0.5..3.0`, а первичная таблица
  труб задает `0.8..3.0`.
- Толщина изоляции в backend допускается `> 0..500 мм`; первичная таблица
  трактуется как рабочий диапазон `10..500 мм`.
- DOCX по трубам дает `q = Q / (L + Lдоп)`, а приложение хранит
  `heat_loss_per_meter` без `K`, чтобы не применить коэффициент запаса второй
  раз в электрическом расчете.
- Defaults сохраненного объекта (`wall_thickness = 0.004`, дефолтные локальные
  элементы и т.п.) являются политикой приложения, а не формулами из DOCX.

## Что Взято Из Первоисточников

### `P-PIPE`: DOCX По Трубопроводам

Подтверждает основную тепловую модель:

```text
тепло идет через стенку трубы -> через изоляцию -> в воздух или грунт
```

Из него взято:

- общая формула полного теплового потока `Q`;
- суммирование сопротивлений `R_стенки + сумма R_из_i + R_внеш`;
- цилиндрическое сопротивление слоя через логарифм;
- наружное сопротивление на воздухе;
- наружное сопротивление в грунте;
- дополнительная длина `Lдоп`;
- формула `q = Q / (L + Lдоп)` в исходном DOCX.

Формула стенки в DOCX использует диаметр и толщину в миллиметрах:

```text
ln(dтр / (dтр - 2 * delta_тр / 1000)) / (2 * pi * lambda_тр)
```

Backend использует радиусы в метрах:

```text
ln(r_outer / r_inner) / (2 * pi * lambda_pipe)
```

Это эквивалентная запись при согласованных единицах.

### `P-PIPE-VAR`: XLSX Переменных Трубы

Из него взяты диапазоны и единицы:

| Символ | Значение по первоисточнику |
|---|---|
| `dтр` | `0.0108..3.0 м` |
| `Tж` | `-90..+600 °C` |
| `Tос` | `-70..+70 °C` |
| `n` | `1..3 слоя` |
| `L` | `0.5..200000 м` |
| `H` | `0..200 м` |
| `n_i` | `0..100` на секцию |
| `delta_тр` | `0.1..40 мм` |
| `lambda_тр` | `0.001..400 Вт/(м*К)` |
| `lambda_из_i` | `0.001..400 Вт/(м*К)` |
| `v` | `0..20 м/с` |
| `K` | `1.05..1.7` |
| `alpha_внеш` | `7..52 Вт/(м2*К)` |
| `lambda_гр` | `0.8..3 Вт/(м*К)` |
| `L_ekv` | `0.1..6.9 м` |

### `P-INSUL`: Справочник Теплоизоляции

Из него взято, что `lambda_из` для справочных материалов не является
постоянной. Она считается как функция расчетной температуры `tm`.

Режимы `tm`:

```text
tm = (Tж + 40) / 2
для открытого воздуха летом, помещения, каналов, тоннелей,
технических подполий, чердаков и подвалов

tm = Tж / 2
для открытого воздуха зимой
```

Backend реализует эту логику через `insulation_temperature_basis`.

### `P-CLIMATE-ALG` И `P-CLIMATE`

Для трубы климатический алгоритм задает:

| Условие | K | Температура среды |
|---|---:|---|
| `D >= 100 мм` | `1.1` | `T1` |
| `D < 100 мм` | `1.12` | `T0` |

В backend это применяется до формулы теплопотерь, если объект использует
климатический источник температуры, а не ручной `ambient_temperature`.

### `P-SOIL`

Используется как справочник `lambda_гр`. В самой формуле трубы грунт входит так:

```text
R_грунта = arccosh(H / r_наружный) / (2 * pi * lambda_гр)
```

DOCX записывает ту же формулу через `ln(x + sqrt(x^2 - 1))`.

### `P-NORM-alpha`

Для наружного воздуха используется:

```text
alpha = 11.6 + 7 * sqrt(v)
```

В backend расчетный наружный `alpha` ограничивается сверху `52`. При `v = 0`
получается `11.6`, поэтому расчетный наружный `alpha` не опускается до `7`.
Диапазон `7..52` относится к ручному/справочному `alpha`.

## Отличия Текущей Реализации От Первоисточников

| Область | Первоисточник | Сейчас в приложении / документах | Статус |
|---|---|---|---|
| Основная формула `Q` | `Q = ΔT / R * (L + Lдоп) * K` | `total_heat_loss = q * effective_length * safety_factor * location_factor` | Совпадает по ядру, но добавлен `location_factor`. |
| Сопротивления трубы и изоляции | Цилиндрические логарифмические сопротивления | Та же модель через радиусы | Совпадает. |
| Наружный воздух | `R_внеш = 1 / (pi * alpha * d_нар_из)`, `alpha = 11.6 + 7sqrt(v)` | Эквивалентно `1 / (2*pi*r*alpha)` | Совпадает. |
| Помещение | В repo-сводке закреплено `alpha = 9.0`; отдельного `K_разм` в первичном DOCX/XLSX нет | `alpha = 9.0` и дополнительно `location_indoor = 0.9` | `location_indoor` требует инженерного/бизнес-подтверждения. |
| Грунт | Формула через `ln[(2H/d)+sqrt((2H/d)^2-1)]` | Эквивалентная `arccosh(H/r)` | Совпадает. |
| Switch подземной ветки | DOCX описывает случай расположения в грунте | Backend включает ветку, если `burial_depth > 0` | Реализационная деталь; `placement=underground` сам по себе не switch формулы. |
| `q` для электроподбора | В DOCX MathML: `q = Q / (L + Lдоп)` | В backend `heat_loss_per_meter = ΔT / R`, без `K`; это используется, чтобы не удвоить запас | Не буквальная копия DOCX; app contract против двойного `K`. |
| `location_factor` | Нет отдельного множителя в проверенных первичных DOCX/XLSX | `location_indoor=0.9`, `location_outdoor=1.0` | App/product policy, source gap. |
| `wind_factor` | Нет в первоисточниках | Админский множитель расчетного `alpha`, после него clamp до `52` | App policy. |
| Диапазон `lambda_гр` | `0.8..3.0` | Backend-схема принимает `0.5..3.0` | Drift, нужно решение. |
| Толщина изоляции | Рабочий диапазон трактуется как `10..500 мм` | Backend принимает `> 0..500 мм` | Drift по нижней границе. |
| Defaults объекта | В DOCX/XLSX нет дефолтных `2 клапана + 2 фланца + 2 опоры` | Object preprocessing добавляет defaults и может увеличить длину на `9 м` | App policy, не первоисточник. |
| `pipe_material = carbon_steel` default | В первичном DOCX нет такого default | Object preprocessing добавляет, если нет `pipe_material` и `pipe_lambda` | App policy. |
| Проверка температуры слоя | `P-INSUL` задает температурные зависимости/диапазоны | Backend проверяет горячую сторону слоя на допустимость материала | Логичная защитная проверка, но не явная формула `P-PIPE`. |
| `surface_temperature` | Не описано как результат в P-PIPE | Backend возвращает `surface_temperature = null` | Реализационная заглушка. |

## Практический Статус

Можно считать подтвержденным первоисточниками:

- многослойная цилиндрическая модель трубы;
- сумма сопротивлений;
- наружное сопротивление на воздухе;
- грунтовое сопротивление через `ln/arccosh`;
- `Lдоп = сумма l_i * n_i`;
- диапазоны диаметра, температур, длины, локальных элементов, `K`, `alpha`,
  `L_ekv`;
- `lambda(tm)` изоляции;
- климатическое правило `D >= 100 мм -> K=1.1`, `D < 100 мм -> K=1.12`.

Нужно отдельно подтвердить или оставить как app policy:

- `location_indoor = 0.9`;
- `wind_factor`;
- расширенный нижний диапазон `ground_conductivity = 0.5`;
- допуск изоляции тоньше `10 мм`;
- дефолтные локальные элементы сохраненного объекта;
- дефолтный материал трубы `carbon_steel`;
- контракт передачи `heat_loss_per_meter` без `K` в электрический расчет.
