## 2. Первичные формулы (извлечены из OMML)

### Труба

```text
[1] Q = (Tж − Tос) / [ 1/(2π·λтр)·ln(dтр/(dтр−2·δтр/1000))
                     + Σ 1/(2π·λиз_i)·ln((dтр+2Σδиз_i)/(dтр+2Σδиз_{i-1}))
                     + Rвнеш ] × (L + Lдоп) × K
[2] Rвнеш(воздух) = 1 / (π·αвнеш·(dтр + 2·Σδиз_i))
[3] αвнеш = 11,6 + 7·√v
[4] Rвнеш(грунт) = 1/(2π·λгр)·ln(2H/D + √((2H/D)² − 1))    # D = dтр+2Σδиз
[5] Lдоп = Σ(li·ni)
```

### Резервуар

```text
[1] Q = (Tж − Tос) / (δр/λр + δиз/λиз + Rвнеш) × S × K
[2] S(круг)  = π·dр²/2 + π·dр·H
[3] S(прям)  = 2·(L+B)·H + 2·L·B
[6] Q(подзем) = [ ΔT/(δр/λр+δиз/λиз+h/λгр)·S1 + ΔT/(δр/λр+δиз/λиз+Rвнеш)·S ] × K
[7] S(возд,круг)  = π·dр²/4 + π·dр·(H−h)
[8] S1(грунт,круг)= π·dр²/4 + π·dр·h
```

## 3. Подтверждено: источник == реализация

- Труба: многослойная цилиндрическая стенка, сумма сопротивлений, грунт через
  `arccosh`, `Lдоп = Σli·ni`, `αвнеш = 11.6 + 7√v`. `Rвнеш(воздух)` источника
  `1/(π·α·D)` эквивалентно коду `1/(2π·r·α)`.
- **λ(T) материалов трубы — точное совпадение** с `pipe_materials.json`:
  углеродистая сталь `60.0 − 0.10·(T+40)`, нерж. `14.0 + 0.01·(T+40)`,
  медь `410.0 − 0.16·(T+40)`, алюминий `242.0 − 0.07·(T+40)`,
  пластик `0.20 + 0.0005·(T+40)`.
- Площади резервуара (круг/прямоугольник) и подземное разбиение `S/S1`.
- Диапазоны трубы: dтр `0.0108–3.0`, Tж `−90..600`, Tос `−70..70`, n `1–3`,
  L `0.5–200000`, δтр `0.1–40 мм`, λ `0.001–400`, v `0–20`, K `1.05–1.7`,
  αвнеш `7–52`, Lекв `0.1–6.9` — совпадают со схемой.
- Суффикс марки `-СТ` (неагрессивная) / `-СР` (агрессивная) и линейная мощность
  серии ТТН/ТТВ/ТТХ.

## 4. Расхождения реализации с источником

| # | Область | Источник | Реализация | Статус |
|---|---|---|---|---|
| 1 | **Rвнеш резервуара** | Формула [4]/[11] = `1/(π·αвнеш·(dтр+2Σδиз))` — цилиндрическая, ссылается на `dтр` | Код: `Rвнеш = 1/α` (плоская стенка) | Источник содержит copy-paste ошибку из трубной формулы; **код физически корректнее**. |
| 2 | `location_factor` (K_разм) | Нет отдельного множителя размещения | `location_indoor=0.9 / outdoor=1.0` множит итог Q | App policy, source gap. |
| 3 | `wind_factor` | Нет | Админский множитель αвнеш | App policy. |
| 4 | `Q_доп` резервуара | В формуле [1] и в списке переменных **отсутствует** | Код прибавляет `q_additional` к Q | Расширение приложения. |
| 5 | λгр | `0.8–3.0` | `0.5–3.0` | Drift нижней границы. |
| 6 | Геометрия резервуара | dр `0.0108–3.0`, H `0.5–200000` | diameter `0.1–30.0`, height `0.1–50.0` | Существенный drift диапазонов. |
| 7 | Толщина изоляции δиз | `0.01…500` (единицы неоднозначны) | `>0..0.5 м` | Нужна сверка единиц. |
| 8 | Сфера | Источник описывает круг и прямоугольник | Код добавляет надземную сферу | Расширение приложения. |
| 9 | Климат | ~622 пункта в `Климат.xlsx` | 539 пунктов в приложении | Расхождение охвата — перепроверить. |

## 5. Крупные пробелы (ТНП требует — реализовано частично/нет)

### 5.1. Полная спецификация аксессуаров

`Расчет_спецификации_трубы_самрег29_05_26.xlsx` задаёт **детальный условный
BOM**, которого нет в коде (`build_basic_specification` делает только кабель +
плоский `accessories.json`):

- Кабельные позиции: `L = Σ(L,секц × N,секц × R,гр)` — с коэффициентом горячего
  резервирования `R,гр` и температурным классом `T,секц`.
- Соединительные комплекты КСН-1/2, КСВ-1/2 по серии и наличию концевых коробок.
- Ремонтные комплекты КСР: `округл.вверх(ΣL/150)` — 1 на 150 м кабеля.
- Коробки СКВ 1201/1202/1601/1602 (+варианты -С/-С1) по условиям
  `dтр ≷ 57 мм`, `N,секц ≷ 3`, индикаторам `К1i/К2i/Кiu`, зоне `Ex`.
- Хомуты ХК30: формула от `dтр` и числа коробок.
- Ленты ЛКС/ЛКВ: `(π·dтр·2.5/1000)·(L/0.3)·1.1`.
- Кабельные вводы (пластик/бронированный по `Ex`), герметики, этикетки,
  заземление, Z-профиль.

Статус: **✅ реализовано 2026-06-08** (формульная часть) —
`formulas/specification/full_builder.py` + `reference_data/spec_accessories.json`,
режим `mode="full"`. Нефформульный «хвост» (КИП, шкаф, монтажные материалы, ЗИП)
остаётся проектными ручными позициями (расширенная БД).

### 5.3. Линейка ТТН/ТТВ/ТТХ: коэффициенты q_б и номиналы

VSDX-блок «Выбор марки кабеля» объявляет параметры мощности линеек как
`Q1(i,j)` (ТТН), `Q2(i,j)` (ТТВ), `Q3(i,j)` (ТТХ), где `Q(i,0)` — номинал,
`Q(i,1)`, `Q(i,2)` — коэффициенты, и отсылает к «табл. формулы для qб для разных
типов кабеля». Формула: `q_б(T3) = q1·T3 + q2`.

В коде это `backend/app/reference_data/cables_tt.json` (поля `series`,
`nominal_power`, `q1`, `q2`, `max_product_temp`, `max_vapor_temp`, `voltage`).
Входы `T1/T2/T3/R/POб` — это `process_temperature` / `vapor_temperature` /
`maintain_temperature` / `aggressive_product` / `required_power_per_meter`.

Открытые вопросы по данным:

| Проблема | Детали | Статус |
|---|---|---|
| **Нет первичной таблицы q_б** | VSDX ссылается на «табл. формулы для qб», но самого файла с коэффициентами `q1/q2` в `ТНП/` нет (есть только λ(T) материалов). Происхождение значений `q1/q2` в `cables_tt.json` первоисточником не подтверждается. | **Needs source** — запросить у заказчика таблицу q_б. |
| **Расхождение номиналов ТТН** | `Расчет_спецификации_трубы_самрег29_05_26.xlsx` («Список материалов Самрег») даёт ТТН **10 / 17 / 25 / 31**, а `cables_tt.json` — **10 / 15 / 25 / 33**. Номиналы 17↔15 и 31↔33 не совпадают. | **Needs business decision** — какой набор актуален. |
| **Суффикс для ТТВ/ТТХ** | В спец-XLSX позиции ТТВ/ТТХ существуют только как `-СР`; для ТТН есть и `-СТ`, и `-СР`. Код же формирует `-СТ`/`-СР` для любой серии по `aggressive_product`, т.е. может выдать несуществующую марку вида `15ТТВ2-СТ`. | **Needs correction** — ограничить суффикс по серии. |

## 6. Замечания к качеству первоисточников (для заказчика)

- **Tank Rвнеш формула [4]/[11]** скопирована из трубной (цилиндрическая, с
  `dтр` и Σδиз) — для плоской стенки резервуара это ошибка. Приложение её не
  повторяет.
- Список переменных резервуара: `H` подписан как «высота резервуара», но
  диапазон `0.5–200000` явно скопирован из длины трубопровода; `B/L/h` без
  явных диапазонов.
- `δиз = 0.01…500` без явных единиц (м или мм) в обоих списках.
- Benchmark-лист резервуара: «упрощённая методика» `9829.67 / 11795.60 Вт` против
  `tscalc 8655 / 10386`, `BARTEC 10768`, `obogrev-kabel 11118.58`. Методика даёт
  ~12–14% выше tscalc, но полного набора входов нет → это **не** строгий
  численный benchmark.

## 7. Вывод

- Расчётное ядро теплопотерь и подбора саморега **соответствует** первичным ТНП
  по физике, формулам и (в основном) диапазонам; λ(T) материалов совпадает точно.
- Реализация местами **сознательно отклоняется** от буквального источника
  (Rвнеш резервуара — в лучшую сторону; диапазоны геометрии, λгр; `Q_доп`,
  `location_factor`, `wind_factor`, сфера — app policy/расширения).
- Главный незакрытый объём из ТНП — **полная условная спецификация аксессуаров**
  (целый XLSX-алгоритм), а также шифрование формул/справочников, MI/скин и
  полноценный multi-variant.
- По линейке ТТН/ТТВ/ТТХ есть **разрыв данных**: первичная таблица `q_б`
  (`q1/q2`) в `ТНП/` отсутствует, а номиналы ТТН в спец-XLSX (17/31) не совпадают
  с `cables_tt.json` (15/33) — нужно подтверждение источника и актуального набора.
- Связанные документы: `heat-loss/*-source-traceability.md` (детальная сверка
  теплопотерь), `electrical/*` и `specification/*` (реализованные алгоритмы).
