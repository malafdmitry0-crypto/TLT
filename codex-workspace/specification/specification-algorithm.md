# Алгоритм формирования спецификации

Источник: backend-код `formulas/specification/builder.py`
(`build_basic_specification`). Дата сверки с кодом: 2026-06-08.

## Назначение

Базовая спецификация = строки кабеля (из успешных электрорасчётов) + базовые
аксессуары из встроенного каталога (`accessories.json` через
`list_basic_accessories()`). Расширенный режим сотрудника (внешняя БД,
группировка, ручные позиции) реализован отдельно в сервисном слое и не входит
в эту чистую функцию.

## Вход

```text
electrical_results: list[dict]   # результаты электрорасчёта по объектам
total_objects_count: int | null  # общее число объектов проекта
```

## Кабельные Позиции

Строятся только по **успешным** результатам — `is_successful_electrical_result`:
есть выбранная марка и нет structured issue-полей (`error_code`, `category`,
`stale`).

Для каждого успешного результата:

```text
cable  = cable_snapshot.cable_mark  или  result.cable_mark  или  result.selected_cable
length = cable_snapshot.commercial_context.required_order_length
         или  result.commercial.required_order_length
         или  result.order_cable_length
если cable и length: cable_totals[cable] += length
```

Длины суммируются по марке кабеля. Приоритет источника длины — длина заказа из
commercial-контекста (учитывает кратность/min-order), затем общая
`order_cable_length` (× 1.1 монтажный запас).

Для каждой марки создаётся одна позиция:

```text
category = "Кабель"
name     = "Греющий кабель {марка}"
article  = commercial.article  или  марка
unit     = "м"
quantity = round(суммарная длина, 2)
params   = {cable_mark, supplier_name, price_per_meter, currency}
```

## Аксессуары

```text
accessory_count = total_objects_count  если задан,
                  иначе len(electrical_results)   # legacy fallback
```

Важно: аксессуары (УЗО, муфты, термостаты и т.п.) заказываются на **каждый
заявленный объект**, а не только на успешно рассчитанные — иначе заказчик
недополучит оборудование для объектов, где кабель будет подобран вручную позже.

Для каждого аксессуара каталога:

```text
quantity = per_object × accessory_count
category, name, article, unit берутся из строки каталога
```

## Сортировка

```text
items.sort(по (category, name))
```

## Что Важно (базовый режим)

- Кабель — только по успешным расчётам; аксессуары — по всем объектам проекта.
- Длина берётся как длина заказа (с монтажным запасом и кратностью), а не
  установленная длина.
- Одинаковые марки агрегируются в одну строку с суммой длин.

# Полная спецификация (условный BOM ТНП)

Реализация: `formulas/specification/full_builder.py`
(`build_full_specification`). Каталог правил:
`reference_data/spec_accessories.json`. Источник:
`ТНП/Расчет_спецификации_трубы_самрег29_05_26.xlsx` (лист «Список материалов
Самрег»). Режим включается `mode="full"` (для Сотрудника; Гость — всегда базовая).
Дата сверки с кодом: 2026-06-08.

## Вход

```text
electrical_results  # успешные позиции: cable_mark, num_circuits,
                    # installed_cable_length, object_id
objects_by_id       # object_id -> {outer_diameter (м), pipe_length (м)}
options             # SpecificationOptions: reserve_coefficient (R,гр),
                    # ex_zone, indication_on_boxes (К1i),
                    # end_section_indication (К2i), top_indication (Кiu),
                    # min_length_for_end_indication (L,К2i)
```

На позицию: `T,секц` — класс (низк.: ТТН/ТЛТ; выс.: ТТВ/ТТХ),
`dтр` = outer_diameter×1000 мм, `N,секц` = num_circuits,
`L,секц·N,секц` = installed_cable_length.

## Кабель

```text
L по марке = Σ(installed_cable_length × R,гр)
L1 = Σ низкотемпературных, L2 = Σ высокотемпературных
```

## Коробки СКВ (Nk1…Nk12)

На позицию `ceil(N,секц/3)` в одну корзину по условиям:

```text
приоритет: К2i (с L,секц≥L,К2i) -> К1i -> обычная
большой dтр (>57): обычная N<3=Nk1(1201) / N≥3=Nk2(1601);
                   К1i: Кiu? Nk4(1601-С1):Nk3(1601-С);
                   К2i: Кiu? Nk6(1201-С1):Nk5(1201-С)
малый dтр (≤57):   обычная N<3=Nk7(1202) / N≥3=Nk8(1602);
                   К1i: Кiu? Nk12:Nk11; К2i: Кiu? Nk10:Nk9
```

## Комплекты, вводы, крепёж, ленты, маркировка

```text
КСН-1 = Σ N низк.×R,гр; КСВ-1 = Σ N выс.×R,гр
КСН-2/КСВ-2 = ×2 (только при К2i)
КСР-1 = ceil(ΣL1/150); КСР-2 = ceil(ΣL2/150)
ввод пластиковый (Ex=нет) / бронированный (Ex=да) = Nk1+Nk2+Nk3+Nk4+Nk7
устройство ввода под изоляцию / Z-профиль = Nk7…Nk12
хомут ХК30 = Σ_i (((dтр·π·1.2)+50)/1000)·2·ceil(N/3)   # коробки больших d (Nk1..Nk6)
крепёжный элемент = (Nk1+Nk2+Nk3+Nk4)·2
ЛКС12 (низк.) = Σ ((π·dтр·2.5/1000)·(Lпоз/0.3))·1.1; ЛКВ12 (выс.) — аналогично
лента алюминиевая = ΣL1+ΣL2
клей NEO = Fl1+Fl2+Fl3+Fl4; герметик = Nk1+Nk2+Nk3+Nk4
этикетка «Внимание электрообогрев» = Σ ceil(Lтр/3.5)
наклейка «Заземление» = Nk1+Nk2+Nk3+Nk4+Nk7+Nk8+Nk11+Nk12
```

## Что Важно (полный режим)

- Считается только **формульная** часть ТНП-листа (кабель + ~25 групп
  аксессуаров с условиями). «Хвост» источника (КИП, шкаф управления, монтажные
  кабели/лотки/трубы, ЗИП) формул не имеет — это проектные ручные позиции,
  не считаются автоматически.
- Параметры `R,гр / Ex / К1i / К2i / Кiu` берутся из `options` с дефолтами
  (R,гр=1.0, остальное — нет); UI спецификации даёт Сотруднику переключатели
  Ex и резерва.
- Кабель в полном режиме берётся как `installed × R,гр` (модель ТНП), а не как
  order-length ×1.1 базового режима.
- Расширенная спецификация (внешняя БД, ручные позиции, аналоги) — отдельный
  сервисный слой (`specification_service.py`), поверх любого режима.
