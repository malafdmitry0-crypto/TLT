# Спецификация: документация алгоритма

Описание фактической реализации формирования спецификации в TLT. Источник
истины — backend-код. Дата сверки с кодом: **2026-06-08**.

## Карта документов

Документы двух типов: **технический** (для программиста/нейронки) и
**инженерный** (простым языком).

### Для программиста / нейронки (код-уровень)

| Файл | Содержание |
|---|---|
| `specification-algorithm.md` | Базовая спецификация (`mode="basic"`): кабель + минимум аксессуаров; **и полная** (`mode="full"`): условный BOM ТНП (`full_builder.py` + `spec_accessories.json`). |

### Для инженера (простым языком)

| Файл | Содержание |
|---|---|
| `specification-engineer-explanation.md` | Что попадает в спецификацию, почему кабель только по успешным расчётам, а аксессуары — на все объекты. |

## Ключевые инварианты (подтверждены кодом)

- Кабель — только по **успешным** электрорасчётам (есть марка, нет
  `error_code`/`category`/`stale`).
- Аксессуары — по числу **всех** объектов проекта (`total_objects_count`), а не
  только успешно рассчитанных.
- Длина кабеля = длина заказа (учёт монтажного запаса × 1.1, кратности,
  min-order), агрегируется по марке.
- Сортировка позиций: `категория → название`.
- Расширенная спецификация сотрудника (внешняя БД, ручные позиции,
  группировка) реализована в сервисном слое, вне чистой функции
  `build_basic_specification`.
