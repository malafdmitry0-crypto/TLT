## EPIC-E-1. Авторизация и сессия Сотрудника

### US-E-01 · Вход по логину и паролю · Must · ✅

**Как** Сотрудник, **я хочу** войти по корпоративному e-mail и паролю, **чтобы**
получить доступ к своим и чужим проектам с полным функционалом.

**Критерии приёмки:**
- На главной — кнопка «Войти как сотрудник», форма «Логин (e-mail)» + «Пароль».
- Успех → «Проводник проектов».
- Неверные данные → «Неверный логин или пароль» (пароль не раскрывается);
  неактивный аккаунт → «Учётная запись отключена, обратитесь к администратору».
- Сессия без лимита «1 проект» и без авто-удаления по неактивности (продление
  токена).

**Связь:** UC-E-01 · `POST /auth/login`, `core/security.py` (JWT 30м/7д).

## EPIC-E-2. Управление проектами в проводнике

### US-E-02 · Проводник проектов с поиском и фильтром · Must · ✅

**Критерии приёмки:**
- Стартовая страница — таблица проектов: название, номер задачи, владелец, даты
  создания/изменения, число объектов, состояние расчёта.
- Поиск по подстроке (название/номер задачи).
- Фильтры: тип объектов (трубы/резервуары/оба), год, номер задачи, владелец.
- Сортировка по любой колонке; клик по строке открывает проект.

**Связь:** UC-E-02 · `GET /projects` + фильтры.

### US-E-03 · Создание нового проекта (без замены) · Must · ✅

**Критерии приёмки:**
- Кнопка «Новый проект»; форма «Название» (обязат.), «Номер задачи», «Описание».
- Создаётся проект «Черновик», владелец = текущий Сотрудник; другие проекты не
  затрагиваются; открывается рабочий стол нового проекта.

**Связь:** UC-E-03 · `POST /projects`.

### US-E-04 · Редактирование свойств проекта · Must · ✅

**Критерии приёмки:** операция «Редактировать свойства»; поля: название, номер
задачи, описание, статус («Черновик»/«Завершён»); изменения видны в проводнике.

**Связь:** UC-E-04 · `PUT /projects/{id}`.

### US-E-05 · Удаление проекта из списка · Must · ✅

**Критерии приёмки:** «Удалить» с подтверждением; каскадное удаление данных;
у Сотрудника может быть ноль проектов (без автосоздания).

**Связь:** UC-E-05 · `DELETE /projects/{id}`.

### US-E-06 · Импорт проекта из CSV (без замены) · Must · ✅

**Критерии приёмки:**
- «Загрузить из CSV» создаёт **новый** проект (владелец — текущий Сотрудник),
  существующие не удаляются.
- Восстанавливаются общие данные/объекты/электрорасчёт/спецификация.
- Некорректный файл отклоняется; конфликт `task_number` → суффикс «(импорт)».

**Связь:** UC-E-06 · `POST /projects/import-csv-bulk`.

### US-E-07 · Создание проекта на основании другого · Should · ✅

**Критерии приёмки:**
- «Создать на основании» в строке проводника; новый проект «‹исходное› (копия)»,
  «Черновик», владелец — текущий Сотрудник (даже если исходный чужой).
- Копируются `params` объектов и порядок; результаты пересчитываются заново.

**Связь:** UC-E-07 · `POST /projects/{id}/duplicate`.

## EPIC-E-3. Командная работа

### US-E-08 · Приватность гостевых проектов и рабочий список · Must · ✅

**Критерии приёмки:**
- В проводнике не видны гостевые проекты подрядчиков; видны проекты других
  сотрудников.
- Запрос Сотрудника к гостевому проекту → `403`; к чужому проекту сотрудника —
  чтение разрешено, изменение/удаление → `403`.
- Администратор имеет полный доступ ко всем проектам.

**Связь:** UC-E-08 · фильтрация владельца в `project_service`.

## EPIC-E-4. Экспорт отчёта в файлы

### US-E-09 · Экспорт отчёта в PDF / DOCX / XLSX · Must · ✅

**Критерии приёмки:**
- Три кнопки экспорта; содержимое — по «Требования к отчёту».
- Корректные MIME-типы, имя «‹номер задачи›_‹название›.‹ext›» (кириллица).
- Тот же endpoint Гостем → сообщение о недоступности.

**Связь:** UC-E-09 · `GET /reports/{id}/export/{fmt}`, `reports/*_generator.py`.
Открытый вопрос — корпоративный визуальный шаблон.

### US-E-12 · Мастер выбора состава отчёта · Must · ✅

**Критерии приёмки:**
- Кнопка «⚙ Состав отчёта» открывает модалку с чекбоксами разделов (титул, общие
  данные, исходные данные, теплопотери, электрорасчёт, спецификация, справочная
  часть).
- Селектор CO: «Активный», «Все сводно», «Конкретный».
- «Применить» сохраняет состав в проекте; ≥ 1 раздел обязателен (VAL-63);
  сводный по CO — при ≥ 2 вариантов (VAL-64).

**Связь:** UC-E-12 · `ReportPage.tsx`. Финальный состав разделов — открытый
вопрос (Q-H / Q-01…25).

### US-E-13 · Сводный отчёт по нескольким вариантам CO · Should · ✅

**Критерии приёмки:**
- Режим «Все варианты сводно»; в разделах «Электрорасчёт» и «Спецификация» —
  данные по каждому CO; активный отмечен ★; доступно во всех форматах.

**Связь:** UC-E-13 · `report_service.py`.

## EPIC-E-5. Расширенная конфигурация Сотрудника

### US-E-10 · Переключение базы расчёта (встроенная / внешняя) · Must · ✅

**Критерии приёмки:**
- Тогглер «База расчёта»: Встроенная / Расширенная внешняя.
- При «Внешней» Select марок/аксессуаров расширяется позициями из БД.
- Гостю недоступно (всегда встроенная, VAL-62); выбор хранится в `common_data`.
- БД отключена админом → сообщение о недоступности.

**Связь:** UC-E-10 · `cable_source`, `GET /references/cables/extended`.
Структура внешней БД — открытый вопрос Q-G.

### US-E-11 · Расширенная спецификация · Must · ✅

**Критерии приёмки:**
- На SC-05 у Сотрудника: сортировка по колонкам, режим группировки (по
  категории/по объекту), «Заменить на аналог» (список из активной базы),
  «+ Добавить позицию».
- При активной внешней БД — аналоги из расширенного каталога.
- Изменения сохраняются в `specifications` (источник позиции, привязка к CO).

**Связь:** UC-E-11 · `specification_service.py`. Полный условный BOM из ТНП —
