## EPIC-G-1. Сессия и единственный проект (только Гость)

### US-G-01 · Вход без регистрации с авто-созданием проекта · Must · ✅

**Как** внешний проектировщик, **я хочу** начать работу одним нажатием «Войти
без регистрации» и сразу получить рабочий проект, **чтобы** перейти к расчётам
без учётной записи.

**Критерии приёмки:**
- На главной видна кнопка «Войти без регистрации».
- Автоматически создаётся гостевая сессия и **один** пустой проект «Мой проект»,
  он сразу активный.
- Гость попадает на рабочий стол активного проекта (списка проектов нет).
- Виден маркер режима «Гость» и название активного проекта.

**Связь:** UC-G-01 · `POST /auth/guest`, `auth_service.create_guest_session`.

### US-G-03 · Создание нового проекта (с заменой текущего) · Must · ✅

**Как** Гость, **я хочу** создать новый пустой проект с названием, **чтобы**
начать «с чистого листа».

**Критерии приёмки:**
- Операция «Создать новый проект»; форма: «Название» (обязат.), «Номер задачи»,
  «Описание».
- Подтверждение: «Текущий проект и все данные будут удалены. Продолжить?»
  (рекомендуется сначала экспорт CSV, US-G-24).
- После подтверждения текущий проект удаляется, создаётся новый активный.
- В сессии по-прежнему ровно один проект.

**Связь:** UC-G-02 · `project_service.create_project` (лимит 1).

### US-G-06 · Удаление текущего проекта · Must · ✅

**Как** Гость, **я хочу** удалить текущий проект одной операцией, **чтобы**
очистить рабочее пространство.

**Критерии приёмки:**
- Операция «Удалить текущий проект» с подтверждением о безвозвратности.
- Удаляются проект и все данные (объекты, расчёты, спецификация).
- На месте удалённого автоматически создаётся пустой «Мой проект».

**Связь:** UC-G-04 · `DELETE /projects/{id}`.

### US-G-07 · Авто-завершение сессии по неактивности · Must · ✅

**Как** владелец системы, **я хочу** чтобы данные неактивного Гостя удалялись,
**чтобы** обеспечить конфиденциальность и не копить мусор.

**Критерии приёмки:**
- Любое действие продлевает сессию; без действий > 20 минут — удаление.
- Вместе с сессией удаляются все проекты и данные (каскад).
- После удаления предлагается войти заново.

**Связь:** UC-G-21 · `_periodic_guest_cleanup` (lifespan), TTL из `config.py`.

## EPIC-G-2. Общие параметры проекта (Гость + Сотрудник)

в каждом объекте.

**Критерии приёмки:**

- Поля: климатический регион, T окружающей среды, напряжение (220/380),
  K запаса, тип прокладки (надземная/подземная), глубина заложения.
- Значения предзаполняют новые объекты; локально переопределяемы.
- При изменении после добавления объектов — предложение пересчитать все.

**Связь:** UC-G-06 · `ObjectWizard.tsx`, `common_data` проекта.

## EPIC-G-3. Ввод объектов и расчёт теплопотерь (Гость + Сотрудник)

### US-G-10 · Добавление трубопровода (плоская форма) · Must · ✅

**Как** Гость, **я хочу** добавить трубопровод через единую плоскую форму (все
поля сразу, ориентир «Тепломаг»), **чтобы** видеть всё в одном месте.

**Критерии приёмки:**
- Постоянно видна плоская форма со всеми полями (геометрия, теплофизика,
  изоляция, температуры, арматура) — часть основного интерфейса, не модалка.
- Шагов/вкладок «Далее» нет; клик по строке → форма в режиме редактирования;
  «+ Добавить» → форма очищается под новую запись.
- Обязательные: нар. диаметр, длина, толщина стенки, материал и толщина
  изоляции, T продукта, T среды. Опциональные: арматура и Lекв, ветер, тип
  прокладки, глубина.
- 1–3 слоя изоляции; имя объекта формируется автоматически.
- После сохранения теплопотери считаются автоматически.

**Связь:** UC-G-07 · `calc_pipe_heat_loss`, `POST /objects`,
[`../heat-loss/pipe-algorithm.md`](../heat-loss/pipe-algorithm.md).

### US-G-11 · Добавление резервуара · Must · ✅

**Как** Гость, **я хочу** добавить резервуар (цилиндр/параллелепипед/шар) и
получить расчёт, **чтобы** определить потребность в обогреве ёмкости.

**Критерии приёмки:**
- «+ Добавить» в режиме «Резервуар» переключает форму, первая колонка —
  «Форма и геометрия резервуара».
- Формы: цилиндр (d+H), параллелепипед (L+W+H), шар (d).
- Изоляция и температуры — как у трубы; площадь и Q считаются автоматически.

**Связь:** UC-G-08 · `calc_tank_heat_loss`,
[`../heat-loss/tank-algorithm.md`](../heat-loss/tank-algorithm.md).

### US-G-12 · Ручной ввод параметров вместо справочных · Must · ✅

**Как** Гость, **я хочу** задавать параметры вручную (в первую очередь λ
изоляции через «Другое»), **чтобы** использовать материалы вне справочника.

**Критерии приёмки:**
- В списке материалов последним пунктом «Другое» → обязательное «λ, Вт/(м·К)»
  (0,001…400), используется вместо табличного.
- Где включён ручной ввод, в форме виден переключатель «Из справочника /
  Вручную».
- Полный перечень ручных параметров — на согласовании (Q-A).

**Связь:** UC-G-13 · `InsulationLayer(material="other")`.

### US-G-13 · Редактирование объекта с авто-пересчётом · Must · ✅

**Критерии приёмки:** клик по строке наполняет форму; после сохранения

## EPIC-G-4. Электротехнический расчёт (Гость + Сотрудник)

### US-G-18 · Автоматический подбор кабеля для всех объектов · Must · ✅

**Критерии приёмки:**
- Кнопка «Выполнить электрорасчёт».
- Для марки «Авто» подбирается марка из активной базы с учётом типа кабеля и
  активного CO.
- Массовый автоподбор **не перезаписывает** ручные марки (только по чекбоксу).
- По объекту: тип, марка, длина, мощность, ток; результат по каждому варианту.
- Нет подходящей марки → статус «Ошибка» с пояснением, остальные считаются.
- Страница «Электрорасчёт»: сводка (длина/мощность/ток) + карточки объектов.

**Связь:** UC-G-14 · `POST /calc/electrical/batch`, `batch_calc_electrical`,
[`../electrical/electrical-orchestration.md`](../electrical/electrical-orchestration.md).

### US-G-19 · Выбор типа и марки кабеля на странице «Электрорасчёт» · Must · ✅

**Критерии приёмки:**
- Для выделенного объекта форма «Кабель»: тип (4 значения), марка («Авто» +
  марки типа), шаг навива, нитки.
- «Авто» по умолчанию; параметры пишутся в текущий CO; переключение CO —
  вкладками.
- Допускается кабель с удельной мощностью меньше линейных теплопотерь (проверка
  по совокупной мощности, US-G-20); недостаток → «Ошибка».
- На странице «Теплопотери» колонок кабеля нет.

**Связь:** UC-G-15, UC-G-25 · `CableSelector.tsx`, dispatch
`_calculate_electrical_result`.

### US-G-20 · Навив и несколько ниток · Must · ✅

**Критерии приёмки:**
- Поля «Шаг навива» (мм) и «Нитки» (1/2/3) для саморег/одножильного/трёхжильного.
- Для MI навив запрещён (шаг 0, ниток 1).
- Шаг 0 = прямая укладка; длина пересчитывается с навивом и нитками.
- Совокупная мощность «уд. мощность × длина × нитки» ≥ теплопотерь объекта.
- Шаг ≤ нар. диаметра трубы → отклоняется с сообщением.

**Связь:** UC-G-16 · `_winding_coefficient` (cap по диаметру),
[`../electrical/electrical-orchestration.md`](../electrical/electrical-orchestration.md).

### US-G-29 · Выбор типа греющего кабеля · Must · ✅ (mineral/skin — бэклог)

**Критерии приёмки:**
- Select «Тип кабеля»: саморегулирующийся (ТЛТ, по умолчанию), одножильный
  постоянной мощности, трёхжильный постоянной мощности, кабель с минеральной
  изоляцией.
- Смена типа обновляет список марок; навив применим ко всем, кроме MI.
- Тип и марка пишутся в выбранный CO; на SC-03 полей кабеля нет.

**Статус:** саморег (ТЛТ, ТТН/ТТВ/ТТХ), одножильный (ТТ Р1), трёхжильный (ТТ Р3)
— ✅; **MI — не реализован** (US-TODO-02); скин (Q-E) — US-TODO-03.

**Связь:** UC-G-25 · [`../electrical/`](../electrical/README.md).

## EPIC-G-7. Множественные варианты расчёта CO1…CO4 (Гость + Сотрудник)

### US-G-30 · Создание нескольких вариантов расчёта · Must · ✅

**Критерии приёмки:**
- По умолчанию один вариант CO1; на SC-04 — CO-вкладки + кнопки «Сделать
  активным / Переименовать / Удалить / Пересчитать».
- «+ Добавить вариант» создаёт CO2…CO4 копией параметров кабеля.
- «Создать на основании» копирует строки электрорасчёта из source CO с
  exact-check марки (валидный ручной выбор сохраняется, не заменяется
  автоподбором); непрошедшие → structured error.
- Лимит 4 варианта (VAL-59); удаление кроме единственного.
- На SC-03 CO не отображается.

**Связь:** UC-G-26 · `variant_number`.

### US-G-32 · Выбор активного варианта · Must · ✅

**Критерии приёмки:**
- Кнопка «★ Сделать активным»; активен только один (VAL-60), отмечен ★.
- Смена активного → спецификация и отчёт пересчитываются под него; теплопотери
  от CO не зависят.

**Связь:** UC-G-28 · `variant_number`.
