## 0. Контекст — что уже есть

### 0.1 Краткая суть продукта

Веб-приложение для инженеров-проектировщиков, которое:
- Принимает параметры обогреваемых объектов (трубопроводы, резервуары) — геометрия,
  изоляция, температуры, условия среды
- Автоматически вычисляет тепловые потери по методике ТНП (формулы Фурье для
  цилиндрической/плоской стенки, грунт, ветер, многослойная изоляция)
- Подбирает греющий кабель (саморегулирующийся ТЛТ, ТТН/ТТВ/ТТХ, резистивный ТТ Р1/Р3)
- Формирует спецификацию оборудования и отчёт (HTML-превью + экспорт PDF/DOCX/XLSX)
- Поддерживает 4 варианта расчёта (CO1..CO4) для сравнения альтернатив

### 0.2 Технологический стек

| Слой | Стек |
|---|---|
| Frontend | React 18, TypeScript, Vite, Ant Design 5, Zustand, TanStack Query v5, @dnd-kit |
| Backend | Python 3.11+, FastAPI, SQLAlchemy 2.x async, Alembic, PostgreSQL 16 |
| Инфраструктура | Docker + docker-compose, nginx/Caddy, Redis (rate limiter) |
| Тестирование | pytest (799 тестов), Vitest + RTL (212), Playwright e2e (48) |

### 0.3 Ролевая модель

| Роль | Вход | Ключевые ограничения |
|---|---|---|
| Гость | Без регистрации, 1 проект, TTL 20 мин | Нет экспорта отчётов, нет внешней БД, нет проводника |
| Сотрудник | Email + пароль, JWT | Полный функционал, включая чужие проекты |
| Администратор | Email + пароль | Управление пользователями, коэффициентами, внешней БД |

### 0.4 Расчётное ядро (что уже умеет)

- **Трубопроводы:** многослойная цилиндрическая стенка (1–3 слоя изоляции), грунт,
  ветер (α = 11,6 + 7·√v по SNiP 41-03-2003), стенка трубы, λ(T) материалов
- **Резервуары:** цилиндр / параллелепипед / шар, плоская стенка, подземная часть
- **Кабели:** ТЛТ (10 марок, 10–100 Вт/м), ТТН/ТТВ/ТТХ, ТТ Р1 (single_core),
  ТТ Р3 (three_core). MI и скин-системы — только как типы без формул.
- **Навив и несколько ниток:** реализовано для саморегулирующихся и резистивных
- **Справочники:** 539 городов РФ (климат), 6 материалов изоляции, грунты, материалы труб

### 0.5 Что НЕ сделано (подтверждённый бэклог)

| Зона | Статус |
|---|---|
| Формулы для MI-кабеля и скин-систем | Нет методики расчёта |
| Новые типы объектов (насосы, площадки) | Нет формул и UI |
| Audit log / снапшот коэффициентов | Нет воспроизводимости исторических расчётов |
| Шифрование формул/справочников (раздел 5 ТЗ) | Не реализовано |
| Inline-редактирование таблиц (Excel-like) | Частично (drag-and-drop есть, inline нет) |
| Финальный шаблон отчёта | Рабочий, но не утверждённый корпоративный |
| Горизонтальное масштабирование | Одноинстансный деплой |

### 0.6 Ключевые архитектурные решения

- Встроенная плоская форма SC-03 (не пошаговый wizard) — все поля видны сразу,
  ориентир — программа «Тепломаг»
- Конвертация мм ↔ м на фронте (форма в мм, API в метрах)
- CO-варианты живут на странице «Электрорасчёт» (SC-04), не на странице теплопотерь
- Zustand + localStorage для персистентности состояния на фронте
- In-memory → Redis rate limiter для защиты гостевого входа
- Каскадное удаление гостевых сессий (TTL + фоновая очистка)

### 0.7 Программа-ориентир

Заказчик при формулировании требований ссылается на программу-аналог **«Тепломаг»**
как на ориентир по UX и подходу к работе с таблицами исходных данных и выбору кабеля.

## 1. Твоя задача

Ты — senior systems engineer, которому дали карт-бланш на предложение **продвинутого
функционала следующего поколения** для этой системы. Твоя задача — **не** просто
закрыть бэклог (это скучно), а предложить то, что выведет продукт на принципиально
новый уровень — функционально, архитектурно и коммерчески.

### 1.1 Требования к выходному документу

Создай **единый структурированный документ** (Markdown), содержащий
**не менее 12 конкретных предложений** продвинутого функционала. Каждое предложение
должно быть оформлено по единому шаблону:

```
### F-XX. [Название фичи — ёмкое, инженерное, на русском]

**Категория:** [Одна из: Расчётное ядро / UX и интерфейс / Интеграции /
Архитектура и инфраструктура / Коммерциализация и безопасность /
Аналитика и AI]

**Приоритет:** [P0 — стратегический / P1 — тактический / P2 — на вырост]

**Аналоги:** 1–3 реальных продукта/решения, где подобное уже работает
(или близкие аналоги). С указанием конкретных названий (Revit, ANSYS,
Тепломаг, Trimble, SmartPlant, AVEVA, AutoCAD Plant 3D, COMOS, Bentley,
EPLAN, SEE Electrical, dsolidworks, любые другие — чем точнее, тем лучше).

**Проблема, которую решаем:** 2–4 предложения. Какую боль пользователя /
бизнеса закрывает фича? Почему текущего функционала недостаточно?

**Инженерное описание:** 8–15 предложений. Что конкретно делаем, как это
работает с точки зрения инженера-пользователя, какие данные на входе/выходе.
Опиши основные экраны/потоки, ключевые алгоритмические или архитектурные
решения.

**Технический контур:** 5–10 предложений. Какие компоненты стека
затрагиваются (фронт / бэк / БД / инфраструктура), какие новые зависимости
или сервисы потребуются, какие изменения в модели данных. Оцени сложность:
Low (1–2 спринта) / Medium (3–5 спринтов) / High (6+ спринтов).

**Почему это «продвинуто»:** 2–3 предложения. Чем это отличается от того,
что есть сейчас, и почему это даёт конкурентное преимущество.

**Риски и ограничения:** 2–4 предложения. Что может пойти не так, какие
данные или согласования потребуются от заказчика, что может заблокировать
реализацию.
```

### 1.3 Стиль мышления

- **Думай как инженер, который проектирует реальную систему**, а не как
  маркетолог, рисующий слайды. За каждой фичей должно стоять понимание:
  какие байты куда пойдут, какие таблицы появятся в БД, какие вызовы API
  будут сделаны.
- **Ссылайся на реальные аналоги.** Если предлагаешь 3D-визуализацию —
  укажи, что в Trimble SysQue или AVEVA E3D это сделано так-то, и мы можем
  пойти похожим путём (или лучше). Если предлагаешь TCO-калькулятор — укажи,
  что в Bentley AutoPIPE или в «СТАРТ-Проф» это реализовано через модуль X.
- **Будь конкретен в цифрах.** Не «ускорит работу», а «сократит время ввода
  проекта со 100 трубами с 4 часов до 45 минут». Не «повысит точность», а
  «снизит ошибку подбора кабеля с ±15% до ±3% за счёт учёта фактора Y».
- **Учитывай российскую специфику.** Продукт ориентирован на рынок РФ и СНГ:
  нормативы (СНиП, СП, ГОСТ Р), климатические справочники (ТНП), типовые
  проектные организации (ПТО, НИПИ, генподрядчики нефтегазового сектора).
  Но не замыкайся только на РФ — думай о потенциале выхода на международный
  рынок (IEC, IEEE, UL).
- **Предлагай неочевидное.** Сделать «ещё один тип кабеля» — это не продвинуто.
  Сделать «систему, которая по тепловизионному снимку с дрона сама определяет
  участки с нарушенной изоляцией и автоматически пересчитывает проект» — вот
  это продвинуто.

### 1.4 Что не нужно делать

- **Не предлагай закрытие текущего бэклога** — это не «продвинутый функционал»,
  а рутина. MI-кабель, скин-системы, inline-редактирование, шаблон отчёта —
  это всё должны сделать в любом случае, не трать на это слоты.
- **Не предлагай «сделать тёмную тему»** или «добавить уведомления в Telegram» —
  это микрофичи, не тянут на «продвинутый функционал следующего поколения».
- **Не пиши общими словами** вроде «использовать облачные технологии» или
  «внедрить Big Data» без конкретного инженерного наполнения. Если облака —
  то какие сервисы, какой оркестратор, какая модель данных в объектном
  хранилище. Если Big Data — то какой пайплайн (Kafka → Spark → ClickHouse?)
  и какие конкретно инсайты извлекаем.
- **Не ограничивай себя текущим стеком.** Если для фичи нужен Rust, WebAssembly,
  WebGL, Kafka, K8s, GPU-расчёты, специализированная СУБД (TimescaleDB,
  PostGIS) — предлагай. Но обосновывай выбор.
- **Код не трогаем.** Результат работы — только документация (Markdown-файл).
  Никаких правок в исходники, миграции, конфиги, docker-файлы. Это чисто
  аналитический этап: исследование → proposals → документ. Реализация —
  отдельной задачей, после утверждения propositions заказчиком.

## 3. Напутствие

Представь, что ты — ведущий инженер, которому дали бюджет в 40 млн рублей и
команду из 8 разработчиков на полтора года. Твоя задача — не «допилить» текущий
MVP до состояния «ну, работает», а создать продукт, который через 2 года
станет **отраслевым стандартом** для проектирования систем электрообогрева
в нефтегазовом секторе РФ и СНГ — а затем и за их пределами.

Конкуренты не дремлют: «Тепломаг» развивает облачную версию, западные
вендоры (Thermon, nVent RAYCHEM, Pentair) вкладываются в цифровизацию
своих экосистем, BIM-мандат для госзаказчиков РФ вступает в силу с 2026 года.
Время для рывка — сейчас.

Покажи, на что ты способен.
