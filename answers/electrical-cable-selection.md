# Отчёт о фактическом алгоритме подбора кабеля (§6.13, ТТН/ТТВ/ТТХ)

**Дата фиксации:** 2026-08-16 (первая фиксация 2026-08-15)
**Проверено по коду:** формульный контракт `electrical-tt-v3-case1-r6` (DEC-19)
**Статус:** снимок фактического поведения; не нормативная документация
**Объект отчёта:** шаг «подбор кабеля» электрорасчёта `self_regulating_tt`, контракт `electrical-tt-v3-case1-r6`
**Первоисточник методики:** Кейс ТНП, ред. 4 от 07.07.2026, §6.13
**Парный отчёт:** [Отчёт о фактическом электротехническом расчёте, разделы §6.14](electrical-tt-calculation.md)
**Аудитория:** продакт-оунер; описано текущее поведение («как есть»), не целевая методика

Электрорасчёт состоит из двух именованных алгоритмов кейса: подбор кабеля
(§6.13, этот отчёт) и формирование нагревательных секций (§6.14, парный
отчёт). В коде оба шага выполняются одним неделимым конвейером
`calculate_electrical_tt`: промежуточного состояния «кабель подобран,
секции не сформированы» не существует, результат сохраняется целиком.
Разделение на два отчёта — редакционное, по границе §6.13/§6.14.

Легаси-линейка условных марок «ТЛТ» и легаси-алгоритм подбора
(блок-схема «Алгоритм Самрег. трубы»: температурно-зависимая мощность,
агрессивность среды → СР/СТ) удалены из кода (DEC-07) и текущему
поведению не соответствуют.

Путь данных шага подбора:

    Тепловой объект (params/results)   q, L, T, Kзап        calculation_service._tt_object_heat_inputs
      + запрос ЭР (навив, нитки, марка)                      cable-selection / batch API
      + assignment-переопределения ЭР                        electrical_assignment_service
      → канонический резолвер входов    приоритет источников electrical_input_resolver.py
      → каталоги power/section/BOM      неизменяемые снимки  electrical_catalog_service
      → подбор марки и ниток            §6.13                self_regulating.py
      → требуемая длина кабеля          L_базы·Kнав·N        → вход §6.14

Сквозной пример (полный разбор — раздел 11): труба с базовыми теплопотерями
25 Вт/м, Kзап = 1,1, длиной 50 м, прямая укладка, T объекта 40 °C,
T среды −30 °C. Автоподбор выбирает `30ТТВ2-СР`, 1 нитку; требуемая длина
кабеля 50 м передаётся в секционирование.

## 1. Общая модель подбора

Подбор не содержит теплофизики. Он принимает готовые теплопотери из
теплорасчёта и решает каталожную задачу:

1. привести требуемую мощность к Вт на метр укладки кабеля и умножить на
   запас: \(P_{\text{треб}} = q \cdot K\);
2. отобрать температурно-пригодные марки:
   \(T_{\text{среды}} \ge T_{\min}\) и \(T_{\text{прод}} \le T_{\max}\);
3. из пригодных выбрать минимально достаточную марку и число ниток:
   \(P_{\text{каб}} \cdot K_{\text{нав}} \cdot N \ge P_{\text{треб}}\);
4. рассчитать требуемую длину кабеля
   \(L_{\text{треб}} = L_{\text{базы}} \cdot K_{\text{нав}} \cdot N\)
   и передать её в алгоритм секционирования (§6.14).

| Шаг | Характер правила | Фактическая запись |
|---|---|---|
| Требуемая мощность | Бизнес-правило §6.13; запас применяется ровно один раз | `P_req = q * K` |
| Коэффициент навива | Геометрия винтовой линии + нормативная таблица максимумов | `K_nav = sqrt(1 + (pi*D/S)^2)` |
| Пригодность марки | Каталожная проверка §6.13 | `T_env >= T_min`, `T_product <= T_max` |
| Покрытие мощности | Каталожная проверка §6.13 | `P_cable * K_nav * N >= P_req` |
| Выбор лучшего | Лексикографическая сортировка §6.13 | `(N, P_cable, P_cable*N, марка)` |

Ни одна из формул не является физическим законом; это принятая методика
источника и паспортные данные каталогов.

## 2. Обозначения

| Обозначение | Величина | Единица |
|---|---|---:|

| \(L_{\text{базы}}\) | базовая длина укладки без заказного запаса | м |
| \(L_{\text{треб}}\) | требуемая общая длина кабеля | м |
| \(D\) | наружный диаметр трубы | мм |

| \(K_{\text{нав}}\) | коэффициент навива | безразмерный |
| \(N\) | количество ниток кабеля | шт. |

| \(T_{\min}, T_{\max}\) | температурные ограничения марки | °C |

## 3. Исходные данные и их источники

### 3.1. Приоритет источников (резолвер)

Каждое каноническое поле разрешается один раз перед формулами в строгом
порядке приоритета (`electrical_input_resolver.py`):

1. `explicit_request` — значение из текущего запроса (cable-selection,
   batch);
2. `assignment_override` — сохранённое переопределение объекта в конкретном
   электрорасчёте (ЭР);
3. `project_setting` — настройки проекта (только \(U\) и \(I_{\text{доп}}\),
   используются в §6.14);
4. `object_heat` — параметры и результаты теплового объекта;
5. mock-профиль (только режимы dev/test; помечает расчёт
   `production_eligible=false`);
6. `not_set` — допустимое «пусто» для трёх полей: шаг навива (прямая
   укладка), нитки (автоподбор), марка (автоподбор).

Источник каждого поля сохраняется в `input_sources` результата.

### 3.2. Поля тепловой карточки объекта, которые читает подбор

| Лейбл формы | Поле объекта | Каноническое поле | Диапазон формы | Как участвует |
|---|---|---|---|---|
| Требуемая температура объекта | `process_temperature` | `product_temperature_c` | −90…600 °C | Проверка \(T_{\text{прод}} \le T_{\max}\) марки |
| Температура окружающей среды | `ambient_temperature` | `ambient_temperature_c` | −70…70 °C | Проверка \(T_{\text{среды}} \ge T_{\min}\) марки; см. 3.3 |
| Температура грунта | `ground_temperature` | участвует в `ambient_temperature_c` | −70…70 °C | Для подземных объектов, см. 3.3 |
| Коэффициент запаса (Kзап) | `safety_factor` / `results.safety_factor_applied` | `safety_factor` | 1,05–1,7 (труба от 1) | \(P_{\text{треб}} = q\cdot K\) |
| Длина трубопровода | `pipe_length` → `results.effective_length` | `base_length_m` | 0,5–200 000 м | База длины кабеля; см. 4.1 |
| Наружный диаметр | `outer_diameter` (м) ×1000 | `outer_diameter_mm` | 10,8–3000 мм | Проверка шага навива и максимума \(K_{\text{нав}}\) |
| Высота обогрева резервуара | `heating_height` | геометрия укладки | от 0,001 м | Длина укладки на резервуар |
| Шаг укладки резервуара | `laying_step` | геометрия укладки | 0,1–0,4 м | Длина укладки на резервуар |
| Количество ниток кабеля | `number_of_threads` | `thread_count` | 1–3 | Фиксация числа ниток |
| — (сохранённый) | `winding_pitch` | `winding_pitch_mm` | см. 3.4 | Коэффициент навива |

Поле «Минимальная температура включения» (`min_switch_temperature`)
подбором **не используется** — оно участвует только в секционировании
(парный отчёт, §6.14).

### 3.3. Расчётная температура среды

Правило `_tt_ambient_temperature` выбирает одно значение \(T_{\text{среды}}\)
из пары «температура воздуха / температура грунта» объекта:

| Условие | Фактическое значение |
|---|---|
| Размещение не «Подземно» | `ambient_temperature`, при его отсутствии `ground_temperature` |
| Подземная труба | `ground_temperature`, при его отсутствии `ambient_temperature` |
| Подземный резервуар | минимум из имеющихся `ambient_temperature` и `ground_temperature` |

Значение используется только в температурной проверке марки (раздел 7)
и в списке марок для ручного выбора. В расчёт длин, токов и мощностей
температура среды не входит.

### 3.4. Поля рабочего пространства ЭР

| Лейбл UI | Поле запроса | Канон | Ограничения UI | Куда идёт |
|---|---|---|---|---|
| Шаг навива, мм (ячейка таблицы) | `winding_pitch_mm` | `winding_pitch_mm` | ≥ 0; строго больше D мм; итоговый \(K_{\text{нав}}\) ≤ максимума диапазона D; для резервуаров редактирование запрещено | \(K_{\text{нав}}\) |
| Ниток (ячейка таблицы) | `thread_count` | `thread_count` | целое 1–3 | Фиксация N |
| Модальное окно «Выбор марки кабеля» → Марка | `cable_mark` (+`mode: auto/manual`) | `manual_cable_model` | точный full_mark из списка | Ручной режим подбора |
| Модальное окно → Количество ниток | `thread_count` | `thread_count` | `auto` либо 1/2/3 | Фиксация N |
| Перезаписать ручные выборы | `skip_manual` (инверсия) | — | чекбокс | Пакетный пересчёт |

Контрол «Критерий подбора» существует в коде UI, но скрыт флагом
(`SHOW_COMMERCIAL_CABLE_BASE_UI = false`); фактически всегда передаётся и
принимается только `selection_policy = technical_minimum` — любое иное
значение отклоняется и резолвером, и формулой.

Значение шага навива 0 равнозначно прямой укладке (\(K_{\text{нав}} = 1\)).

Ручной выбор кабеля выполняется атомарно: эндпоинт `cable-selection`
сначала сохраняет намерение пользователя в переопределения assignment
(марка/нитки/навив, с версионированием), затем запускает полный конвейер
подбор + секционирование и возвращает готовый результат.

### 3.5. Поля, исключённые из контракта TT

Запрос с любым из этих полей отклоняется с кодом `ELECTRICAL_INPUT_RETIRED`:
`max_section_start_current_a` (в запросе), `maintain_temperature`,
`vapor_temperature`, `steam_tracing`, `aggressive_product`,
`winding_coefficient`, `connection_type` и их алиасы.

При этом сама форма объекта по-прежнему собирает и хранит
«Температура поддержания», «Пропарка», «Температура пропарки», «Среда»,
«Температурная группа» — TT-расчёт эти параметры объекта не читает.
Единственная температура продукта в расчёте — «Требуемая температура
объекта» (`process_temperature`).

## 4. Производные входы из теплорасчёта

Расчёт доступен только для объекта с актуальными (не stale) тепловыми
результатами; иначе `ELECTRICAL_HEAT_LOSS_REQUIRED`.

### 4.1. Труба

**Смысл действия:** взять из теплового результата базовые (до запаса)
линейные теплопотери и эффективную длину.

\[
q = \text{heat\_loss\_per\_meter\_base}
\qquad
L_{\text{базы}} = \text{effective\_length} = L + n_{\text{лок}} L_{\text{экв}}
\]

Резерв: при отсутствии `effective_length` берётся `pipe_length`. Локальные
элементы теплорасчёта тем самым увеличивают и длину закупаемого кабеля.

### 4.2. Резервуар

**Смысл действия:** снять тепловой запас с проектной суммарной теплопотери
(она уже содержит \(K_{\text{тепл}}\)), распределить её по длине укладки и
позволить электрической формуле применить запас заново — итог равен исходной
проектной теплопотере при совпадении запасов.

Длина укладки по поверхности:

\[
L_{\text{базы}}
=
\frac{\text{периметр}}{2}\cdot
\frac{h_{\text{обогр}}}{w_{\text{шаг}}}
\qquad
\text{периметр}=
\begin{cases}
\pi D_{\text{рез}}, & \text{цилиндр}\\
2(l+w), & \text{прямоугольный}
\end{cases}
\]

\[
q =
\frac{\text{total\_heat\_loss\_design} / K_{\text{тепл}}}{L_{\text{базы}}}
\]

Тепловой результат резервуара имеет вид
\(Q_{\text{расч}} = q_{\text{уд}} S K_{\text{тепл}} + Q_{\text{доп}}\), поэтому
деление на \(K_{\text{тепл}}\) и последующее умножение электрорасчёта на тот
же \(K\) восстанавливают \(Q_{\text{расч}}\) точно, включая долю
\(Q_{\text{доп}}\). Бизнес-правило §6.13: «запас применяется один раз».

Для резервуара любые трубные входы навива (`winding_pitch`,
`outer_diameter_mm`) в запросе, параметрах объекта или переопределениях ЭР
блокируются кодом `ELECTRICAL_TANK_LAYOUT_INPUT_UNSUPPORTED`;
\(K_{\text{нав}} = 1\). Допустимые формы — только `cylindrical` и
`rectangular`.

### 4.3. Требуемая мощность

\[
P_{\text{треб}} = q \cdot K
\]

\(K\) берётся из `results.safety_factor_applied` теплорасчёта (резерв —
`params.safety_factor`) и может быть переопределён на уровне запроса или
assignment.

## 5. Каталоги подбора

Подбор использует три снимка каталогов; их версии и контрольные суммы
включаются в результат и в фингерпринт расчёта. Для production-расчёта все
три каталога должны быть активными зарегистрированными версиями с
контрольной суммой; иначе расчёт блокируется
(`ELECTRICAL_CATALOG_SOURCE_UNREGISTERED`) либо помечается предупреждением
`ELECTRICAL_POWER_CATALOG_PROVISIONAL` и `production_eligible=false`.

### 5.1. Power-каталог (паспортные мощности)

14 базовых моделей; `nominal_power` — паспортная мощность \(P_{\text{каб}}\),
`max_product_temp` — \(T_{\max}\):

| Серия | Модели (P, Вт/м) | \(T_{\max}\), °C |
|---|---|---:|
| ТТН | 10ТТН2 (10), 17ТТН2 (17), 25ТТН2 (25), 31ТТН2 (31) | 65 |
| ТТВ | 15ТТВ2 (15), 30ТТВ2 (30), 45ТТВ2 (45), 60ТТВ2 (60) | 120 |
| ТТХ | 15ТТХ2 (15), 30ТТХ2 (30), 45ТТХ2 (45), 60ТТХ2 (60), 75ТТХ2 (75), 90ТТХ2 (90) | 150 |

Температурные коэффициенты мощности `q1`, `q2` в строках присутствуют, но
текущим расчётом не используются: мощность берётся паспортной константой
(легаси-формула \(P(T_3)\) удалена вместе с линейкой «ТЛТ»). Поля
`max_vapor_temp` и `voltage` каталога в расчёте также не участвуют.

### 5.2. Источник Tмин марки — каталог секционирования

Отдельного паспортного ограничения по температуре окружающей среды в
power-каталоге нет. \(T_{\min}\) марки выводится как минимальная
температура включения модели по строкам каталога секционирования
(«Параметры Кабеля.xlsx», подробно — парный отчёт §6.14); сейчас это
−40 °C для всех 14 моделей.

### 5.3. BOM-каталог (номенклатура)

18 позиций полных марок: для ТТН существуют исполнения «-СТ» и «-СР»
(8 позиций), для ТТВ и ТТХ — только «-СР» (10 позиций). Каждая позиция несёт
`nomenclature_code`. Кандидат подбора — каждая полная марка BOM, чей префикс
до дефиса совпадает с базовой моделью power-каталога; отсутствие BOM-позиции
для выбранной марки блокирует расчёт (`SPEC_CABLE_NOMENCLATURE_MISSING`).

## 6. Коэффициент навива

**Тип формулы:** длина винтовой линии на цилиндре (геометрия) + нормативная
таблица максимумов из §6.13.

Прямая укладка (шаг не задан или 0):

\[
K_{\text{нав}} = 1
\]

При заданном шаге \(S\) (мм) и диаметре \(D\) (мм):

\[
S > D
\quad\text{иначе отказ}
\qquad
K_{\text{нав}} = \sqrt{1+\left(\frac{\pi D}{S}\right)^{2}}
\]

Максимум по диаметру:

| Диаметр, мм | \(K_{\text{нав}}^{\max}\) |
|---|---:|
| < 57 | 1,0 |
| = 57 | 1,1 |
| 57 < D ≤ 75 | 1,2 |
| 75 < D ≤ 89 | 1,3 |
| 89 < D ≤ 108 | 1,4 |
| > 108 | 1,5 |

Превышение — отказ `ELECTRICAL_WINDING_FACTOR_LIMIT_EXCEEDED`. Следствие
таблицы: для труб диаметром меньше 57 мм любой навив недопустим
(\(K_{\text{нав}}>1{,}0\) при любом \(S>D\)). Для резервуаров всегда
\(K_{\text{нав}}=1\).

Результат округляется до 6 знаков.

---

## 7. Температурная пригодность марки

**Тип правила:** каталожная проверка §6.13.

Марка пригодна, если одновременно:

\[
T_{\text{среды}} \ge T_{\min}
\qquad\text{и}\qquad
T_{\text{прод}} \le T_{\max}
\]

где \(T_{\max}\) — `max_product_temp` power-каталога (65/120/150 °C), а
\(T_{\min}\) — минимальная температура включения модели из каталога
секционирования (сейчас −40 °C у всех моделей).

Если пригодных марок нет — `ELECTRICAL_CABLE_TEMPERATURE_LIMIT_EXCEEDED` с
уточнением: `ambient_below_minimum`, `product_above_maximum` либо
`temperature_combination_unsupported` (каждое ограничение достижимо, но ни
одна марка не проходит оба сразу).

Температура включения \(T_{\text{вкл}}\) в проверке пригодности **не
участвует** — она используется только при выборе строки секционирования
(парный отчёт §6.14).

## 8. Подбор марки и числа ниток

### 8.1. Автоматический режим

Кандидаты — все температурно-пригодные полные марки BOM; для каждой
проверяются нитки \(N = 1, 2, 3\):

\[
P_{\text{каб}} \cdot K_{\text{нав}} \cdot N \ge P_{\text{треб}}
\]

Из прошедших выбирается минимальный по лексикографическому ключу §6.13;
с 2026-08-16 ничьи разрешаются явными рангами (DEC-19):

1. \(N\) по возрастанию;
2. \(P_{\text{каб}}\) по возрастанию;
3. \(P_{\text{каб}} \cdot N\) по возрастанию;
4. температурный класс серии: ТТН → ТТВ → ТТХ;
5. исполнение: «-СТ» раньше «-СР»;
6. полная марка по алфавиту (стабилизатор).

Если ни один кандидат не прошёл — `ELECTRICAL_CABLE_POWER_INSUFFICIENT`.
Порядок ошибок соответствует §6.13: сначала температуры, затем мощность.

Следствия сортировки в текущих каталогах:

- при равной паспортной мощности серию решает температурный класс
  (30 Вт/м есть у ТТВ и ТТХ — выбирается «30ТТВ2-СР» как более низкий класс);
- у базовых моделей с двумя исполнениями («-СТ» и «-СР», серия ТТН)
  автоподбор берёт стандартное «-СТ»; «-СР» достижимо только ручной маркой.
  Выбор исполнения по умолчанию помечается в результате
  (`cable.execution_source = "default"`) и предупреждением
  `ELECTRICAL_EXECUTION_DEFAULTED`.

### 8.2. Ручной режим

Заданная марка ищется по точному `full_mark`; легаси-марка «ТЛТ-…» —
отказ `ELECTRICAL_LEGACY_CABLE_MARK_UNSUPPORTED`; не найдена —
`ELECTRICAL_CABLE_NOT_FOUND`. Марка не подменяется: она проходит те же
температурные и мощностные проверки, и при провале сохраняется ошибка.
Если нитки не заданы, для ручной марки принимается \(N = 1\) (§6.13).
Заданное пользователем число ниток (1–3) фиксируется без перебора.

Источник выбора ниток сохраняется: `manual` (задано), `manual_default`
(ручная марка без ниток), `auto` (перебор).

### 8.3. Установленная мощность

\[
P_{\text{уст}} = P_{\text{каб}} \cdot K_{\text{нав}} \cdot N
\]

Навив и нитки увеличивают установленную мощность на метр объекта — это
правило §6.13 (`P_installed_per_meter = P_cable * K_nav * N`).

## 9. Требуемая длина кабеля — передача в §6.14

\[
L_{\text{треб}} = L_{\text{базы}} \cdot K_{\text{нав}} \cdot N
\]

Для трубы \(L_{\text{базы}}\) — эффективная длина теплорасчёта (раздел 4.1),
для резервуара — длина укладки по поверхности (раздел 4.2).

Выбранная марка, её паспортная мощность и \(L_{\text{треб}}\) передаются в
алгоритм формирования нагревательных секций; фактическая длина, заказная
длина, токи и мощности определяются уже там
([парный отчёт](electrical-tt-calculation.md)).

## 11. Сквозной пример (шаг подбора)

Труба: базовые теплопотери \(q = 25\) Вт/м, \(K = 1{,}1\), эффективная длина
50 м, прямая укладка, \(T_{\text{прод}} = 40\) °C, \(T_{\text{среды}} = -30\) °C,
автоподбор. Числа получены прогоном фактических формул на текущих каталогах.

1. Требуемая мощность: \(P_{\text{треб}} = 25 \cdot 1{,}1 = 27{,}5\) Вт/м;
   \(K_{\text{нав}} = 1\).
2. Температурная пригодность: все 14 моделей проходят
   (\(-30 \ge -40\)); по \(T_{\text{прод}} = 40 \le 65/120/150\) — все.
3. Кандидаты при \(N=1\): \(P_{\text{каб}} \ge 27{,}5\) → 31ТТН2 (31),
   30ТТВ2 (30), 45ТТВ2, 60ТТВ2, 30ТТХ2 (30), 45ТТХ2, 60ТТХ2, 75ТТХ2, 90ТТХ2.
4. Сортировка: минимальная мощность 30 у 30ТТВ2 и 30ТТХ2; более низкий
   температурный класс серии → **`30ТТВ2-СР`**, \(N = 1\), серия ТТВ
   (единственное исполнение, `execution_source = "single"`);
   \(P_{\text{уст}} = 30\) Вт/м.
5. Требуемая длина: \(L_{\text{треб}} = 50 \cdot 1 \cdot 1 = 50\) м →
   передаётся в §6.14 (продолжение примера — в парном отчёте).

Вариант с навивом: та же труба Ø108 мм с шагом навива 500 мм даёт
\(K_{\text{нав}} = \sqrt{1+(\pi\cdot108/500)^2} = 1{,}208502\)
(максимум для Ø108 — 1,4, проходит); установленная мощность на метр
\(25 \cdot 1{,}2085 = 30{,}2\) Вт/м — теперь достаточно 25ТТН2, и автоподбор
выбирает **`25ТТН2-СТ`** с длиной \(50 \cdot 1{,}2085 = 60{,}425\) м
(у 25ТТН2 два исполнения; взято стандартное «-СТ» по DEC-19, в результате
`cable.execution_source = "default"` и предупреждение
`ELECTRICAL_EXECUTION_DEFAULTED`).

## 12. Справочно: зафиксированные особенности шага подбора

Подраздел описывает наблюдения «как есть», выявленные при сверке кода с
§6.13 и каталогами. Оценок и рекомендаций не содержит.

### 12.1. Tмин марки — производная от каталога секционирования

Паспортного ограничения по температуре окружающей среды у марок нет;
\(T_{\min}\) выводится как минимальная температура включения модели в
каталоге секционирования (−40 °C у всех моделей). Следствие: при расчётной
температуре среды ниже −40 °C (например, климатическая политика труб
D < 100 мм подставляет абсолютный минимум — для строки «Москва» −43 °C)
все марки отклоняются с `ambient_below_minimum`, при том что температура
включения объекта ограничена формой диапазоном −40…10 °C и в проверке
пригодности не участвует.

### 12.2. Температура среды и температура включения не связаны

\(T_{\text{среды}}\) (проверка пригодности, этот отчёт) и
\(T_{\text{вкл}}\) (выбор строки секционирования, парный отчёт) —
независимые входы; соотношение между ними не проверяется. Форма допускает
\(T_{\text{вкл}}\) теплее расчётной температуры среды.

### 12.3. Исполнение по умолчанию — «-СТ» (DEC-19, 2026-08-16)

Признак агрессивной среды из контракта исключён; правило выбора исполнения
закреплено DEC-19: при автоподборе для базовых моделей ТТН, имеющих оба
исполнения, берётся стандартное «-СТ», исполнение «-СР» достижимо только
ручным выбором полной марки. Выбор по умолчанию помечается
`cable.execution_source = "default"` и предупреждением
`ELECTRICAL_EXECUTION_DEFAULTED`; при единственном исполнении —
`"single"`, при ручной марке — `"manual"`. Поля формы «Среда» и
«Температурная группа» на выбор по-прежнему не влияют.
До 2026-08-16 ничья решалась алфавитом полной марки и всегда давала «-СР»
(«Р» < «Т») — сохранённые ранее результаты могли зафиксировать «-СР».

### 12.4. Резервуар: два коэффициента запаса

Снятие теплового запаса делит `total_heat_loss_design` на
\(K_{\text{тепл}}\) из теплового результата, а электрорасчёт умножает на
разрешённый резолвером \(K\) (который может быть переопределён запросом или
assignment). При \(K \ne K_{\text{тепл}}\) слагаемое \(Q_{\text{доп}}\)
масштабируется отношением \(K/K_{\text{тепл}}\).

### 12.5. Длина трубы включает локальные элементы

База длины кабеля трубы — `effective_length` теплорасчёта
(\(L + n_{\text{лок}} L_{\text{экв}}\)): эквивалентная длина локальных
элементов увеличивает требуемую и заказную длину кабеля.

### 12.6. Поля формы, не участвующие в TT-подборе

«Температура поддержания», «Пропарка», «Температура пропарки», «Среда»,
«Температурная группа» собираются и сохраняются в параметрах объекта, но
TT-расчёт их не читает (контракт отклоняет их только при явной передаче в
электрический запрос). Температурные коэффициенты `q1`/`q2` и поля
`max_vapor_temp`, `voltage` power-каталога расчётом также не используются.

### 12.7. Навив увеличивает установленную мощность

\(P_{\text{уст}} = P_{\text{каб}} K_{\text{нав}} N\) — по §6.13 навив
одновременно увеличивает длину кабеля на метр трубы и засчитывается в
покрытие требуемой мощности, поэтому при навиве может пройти более слабая
марка (пример в разделе 11).
